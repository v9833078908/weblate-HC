# judge-cost-latency-ab

Артефакты экспериментов из плана
`docs/product/plans/2026-09-17-judge-batching-and-latency-experiments.md`:
пакетная оценка Qwen (эксперимент A) и ускорение участника DeepSeek
(эксперимент B).

## Что здесь лежит

Каждый эксперимент получает собственную директорию `<YYYY-MM-DD>-<slug>/`,
создаваемую runner'ом:

    analysis/probes/judge-cost-latency-ab.py --prepare \
        --corpus <путь к размеченному корпусу> \
        --experiment-id 2026-09-17-anvil-qwen-batch

Внутри экспериментной директории:

- `corpus.json` — зафиксированная копия размеченного корпуса (тексты),
- `corpus.split.json` — разбиение dev/heldout по семействам исходной строки
  с сидом и списком исключений,
- `manifest.json` — манифест эксперимента: плечи, расписание слотов,
  бюджет, цены, критерии решения,
- `frozen-profiles-<arm>.json` — зафиксированные resolved-профили плеча,
- `journal.jsonl` — журнал блоков и каждого POST,
- `results/block-<slot>.json` — результаты блока (попытки, вердикты, usage),
- `results/interrupted-<slot>.json` — незавершённый блок с оплаченными
  попытками,
- `summary.json` — офлайн-сводка и вердикты гейтов.

Формат manifest и CLI описаны в docstring runner'а; шаблон — в
`manifest.template.json`.

## Приватность

- Директории экспериментов игнорируются git'ом (`.gitignore`): тексты строк
  и разметка остаются в этом закрытом хранилище и не коммитятся.
- Права файлов ограничиваются runner'ом (0700 для директорий, 0600 для
  файлов).
- В docs публикуются только обезличенные агрегаты и hash манифеста.
- Ключи провайдеров живут в переменных окружения процесса и никогда не
  записываются в артефакты; сырые тела ошибок провайдера тоже не пишутся —
  только класс ошибки, HTTP-статус и failure kind.

## Стадии

1. `--prepare` — разбиение корпуса и скелет манифеста (офлайн).
2. Человек заполняет `budget` (числовые лимиты + признание остаточного
   риска), `prices`, `est_tokens`.
3. `--dry-run` (режим по умолчанию) — проверка манифеста, scope по языкам,
   формула вызовов и оценка стоимости (офлайн).
4. `--execute --slot <id>` — платный прогон одного слота расписания против
   изолированной QA-БД (`DJANGO_SETTINGS_MODULE=weblate.settings_test` +
   `CI_DB_*`), через настоящий `run_judge_batch` с guard'ом на границе
   каждого POST. Требует явного согласования численного объёма.
5. `--summarize` — офлайн-пересчёт сводки и гейтов из сохранённых блоков.
