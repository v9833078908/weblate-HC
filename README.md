# Визард БДХК → внешний Weblate

Самостоятельный FastAPI и React-визард. Читает карточки через фасад БДХК, принимает видимые листы локкита, создаёт отдельный проект внешнего Weblate и возвращает XLSX/CSV/JSON. Worker хранит snapshot задания в собственной SQLite и не повторяет платный запрос после неизвестного ответа.

План: `docs/product/plans/2026-10-01-external-fastapi-wizard.md`. Разработка и история находятся в отдельном репозитории; существующие службы БДХК не входят в него.

## Локальный запуск

Python 3.12+, Node 24, pnpm 11.19.0 и uv. Из корня:

```powershell
uv sync --locked --dev
pnpm --dir console install --frozen-lockfile
pnpm --dir console build
$env:PYTHONPATH='backend'
uv run python -m app create-user
uv run uvicorn app.main:create_app --factory --app-dir backend --host 127.0.0.1 --port 18511
```

В другом терминале с тем же `PYTHONPATH` и настройками: `uv run python -m app.worker`. Вход — `http://127.0.0.1:18511/auth/login`. Пароля по умолчанию нет; CLI запрашивает имя и пароль длиной не менее 12 символов.

Настройки берутся из переменных окружения; `.env` автоматически не исполняется и не загружается. Образец — `.env.example`. Для Windows задайте `BDHC_API_TOKEN_FILE`, `WEBLATE_API_TOKEN_FILE` на существующие защищённые файлы и `WIZARD_PUBLIC_ORIGIN` на точный origin открытого приложения. Три интеграции имеют разные ключи. Для ручного профиля переменные `PROFILE_LLM_*` не нужны. Во внешний Weblate уходят только нормализованные PO/TBX, а не исходный Excel. Перевод включает выбранные языки и только пустые target-значения.

`/health/live` проверяет API; `/health/ready` дополнительно проверяет heartbeat worker. Пользовательские API закрыты cookie-сессией, изменения требуют CSRF. Исходники, БД и секреты не раздаются статически.

## Обработка локкита

Поддерживаются CSV/TSV/XLSX, табличный TXT и ZIP с такими таблицами. Пределы: 20 MiB на таблицу, 50 MiB на ZIP, 100 MiB суммарно/после распаковки, не более 100 файлов. Только `visible`-листы. Формулы допускаются в явно игнорируемых служебных колонках; формулы source/target запрещены. Неполные строки и все конфликтующие ключи одного листа попадают в карантин. Одинаковые ключи разных листов сохраняются в отдельных компонентах. Исходные строки карантина остаются в возвращаемых данных, но не отправляются на перевод.

Экспорт сохраняет данные, ключи, порядок и готовые target-значения. Оформление, макросы и вычисление формул Excel не переносятся. XLSX содержит текстовые ячейки; CSV возвращается ZIP с отдельной таблицей на лист, а значения, начинающиеся с `=`, `+`, `-`, `@`, защищаются апострофом от выполнения. JSON сохраняет исходные строковые значения.

Черновики живут час, подтверждение БДХК — десять минут. Worker очищает истёкшие черновики; задания и экспорты хранят собственные снимки и не удаляются автоматически. Неизвестный исход MT показывается отдельно: «возобновить» проверяет результат, не отправляя тот же платный POST снова. Отмена прекращает дальнейшие локальные этапы; принятый удалённый перевод может продолжаться.

## Необходимые проверки

```powershell
uv run pytest tests -q --basetemp=.superpowers/pytest-check
uv run ruff check backend/app tests scripts
pnpm --dir console typecheck
pnpm --dir console test
pnpm --dir console build
```

Пять файлов новых backend-проверок охватывают доступ, БДХК, данные, восстановление и безопасный клиент Weblate. Нагрузочные и длительные проверки оставлены после запуска.

## Выпуск и установка

После фиксации проверенного кода: `uv run python scripts/package_release.py`. Архив в `artifacts/` содержит committed source, сборку UI и requirements с хешами. Секреты, настоящие локкиты, логи и БД в него не входят.

Конкретная процедура установки, отдельные systemd-службы, адрес и откат описаны в `docs/product/guides/deployment.md`. Production устанавливается только после отдельного разрешения владельца. Сборка архива не меняет работающий сервер и не запускает платный MT.
