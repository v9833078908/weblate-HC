# Замер: дрейф повторов в need-for-greed (прод)

Дата: 2026-09-03. Инстанс: <https://l10n.herocraft.com>, проект
`need-for-greed`, 8 компонентов, 18 языков. Read-only, через REST API.

Воспроизведение:

```sh
PROD_WEBLATE_API_TOKEN=... uv run python analysis/probes/source-repeat-drift.py \
    --captured-at 2026-09-03
```

Сырой вывод: `analysis/data/source-repeat-drift-2026-09-03/need-for-greed.json`.

Замер отвечает на вопрос, которого стоковый чек `inconsistent` не задаёт:
внутри одного проекта и одного целевого языка взять все группы юнитов с
одинаковым текстом источника и посмотреть, разошлись ли переводы.
`Unit.objects.same()` (`weblate/trans/models/unit.py:377-392`) фильтрует по
`source` **и** `context`, а в монолингвальных игровых форматах `context` —
это ключ строки, поэтому такие группы в стоке не собираются никогда.

## Главный вывод: глоссарий надо исключать, а не чинить

201 из 290 расхождений — это пара «глоссарный термин ↔ обычная строка с тем же
текстом». Это не дефект: глоссарий даёт лемму, а строка UI — контекстную форму.
Если убрать компоненты с `is_glossary=True` из сравнения, остаётся:

| Сравнение цели | Групп | Юнитов | внутри компонента | между компонентами |
|---|---|---|---|---|
| строгое | **122** | **259** | 118 | 4 |
| без учёта регистра | 116 | 247 | 112 | 4 |
| без учёта пунктуации | 116 | 247 | 112 | 4 |

Два следствия для конструкции чека:

1. **Исключение глоссария снимает 168 из 290 групп (58%)**, и при этом убивает
   146 из 150 межкомпонентных расхождений: после исключения между компонентами
   остаётся всего 4 группы, остальные 118 — внутри одного компонента.
2. **Косметические свёртки объясняют всего 6 групп из 122 (5%)**. На hub-1 та
   же доля была 3 из 25 (12%,
   `docs/operations/audits/2026-08-20-heart-abyss-hub-1-translation-qa.md:147-149`).
   Отдельные флаги `ignore-case`/`ignore-punctuation`/`ignore-whitespace` этого
   не оправдывают: то же гасится стандартным `ignore-repeat-drift` на юните или
   погашением строки чека.

Исключение глоссария в проде достигается бесплатно: у `glossary`
`allow_translation_propagation=False`, а стоковые батч-чеки и так требуют
`allow_translation_propagation=True` (`weblate/checks/consistency.py:95-96`,
`:117-120`). Проверено 2026-09-03 через API: у 7 обычных компонентов
`propagation=True`, у `glossary` — `False`.

По компонентам (группа считается в каждом компоненте, где у неё есть юнит):


По языкам:


Ни одна из 122 групп не содержит двух юнитов с одинаковым `context`, то есть
**стоковый `inconsistent` не видит ни одной (0 из 122)**. Это третье
независимое подтверждение архитектурного вывода: на dev-зеркале col4/fr было 0
из 84 (`docs/llm-first/measurements/2026-08-13-phase0-measurements.md:505-511`),
на проде hub-1 — 0 из 25
(`docs/operations/audits/2026-08-20-heart-abyss-hub-1-translation-qa.md:251`).
Отдельно проверено, что проект в момент замера чист: после пересчёта
`updatechecks` на `need-for-greed/ui` активных проверок по всем 8 компонентам и
18 языкам — 0.

## Глоссарий: отдельные классы для аудита

Замерено на том же срезе (`need-for-greed/glossary`, 300 терминов,
298 различных ru-источников):

| Класс | Определение | Найдено |
|---|---|---|
| A. дубль термина | один ru-источник под >1 `context`, переводы в одном языке разошлись | 2 источника, 22 ячейки «источник × язык» |
| B. схлопывание | один перевод в языке на >1 различный ru-источник | 24 ячейки «язык × перевод» |
| C. самопротиворечие | перевод термина X равен источнику термина Y | **0** |
| D. стем-дубль | два ru-термина — формы одной леммы | 5 групп, все 5 намеренные |

Класс A целиком объясняется намеренными омонимами миграции на ru-источник:
`Белоземье` (из `Belomar` и `Whitelands`) и `Сундук Конунга` (из
`Chest of the Jarl` и `Jarl Chest`). Класс B содержит настоящие дефекты:
`скупщик` и `торговец` дают один перевод в `bg`/`de`/`es`, `лошадь` и `скакуха`
— один `kabayo` в `fil`.

Строка «целиком внутри `glossary`: 0» в таблице выше и класс A не
противоречат друг другу: оба дубля класса A имеют тот же ru-текст и в обычном
компоненте (`Белоземье` — `ui/terrain2Title`, `Сундук Конунга` —
`loot/winter.chest`), поэтому их группы посчитаны как смешанные
«глоссарий + обычный компонент», а не как замкнутые в глоссарии. Дубль,
существующий только внутри глоссария, в этом срезе не встретился — но чек
дрейфа его и не увидел бы, а аудит увидит.

Классы C и D по этим числам в v1 не нужны: C не даёт находок структурно (ru
источник против латинских целей), D даёт 5 находок и все ложные
(`Артефакт`/`Артефакты`, `Сундук`/`Сундуки`, `Яйцо`/`Яйца`, `Геод`/`Геоды`,
`Металл`/`Металлы` — намеренные пары единственного и множественного числа).

## Ограничения замера

- Один проект, один срез, одна дата. Доли (5,7% групп с дрейфом от 5 117
  повторных) на другие проекты не переносятся без повторного прогона.
- Классификация «внутри/между компонентами» считается по свёртке цели того же
  прогона; при другой свёртке числа меняются, поэтому в таблицах указаны все
  четыре свёртки.
- Сравнение идёт по форме 0 множественного числа (`target[0]`): проект
  практически не использует плюрали, для проектов с плюралями замер надо
  расширить.
- Замер не решает, какое из расхождений законно. Он считает группы; решение о
  каждой — за владельцем.
