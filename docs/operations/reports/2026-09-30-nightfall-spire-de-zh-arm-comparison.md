# Nightfall Spire: сравнение их пайплайна и Weblate на de + zh_Hans

Дата: 2026-09-30. Инстанс: `l10n.herocraft.com` (`hcgameloc-weblate-1`).
Повод: команда разработчиков предложила сравнить свой машинный перевод с тем,
как переводит Weblate, на двух языках. Отдельный вопрос владельца — можно ли
через API применить правки по critical/major из неудачных проверок и
вердиктов судей.

## Постановка

| | Рука A (их пайплайн) | Рука B (Weblate) |
|---|---|---|
| Где | `nightfall-spire/strings`, `de` и `zh_Hans` | `nightfall-spire/strings-arm-weblate` (создан 2026-09-30) |
| Текст | колонки German / ChineseSimplified пакета `Nightfall Spire Localization.xlsx` | машинный перевод с нуля |
| Источник | `en.po`, 1607 строк, ключ = `Code` пакета | тот же `en.po` (копия), 1607 строк |
| Контекст | глоссарий проекта, persona/style/`language_instructions` проекта | те же (компонент в том же проекте) |
| Движок | их модель и промпт (в пакете только промпты) | `openrouter`: `google/gemini-3.7-flash` для de, `deepseek/deepseek-chat-v3.1` для zh_Hans |

Проверки постановки:

- рука A — действительно их пакет: 1581–1593 строки из 1607 совпадают с
  колонками XLSX посимвольно, остальные 14–26 отличаются только экранированием
  PO (`\n` и `"`);
- исходники в руках совпадают полностью: 1607 ключей, 0 расхождений, 0
  пропусков;
- компонент руки B повторяет настройки руки A (`po-mono`, `*.po`, шаблон
  `en.po`, `new_lang: add`, тот же `language_regex`).

Выборка судей: 300 ключей, по 100 в каждой полосе длины исходника
(≤ 20, 21–60, > 60 символов), порядок — `sha256("nightfall-2026-09-30" + ключ)`,
одинаковая в обеих руках и обоих языках. Строки без букв (только плейсхолдеры
и разметка) исключены: 1591 из 1607 строк судимы. Прогоны судей — те же места,
что в проде (`deepseek-v4-pro`, `atlas/qwen3.8-max`), запущены через producer
API в режиме proposal-only: вердикты пишутся, текст не меняется, а найденные
исправления складываются кандидатами и ждут решения продюсера.

## Layer-0: проверки Weblate (бесплатно, 100 % строк, 1607 в каждой колонке)

Числа сняты с живых проверок юнитов (`active_checks`), не из кэша статистики.

| Проверка | A/de | B/de | A/zh_Hans | B/zh_Hans |
|---|---:|---:|---:|---:|
| `same` (перевод = исходник) | 64 | 38 | 27 | 1 |
| `end_stop` | 19 | 0 | 9 | 9 |
| `escaped_newline` | 12 | 0 | 0 | 0 |
| `game-markup` | 10 | 0 | 12 | 0 |
| `double_space` | 9 | 0 | 0 | 0 |
| `multiple_capital` | 6 | 0 | 0 | 0 |
| `game-number` | 3 | 1 | 7 | 0 |
| `game-token` | 0 | 0 | 10 | 0 |
| `end_colon` | 2 | 0 | 0 | 0 |
| `end_exclamation` | 1 | 0 | 8 | 0 |
| `cyrillic-leak` | 1 | 0 | 1 | 0 |
| `duplicate` | 0 | 0 | 0 | 1 |

Разбор:

- `escaped_newline` — реальный дефект их пакета: литерал `\n` в немецком потерян
  и заменён пробелом. Пример: исходник `Beat  \n <color=#FFD000>Night
  [0]</color>.` → A: `Meistere    die <color=#FFD000>[0].</color> Nacht.`
- `game-markup` и `game-token` — механика, которую ломает их пайплайн
  (10–12 строк в каждом языке); у руки B таких нет.
- `cyrillic-leak` в обоих руках — **ложное срабатывание**: строка
  `Misc.Locale.Russian` с исходником `Русский` (самоназвание языка) обязана
  остаться кириллицей.
- `same` — смешанный класс: имена героев и навыков, самоназвания языков и
  служебные слова (`PvP`, `Portal`) обязаны совпадать; но есть и недоперевод
  (`Button` → `Button`, `Lvl. [0]` → `Lvl. [0]`). Разобран по строкам, не по
  счётчику.
- `end_stop` у zh_Hans в обеих руках (9 и 9) — не дефект, а разница конвенций:
  китайская точка `。` против отсутствия точки в исходнике.

## Что почищено в руке B до судей

Проход по проверкам (по указанию владельца), только механическое и только
подтверждённые ложные срабатывания:

| Что | Строк | Как |
|---|---:|---|
| `escaped_newline` / `newline-count` | 5 | реальный перевод строки заменён на литерал `\n`, как в исходнике |
| Полноширинные цифры и `．／％` | 16 | приведены к полуширинным (`２` → `2`, `９０％` → `90%`) |
| `same` без переводимых слов и на самоназваниях языков | 38 | флаг `ignore-same` |
| `game-number`, где число выражено словом (`verdoppelt`, `双倍`, `七五折`, `三颗`, `第三周`) | 12 | флаг `ignore-game-number` |
| `cyrillic-leak` на `Русский` | 2 | флаг `ignore-cyrillic-leak` |
| `multiple_capital` на разобранных немецких строках | 3 | флаг `ignore-multiple-capital` |

Семантику не трогали: недопереводы (`Button`), `end_stop` у китайского,
`game-markup`/`game-token` у руки A — это то, что должен увидеть судья.

## Вывод

На этой выборке (300 ключей на язык, 1591 судимая строка из 1607) машинный
перевод Weblate даёт меньше блокирующих замечаний, чем пакет команды, в обоих
языках: de — 5.7 % против 8.0 %, zh_Hans — 4.0 % против 10.4 %; по ключам
перевес в пользу Weblate 18:11 (de) и 26:7 (zh_Hans).

Основной источник разрыва — терминология: 42 блокирующих замечания категории
`terminology` у их пайплайна против 14 у Weblate. Глоссарий проекта собран из
их же таблицы, и Weblate получает его в контексте запроса, а их пайплайн, судя
по результату, применяет его менее строго.

Оговорки, без которых вывод читается неверно:

- судья — не носитель языка; он сравнивает два текста одним и тем же
  прибором, но не даёт абсолютной оценки качества;
- выборка 300 из 1591 судимой строки (18.9 %), по 100 на полосу длины
  исходника; на всей компоненте соотношение может отличаться;
- рука A не проходила механическую нормализацию (см. Layer-0): её
  `escaped_newline` 12, `game-markup` 10, `game-token` 10, `double_space` 9 —
  это отдельные дефекты, которые судья не проверяет;
- четыре строки zh_Hans в руке B заполнены вручную (движок не отдал
  результат), это единственный не-модельный текст;
- их модель и промпт неизвестны: сравнение — «их пайплайн против нашего», а не
  «промпт против промпта».

### Что показал ремонт

Ремонт по вердиктам работает, но не сходится сам: из 55 блокирующих строк
42 снялись одной итерацией (перевод заново с причиной отказа), 12 остались
блокирующими, 1 стала хуже и была откачена вместе с четырьмя другими
сомнительными правками. Причины две, и обе важны для продукта:

1. **Судья ошибается на терминологии.** На двух строках он выдал
   самопротиворечивую ошибку («цель `伏特里克` не совпадает с утверждённой
   формой `伏特里克`»), на других — применил глоссарий к составному термину
   (`Ball Lightning` → требует `雷电` для `Lightning`) или потребовал
   аббревиатуру, которой в глоссарии нет. Из-за противоречивого указания
   движок не смог сгенерировать исправление вообще (5 `failed`).
2. **Перевод может обменять один дефект на другой.** Пять правок пришлось
   откатить: английский текст внутри плейсхолдера, несуществующее слово,
   сломанный паттерн имени, критичный пропуск.

Практический вывод: массово применять кандидатов нельзя — продукт и не
позволяет без подтверждения там, где пахнет конфликтом с глоссарием. Правильный
режим — применение пачкой по «обычным» строкам и поштучный разбор спорных
(ровно то, что сделано здесь).

## Правки по API (critical/major)

Путь, проверенный на этом же проекте:

1. Перечислить: `/api/units/?q=judge:reject` (critical), `judge:flag`
   (major), `has:check`, `check:<id>`.
2. Кандидаты на исправление: `weblate judge_backfill_candidates
   nightfall-spire/strings` — сначала dry-run (бесплатно), затем
   `--write --user <кто> --limit N` (один платный вызов ремонта на строку).
3. Применить: `POST /api/suggestions/{id}/accept/` (без revision) либо
   producer API `decisions/<unit>/apply-candidate/` и
   `projects/<slug>/decisions/apply/` (требуют `revision`, который по HTTP
   не отдаётся — нужен shell).
4. Права: `unit.review` + `translation.auto` (+ `suggestion.accept`).
   Гейты: строка в `approved` требует подтверждения потери статуса,
   вердикт с категорией `terminology` — отдельного подтверждения; массовое
   применение такие строки отвергает.
5. Откат: `POST /api/producer/judge-applications/{id}/undo/`.

Правка текста напрямую — `PATCH /api/units/{id}/` с `{"target": [...],
"state": 20}`; число плюральных форм должно совпадать с языком (проверено:
200 и 400 соответственно).

Флаги в Weblate пишутся через **запятую** (`ignore-same,ignore-game-number`),
не через пробел: пробельная запись превращается в один нерабочий флаг.

## Ремонт их пакета (по указанию владельца)

Dry-run `judge_backfill_candidates nightfall-spire/strings` по 55 блокирующим
строкам (24 de + 31 zh_Hans): **50 уже имели готовые кандидаты** — их
подготовили сами прогоны судей, — а 5 не имели.

| Шаг | Результат |
|---|---|
| Генерация 5 недостающих кандидатов (`--write --limit 5`) | 5 `failed`: движок не отдал ни одного варианта (`Voltrik*` ×4 и `UI.DefeatPanel.Header`, zh_Hans) |
| Применение готовых кандидатов | **50 применено**, из них 38 с категорией `terminology` (потребовали подтверждения конфликта с глоссарием), потери статуса `approved` не было |
| Перепроверка тех же 55 строк тем же судьёй | **снято 42**, осталось блокирующими 12, стало хуже 1 |
| Откат | 5 правок откачены (3 через `judge-applications/undo`, 2 — прямой записью: гард отказал, потому что перепроверка записала по ним новые предложения) |

Откачены именно те правки, где новая версия объективно хуже:

| Строка | Было | Стало (откачено) | Почему |
|---|---|---|---|
| `Resources.view_upgrade_heroslot.Description` (de) | `Verbessere {Value/amount} {amount[Heldenplatz\|Heldenplätze]}` | `…Helden-{amount[slot\|slots]}` | **английский текст внутри плейсхолдера** |
| `UnitViewData.ViverBossViewData.Info` (de) | `Er ist ein Wyvern.` | `Er ist wyver.` | несуществующее слово |
| `PowerUpViewData.VoltrikPowerUp7ViewData.Name` (de) | `Verbesserte Impulsentladung+` | `Verbessert: Impulsentladung+` | сломан паттерн имени способности |
| `PowerUpViewData.Rerolls_LP_PowerUp_ViewData.Name` (de) | `Mehr Neuwürfe` | `Mehr Neu würfeln` | читается как команда, лишний пробел |
| `PurchasableItem.BaseVipAccountOfferViewData.Description` (zh) | `…1000经验，以及每日50水晶+1000金币` | `…每日1000经验、50水晶和1000金币` | major → **critical** (omission) |

Итог ремонта: из 55 блокирующих строк **42 снято**, 13 остались. Все 13 — это
разобранные выше случаи (шум судьи, спорная строгость глоссария, каламбуры);
кандидатов по ним сейчас нет, `judge_backfill_candidates --write` может
сгенерировать их заново (13 платных вызовов), но повторный автоматический
проход по ним снова даст то же качество решений — их место у человека.

Скорость и цена: 50 применений — бесплатно, перепроверка 55 строк — 40
вызовов судей, генерация кандидатов — 5 вызовов ремонта (все пять неудачные).

Кандидаты — это не текст судьи, а заново переведённые строки движком проекта
(`openrouter`) с причиной отказа в запросе. Примеры: `2 Etagen` → `2 Stockwerke`
(термин из глоссария), `提升暴击率` → `提升暴击几率`, `要有闪电` → `要有雷电`.
Часть кандидатов спорная: `Er ist ein Wyvern.` → `Er ist wyver.` — такие
строки перепроверка должна поймать и откатить.

Пять строк без кандидата разобраны вручную:

| Строка | Что говорит судья | Разбор |
|---|---|---|
| `PowerUpViewData.VoltrikPowerUp6ViewData.Description`, `…7…` | «цель `伏特里克` не совпадает с утверждённой формой `伏特里克`» | **дефект судьи**: сравнение самопротиворечиво, глоссарий и цель совпадают посимвольно |

Первый случай стоит починить в самом судье: самопротиворечивая ошибка
терминологии не только оставляет строку блокирующей, но и делает
бесполезным ремонт — движок не может выполнить противоречивое указание и
возвращает пустой результат.

## Когда можно передавать команде

Продукт сам считает готовность: на странице компонента блок :guilabel:`AI
judge` показывает три счётчика и даёт кнопку :guilabel:`Download for hand-off`
только когда одновременно выполнено:

1. ни одной строки с незакрытым блокирующим вердиктом (`needs_human = 0`);
2. ни одной непроверенной строки (`not_reviewed = 0`);
3. ни одного неразобранного ответа судьи (`unparsed = 0`);
4. ни одна проверенная строка не изменилась после вердикта — сверяется хеш
   текста и контекста, так что ручная правка снова делает строку непроверенной.

Счётчики на 2026-09-30 после ремонта (блокирующие — по живым проверкам
юнитов, остальное — из статистики продукта):

| Язык | Всего | Проверено судьёй | Блокирующих сейчас | Не проверено |
|---|---:|---:|---:|---:|
| de | 1607 | 300 | 7 | 1307 |
| zh_Hans | 1607 | 300 | 6 | 1307 |
| остальные 13 языков | 1607 | 0 | 0 | 1607 |

То есть **сейчас передавать нельзя**: охват судьи 18.7 %, 13 блокирующих строк
(все — разобранные выше спорные случаи), у остальных языков проверок не было
вовсе. Механический бэклог гейт вообще не проверяет — а он есть:
`escaped_newline` 12 (de), `game-markup` 10/12, `game-token` 10 (zh_Hans),
`double_space` 9 (de), `end_stop` 19/9.

Порядок до передачи:

1. **Механика (бесплатно).** Автофикс терминальных знаков и пробелов
   (`end_stop` 3 из 19, `end_colon` 2, `end_exclamation` 1, `double_space`
   4 из 9 у de; `end_stop` 9 и `end_exclamation` 8 у zh_Hans), затем
   построчный разбор `escaped_newline`, `game-markup`, `game-token` — это
   правки в их файлах, часть чинится в самом исходнике.
2. **Судить весь объём.** 1307 непроверенных строк на язык ≈ 915 вызовов на
   язык (по замеру 300 строк = 210 вызовов); для de + zh_Hans ≈ 1830 вызовов.
   Все 16 языков пакета — ≈ 18 000 вызовов, поэтому разумно закрывать языки
   по мере надобности.
3. **Закрыть блокирующие.** Кандидаты (`judge_backfill_candidates --write`) +
   применение, спорные — вручную; каждая правка обнуляет вердикт, поэтому
   после правок строки нужно перепроверять (в UI это делает «Принять
   исправление», в API — отдельный вызов).
4. Кнопка :guilabel:`Download for hand-off` появляется сама — это и есть
   объективный сигнал «готово к передаче».

Реалистично: de + zh_Hans — один рабочий день на механику и два полных
прогона судей; остальные языки — после того, как механика закрыта одинаково
для всех.
