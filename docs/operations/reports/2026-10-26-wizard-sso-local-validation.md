## Что реализовано

- Weblate OIDC provider на Django OAuth Toolkit: штатный вход/MFA, S256 PKCE,
  одноразовый code, стабильный subject, RS256/JWKS и перекрытие signing keys.
- Делегация с закрытой матрицей scopes и актуальными штатными правами Weblate.
  Профиль переводчика доступен без API-ключей, routing и URL провайдера.
- Wizard Authlib-клиент, серверная транзакция state/nonce/PKCE, собственная
  Secure/HttpOnly/SameSite=Lax сессия и зашифрованные серверные grants.
- Явная операторская привязка прежних владельцев с dry-run и аудитом. Совпадение
  логина не объединяет аккаунты. Общий служебный token fallback в SSO запрещён.
- Ограниченные сроки, ротация refresh, durable отзыв при logout, пауза фоновых
  операций при утрате доступа. Новый вход сам не возобновляет задания.
- Сохранение ключей операций и ответов; нет автоматического повторного платного
  запроса при неизвестном результате. Старое служебное задание нельзя перепривязать.
- Точный rollback bridge для аддитивной схемы `0005`, без восстановления старой
  БД поверх новых журналов; workers и внешние записи при откате остаются выключены.

Оба флага SSO выключены по умолчанию. Пароли Weblate в Wizard не передаются.
Обычные Token/Bearer/Session API-клиенты Weblate сохраняют прежнее поведение.

## Отдельное ревью и исправления

Рецензент проверил обе ветки целиком, без доступа к production/приватным данным.
Critical замечаний нет; три Important воспроизведены и исправлены одним проходом:

1. Чтение и захват refresh теперь сериализованы короткой SQLite-транзакцией,
   обновление привязано к исходному ciphertext. Параллельный читатель ограниченно
   ждёт победителя. Живое обновление даёт временную паузу, потерянное — новый вход;
   старый refresh повторно не отправляется. Реальный двухпоточный тест подтверждает
   один запрос refresh и одинаковый свежий access token у обоих читателей.
2. Локальный auth-отказ до quality POST сохраняет возобновляемый отказ с прежним
   operation key. После явного восстановления цикл завершается без второй записи.
3. Отзыв до MT и между chunks сохраняет неотправленные строки отдельно от
   неизвестной оплаты. Типизированный отказ delivery guard проходит через
   стандартную обёртку machinery; отсутствие финансового claim проверяется
   по каждой строке. Полученный ответ остаётся `received`. Явная сверка с новой
   делегацией того же актора обновляет только binding, применяет сохранённый ответ
   или освобождает доказанно неотправленные строки. Legacy/чужой актор отвергаются;
   неизвестный paid result остаётся заблокированным.

Все замечания исправлены, отложенных Minor нет. Рецензент не подтверждал действительную
production-конфигурацию, приватные данные и платных провайдеров: они исключены из
этого этапа. Повторный запуск им полных suites не требовался; приведены результаты
проверок исполнителя.

Решение по рабочему окружению: повторно использованы отдельные implementation
clones на новых ветках, поскольку app worktree относится к внешнему репозиторию,
а приложения имеют собственные Git. При ошибке выбора понадобится повторить
локальную интеграцию; production этим решением не меняется.

## Ограничения и последующий перенос

Не выполнялись production SSH, миграции, остановка/перезапуск production или
shared dev-stack. Git main не изменяется. Реальные адреса HTTPS, клиент OIDC,
TLS trust и секреты production потребуют отдельной операторской настройки.
Немедленный удалённый отзыв при недоступной сети не гарантируется: локальный
доступ закрывается сразу, отзыв на Weblate повторяется из outbox. Уже принятый
провайдером запрос может завершиться с сохранением ответа и квитанции.

Для production действует отдельный план переноса и отката. Новые входы и
задания разрешаются только после проверки данных и квитанций с выключенными
внешними записями. Старое задание остаётся изолированным.
