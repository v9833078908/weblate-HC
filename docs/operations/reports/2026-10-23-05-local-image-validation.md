## Решения при проверке

- Использованы существующие изолированные publication-клоны и точный опубликованный
  commit; исполняемый код в этом этапе не редактировался. Стоимость ошибки выбора
  кандидата закрыта проверкой SHA, label revision и хешами установленных файлов.
- Предыдущее ревью исполняемого кода остаётся действующим; новый материал —
  свидетельства реальной сборки и проверки. Перед публикацией этот пакет проходит
  отдельное ревью полноты и корректности заявлений; оно завершено без
  Critical/Important, область аутентификации дополнена реальным HTTP-тестом.
- Первая дополнительная проверка архива ошибочно ожидала равенства OCI manifest
  и config digest. В containerd-backed Docker это разные сущности. Проверена
  полная цепочка обоих digest и всех слоёв; сохранены оба идентификатора.
  Архив не пересобирался и проверки идентичности не ослаблялись.
- Docker сообщает сжатый размер 592047379 байт. Резерв импорта рассчитан независимо
  по фактически распакованным слоям 1909328384 байт. Для этого образа оба расчёта
  дают минимум 8 ГиБ; сжатый размер нельзя выдавать за несжатый.

## Что требуется перед переносом

Разрешения на перенос и deployment сейчас нет. На целевом сервере заново
проверяются место, baseline image/source/миграции и согласованные backups;
старый допуск не используется. Известный прежний недостаток места на production
этой локальной сборкой не устранялся и заново не измерялся.

При дальнейшем разрешённом импорте учитывается формат ID целевого Docker:
на этой рабочей станции Image.Id равен OCI manifest digest, другой image store
может показывать config digest. Нельзя просто игнорировать несовпадение gate.
Нужно сверить архив SHA, config и RootFS, label revision и платформу и сохранить
однозначную привязку фактического target ID. Совместимость импорта с конкретным
production Docker на этом этапе не проверялась.

Собранный образ и архив сохраняются. Изменения этого этапа в Git ограничены
планом, данным отчётом и JSON-манифестом; приложение и миграции не менялись.
Публикация — только в feature-ветках, автор и committer y.bazenkov.

большие архивы не перехешировал самостоятельно. Исполнитель отдельно проверил

workers, живой БД, target import, текущего места и backups остаётся будущей

при публикации; этот вердикт не разрешает merge или deployment.
