## Ремарка про объем и эффективность

**Почему цифра токенов выглядит огромной, а расход - нет.** Из 4.94 млрд токенов 4.80 млрд (97%) - это cache read: агент на каждом шаге перечитывает уже закэшированный контекст сессии. Новых токенов реально сгенерировано/прочитано ~148 млн. Cache read стоит ~10% от цены input либо $0 в подписке - поэтому "миллиарды токенов" = ~$2 640, а не десятки тысяч долларов.

**Про "съеденные" Kimi и GLM.** Это было сознательное решение, а не утечка: 1.24 млрд токенов (25% объема) намеренно уведены на фиксированные подписки Kimi K3 и GLM (механическая работа, ресерчи, субагенты) - именно чтобы НЕ жечь дорогие модели. Квоты выбраны до конца, потому что они самые дешевые в пересчете на токен. Дорогой Opus ($1 754 из $2 640) шел только на архитектуру, сложный код и платные эксперименты judge.

**Про темп "в одно лицо".** Написано руками агентов, проверено человеком: 25.5k строк кода+тестов и 102k строк проектной документации за 10 рабочих дней - это и есть причина расхода. Эквивалентная команда (бэкенд + QA + техпис + локализационный инженер) стоила бы кратно дороже $190/рабочий день, в которые обошлись агенты.

**Меры по снижению расхода (уже применяются / план):** маршрутизация ресерчей на подписочные модели по умолчанию; короче сессии = меньше cache-write; платные эксперименты - только с запечатанным корпусом и gate-критериями (уже правило); ежемесячный отчет расхода по эпикам из логов сессий.
