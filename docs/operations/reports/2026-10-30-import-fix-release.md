## Подготовка

Кандидат `sha256:cdf45b1707f9963c4ce1ab46a8a3785a3d549f60d698d388842473f21bba6000`
собран непосредственно из прежнего production-образа
`sha256:2a84408f40e404b361f77a8245ea393b7534ddd9f8fa0544a0f4f3a2d4ead5be`
с заменой пяти файлов приложения из целевого коммита. Их исходное содержимое
перед сборкой совпало с ревизией прежнего образа
`6b211b5a449b4e827a4e80d7df9e237a69c603ea`; монтирования не перекрывают эти
файлы. В изолированном контейнере без сети синтетический импорт обработал
9483 из 9483 строк при лимите памяти 450 МиБ и пиковом RSS около 291 МиБ.

Запущенный до выпуска платный перевод дождались без прерывания: Celery сообщил
`SUCCESS`. Перед переключением проверили отсутствие активных и зарезервированных
задач на пяти воркерах и пустые очереди.

## Резервная копия и переключение

На время обслуживания вход в Weblate закрыли и остановили приложение. В
`/srv/hcgameloc-releases/import-recovery-9f6b883/` сохранены согласованный
PostgreSQL dump и архив `/app/data`; контрольные суммы обоих файлов повторно
проверены. Dump восстановлен в отдельный PostgreSQL без сети, проверено наличие
499686 строк `trans_unit`. Архив файлов распакован и сверен. Это проверка
восстановимости данных, а не восстановление production из копии.

После запуска нового контейнера Docker health стал `healthy`, однако первая
проверка страницы входа внутри сервера вернула HTTP 502. Сценарий сразу запустил
откат, не открывая доступ пользователям. По времени файлов сценария проверка
очередей завершилась около 14:25 UTC, откат и восстановление nginx — около
14:41 UTC. Это приблизительные границы окна обслуживания.

## Состояние после отката

Прежний образ `2a84408f40e4…`, ревизия `6b211b5a449b…`, снова запущен и
имеет статус `healthy`. Страница входа через host nginx ответила HTTP 200;
Granian, nginx и шесть процессов Celery работают. Автоматический наблюдатель
завершился со статусом `cutover-failed` и больше не выполняет выпуск. Новый
образ не оставлен работающим. Повторное переключение не запускалось.

Причина единственного 502 не установлена: контейнер кандидата был пересоздан
при откате, его журнал не сохранился. Гонка готовности при старте приложения —
возможное объяснение, но доказательств недостаточно. Локально подготовлен
вариант сценария с ограниченным повтором проверки страницы входа и сохранением
приватного журнала при отказе; проверены имитации временного и постоянного
отказа. Он не применён к production.
