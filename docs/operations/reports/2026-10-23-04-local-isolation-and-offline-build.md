## Изменения

- Wizard: статус `archived_unknown`, постоянная запись `run_isolation` без новой
  миграции, офлайн CLI с dry run по умолчанию и одной SQLite-транзакцией.
  Проверяются полный долговечный снимок бэкапа, свежая сверка, аренды и операции.
- Запрет resume/cancel, claim, поздних callback и платных действий по remote-project
  identity, включая quality и генерацию профиля. Другой owner/alias не обходит
  запрет; задачи остальных известных проектов продолжают выбираться.
- Preflight допускает только согласованную архивную запись. Другой unknown,
  повреждение журнала или неопределённая quality-операция сохраняют блокировку,
  даже при failed-цикле или отсутствующем родителе. Откат только кода тоже
  валидирует архив. Payload, ключи и финансовый исход операции не меняются.
- Карточка показывает изоляцию и неизвестный результат без кнопок повторной
  отправки. Диагностика, обновление состояния и клавиатурная навигация доступны.
  API-контракт запрещает resume и успешный outcome для архивного состояния.
- Weblate: только операторские инструменты подготовки контекста и контроля места,
  документация и lint-настройки тестов. Django/MT/judge runtime в этом этапе
  не изменялся; новых миграций нет. install/rollback используют новый preflight,
  сами shell-сценарии в этом этапе не переписывались.

## Решения и исправления ревью

1. Использованы два уже изолированных publication-клона на пользовательских
   ветках: исходный checkout и существующий стенд не редактировались.
2. Повреждённый журнал блокирует обе сохранённые идентичности; orphan-запись
   без восстанавливаемой идентичности закрывает допуск глобально. Это осознанный
   отказ до ручной сверки. Известные посторонние проекты остаются доступны.
3. Бэкап сверяется по всему долговечному SQLite-снимку; сессии и heartbeat
   исключены как меняющаяся служебная информация. Гонки поздних callback
   закрываются также условием SQL по архивному статусу и наличию записи.
4. Async MT требует реальный Store как источник полномочий изоляции. Старый
   интеграционный тест, не передававший Store, исправлен; пропуск проверки
   при отсутствии хранилища запрещён.
5. Замечание P1 принято: terminal/failed цикл не доказывает исход внешнего
   запроса. Независимый scan quality_operations и шесть регрессий воспроизвели
   прежний допуск и проверили отказ без изменений БД.
6. Замечание P2 принято: smoke — проверка упаковки через find_spec machinery,
   импорт базовых модулей и pin NumPy, без Django-моделей/настроек/ключей.
   Команда проверена в холодном subprocess с положительными и отрицательными
   фикстурами; это не тест реального нового образа или Django initialization.
7. Выполнен один цикл исправлений после независимого ревью, без повторного
   ревью по принятому процессу. Открытых Critical/Important и отложенных Minor нет.
8. Форматные mixed-CRLF файлы приведены к LF для git diff --check. Извлечение
   русскоязычных task briefs выполнено локальным Python; спецификация не менялась.
   Исторические исходные упоминания моделей/инструментов сохранены по указанию
   пользователя, новые публикационные тексты и Git identity используют его имя.

Первый полный запуск в Windows sandbox дал 119 passed и 358 ошибок Temp;
он не является результатом продуктовой проверки. Использованы отдельные
локальные временные каталоги и процесс с разрешённым доступом; остановлены
только идентифицированные собственные зависшие тестовые процессы. Dedicated
venv создан отдельно от runtime стенда. Первые новые фикстуры quality-cycle,
Temp и браузерных backend meta-настроек исправлены до итоговых прогонов;
pycache тестовых модулей отключён для детерминированной проверки версии.
Служебные Node NO_COLOR/FORCE_COLOR warnings не связаны с доступностью.

## Границы проверки и дальнейший перенос

Ревью не подтверждает фактическую остановку production writers, состояние
live-сервисов/схемы/диска, биллинг провайдера, реальную сборку, импорт или очистку.
Намеренная подмена обеих идентичностей администратором БД и действия пользователей
напрямую в Weblate находятся вне локальной защиты визарда. Revision записи
выявляет повреждение, но не является криптографической защитой от администратора.

Фактический образ не собран и не импортирован, Docker не очищался. Проверка
синтаксиса/подготовки и синтетическая packaging-регрессия не заменяют будущий
тест собранного образа. Полная Django CI, pylint и mypy всего Weblate не
запускались: runtime Weblate не менялся. Ранее выполненные интеграционные
проверки production-исправлений этим отчётом не заменяются.

Перед production нужны отдельное разрешение, новая сверка baseline и
проверенный архив текущего образа. В разрешённое окно — прекратить старых
писателей, сделать и проверить согласованный бэкап, свежую read-only сверку,
применить изоляцию и снять второй бэкап как install baseline. Затем отдельно
разрешённая внешняя сборка, проверка фактического места, согласованные
очистка/импорт, установка Weblate, затем визарда и приёмка с выключенными
внешними записями/профилями. Старое задание не продолжать. Откат сохраняет
актуальную БД и журнал; старые workers не включаются. Merge и deploy сейчас
не выполняются; пользователь выбрал публикацию feature-веток без PR.
