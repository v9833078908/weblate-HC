## Изменения

Наличие ProducerRun больше не включает durable-доставку для обычного задания
судьи. Native Weblate сохраняет настроенные streaming, retry/fallback и
retry исправляющего движка. Визард сохраняет запрет повторного платного запроса,
журнал ответов, восстановление и verify_only. Поле политики из тела клиентского
запроса не включает этот режим.

`weblate/trans/delivery_policy.py` задаёт серверную политику `wizard-v1`:
её сохраняют принятый MT endpoint, callback после резервирования quality receipt
и доверенная OAuth-делегация. Контекст допуска сбрасывается после callback,
включая отказ/исключение. Фоновые процессы читают сохранённую политику, а не
контекст исходного HTTP-запроса. Неизвестная политика и циклическое происхождение
заданий закрывают доступ вместо перехода к обычной отправке.

Исторические делегации, MT receipts, собственные финансовые журналы и цепочка
`resumed_from` удерживают защиту старых операций. Resume сохраняет вычисленный
режим родителя явно. Новая фоновая deferral-задача не получает возможности
заново оплатить неопределённую работу визарда: происхождение определяется по
сохранённому verdict и его run; автоматическая deferral закрывается, но исходное
неопределённое задание не завершается и не возобновляется. Его восстановление
остаётся явным действием через существующую сверку.

В старом клиентском пути Wizard `start_judge` добавлен стабильный Idempotency-Key
из estimate_id. Основной full-quality путь уже передавал ключ. Это сохраняет
серверный допуск и при служебном token, когда OAuth-делегации нет.

Схема БД и миграции этой доработкой не меняются: признак записывается только
при принятии новых операций в существующий JSON. Данные и секреты production
не копировались для этих тестов. Проверки реализации шли в отдельных worktrees
и одноразовых контейнерах; последующее переключение ручного стенда описано ниже.

Weblate запускался в отдельной синтетической PostgreSQL test DB на внутренней
Docker-сети без внешнего выхода, без production credentials и воркеров.
Wizard использовал отдельные test DB и MockTransport. Успех означает проверку
программных контрактов; качество настоящих LLM и доступность production
провайдеров этим не измерялись. Фронтенд не менялся; новая browser-приёмка
конкретного production-выпуска остаётся этапом установки.

Первый широкий прогон: 528 PASS и один FAIL нового fallback-теста. Причина была
в тесте: вызов без номера места использовал совместимый no-seat API, который
по контракту не включает fallback. Тест исправлен на настоящий seat=1 и полную
конфигурацию резервного endpoint; он проходит и на production-ревизии, и на
исправленном кандидате. Код fallback и настройки production не изменялись.

Независимое read-only ревью выявило два Important: потерю происхождения при
deferral и историческом resume. Оба исправлены в одном проходе, добавлены
проверки запрета дополнительной отправки. Повторного независимого подтверждения
production-готовности не было; итоговые тесты выполнены исполнителем.

Локальные протоколы находятся в `.superpowers/native-compatibility-20261028/`
основного рабочего каталога: `red.log`, `baselinefinal.log`, `finaltarget.log`,
`final.log`, `producerfinal.log`, `wizard-red.log`, `wizard-green.log`,
`wizard-green.xml`, `wizard-green-network.json`. Первый клиентский RED выявляет
отсутствие ключа в старом пути запуска. Три предупреждения Wizard относятся к
deprecated API зависимостей и не являются падениями. Ruff доступен версии
0.16.10; для изменённых файлов использована конфигурация проекта с явным
переопределением required-version, без изменения закреплённой версии в репозитории.

Wheel собран прямым вызовом штатного `setuptools.build_meta.build_wheel` из
временной копии дерева в контейнере без сети. Во временном образе нет pip и
исполняемого build frontend; попытка использовать uv backend также не подходит
проекту с setuptools. Конфигурацию проекта и зависимости ради сборки не меняли.
Артефакт `hcgameloc-2026.8.1.dev0-py3-none-any.whl`: 10991655 байт,
SHA-256 `78cb02c79eecb42a11792e3d0415058e96f10e63335d3554eced8c3d332bcc64`.
ZIP CRC и побайтовое совпадение 7 затронутых runtime-модулей проверены;
`wheel-backend.log` и `wheel-proof.json` сохранены локально. Это пакет Python,
а не готовый production-образ с проверенной конфигурацией и локализациями.

## Оставшиеся условия переноса

### Ручной локальный стенд

После отдельного разрешения пользователя 28 октября ручной стенд переключён на
исправленные ветки Weblate и Wizard. Адреса сохранились:
`https://127.0.0.1:19443/` и `https://127.0.0.1:19444/auth/login`.
Использованы прежние локальные PostgreSQL/SQLite, тома, uploads, сертификаты и
учётные записи. Миграции этой доработки отсутствуют; повторное заполнение данных
не выполнялось. Старый контейнер сохранён остановленным.

Перед переключением сделана приватная копия баз, файлов и настроек в
`.superpowers/local-testing-20261027/backup-before-native-20261028-211240/`
основного рабочего каталога. Доступ ограничен текущим пользователем и SYSTEM.
PG dump проверен через pg_restore list, SQLite — через integrity_check и backup
API. Хеши и количества 11 бизнес-таблиц Weblate и 10 защищаемых таблиц Wizard
совпали до/после переключения и браузерной проверки; изменяемые сессии и heartbeat
исключены из проверки неизменности бизнес-данных.

Weblate healthy; Wizard live/ready подтверждают работу API, БД и worker.
Браузерная проверка прошла: ссылка Weblate, согласие SSO и переход к проектам
Wizard без повторного пароля. Все браузерные запросы ограничены двумя локальными
адресами, платные маршруты дополнительно блокировались. Внешняя запись Wizard,
циклы качества и LLM-агент выключены; Weblate находится во внутренней Docker-сети.
Журналы оплачиваемых операций остаются пустыми. Production не подключался.

`start.ps1` теперь использует новые исходники и прежнее окружение зависимостей.
Локальные протоколы: `native-switch.json`, `native-switch-health.json`,
`native-navigation-live/result.json`. Подготовлен
`rollback_local_native_versions.ps1`, возвращающий прежний код с сохранением
текущих БД; его синтаксис проверен, сам откат после успешного переключения не
выполнялся. Приватные настройки, ключи и бэкапы в Git не публикуются.

### Production

Перед production нужны новый согласованный комплект образов/выпусков, актуальная
инвентаризация и бэкапы, репетиция старого точного образа на актуальной новой
схеме, проверка HTTPS/OIDC-конфигурации и разрешённое окно переключения. Готовые
переводы и журналы сохраняются; тестовая БД не заменяет production. Новые
journal-задачи нельзя передавать старому коду при откате. Никакие main-ветки
этой работой не объединяются.
