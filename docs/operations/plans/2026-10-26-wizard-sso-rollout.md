# Перенос входа Wizard через Weblate

Статус: инструкция подготовки; выполнение на production отдельно не разрешено.
Основание: `docs/product/plans/2026-10-26-weblate-wizard-single-sign-on.md`.
Настройки: `docs/product/guides/weblate-wizard-single-sign-on.md`.

1. Сверить production HEAD/image, место и расхождения с проверенным кандидатом.
   Уточнить HTTPS origins, сертификаты, DNS и доверие TLS между двумя серверами.
   Не совмещать перенос с неподтверждённым новым обновлением Weblate.
2. Проверить текущие образы и восстановимость резервных копий. В разрешённое окно
   остановить писателей, сделать свежий бэкап до изоляции старого задания,
   сохранить его изоляцию без возобновления и сделать второй проверенный бэкап.
   Включить БД, файлы, конфигурацию, signing/encryption keys и оплаченные журналы;
   не помещать секреты в Git/публичные отчёты. Место под образы согласовать отдельно.
3. Установить Weblate, первоначально оставляя флаг работающего сервиса выключенным.
   Для миграционного management process включить подготовленную SSO-конфигурацию
   с RSA key, чтобы применились и wizard_auth, и optional oauth2_provider migrations.
   До запуска убедиться, что migration plan не меняет переводы/оплаченные журналы.
4. Установить Wizard, выполнить миграцию 0005; внешние записи и profile agent
   оставить выключенными. Подготовить client secret и encryption key вне БД/Git.
   Выполнить dry-run списка явно проверенных привязок старых аккаунтов.
5. Зарегистрировать OAuth-клиент с точным HTTPS callback; включить SSO сначала
   для проверки выбранными пользователями. Проверить MFA, отсутствие чужих
   проектов, авторизацию API/worker и read-only доступ. Не возобновлять старое
   задание; вход и миграции не должны ставить его обратно в очередь.
6. Сверить числа и отпечатки защищённых таблиц, исходные владельцы и квитанции.
   Только после отдельного допуска включить новые внешние записи. Зафиксировать
   версии обоих приложений и текущие образы; не включать service-token fallback.

## Откат

Сначала отключить новые внешние операции, отозвать OAuth-клиент/делегации и
остановить новые workers. Если Weblate недоступен, остановить его исполнителей
в разрешённом окне: один локальный logout не является подтверждением удалённого
отзыва. Вернуть сохранённые образы и конфигурацию, не стирая новые квитанции.

Wizard поддерживает read-only code rollback для точной схемы 0005 с отдельным
`--allow-sso-addition`: проверяются отпечатки трёх новых таблиц и sessions.
Неизвестные столбцы/таблицы/триггеры не допускаются. Bridge добавляет только
проверенные декларации миграций прежнему коду; старые workers остаются отключены
и masked. Настройки SSO, внешних записей и общего API-токена при откате выключаются.
Таблицы identity/grants остаются в БД; текущие токены не работают в старом коде.

В Weblate оставить аддитивные auth/OAuth-таблицы, если проверено чтение прежним
образом; не выполнять обратные удаления таблиц, содержащих новые данные, вслепую.
Не восстанавливать старую БД поверх новых переводов или квитанций. Полный restore
допустим только после доказательства отсутствия новых durable записей; иначе
сначала сверка и отдельная процедура сохранения новых данных.
