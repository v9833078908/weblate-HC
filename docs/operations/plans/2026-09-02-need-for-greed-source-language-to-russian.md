## Решение владельца

Исходный язык всех компонентов `need-for-greed` становится **русским** вместо
английского. Вчера (2026-09-01) разработчик добавил новые ключи с русским
текстом, и они легли в английский перевод; после переезда эти ключи должны
быть на русском в `ru` как источник. Заметки глоссария обязаны попасть в
контекст LLM (`weblate/machinery/llm.py:157` шлёт `source_explanation` /
`target_explanation` глоссария в промпт).

## Почему пересоздание, а не смена поля

`Component.clean()` (`weblate/trans/models/component.py:5530-5543`) запрещает
менять `source_language` у существующего компонента: «Source language can not
be changed, please recreate the component instead». Прецедент с обратной
сменой (`ru` -> `en`) выполнен и задокументирован в
`docs/operations/plans/2026-08-19-space-arena-source-language-to-english.md`;
этот план повторяет ту же схему (пересоздать рядом, перенести состояние из БД,
заархивировать старое, переименовать слаги), поэтому общие механики там не
дублируются - читать оба.

   источником истины по заметкам; истина - в БД.** Заметки надо снять через
   API и вписать в TBX перед импортом. (Сам дефект API - вне объёма, завести

   что `ru.po` несёт `Language: ru`. Multilingual CSV не нужен.
4. Что переживает пересоздание файлами: текст всех 18 языков, `fuzzy`
   (needs editing). Что живёт только в БД и требует переноса: флаги

   предложения, метки, скриншоты, approved-состояния, explanations
   глоссария и исходных строк, история (не переносится).
5. Матчинг глоссария: `get_glossary_units` отбирает глоссарии по
   `component__source_language` переводимого компонента
   (`weblate/glossary/models.py`), поэтому глоссарий тоже обязан стать
   `ru`-источником, иначе он инертен.

## Риски

- **Заметки глоссария теряются при любом файловом экспорте**, пока дефект API
  не исправлен. Поэтому TBX собирается из БД (Фаза 2.4), и после переезда
  любые правки explanation через API снова будут жить только в БД. Заводить
  отдельную задачу на `weblate/api/views.py:3866`.
- **Ре-база источник-зависимых проверок** - неизбежное следствие смены
  источника, не дефект метода.
- **Вчерашние ключи могут быть не закоммичены** до Фазы 1; скачивание кита
  их коммитит. Если разработчик правил через UI после 09:35, кит из
  `Downloads` устарел - использовать только кит Фазы 1.
- **Ключи снова могут пропасть** при добавлении через UI (см. Фаза 3.4);
  без воспроизведения на новом компоненте план не закрывать.
- **Вердикты судьи и `LLMUsageLog`** привязаны к юнитам старых компонентов и
  на новые не переносятся.
- **Откат:** старые компоненты живут до Фазы 6; откат = удалить `-ru`.
