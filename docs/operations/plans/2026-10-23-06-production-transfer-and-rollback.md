Основание: `docs/operations/reports/2026-10-23-06-production-readiness.md`.
Продолжает задачу 5 из `docs/operations/plans/2026-10-23-02-maintenance-isolation-and-external-build.md`.
Документ не разрешает обновление, перезапуск, очистку, экспорт секретов или
возобновление старого задания. Этапы ниже выполняются только после отдельного
разрешения и повторной проверки их условий.

## Условия допуска

- Точный current baseline: source e7520b439f69294923f86895a3a63b5bc8d386d3,
  image 4af5111b69abe2a0c5d6c6a4b562b78586d92c366817314498e834a528d10e70.
  Любое новое изменение останавливает процедуру и требует нового обследования.
- Локально включён независимый DeepSeek native-thinking fix, проверены reasoning
  payload и совместимость текущих env-настроек; оплачиваемых проб нет.
- Новый образ собран из зафиксированного кандидата, проверены все слои, config,
  label revision, platform, NumPy и установка миграций на восстановленной копии
  свежего baseline. Исторического source 2b8e748/image8a2119 недостаточно.
- В Docker storage и временной ФС достаточно `max(8 ГиБ, 2 × фактические несжатые
  слои нового образа + 3 ГиБ)`. Если обе директории на одной ФС, это один порог,
  а не два независимых свободных объёма. Сейчас недостаёт около 4,46 ГиБ до 8.
- Проверены и восстановлены текущие DB/files/config/secrets/systemd и image archive;
  конфигурация и права доступа совпадают. Секреты хранятся только приватно.
- Старый job не возобновляется, unknown не трактуется как неоплаченный. Сохраняются
  все готовые переводы, 39 квитанций, payload и ключи. Нет активных lease или
  других неопределённых незапечатанных операций. Очереди не очищаются/не перекидываются.

## Подготовка до окна

1. Локально сохранить новый production-снимок без секретов; интегрировать e7520b4
   в пользовательскую ветку, не теряя recovery, verify-only, RESTRICT и advisory
   glossary. Новых миграций сам e7520b4 не добавляет, но весь граф кандидата снова
   сверяется с фактически применённой схемой. Выполнить целевые тесты judge,
   reconciliation/immutable-mode и полный согласованный регресс.
2. Пересобрать локальный образ, повторить Django/schema/API/token smoke, зависимостную
   и архивную проверки. Зафиксировать новый source SHA, manifest/config digest,
   RootFS diff_ids, SHA архива и несжатый размер. Ничего не публиковать в main.
3. После отдельного разрешения сохранить текущий image4af5111 вне сервера и
   проверить обратную загрузку/ограниченный web-only откат локально. Не заменять
   его архивом3f0cf69e или5a2102. Если server image меняется — повторить этот шаг.
4. Только после согласования архивной ценности и нового allowlist удалять по одному
   точному image ID: без тегов, без ссылок из любых, в том числе остановленных,
   контейнеров, без активной сборки. Текущий/откатный image, volumes, Redis,
   PostgreSQL, Cathedral и общий cache не затрагивать. Не применять prune/force.
   После каждого удаления измерять фактическое место; если порог не достигнут,
   остановиться и отдельно решить вопрос с диском.
5. По отдельному разрешению передать и импортировать образ, не меняя running
   контейнеры. Проверить SHA файла до/после передачи. У Docker29/containerd Image.Id
   соответствует manifest digest, у целевого Docker28/overlay2 идентичность может
   выражаться config digest: сверить config/RootFS/label/platform, записать точный
   target ID. Несовпадение нельзя обходить флагом игнорирования. До этого не
   использовать старый helper manifest с предположением о равенстве ID.

## Согласованное окно установки

6. Закрыть приём новых внешних/профильных вызовов Wizard и новых пользовательских
   MT/judge/repair в Weblate. Безопасно завершить известные активные операции;
   при действующей аренде, новой неизвестной операции или меняющихся очередях
   остановить переход. Не отправлять unknown-запросы повторно.
7. Прекратить все старые Wizard API/worker/profile-worker writers и писателей
   Weblate/Celery/scheduler. Зафиксировать очередь и журналы без ручных HDEL/LPUSH,
   purge или сброса Redis. Один флаг external writes не заменяет остановку старого API.
8. Сделать согласованный полный backup **B0** до изоляции: PostgreSQL, файлы,
   SQLite, uploads/exports, env/secrets, systemd/compose, источники и image identity.
   PostgreSQL/Redis volumes не удалять. Backup можно выводить вне переполненного
   диска, но только в отдельно разрешённый приватный каталог. Проверить SHA,
   восстановление, вход и данные; не ограничиваться tar listing.
9. Повторить read-only сверку старого job8add8aa4… и remote-пакета. При текущем
   payload f536c0bc… и истёкшей аренде сначала выполнить dry run проверенной
   `deploy/isolate_legacy_run.py` с B0 manifest формата `verify_backup.py` и свежим
   run-reconciliation.json (не старше900секунд). Внешний исторический manifest
   online-копии другого формата не подставлять. При отказе не менять hash/intent
   для обхода. По разрешению применить изоляцию одной транзакцией.
10. Проверить: изменились только archived_unknown и одна run-isolation запись;
    1310 целевых переводов, 39 квитанций и исходный payload/ключи прежние. Сделать
    и проверить полный backup **B1 после изоляции** — install baseline. В B1
    записано имя всё ещё старого установленного Wizard release. B0 хранится для
    истории, поверх рабочей базы при обычном откате не восстанавливается.
11. Установить сначала новый Weblate в режиме без producers/Celery/beat. Явно
    выполнить только согласованный migrate plan с остановкой при ошибке. Обычный
    `deploy/vps.sh deploy`/compose default не использовать: они могут собрать
    образ и включить workers. Проверить health/API, журналы и контрольные данные.
12. Затем установить проверенный Wizard bundle (runtime кандидата6bf19b8,
    опубликованного вместе с документацией4409a7c, либо новый явно проверенный
    кандидат), B1 и уникальный release ID. external writes/profile agent выключены.
    Для pip/temp выбрать каталог на /opt с достаточным запасом, не молча расходовать
    отдельный /tmp tmpfs. `install.sh` запускает API и worker: это требует явного
    разрешения в окно и предварительного подтверждения guards/изоляции. Profile
    worker оставлять выключенным. Нельзя запускать installer как read-only probe.
13. Проверить archived_unknown, resume_allowed=false, запрет claim и новых платных
    действий по тому же remote-project даже с другим owner/alias; диагностика
    читается, другие проекты доступны, данные/квитанции прежние. Проверить API
    capabilities, вход и состояние миграций. Платных canary-запросов не делать.
14. Только после приёмки и отдельного допуска включать необходимые producers и
    новые записи для разрешённых проектов. Старый job/пакет не возобновлять.
    Неизвестные результаты остаются неизвестными; прямые действия пользователя
    в Weblate локальным Wizard fence не покрываются.

## Откат

1. При провале health/API, схемы, guards или контрольных digest запретить новую
   обработку и остановить новый API/producers/workers. Сохранить состояние отказа
   и новые журналы. Не делать автоматического downgrade миграций и возврата B0.
2. Сначала остановить dispatch Wizard, затем вернуть Weblate на сохранённый current
   image4af5111 (либо новый baseline, если он отдельно согласован), с **актуальными**
   DB/Redis/файлами. Запускать только web-only конфигурацию
   `deploy/rollback-web-only.compose.yml` + `rollback-web-only.conf`, без Celery,
   beat и автоматических migrate. При несовместимости чтения оставить maintenance
   и разбирать офлайн, а не восстанавливать старый dump поверх новых квитанций.
3. Для Wizard — code-only rollback через проверенный `deploy/rollback.sh` и B1
   с additive migration bridge; сохранённая текущая БД и архивная запись остаются.
   external writes/profile agent выключены. Оба Wizard worker отключены и
   замаскированы, включая перезагрузку; API только чтение. Перед фактическим вызовом
   проверить script/dry-run, backup manifest и root пути; full restore не применять.
4. Сверить payload, переводные digest, квитанции и изоляцию. Старый job не queued,
   worker его не выбирает, paid request не повторён. Redis не очищать и broker
   сообщения вручную не возвращать. Дальнейший запуск workers только после
   отдельной сверки результата и разрешения.

## Стоп-условия и границы

Любое несовпадение baseline, недостающий backup/current image archive, мало
места, неподтверждённая идентичность target image, lease/new intent, потеря
перевода/receipt, несогласованный migrate plan или риск повтора оплаты означает
остановку. На текущий момент уже действуют первые три условия.
Этот порядок прошёл самопроверку по текущему коду install/rollback и наблюдениям;
production-исполнение, rollback rehearsal текущего4af5111 и будущий rebuild
не заявляются выполненными. Разрешение на них данным документом не выдаётся.
