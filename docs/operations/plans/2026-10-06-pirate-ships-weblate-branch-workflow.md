# Pirate Ships: завершение интеграции Weblate с Git

**Статус:** план для команды игры, 2026-10-06.

## Цель

Тексты меняются только в Weblate. Файлы `Localization_*.json` в любой
ветке - копия, которую скилл скачивает из Weblate. Из файлов в Weblate
ничего не отправляется.

```text
            ┌──────────── Weblate ────────────┐
            │  один текст на ключ для всех     │
            │  переводы, MT, судья, глоссарий  │
            └───▲──────────────┬──────────┬────┘
   добавь ключ │              │ pull     │ push (снимок)
   (только API)│              ▼          ▼
   feature-A  feature-B  master  release/*     ветка localization
```

строк. Этап 2 (команда) - по её согласию.

## Правила веток

Weblate не ветвит тексты: у ключа один текст для всех веток.

1. **Новый ключ - в любой ветке.** Брошенная ветка оставит только
   неиспользуемый ключ.
2. **Существующий текст в экспериментальной ветке не менять.** Нужен
   другой - новый ключ (`<key>_v2`) и ссылка на него в коде ветки.
3. **Правка существующего текста** (опечатка, новое имя термина) - только
   из `master` или в интерфейсе Weblate. Действует сразу для всех веток.
4. **Перед слиянием в `master` и перед релизом** - `pull-from-weblate`.
   Иначе старая ветка вернёт старый текст (так было с «Картечница» ->
   «Мортира»).
5. **Переименование и удаление ключа** - только в Weblate, затем
   `pull-from-weblate`. Не в файлах.
6. **Релиз:** `validate-localization` сравнивает файлы с Weblate и
   проверяет, что у каждого ключа с непустым RU есть 15 переводов.

```text
новая фича:   ветка -> "добавь ключ" -> Weblate (RU, EN, 14 языков) -> pull -> коммит
опечатка:     master -> "обнови исходник" -> Weblate -> pull в master (ветки - при своём pull)
эксперимент:  ветка -> "добавь ключ X_v2" -> код ветки ссылается на X_v2
слияние:      ветка -> pull-from-weblate -> merge в master
релиз:        release -> pull-from-weblate -> validate -> сборка
```

## Скиллы

| Скилл | Что сделать |
| --- | --- |
| «добавь перевод» | Найти ключ: `GET /api/translations/pirate-ships/localization-json/ru/units/?q=key:="K"`. Есть с тем же RU - взять переводы; с другим RU - остановиться (правило 2). Нет - `POST .../ru/units/` `{"key": "K", "value": ["RU"]}`, затем `POST .../en/autotranslate/` и то же для 14 языков (`de es fr pt_BR pl it th id zh_Hans ko ja tr vi nl`), тело `{"mode": "translate", "auto_source": "mt", "engines": ["openrouter"], "threshold": 80, "q": "state:empty AND key:=\"K\""}`. Затем `pull-from-weblate`. Пустой перевод - ошибка, не `""` |
| «обнови перевод» | Разделить. «Обнови исходник K RU» - `PATCH /api/units/<id RU>/` `{"target": ["RU"], "state": 20}`, только из `master`, затем перевод языков как выше. «Обнови перевод K <язык> текст» - найти юнит в `.../<язык>/units/?q=key:="K"`, `PATCH` его, RU не трогать |
| `validate-localization` | Только чтение: сравнить файлы ветки с Weblate, вывести расхождения и пропуски. Ничего не отправлять |
| `migrate-legacy-localization` | Удалить |
| `pull-from-weblate` (новый) | `GET /api/components/pirate-ships/localization-json/file/` (ZIP всех языков), взять ключи из `Localization_ru.json` ветки плюс только что добавленные, перезаписать файлы: табы, UTF-8 без BOM, порядок ключей как в файле. Имена файлов в ZIP игровые (`cn`, `jp`, `kr`, `pt`). Непереведённого ключа в файле языка нет - это пропуск, его ловит `validate-localization` |
| `delete-key` (новый) | `DELETE /api/units/<id RU>/` - ключ уходит из всех языков сразу. Удалять юнит другого языка нельзя (403). Затем `pull-from-weblate` |

Общее для всех: после записи перечитать юнит (`GET /api/units/<id>/`) -
автоисправления Weblate могут поменять текст. Порог 30 убрать: на
LLM-перевод он не действует, а слабые совпадения из памяти пропускает.

## Глоссарий

- Файл `Localization/Glossary/glossary.csv` (вне `Assets/`): строка на
  термин, колонки `ru`, `explanation`, `flags`, 15 языков. Меняется только
  в `master`.
- `glossary-pull`: по каждому языку
  `GET /api/translations/pirate-ships/glossary-ru/<lang>/units/`, свести по
  RU, записать CSV, коммит.
- `glossary-push` (только из `master`), по разнице с прошлой выгрузкой:
  - новый термин: `POST .../glossary-ru/ru/units/`, затем
    `PATCH /api/units/<id>/` `{"extra_flags": "terminology", "explanation": "..."}`,
    затем `PATCH` перевода каждого языка;
  - правка перевода или пояснения: `PATCH /api/units/<id>/`;
  - удаление: `DELETE /api/units/<id RU>/` (уходит из всех языков);
  - текст RU-термина на месте не меняется (403): удалить и добавить
    заново.
- Машинный перевод берёт термины только из Weblate, поэтому правка CSV
  действует после `glossary-push`.
