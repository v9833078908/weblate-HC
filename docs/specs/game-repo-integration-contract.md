# Контракт интеграции с игровым репозиторием

Что должна дать команда разработки игры, чтобы Weblate подключился к её гиту, и
что взамен обещает Weblate. Документ написан как контракт: левая часть -
требования к репозиторию, правая - поведение, на которое можно рассчитывать.

Рабочий пример на всём протяжении - **Pirate Ships** (репозиторий
`Tempest_f2p`, SCM-Manager в офисной сети). Все числа и ответы сервисов в
разделе «Замеренное состояние» получены на живых системах 2026-08-11.

Смежные документы: `docs/specs/continuous-localization-loop.md` (полный цикл по
ролям), `docs/specs/producer-guide.md` (работа продюсера в интерфейсе),
`docs/specs/loc-kit-ingest.md` (импорт терминологии), `deploy/README.md`
(боевой стенд).

Пароль сервисной учётной записи в репозиторий не кладётся: он живёт в
credential-store гита Weblate (`/app/data/home/.git-credentials`, в боевом
развёртывании - аналог в data-директории), потому что символы `,` и `;` в нём
нельзя встроить в URL компонента: raw-вариант ломает парсинг git'а, а
percent-encoding SCM-Manager не декодирует.

Блокеры сняты: ветка есть, запись подтверждена, полный цикл «строка →
переводы → push → файлы в репозитории» прогнан на живом сервере (см. 5.5).

### 5.5 Прогон на живом репозитории (2026-08-14)

| Проверка | Результат |
|---|---|
| Пуш от `localization.service` | работает: ветка создана пустым коммитом-пробой (удалена), затем минимальным файлом |
| Orphan-ветка | принята сервером; клонировать master не требуется, что обходит проблему ниже |
| Weblate → push | 4 языка (en/es/fr/de) уехали в репозиторий отдельными коммитами `chore(l10n): update …`, автор `Hero Craft Admin <weblate@example.com>` |
| Формат записи | табы, UTF-8 без BOM, порядок ключей сохранены |
| Новые языки из интерфейса | `Localization_es/fr/de.json` созданы Weblate самостоятельно |

Ограничение, обнаруженное на живом сервере: SCM-Manager 1.x (JGit 4.5.3)
**не отдаёт полный клон** - `git fetch` обрывается через 30 с
(`Connection reset by peer` на этапе генерации пака, 452 291 объект).
Shallow (`deepen 1`) сервер принимает, но пак генерит дольше таймаута.
Практический вывод: Weblate может работать только с ветками, созданными
специально для локализации (orphan или узкая история), - клонировать
master целиком он не сможет. Мерж ветки `localization` в `master` делает
разработчик на своей стороне.

## Три канала, которые настраиваются отдельно

```text
репозиторий игры --(1) clone/fetch: URL + доступ--> Weblate
репозиторий игры --(2) webhook на push------------> Weblate
Weblate ----------(3) push в ветку или PR---------> репозиторий игры
```

Любой канал можно не включать. Минимальная рабочая конфигурация - только
первый: Weblate читает строки, переводы забираются выгрузкой. Канал 3 включается
отдельным решением, канал 2 не обязателен вовсе.

## Часть 1. Что даёт разработчик

### 1.1 Доступ к репозиторию

| Требование | Пояснение |
|---|---|
| Точный URL для клонирования | Совпадение важно: вебхуки Weblate сопоставляют компонент по точному URL из payload |
| Адрес, доступный **с сервера Weblate** | Не «работает у меня в браузере». Внутренние имена и хайрпин-NAT ломают доступ - см. 5.1 |
| Одна **сервисная** учётная запись | Персональных VCS-креденшелов у пользователей Weblate нет: доступ один на компонент, он хранится в URL компонента |
| Права: чтение обязательно, запись - по решению | Пуш включается отдельно, стартовать можно в режиме чтения |

Способы аутентификации, по убыванию предпочтительности: SSH-ключ Weblate
(публичный ключ выдаём мы, разработчик добавляет его как deploy key с правом
записи), HTTPS-токен, HTTP Basic. Последний передаёт пароль открытым текстом и
допустим только для внутренней сети и только для сервисной учётки.

### 1.2 Ветка

Ветка - настройка компонента, а не выбор в момент коммита. Выбирать ветку
«каждый раз» нельзя. Варианты:

- одна долгоживущая ветка локализации, которую команда игры мержит к себе
  когда удобно (рекомендуется);
- отдельный компонент Weblate на каждую ветку;
- смена поля `branch` в настройках - Weblate перечитает переводы из новой ветки.

Pirate Ships: ветка `localization`.

### 1.3 Формат файлов локализации

Контракт:

| Требование | Значение для Pirate Ships |
|---|---|
| Один файл на один язык | `Assets/Resources/Data/Localization_<код>.json` |
| Плоский объект «ключ - текст» | `{"id_строки": "текст"}` |
| Строгий JSON | без `//` и `/* */` комментариев |
| Кодировка | UTF-8 **без BOM** |
| Отступы | табы, один таб на уровень |
| Порядок ключей | как в файле; Weblate его сохраняет и дописывает новые ключи в конец |
| Файл исходного языка | `Localization_ru.json`, он же шаблон |

```json
{
	"support_email_prompt_title": "Вам нужна помощь?",
	"lang_name_ru": "Русский"
}
```

Почему именно плоский объект, а не массив записей: Weblate сопоставляет строки
по ключу. В массиве `[{"id": ..., "text": ...}]` ключей нет, и парсер выдаёт
позиционные идентификаторы `[0].id`, `[0].text` - вставка строки в середину
файла сдвигает всё, что ниже, и переводы уезжают на чужие места. Если массив
принципиален, единственная поддерживаемая форма - go-i18n v1:
`[{"id": ..., "translation": ...}]` (формат `go-i18n-json`), где значение
обязано лежать в поле `translation`.

### 1.4 Коды языков

Weblate сопоставляет файлы по коду **языка** (ISO 639-1), а не страны
(ISO 3166-1). Это разные стандарты, и на трёх кодах они расходятся:

| Код в игре | Код страны | Язык в Weblate | Что происходит |
|---|---|---|---|
| `cn` | Китай | `zh_Hans` | встроенный алиас, отрабатывает сам |
| `jp` | Япония | `ja` | встроенный алиас, отрабатывает сам |
| **`kr`** | Корея | **`kr` = канури** | алиаса нет, Weblate молча заведёт язык канури |

Отдельно проверяется **вариант** языка: код может быть валидным, но указывать
не на тот диалект. У Pirate Ships файл `Localization_pt.json` - бразильский
португальский (175 вхождений `você`, ни одного европейского маркера), а голый
`pt` в Weblate - это европейский. Разница не косметическая: от неё зависят
правила множественного числа и то, какой вариант закажет машинный перевод.

Решение, не требующее правок в игре: в настройках проекта заполняется
:guilabel:`Language aliases` строкой `kr:ko,pt:pt_BR`. Weblate внутри работает
с корейским и с pt-BR, а на диск пишет `Localization_kr.json` и
`Localization_pt.json` (`Component.get_language_alias`, обратный маппинг при
записи там же).

Заполнять алиасы нужно **до** создания компонента. Исправлять их потом дорого:
удаление перевода в Weblate удаляет файл из репозитория (см. 2.4), а
единственный безопасный откат - `Reset` клона, пока удаление не ушло в пуш.

### 1.5 Чего в файлах быть не должно

- Контекста для переводчиков и для машинного перевода - он живёт в Weblate,
  см. часть 3.
- Комментариев любого вида: строгий JSON их не допускает.
- Нескольких языков в одном файле.

## Часть 2. Что делает Weblate

### 2.1 Настройки компонента

| Поле | Pirate Ships |
|---|---|
| Version control system | `Git` |
| Source code repository | `http://<логин>:<пароль>@192.168.0.3:8080/scm/git/Tempest_f2p` |
| Repository branch | `localization` |
| Repository push URL | пусто на старте |
| File mask | `Assets/Resources/Data/Localization_*.json` |
| Monolingual base language file | `Assets/Resources/Data/Localization_ru.json` |
| File format | `JSON file` (`json`) |
| Source language | `ru` |
| Manage strings | включено - новые ключи заводятся из интерфейса |
| Edit base file | включено - новый ключ пишется в файл исходного языка |
| Push on commit | выключено, пока пуш не согласован |
| JSON parameters | indent `1`, style `tabs`, sort keys выключено |
| Language aliases (проект) | `kr:ko,pt:pt_BR` |

Формат работает как моноязычный именно потому, что заполнен шаблон: форматы,
которые поддерживают оба режима (JSON в их числе), становятся моноязычными при
непустом `template`.

### 2.2 Настройки инстанса

Клонирование проходит через две проверки, обе отказывают по умолчанию для
внутренних адресов:

| Настройка | Зачем |
|---|---|
| `WEBLATE_VCS_ALLOW_SCHEMES` | должен содержать схему URL; `http` в дефолт не входит |
| `WEBLATE_VCS_ALLOW_HOSTS` | хост внутренней сети иначе отклоняется как непубличный адрес |

`WEBLATE_VCS_ALLOW_HOSTS` - **эксклюзивный** список: как только он не пуст,
любой другой хост репозитория тоже надо в него добавить. Внутренние URL
(`local:`, `weblate://`) проверку не проходят и не затрагиваются. Обе
переменные описаны в `deploy/environment.example`.

### 2.3 Авторство и сообщения коммитов

| Что | Поведение |
|---|---|
| Автор коммита | переводчик: Weblate вызывает `git commit --author "<имя> <почта>"` |
| Коммиттер | техническая учётка, одна на компонент |
| Имя и почта в истории | по умолчанию обезличенные (`Hero Craft Localization user <id>`), включается настройками приватности стенда |
| Сообщение коммита | шаблон компонента с подстановками (`{{ language_name }}`, `{{ author }}`), поля для произвольного текста нет |

Если разработчику нужен произвольный текст сообщения - это режим без пуша:
Weblate отдаёт файлы, человек коммитит сам.

### 2.4 Что проговорить заранее

- **Не делать squash-merge коммитов Weblate.** После squash Git перестаёт
  узнавать собственные коммиты Weblate, и следующий rebase падает. Лечится
  только `Reset and reapply`.
- **Не править файлы переводов руками**, пока Weblate подключён на запись:
  одновременная правка одного файла с двух сторон - гарантированный конфликт.
  Штатная процедура на время массовых правок: `wlc lock`, `wlc commit && wlc
  push`, правки, `wlc pull`, `wlc unlock`.
- **Переименование ключа** для Weblate равно удалению и добавлению строки:
  переводы старого ключа остаются только в памяти переводов, а пояснение
  теряется.
- **Не удалять язык из Weblate, чтобы что-то переделать.** Удаление перевода
  удаляет файл из репозитория и коммитит удаление
  (`chore(l10n): remove Portuguese translation` - поймано на стенде). Пока
  коммит не ушёл в пуш, спасает `Reset`; после пуша файл возвращает уже
  разработчик.

## Часть 3. Где живёт контекст

В игровой репозиторий уходят только идентификаторы и тексты. Контекст остаётся
в Weblate и попадает в промпт машинного перевода.

| Поле | Хранится | Правит | Уходит в игру | В промпт LLM |
|---|---|---|---|---|
| Explanation (пояснение строки) | база Weblate | локализация в интерфейсе | нет | да, поле `explanation` |
| Комментарий разработчика | файл перевода | разработчик | да, это и есть файл | да, поле `note` |
| Глоссарий (лок-киты) | компонент-глоссарий Weblate | локализация | нет | да, термин + пояснения |

Для JSON-форматов запись пояснения в файл невозможна на уровне кода:
`supports_explanation` равен `True` только у формата TBX. То есть «оставить
контекст на стороне Weblate» - это не договорённость, а свойство формата.

Права: пояснение правится с разрешением `source.edit` («Edit additional string
info», входит в роль «Edit source»), отдельно от права переводить. Массовая
заливка - `PATCH /api/units/<id>/` с телом `{"explanation": "..."}`.

**Пояснения привязаны к ключу строки и живут только в базе.** Переименование
ключа или пересоздание компонента их теряет, поэтому исходный набор пояснений
хранится файлом `explanations.json` в этом репозитории и заливается заново при
необходимости.

## Часть 4. Первичная миграция

Скрипт `scripts/convert-localization-json.py` превращает сводную таблицу игры в
файлы по языкам:

```sh
python scripts/convert-localization-json.py Localization.json out/
python scripts/convert-localization-json.py Localization.json out/ --shape go-i18n
```

Что он делает: снимает BOM, вырезает `//` и `/* */` комментарии, привязывает
каждый комментарий к записи, в которой он написан, раскладывает языки по файлам
и складывает комментарии в `out/explanations.json` для заливки в Weblate.

Перед записью каждый сгенерированный файл разбирается обратно той же
библиотекой, которой пользуется Weblate, и значения сверяются с исходной
таблицей; расхождение останавливает прогон.

Отдельно проверяется, что сериализация Weblate воспроизводит файл байт в байт -
иначе первый же коммит Weblate переформатирует весь файл и превратит правку
одной строки в тысячестрочный diff.

внутренний адрес сразу.

Это внешний адрес SCM-Manager: он доступен с рабочей машины, но **не** с

### 5.3 Результат конвертации

| Форма | Объём 16 файлов |
|---|---|
| плоский объект (выбрана) | 5 272 539 байт, `Localization_ru.json` - 405 831 |
| массив go-i18n v1 | 7 066 434 байта |
| исходная сводная таблица | 3 888 915 байт |

Разница между формами - служебные поля, повторённые в каждой записи. Основной

Двенадцать комментариев вынесены в `explanations.json` (1327 байт) и в игровой
репозиторий не попадают.

### 5.4 Прогон на дев-стенде

Конфигурация из 2.1 собрана целиком на локальном стенде: конвертированные
файлы положены в git-репозиторий с веткой `localization`, компонент создан по
API, репозиторий подключён по пути (`file`), пуш - в тот же репозиторий
(`receive.denyCurrentBranch = updateInstead`).

Стенд остаётся поднятым и воспроизводит боевую конфигурацию целиком:
компонент `pirate-ships/localization` на дев-инстансе, репозиторий игры -
`dev-docker/data/tempest-loc` (каталог в `.gitignore`, пересобирается
конвертером из части 4).

| Проверка | Результат |
|---|---|
| Раскладка файлов и коды языков | 16 языков, файлы разработчика не тронуты: `Localization_kr.json` -> корейский, `_jp` -> японский, `_cn` -> китайский упрощённый, `_pt` -> pt-BR |
| Строки | 3735 из шаблона `Localization_ru.json`, исходный язык `ru` |

| Правка перевода -> коммит | `1 file changed, 1 insertion(+), 1 deletion(-)`: табы, порядок ключей и экранирование не тронуты |
| Кириллица и CJK после записи Weblate | остаются сырым UTF-8, не `\uXXXX` |
| BOM | файлы остаются без BOM (`7b 0a 09`) |

| Новый ключ со стороны разработчика | после `pull` появляется строкой во всех 16 языках |

Статистика перевода обновляется отложенно: сразу после импорта счётчики могут
отставать на минуту. Считать по ним расхождение раньше - ложная тревога.

## Следующие шаги

### Согласовано с разработчиком

| Вопрос | Ответ |
|---|---|
| Доступ | сервисная учётная запись `localization.service`, проверена с сервера Weblate |
| Каталог | `Assets/Resources/Data/` |
| Ветка | `localization` |
| BOM | не нужен: `StreamReader` без явной кодировки читает UTF-8 без метки, Newtonsoft получает уже разобранную строку |
| Испанский | обычный, отдельного варианта нет - алиас не заводим, остаётся `es` |

Испанский стоит перепроверить по тексту силами локализации: разработчик
вариантами не занимается, а в файле встречается `ustedes`. Это не блокер -
алиас добавляется отдельным решением, но только вместе с пересозданием
перевода.

### Решено 2026-08-14

1. **Ветку `localization` завели мы** (orphan, пуш от `localization.service`),
   право записи подтверждено.
2. **Полный клон master Weblate сделать не может** (см. 5.5) - рабочая схема
   только с отдельной локализационной веткой.
3. **Режим записи проверен**: пуш в `localization` работает; `Push on commit`
   на боевом компоненте всё равно включаем отдельным решением.

### Порядок работ, когда ветка появится

1. Создать компонент по таблице 2.1, алиасы `kr:ko,pt:pt_BR` заполнить
   **до** создания.
2. Залить 12 пояснений из `explanations.json` через `PATCH /api/units/<id>/`.
3. Проверить первый коммит Weblate: diff должен быть в одну строку. Если нет -
   расходится конфигурация формата, а не данные.
4. Прогнать конфликт (разработчик и переводчик правят один файл одновременно) -
   единственный сценарий контракта, не проверенный вживую.
