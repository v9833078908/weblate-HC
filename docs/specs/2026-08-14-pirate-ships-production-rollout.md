## 2. Три вопроса, которые нужно закрыть сегодня

### Вопрос 1. Кто создаёт ветку `localization`

В репозитории `Tempest_f2p` ветки `localization` нет. Варианты:

- **Разработчик** создаёт её от `master`, кладёт 16 JSON-файлов (мы даём готовый архив
  или скрипт) и пушит. Тогда правая часть контракта запускается без нашего пуша
  в репозиторий.
- **Мы** создаём ветку и пушим 16 файлов сами — тогда нужно право записи для
  `localization.service` (вопрос 2) и разрешение на первый пуш в чужой репозиторий.

**Рекомендация:** разработчик. Это быстрее и не требует проверки прав на запись
до старта.

### Вопрос 2. Право записи для `localization.service`

Проверено только чтение. Запись — это пуш в репозиторий игры, и проверять её
можно только с разрешения владельца. Нужно сегодня:

- Подтвердить, что у `localization.service` есть право записи в SCM-Manager.
- Либо выдать его (роль `WRITE` на репозиторий `Tempest_f2p`).

Без этого канал 3 (Weblate → репозиторий игры) останется в режиме чтения.

### Вопрос 3. Режим работы: авто-пуш или выгрузка

| Режим | Как переводы попадают в игру | Что нужно |
|---|---|---|
| **Авто-пуш** (рекомендуется) | Weblate коммитит и пушит в `localization` сам. Разработчик делает `git pull` когда удобно | Право записи (вопрос 2) |
| **Ручная выгрузка** | Продюсер скачивает ZIP на странице компонента и передаёт разработчику | Ничего, кроме ветки с файлами |

Стартовать можно с ручной выгрузки, а авто-пуш включить следующим шагом —
для этого просто заполняется поле `push` в настройках компонента.

## 3. Как будет выглядеть работа после перехода

### Разработчик

1. Новая строка: добавляет ключ и русский текст в `Localization_ru.json`,
   коммитит, пушит в `master`.
2. При следующем мерже `master` в `localization` (или сразу при вебхуке) Weblate
   подхватывает новый ключ — он появляется во всех 16 языках как непереведённый.
3. **Не правит файлы переводов руками.** Любая правка `Localization_fr.json`
   одновременно с переводчиком в Weblate — конфликт.
4. Забирает переводы: `git pull` из `localization` когда удобно.
5. Переименование ключа = удаление + добавление: переводы старого ключа остаются
   только в памяти переводов Weblate, пояснение теряется.

### Продюсер / локализация

1. Видит новые строки на дашборде проекта.
2. Жмёт «Автоматический перевод» → OpenRouter переводит всё непереведённое.
3. Просматривает результат, правит что нужно.
4. Если пуш включён — переводы уезжают в репозиторий автоматически.
5. Если пуш выключен — скачивает ZIP и передаёт разработчику.

### Переводчики (если появятся)

- Работают только в веб-интерфейсе Weblate.
- У каждого свой логин. Коммиты подписаны обезличенно
  (`Hero Craft Localization user <id>`).
- Проверки качества (плейсхолдеры, теги, пунктуация) срабатывают при сохранении.
- Почтовые уведомления о новых строках — по подписке на проект.

## 4. Пошаговый план запуска

### Этап 0. Встреча (сегодня)

- Закрыть три вопроса из раздела 2.
- Передать разработчику архив из 16 JSON-файлов и скрипт `convert-localization-json.py`.

### Этап 1. Ветка и файлы (разработчик)

- Создать ветку `localization` от `master`.
- Положить 16 файлов `Localization_*.json` в `Assets/Resources/Data/`.
- Запушить.
- **Проверка:** `git ls-remote --heads origin localization` отдаёт HEAD.

### Этап 2. Компонент в Weblate (мы)

- Создать проект `pirate-ships`.
- Заполнить алиасы языков (`kr:ko,pt:pt_BR`) **до** создания компонента.
- Создать компонент по таблице ниже.
- Залить 12 пояснений из `explanations.json`.
- **Проверка:** страница компонента показывает 16 языков, 3847 строк, счётчики
  перевода сошлись.

Настройки компонента:

| Поле | Значение |
|---|---|
| Source code repository | `http://localization.service:<пароль>@192.168.0.3:8080/scm/git/Tempest_f2p` |
| Repository branch | `localization` |
| Push URL | пусто (пока) |
| File mask | `Assets/Resources/Data/Localization_*.json` |
| Template | `Assets/Resources/Data/Localization_ru.json` |
| File format | JSON file |
| Source language | Russian |
| Manage strings | вкл |
| Edit base file | вкл |
| Push on commit | выкл |
| JSON indent | 1, tabs, sort keys выкл |

### Этап 3. Первый коммит Weblate (мы)

- Сделать тестовую правку в любом переводе.
- **Проверка:** diff должен быть в одну строку. Если нет — расходится
  форматирование, а не данные.

### Этап 4. Прогнать конфликт (совместно)

- Разработчик и переводчик одновременно правят один файл.
- Это единственный сценарий контракта, не проверенный на живом репо
  (на стенде сымитирован).

### Этап 5. Включение авто-пуша (опционально, отдельным решением)

- Заполнить `push` в настройках компонента.
- Включить `push_on_commit`.
- Настроить `commit_pending_age` (по умолчанию 24 ч — правка ждёт сутки
  перед коммитом; для игры можно уменьшить до 1–4 ч).

## 5. Что каждая сторона обязуется делать

### Команда Pirate (разработка)

- Вести исходные строки в `Localization_ru.json`, пушить в `master`.
- Мержить `master` в `localization` при появлении новых ключей (или настроить
  вебхук — см. ниже).
- Не править файлы переводов руками.
- Не делать squash-merge коммитов Weblate.
- Не переименовывать ключи без предупреждения.
- Сказать нам, если SCM-Manager, репозиторий или сетевой доступ меняются.

### Локализация (мы)

- Поддерживать компонент в Weblate: мониторить ошибки клонирования, пуша,
  конфликты.
- Следить за метриками качества перевода.
- Настроить автоперевод новых строк.
- Вести глоссарий проекта.
- При проблеме с репозиторием — диагностировать и эскалировать, а не править
  файлы в обход Weblate.

## 6. Дальше: что можно включить потом

| Возможность | Что даёт | Когда имеет смысл |
|---|---|---|
| Вебхук на пуш в `localization` | Новые ключи появляются в Weblate мгновенно, без ручного pull | Когда разработчик начинает регулярно пушить в `localization` |
| Глоссарий проекта | Термины и утверждённые переводы; LLM соблюдает их | Когда есть таблица терминов (лок-кит) |
| Ручная заливка локализации через API | Продюсер заливает переводы без доступа к гиту | Если появляется выделенный продюсер |
| PR-режим вместо прямого пуша | Разработчик ревьюит коммиты Weblate перед мержем | Если нужен контроль над тем, что попадает в ветку |
| Автоперевод при обновлении (аддон) | Новые строки переводятся автоматически, без кнопки | Когда поток новых ключей стабильный |

- Архив из 16 JSON-файлов (результат работы `convert-localization-json.py`).
- Скрипт `scripts/convert-localization-json.py` — разработчик сможет перегенерить

## Приложение Б. Команды для разработчика

Создание ветки и заливка файлов (шаблон):

```sh
git checkout master
git checkout -b localization
# раскопировать 16 JSON-файлов в Assets/Resources/Data/
git add Assets/Resources/Data/Localization_*.json
git commit -m "feat(l10n): add per-language localization files for Weblate"
git push origin localization
```

Обновление файлов при добавлении новых ключей в `master`:

```sh
python scripts/convert-localization-json.py Localization.json out/
cp out/Localization_*.json Assets/Resources/Data/
git checkout localization
git add Assets/Resources/Data/Localization_*.json
git commit -m "chore(l10n): sync localization files from master"
git push origin localization
```

Массовая правка переводов (процедура без конфликтов):

```sh
wlc lock pirate-ships/localization
wlc commit && wlc push
# ... правите файлы ...
git push origin localization
wlc pull
wlc unlock
```
