# План: детерминированное распознавание term/description китов

**Goal:** Глоссарный кит, где термин и его описание лежат на соседних строках,
разбирается детерминированно как термины с пояснениями, а не как вдвое большее
число «терминов».

**Status:** не начат. Отложено осознанно при исполнении
`docs/plans/2026-08-10-loc-kit-glossary-deterministic-infer.md` (v0 закрыл
только таблицы «одна строка = один термин»).

## Почему это нужно

`infer_glossary_profile` (v0) всегда эмитит `record_stride: 1`. Реальный кит
`Heart Abyss_Localization - Terms.csv` устроен иначе - чередование
term/description с секционными строками:

```text
 1  ru,en,fr,it,de,ja,...          <- header
 2  Russian,English,...            <- caption (skip)
 3  Персонажи / Characters         <- секция
 4  Леон / Leon                    <- термин
 5  [532 символа описания]         <- описание термина из строки 4
 6  Аки / Aki                      <- термин
 7  [200 символов описания]
...
18  (пустая)
19  Термины                        <- секция
20  Дзинко                         <- термин
21  [209 символов описания]
...
29  [343 символа описания]
```

Измерено на реальном файле (29 строк, 11 колонок, заполнены `ru`, `en`, `ja`):

- v0 выдаёт `source_lang: ru`, `initial_target_languages: [en, ja]`,
  `skip_rows: [2]`, регионы `3-17` и `19-29` со `record_stride: 1` →
  **26 «терминов»**, из которых 13 - абзацы описаний, а 2 - секционные
  заголовки. Число совпадает с ожиданием исходного плана, но смысл неверный:
  глоссарный термин длиной 532 символа термином не является.
- `docs/specs/loc-kit-ingest.md` уже содержит рукописный профиль ровно для этой
  формы (`term-description-pairs`, `skip_rows: [2, 18]`, регионы
  `section_row: 3 / 4-17` и `section_row: 19 / 20-29`).

## Что делать

Расширить `infer_glossary_profile` (или добавить соседнюю функцию) так, чтобы
форма term/description распознавалась детерминированно и эмитилась как v2
`record-map` с `record_stride: 2`:

- `term_row_offset: 0`, описания - через `grammar.notes` с `row_offset: 1`
  (`scope: source` для колонки языка-источника, `scope: target` для каждого
  целевого языка);
- секционные строки - как `section_row` + `section_column` у региона (строка,
  заполненная только в языковых колонках и не имеющая парного описания);
- регион обязан быть чётной длины; `record_stride: 2` требует, чтобы диапазон
  делился на 2 нацело (это уже проверяет `parse_profile`).

**Критерий распознавания** - главный вопрос дизайна, а не деталь реализации.
Нельзя угадывать «строка длиннее 200 символов = описание» (спека прямо
запрещает такую эвристику). Нужен структурный признак. Кандидаты:

1. Чередование: строки на чётных смещениях от начала региона заполнены в тех же
   языковых колонках, что и нечётные, но никогда не бывают «короткими» -
   слишком близко к эвристике по длине.
2. Секционные строки как границы: строка, заполненная только в подмножестве
   языковых колонок и не имеющая парной строки, - секция; всё между секциями
   разбивается на пары. Требует, чтобы кит был строго парным между секциями.
3. Явный сигнал оператора в UI: чекбокс/радио «в этой таблице описание термина
   лежит на следующей строке». Детерминированно, честно, без угадывания -
   но добавляет шаг в визард.

Рекомендация: сначала решить, вариант 2 или 3, и только потом писать код.
Вариант 3 дешевле и не может ошибиться; вариант 2 не требует от оператора
понимания структуры.

## Что уже сделано и не входит в эту задачу

- Whitespace: outer whitespace у **описания** теперь warning с обрезкой
  (`tbx.trimmed_outer_whitespace`), у **термина** остаётся error
  (`tbx.unsupported_outer_whitespace`). Проверено: с рукописным профилем
  `record_stride: 2` реальный кит проходит gate, кроме двух строк с настоящими
  терминами `'Нелюди '` и `'Ёкаи '` (строки 22 и 26) - их обязан починить
  человек в исходной таблице.
- v0 для таблиц «только языковые колонки, одна строка = один термин» работает
  и покрыт тестами.

## Тестирование

- standalone: кит с чередованием term/description даёт `record_stride: 2`,
  корректные `notes` с `row_offset: 1` и секции из `section_row`; кит с
  нечётным регионом отклоняется, а не округляется;
- contract: такой кит доходит до превью, где число терминов равно числу
  терминов, а описания видны как пояснения, а не как отдельные записи;
- живой smoke на реальном `Terms.csv` после починки двух term-ячеек.
