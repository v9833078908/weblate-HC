Соглашение прода: **все** компоненты во всех проектах используют `repo:
local:` и `edit_template: True`. Внешних VCS-репозиториев на проде нет.

## Что будет сделано

1. Для каждого из семи компонентов (без `glossary`) выгрузить из дева через
   API текущий файл каждого языка (`GET /api/translations/<project>/<comp>/<lang>/file/`)
   и упаковать в ZIP: `en.xlsx`, `es.xlsx`, `pt.xlsx`, `ru.xlsx` в корне.
   Контрольная проверка перед отправкой: хеши выгруженных файлов совпадают с
   `git show HEAD:<lang>.xlsx` во внутреннем клоне дева.
2. Создать компонент на проде штатным путём
   `POST /api/projects/need-for-greed/components/` с `zipfile` (тот же код
   `LocalRepository.from_zip`, что и в UI-мастере), полями `name`, `slug`,
   `file_format=xlsx`, `filemask=*.xlsx`, `template=en.xlsx`,
   `new_base=en.xlsx`, `source_language=en` и настройками, повторяющими дев:
   `edit_template=True`, `manage_units=True`,
   `allow_translation_propagation=True`, `enable_suggestions=True`,
   `push_on_commit=True`, `auto_lock_error=True`, `new_lang=add`,
   `language_regex=^[^.]+$`, `merge_style=rebase`, `commit_pending_age=24`,
   `priority=100`. Запрос идёт через VPN-шлюз, локальным для VPS `curl` на
   `http://127.0.0.1:8081/api/` с токеном `PROD_WEBLATE_API_TOKEN`.
3. После фонового Celery-парсинга догнать PATCH-ом всё, что сериализатор не
   принял при создании (по опыту клонирования Pirate Ships это в первую
   очередь `edit_template` и `allow_translation_propagation`), и пересчитать
   batch-чеки.
4. Сверить результат с девом (см. «Проверка»).

Файлы репозитория: добавляется только этот план. Кода в `weblate/` изменение
не касается, деплой образа не требуется - работа идёт через API прода.

## Словарь прода

Словарь не переносится и не правится: dev-глоссарий (5 языков, `*.tbx`)
игнорируется, прод-глоссарий (`tbx/*.tbx`, en + ru, 303 термина) остаётся как
есть.

Одно неизбежное следствие, о котором нужно знать заранее. Weblate сам
добавляет в глоссарий проекта языки, появившиеся в обычных компонентах:
`Component.schedule_sync_terminology` -> `sync_glossary_languages`
(`weblate/glossary/tasks.py:28`). Как только на проде появятся компоненты с
es и pt, в прод-глоссарии будут созданы `tbx/es.tbx` и `tbx/pt.tbx` с 303
исходными терминами и **пустыми** переводами. Существующие en и ru термины,
их переводы, пояснения и флаги при этом не меняются. Удалить эти языки руками
можно, но не навсегда: `cleanup_stale_glossaries` удаляет только языки,
которых нет в обычных компонентах, а es/pt там как раз будут.

Варианты:

- **A (рекомендуется).** Переносим все четыре языка. Содержимое словаря
  неизменно, но в нём появляются пустые es/pt.
- **B.** Переносим только en + ru, переводы es/pt на прод не попадают.
  Словарь остаётся строго двухязычным.

## Проверка

До импорта - снимок прод-глоссария: число юнитов, SHA-256 файла
`tbx/ru.tbx` из API и хеш множества `(context, source, target, explanation,
extra_flags)` по всем 303 терминам. После импорта - тот же снимок и
побайтовое сравнение; расхождение в en/ru = откат.

По каждому компоненту:

- полевой diff прод-компонента против дев-компонента по списку настроек из
  пункта 2 (ожидается пустой);
- на каждый язык `total`/`translated`/`fuzzy` совпадают с девом;
- равенство множеств `(context, source, target)` по всем 3544 юнитам
  дев vs прод;
- состояния юнитов: `{20: N}` без `100` (иначе `edit_template` не применился);
- `GET /` логина отвечает 200, новых alert'ов у проекта нет.

## Вне объёма

- Перенос истории изменений и авторства: при импорте файлами он не
  переносится, на проде будет «компонент создан» + импорт. Комментариев,
  предложений и меток в деве нет, так что больше терять нечего.
- Правка настроек проекта на проде, правка словаря, любые изменения в других
  проектах прода.
- Пересборка образа и деплой кода (`deploy/vps.sh deploy`) - не требуется.
- Подключение реальных VCS-репозиториев вместо `local:` - на проде такого
  соглашения нет.

## Результат

Выполнено 2026-08-17 по варианту A. Все семь компонентов созданы на проде
через `POST /api/projects/need-for-greed/components/` с `zipfile`
(`local:`-репозиторий, четыре файла `en/es/pt/ru.xlsx` в корне архива);
сериализатор принял все настройки сразу, догоняющий PATCH не потребовался.

Проверено фактами:

- ZIP собран из файлов, выгруженных из дев-API; SHA-256 всех 28 файлов
  совпали с `git show HEAD:<lang>.xlsx` во внутренних клонах дева.
- Настройки: по каждому компоненту diff против дева пуст. Отличаются только
  окружение-зависимые поля (`*_url`, домен в `source_language`) и завершающий
  перевод строки в `effective_pull_message` (CRLF на проде против LF в деве).
- Данные: 3544 юнита, множества `(context, source, target)` дев и прод
  совпадают по всем 28 парам компонент/язык; распределение состояний
  `{20: N}` идентично, read-only `100` нет - `edit_template` применился.
- Прод-глоссарий: en и ru не изменились, `units_sha` и SHA-256 `tbx/ru.tbx`
  до и после импорта идентичны (303 термина, 100 %). Как и предсказано,
  Weblate сам создал `tbx/es.tbx` и `tbx/pt.tbx` - 303 исходных термина,
  переводов нет. Из-за этого проект показывает es/pt как 74,5 % (886 из 1189).
- Ни одного pending-коммита и ни одного alert'а у восьми компонентов,
  страница логина отвечает 200, все восемь компонентов видны в UI проекта.

Единственное расхождение по чекам - `reused` на проде срабатывает на три
юнита больше (`ui/ru`: `terrain1Biome2Title`, `terrain2Title`; `loot/ru`:
`winter.chest`). Это не артефакт импорта: `reused` считается по проекту, а в
прод-глоссарии два разных исходных термина делят один ru-перевод
(`Chest of the Jarl` и `Jarl Chest` -> `Сундук Конунга`, `Meteorfall` и
`Starfall` -> `Звездопад`, `Belomar` и `Whitelands` -> `Белоземье`). В деве
глоссарий другой, поэтому там этих совпадений нет.
