# План: морфологическое сравнение для глоссарного гейта

Статус: **ожидает согласования**. Обоснование и все числа -
`docs/misc/2026-08-11-glossary-enforcement-analysis.md`.

Цель: дать LLM-first пайплайну точный глоссарный hard-гейт и отдельный
морфологический advisory, не раздувая глоссарии словоформами и не превращая
неуверенное совпадение в обязательную перепись корректного перевода.

Исследование memoQ, Phrase, Trados, Okapi, QA Distiller и TBX показало общий
паттерн: каноническая форма остаётся в глоссарии; exact/fuzzy/custom выбираются
пер-термин и пер-язык; морфология даёт подсказку или warning. Жёсткими делают
только точные правила. Подробности и ссылки - в отчёте.

## Задача 1. Морфологический фильтр на стороне цели

Файлы: `pyproject.toml`, `weblate/checks/glossary.py`, новый
`weblate/checks/morphology.py`, тесты в
`weblate/checks/tests/test_glossary_checks.py`.

- Объявить `snowballstemmer` в `[project] dependencies` (BSD-3-Clause, чистый
  Python, 762 КБ, без своих зависимостей).
- `weblate/checks/morphology.py`: закрытая карта код языка -> алгоритм Snowball
  и функция `contains_inflected(term, text, language)`, которая сравнивает
  последовательность основ как непрерывный отрезок.
- Карта является allowlist: новый язык добавляется только после корпусного
  замера. Индонезийский не входит - 152 из 206 снятых срабатываний оказались
  ложными.
- Exact остаётся первым и дешёвым путём. Snowball вызывается только после
  exact-miss и может только **снять** срабатывание, но не создать его.
- `forbidden`, `read-only` и будущий exact-флаг не проходят через Snowball.
- Сторону источника в `weblate/glossary/models.py` не менять: +34% вхождений от
  стемминга, но 42% прироста приходится на шумные термины.

Приёмка: положительные тесты `Корабль`/`корабля`,
`Двигатель`/`двигателя`, `Bauplan`/`Bauplänen`,
`Galaktischer Träger`/`Galaktischen Trägers`, `Modül`/`modülüne`; отрицательные
`Dukungan`/`pendukung`, `Batas terakhir`/`Perbatasan Terakhir`; отдельные тесты,
что forbidden/read-only используют только exact.

## Задача 2. Разделение hard и advisory в LLM feedback

Файлы: `weblate/checks/glossary.py`, `weblate/machinery/llm.py`,
`weblate/machinery/tests.py`, тесты глоссарного чека.

- Вынести оценку термина в структурированный результат:
  `hard_failures` и `advisories`. UI-чек может показывать их вместе, но LLM
  должен получать разную семантику.
- Hard: точное появление `forbidden`; отсутствие точной формы для
  `read-only`/exact-термина.
- Advisory: у обычного склоняемого термина не найдено ни exact, ни разрешённое
  морфологическое совпадение.
- Не передавать `check_glossary` в общий `failing_checks` без классификации.
  Правило 23 оставить только для hard. Advisory формулировать как «проверь
  термин; сохрани перевод, если это грамматическая форма канонического термина».
- Сам глоссарий в prompt остаётся первичным механизмом; check остаётся
  контрольным слоем после ответа.

Приёмка: тест с корректной склонённой формой не получает обязательную команду
переписать строку; exact forbidden/read-only получает; advisory не смешивается
с обычными failing checks и не утверждает, что изменение обязательно.

## Задача 3. Режим и область применения пер-термин и пер-язык

Файлы и миграция зависят от выбранного хранения; предпочтительный контракт -
флаги на target-юните глоссария, потому что юнит уже привязан к языку.

- `read-only` и `forbidden` сохраняют exact-семантику.
- Добавить явный exact-флаг для канонических имён, сокращений и терминов, где
  склонение запрещено.
- Добавить opt-out applicability-флаг для омографов и канонических ярлыков,
  которые в данном языке нельзя проверять во всех контекстах.
- Не выводить эти флаги автоматически из длины, регистра или части речи.

Основание: пересечение безопасных терминов по всем языкам - 5 из 299. `Build`
как имя экрана и `build` как глагол не различаются ни stem, ни lemma.

Приёмка: один термин можно сделать exact в одном языке и advisory либо
отключённым в другом, не дублируя весь глоссарий.

## Задача 4. Замер продуктового кода на трёх китах

Файлы: `docs/misc/glossary-blindspot-probe.py`, результат в
`docs/misc/2026-08-11-glossary-enforcement-analysis.md`.

Прогнать замер через продуктовую функцию вместо локальной копии. Отдельно
посчитать hard, advisory, снятые морфологией и ошибочно снятые случаи.
Расхождение с базовым снятием 14-66% - исследовать, а не принимать как норму.

## Задача 5. Go/no-go на выходе пайплайна

Все числа стороны цели сейчас получены на легаси-переводах из китов. Нужен
прогон по строкам, которые произвёл LLM-first пайплайн, и ручная разметка всех
hard плюс стратифицированной выборки advisory. Чтение прода согласовать
отдельно по правилу про деплой.

Включение допускается сначала canary на COL4, затем пер-язык. Критерий go:
нулевые ложные hard на размеченной выборке; advisory не меняют корректные строки
автоматически.

## Вне объёма

- Перечисление словоформ как основной механизм.
- Стемминг стороны источника.
- Нейронный лемматизатор до сравнения с дешёвым фильтром на выходе пайплайна.
- Включение `GlossaryCheck` по умолчанию до задач 2, 3 и 5.
- Изменение `LLM_FULL_GLOSSARY_LIMIT` до задач 1-4 и отдельного замера цены.
