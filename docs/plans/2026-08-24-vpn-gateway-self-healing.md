# Самодостаточный VPN-шлюз hc-vpn-gw

Дата: 2026-08-24. Статус: одобрено, в работе.

## Проблема

Доступ к VPS через hc-vpn-gw ломался дважды по одной причине и имеет ещё два
скрытых дефекта:

1. Секреты (profile.ovpn/auth/askpass) живут в `$TMPDIR/hc-vpn-gw-secrets` и
   монтируются read-only. macOS чистит `/var/folders/.../T`, рестарт Docker
   Desktop рвёт маунт. `--restart unless-stopped` перезапускает процесс над
   пустым каталогом — бесконечный рестарт-луп, который лечится только ручным
   `./deploy/vps.sh up`.
2. MTU 1100 на tun0 ставит `vps.sh` снаружи через `docker exec` — только когда
   его запускает человек. Docker-инициированный рестарт поднимает тоннель с
   `tun-mtu 1500` из профиля: контейнер «Up», SOCKS отвечает, а SSH молча
   виснет на key exchange.
3. Мёртвый peer не детектируется: openvpn-процесс жив, контейнер «здоров»,
   трафик в никуда. Keepalive в профиле нет.

## Решение

Принцип: всё, что нужно тоннелю, живёт внутри контейнера и переустанавливается
его entrypoint'ом при каждом старте. Тогда штатная политика рестарта Docker
лечит все три сценария без человека.

- `deploy/vps.sh` (`gateway_up`): вместо bind-mount — `docker create` +
  `docker cp` секретов в `/vpn` внутри контейнера + `docker start`, затем
  немедленный `rm -rf $SECRETS_DIR`. Секреты живут в writable-слое контейнера
  внутри Linux-VM Docker Desktop; на macOS-диске остаются только на секунды.
  Оба `docker exec ... ip link set ... mtu` удаляются, `TUN_MTU` передаётся
  контейнеру через `-e`.
- `deploy/vpn-gateway/entrypoint.sh`: после подъёма tun0 —
  `ip link set dev tun0 mtu "${TUN_MTU:-1100}"`; openvpn получает
  `--ping 10 --ping-exit 120`, чтобы мёртвый peer завершал процесс, контейнер
  выходил и Docker его перезапускал (чистое переподключение максимум за
  ~2.5 минуты).
- `vps.sh status`: дополнительно показывает MTU tun0 и проверяет достижимость
  `$VPS_HOST:22` через SOCKS, чтобы зелёный статус означал рабочий путь до
  VPS, а не только открытый локальный порт.
- `deploy/README.md`: обновить операторский раздел.

## Компромисс

Секреты переживают жизнь контейнера внутри Docker-VM (до `docker rm`). Доступ
к ним требует root в VM — эквивалентно любому named volume. Альтернатива
(launchd-watchdog поверх bind-mount) сохраняет эфемерность, но добавляет вторую
движущуюся систему и окна простоя; отклонена.

## Вне скоупа

launchd-агенты, WireGuard, любые изменения на VPS.

## Верификация

1. `docker restart hc-vpn-gw` → сам поднимается, `tun0 mtu 1100`, SOCKS
   отвечает, SSH до VPS проходит — без запуска vps.sh.
2. Удаление `$TMPDIR/hc-vpn-gw-secrets` + `docker restart` → работает.
3. `docker exec hc-vpn-gw pkill openvpn` → контейнер перезапускается Docker'ом,
   тоннель восстанавливается.
4. `./deploy/vps.sh status` показывает MTU и достижимость VPS.
