# Постоянные проекты и безопасное обновление лок кита

## Запасной исходник строки

В новом выпуске заявленный язык остаётся выбором пользователя. Если его текст в конкретной строке пуст, визард использует русский, затем английский текст из подтверждённых языковых колонок. Колонка заявленного языка может отсутствовать целиком. Другие языки, соседние строки и формулы запасным источником не являются.

На экране проверки видны строки с данными, допущенные строки и реальные проблемы. Пустые строки исключены из сообщений и счётчиков, включая просмотр старых заданий без изменения их исторических данных. Для строк с ключом без допустимого текста остаются координаты и причина. Автоматический выбор запасного источника показывается в раскрываемой сводке.

Один лист может иметь несколько технических компонентов с разными исходными языками. Weblate получает фактический source каждой группы; исходная пустая ячейка не заполняется запасным текстом. Перевод на фактический исходный язык не запускается. Готовые переводы сохраняются, выгрузка объединяет группы в прежний лист и порядок строк.

Между версиями ключ остаётся общим для всех групп одного листа. Если уже опубликованный ключ сменил исходный язык или текст, сравнение блокирует повторное создание и требует решения; готовые переводы не удаляются. Дополнительные группы могут создаваться только в подтверждённом проекте, которым владеет визард. Режим чтения старых внешних проектов сохраняется.

«Структура колонок» закрыта по умолчанию. Однозначно служебные формульные колонки показываются кратко по буквам, а языковые, ключевые и смешанные колонки требуют явного подтверждения. Глоссарий применяется только при совпадении источника и цели; автоматического обращения глоссария нет. В сведениях о запасном исходнике показана доступность подходящей пары языков.

Проверки и точка возврата: `docs/product/reports/2026-10-11-row-source-fallback-verification.md`.

Выпуск добавляет постоянную связь между локальным проектом визарда и внешним Weblate. Подключение существующего проекта, сравнение файлов и скачивание выполняются без записи во внешний проект. Старые проекты и привязки из прежнего журнала защищены от записи, включая возобновление старых заданий.

## Выбор языков локализации

На шаге «Языки» выберите «Язык, с которого переводить». Варианты показываются полным русским названием с кодом. Слева перечислены языки выбранных видимых листов лок-кита; наличие колонки не означает, что все её строки переведены. Галочками отметьте языки для обработки. Язык источника виден, но недоступен как цель.

Справа находятся дополнительные языки: русский, английский, французский, итальянский, немецкий, китайский упрощённый, корейский, японский, португальский бразильский, испанский мексиканский, польский, чешский, голландский. Здесь также сохраняются ранее выбранные и подключённые внешние языки. Если язык есть в лок-ките, его карточка показывается только слева. Существующие внешние языки помечены «Уже есть в проекте Weblate».

В поле «Добавить свой язык» введите русское или английское название либо код, затем нажмите Enter или «Добавить». Неоднозначное название требует выбора варианта. Неизвестный язык не добавляется. Повторный ввод выбирает уже существующую карточку. `pt` и `pt_BR`, как и `es` и `es_MX`, остаются разными языками.

Справочник загружается из Weblate только чтением и проверяется перед сохранением и запуском. При недоступности справочника старые значения остаются видимыми; сохранение и добавление новых целей блокируются. Специальные варианты с `@`, например `de@formal`, пока не поддерживаются форматом лок-кита: они не превращаются автоматически в базовый язык.

Названия выбранных языков подставляются в шаблон инструкций. Ручные правки роли и стиля сохраняются. Сохраните языки, затем при необходимости обновите инструкции на шаге «Контекст и термины».

## Подключение существующего проекта

На странице «Проекты» поле «Поиск проекта» фильтрует добавленные локальные проекты по названию и slug. Кнопка «Найти» или Enter дополнительно запускает поиск во внешнем Weblate по части названия или slug без учёта регистра. Пока запрос не отправлен, внешние результаты не показываются; ошибка доступа отображается отдельно от отсутствия совпадений.

Найденные внешние проекты показываются отдельно. «Подключить для чтения» открывает подтверждение с выбранным проектом; сам поиск и открытие этого окна ничего не подключают и не создают. Если найденный проект уже подключён, предлагается открыть существующую локальную карточку. Подтверждение сохраняет локальную связь, а внешние данные читает через GET.

При создании локального проекта визард ищет точное совпадение названия или slug. Пользователь выбирает найденную цель и подтверждает подключение. Загружается снимок компонентов, исходных строк, переводов, языков и глоссариев. Одна внешняя цель не привязывается к конкурирующим локальным проектам.

Панель подключения показывает время снимка и проблемы отдельных компонентов. Кнопка обновления выполняет GET и сохраняет новую локальную копию. Скачивание проекта использует последний полученный снимок; сохранённая выгрузка конкретного завершённого задания остаётся прежней. Если исходный XLSX недоступен, скачивается восстановленная таблица, без обещания восстановить оформление оригинальной книги.

## Новые проекты визарда

При открытии проекта визард сначала восстанавливает активный черновик. Если часовой срок черновика закончился, локальный POST восстанавливает последнюю сохранённую версию обычного лок-кита из приватных оригиналов: листы, язык источника и выбранные цели. Создаётся новый временный черновик; сохранённая версия и Weblate не меняются. Глоссарии не используются вместо лок-кита. Для старых версий без карты файлов неоднозначное сопоставление оригиналов блокируется.

На шаге «Файлы» у открытого черновика доступна кнопка «Загрузить новый лок-кит». Выберите обновлённые файлы: после успешного анализа откроется отдельный черновик на первом шаге. Прежняя загрузка, история заданий и внешние данные сохраняются. Отмена выбора файла или ошибка анализа оставляет прежний черновик открытым; тот же файл можно выбрать повторно.

Выберите листы и языки, затем на шаге «Проверка и запуск» сопоставьте листы с существующими компонентами, рассчитайте и подтвердите изменения. Старая ссылка на загруженный файл глоссария и прежнее сравнение в новый черновик не переносятся; опубликованный глоссарий остаётся в проекте.

По умолчанию `WIZARD_EXTERNAL_WRITES=0`: все внешние POST, PATCH и DELETE запрещены на уровне клиента и запуск задания запрещён маршрутом API. Для разрешённой оператором работы с новыми проектами требуется явное включение записи. Это не снимает защиту с подключённых существующих проектов.

Проект, созданный этим выпуском после включения записи, получает привязку сразу после подтверждённого создания во внешнем API. Последующие задания используют ту же цель и сохраняют языки. Пользователь сопоставляет каждый видимый лист с отдельным компонентом и рассчитывает изменения. Отчёт показывает новые ключи и исходный текст, пояснения, сохранённые внешние строки, готовые переводы для загрузки и точные ключи для машинного перевода.

Изменение исходного текста под прежним ключом блокируется. Отсутствие строки в новой книге не удаляет её в Weblate. Готовые внешние переводы не перезаписываются. Для прежнего языка переводятся новые пустые строки; старые пустые добавляются только по отдельному выбору. Для нового языка отбираются выбранные строки без перевода. Каждая MT-порция содержит не более 100 проверенных unit ID, широкого запасного запроса `state:empty` нет.

Оригиналы обычного лок-кита и пользовательского глоссария сохраняются в приватном `data/versions/` независимо от временного черновика. Скрытые и veryHidden листы сохраняются только внутри неизменённого оригинала; в обработку не попадают.

## Инструкции и глоссарий

Шаблон роли обновляет проект и языки. Для произвольных ручных инструкций требуется подтверждение их соответствия выбранным языкам. Перед записью показываются инструкции до и после. Карта инструкций сохраняет невыбранные языки. Ключи, routing и base_url существующего project-level сервиса сохраняются при замене конфигурации, обрабатываются только в памяти backend и не попадают в пользовательский снимок.

Пояснение новой исходной строки передаётся через поддерживаемое поле unit explanation и проверяется чтением до перевода. Подтверждение доставки в API не доказывает, что конкретная внешняя LLM-задача действительно использовала инструкции: журналы Django/Celery серверным доступом не получены.

Существующий глоссарий читается без повторной публикации. Для нового проекта визарда загруженная таблица предварительно показывается с терминами и переводами; публикация требует отдельной галочки. Создаётся новый компонент версии глоссария, прежний компонент не изменяется. Пересекающиеся исходные термины блокируются до публикации. Полную книгу автоматически на платный перевод не отправлять при приёмке.

## Ошибки и возобновление

Перед внешней записью сохраняется intent. После timeout выполняется чтение результата; неизвестный POST автоматически не повторяется. Неподтверждённый платный запрос сохраняет блокировку цели даже после отмены. Подтверждённый отказ требует исправленного плана, а не слепого повторения. Диагностический JSON доступен только владельцу и содержит этап, компонент, язык, correlation ID, HTTP-код и безопасную причину без токенов и полного текста игры.

Ожидание машинного перевода продолжается 30 минут без увеличения числа заполненных строк. Новый прогресс продлевает это окно, но одна операция не наблюдается дольше двух часов. Настройки `WIZARD_MT_OBSERVATION_SECONDS=1800` и `WIZARD_MT_MAX_OBSERVATION_SECONDS=7200` задаются на сервере; допустимо `60 <= idle <= maximum <= 86400` секунд. Счётчик, время последнего прогресса и дедлайн сохраняются вместе с intent и переживают перезапуск. В новом intent время операции сохраняется до POST. Для старых записей без этого времени применяется консервативная граница от сохранённого начала задания и прежнего дедлайна, если он есть: перезапуск не создаёт новое двухчасовое окно. Повторный платный запрос не отправляется. Такой же порядок действует для пакетов перевода новых строк при обновлении проекта. Пятиминутное ожидание прочих операций и HTTP-таймаут отдельного запроса не меняются.

После истечения окна состояние остаётся неподтверждённым: отсутствие новых строк не доказывает остановку Celery. API задания (`coverage`) и диагностический JSON содержат количество полученных переводов и границы наблюдения без текста игры. Незаполненную строку можно исправить в Weblate, затем продолжить задание — визард прочитает результат и подтвердит этап. Увеличение времени не заменяет исправления строки, которую внешний сервис пропустил. Автоматический платный повтор и пропуск обязательных строк не выполняются.

История проекта предоставляет задания и неизменяемые выгрузки. Нагрузочная приёмка отложена; поведение с конкурентной внешней записью проверяется перед операциями, но без conditional update на стороне API абсолютная атомарность не обещается.

## Установка и возврат

Перед установкой повторить полный бэкап текущего baseline с помощью нового `deploy/backup.sh`, сверить SHA256, сохранить приватную копию вне сервера и проверить восстановление БД, файлов, входа и приложения. Установщик требует успешный `restore-result.json`, совпадение текущего baseline и отсутствие активных или неопределённых внешних операций. В начале оставить запись выключенной.

Команды выполняются только после отдельного разрешения установки. Путь выпуска и бэкапа должен быть фактически проверенным:

```bash
sudo bash /path/to/extracted-release/deploy/backup.sh /opt/bdhc/weblate-wizard/shared/backups/full-NEW-STAMP
sudo bash /path/to/extracted-release/deploy/install.sh /path/to/extracted-release release-NEW-ID /opt/bdhc/weblate-wizard/shared/backups/full-NEW-STAMP
sudo bash /path/to/extracted-release/deploy/rollback.sh /opt/bdhc/weblate-wizard/shared/backups/full-NEW-STAMP code --dry-run
sudo bash /path/to/extracted-release/deploy/rollback.sh /opt/bdhc/weblate-wizard/shared/backups/full-NEW-STAMP full
```

Откат сохраняет состояние после обновления в `pre-rollback-*`, восстанавливает выбранный комплект и запускает только API. Worker отключается и маскируется, поэтому перезагрузка его не запускает. Перед возобновлением сопоставить сохранённый журнал с внешним Weblate. Затем оператор восстанавливает unit из проверенного выпуска, снимает mask и включает worker; делать это без сверки запрещено. Локальное восстановление не отменяет внешних записей и переводов.

Основные службы БДХК, бот и внешний Weblate не перезапускаются этими скриптами. Файл `shared/previous-release` не используется для выбора точки возврата: baseline указан в manifest полного бэкапа.
