Визард установлен 2026-10-02 после явного разрешения владельца. UI доступен по `http://192.168.0.180:18511/console/`, runtime commit `e5d2ebd`; действующие службы БДХК сохранены. Команды ниже описывают установку и последующие согласованные обновления. Установка затрагивает только `/opt/bdhc/weblate-wizard` и `wizard-*` systemd-службы.

Текущий выпуск от 2026-10-05 — `release-9868b21a17d4`, агент инструкций GPT-6 Luna включён. После отдельного разрешения владельца внешняя запись включена для работы с новыми проектами визарда. Подключённые ранее существовавшие проекты остаются только для чтения; коллизия резервируемого slug блокирует запись. Условия разрешения: `docs/product/reports/2026-10-05-04-new-project-write-enabling.md`. Исправление запуска с экспортированным глоссарием, проверка полного запроса и текущий бэкап: `docs/product/reports/2026-10-05-05-exported-glossary-launch-fix.md`.

## Готовый выпуск

Архив формируется из committed source и локально проверенной сборки UI скриптом `scripts/package_release.py`. Requirements с хешами экспортируются из `uv.lock` командой `uv export --locked --no-dev --no-emit-project --format requirements-txt --output-file requirements.txt`. Серверу нужен Python 3.12+ с `venv`/pip и доступом к индексам зависимостей. Node на сервере не нужен: frontend уже собран. Архив не содержит токенов и данных пользователей.

## Предварительная проверка

По SSH записать PID и health действующих основного API `127.0.0.1:19100`, UI `18501`, фасада `19101` и Telegram-бота; проверить свободный `18511`, место на диске и возможность создавать отдельного системного пользователя. Не выполнять сборки, management commands и перезапуски старых служб. Проверить версию Python и наличие `python3 -m venv`.

Для варианта, аналогичного текущему UI карточек, адрес: `http://192.168.0.180:18511/console/`. API: `http://192.168.0.180:18511/api/producer/`. Это адрес корпоративной сети. Интернет-доступ отдельно требует согласованного HTTPS-имени, сертификата и сетевой публикации; готовый образец nginx — `deploy/proxy.conf.example`. Не расширять доступ к основному API/фасаду.

## Отдельные файлы и запуск

Распаковать архив в отдельный staging-каталог. Подготовить только новый корень:

```bash
sudo install -d -m 0750 /opt/bdhc/weblate-wizard/shared/secrets
sudo install -m 0640 /path/to/release/.env.example /opt/bdhc/weblate-wizard/shared/wizard.env
```

В `wizard.env` зафиксировать фактический origin, bind и порт. Существующие БДХК/Weblate токены передать в `shared/secrets/bdhc_readonly_token` и `shared/secrets/weblate_api_token` отдельным защищённым способом. Не передавать значения аргументами команды, через Git, отчёты или журналы. Не переносить SSH/Git-инструкцию. `PROFILE_LLM_*` можно оставить пустыми: ручные инструкции предусмотрены.

Автоматический цикл качества управляется отдельным флагом `WIZARD_QUALITY_CYCLE_ENABLED`. До проверки совместимого Producer API держать его равным `0`. Для согласованной локальной приёмки указать `WEBLATE_API_BASE_URL`, включить одновременно `WIZARD_EXTERNAL_WRITES=1` и `WIZARD_QUALITY_CYCLE_ENABLED=1`, затем проверить `/api/producer/integration-policy/`: оба признака должны быть `true`. Токен Weblate должен иметь `translation.auto` и `unit.review`; проект — ровно два доступных места судей и настроенный MT-движок. Включение флага само по себе ничего не запускает: цикл явно выбирается пользователем для конкретного задания.

После разрешения на deployment:

```bash
sudo bash /path/to/release/deploy/install.sh /path/to/release release-<commit> /opt/bdhc/weblate-wizard/shared/backups/<verified-backup>
sudo -u weblate-wizard env \
  WIZARD_DATA_DIR=/opt/bdhc/weblate-wizard/shared/data \
  PYTHONPATH=/opt/bdhc/weblate-wizard/current/backend \
  /opt/bdhc/weblate-wizard/current/.venv/bin/python -m app create-user
curl --fail http://127.0.0.1:18511/health/live
curl --fail http://127.0.0.1:18511/health/ready
systemctl status wizard-api wizard-worker wizard-backup.timer
```

Имя и пароль вводятся интерактивно, пароля по умолчанию нет. Инсталлятор создаёт собственного пользователя службы, venv, каталог данных, systemd units и автозапуск. Основной API, UI, фасад и бот не входят в список restart/stop. Для последующих обновлений сначала согласовать deployment, остановить только worker, сделать backup и проверить отсутствие активных заданий; только затем запускать инсталлятор.

Проверить вход и авторизованный API с рабочего компьютера по согласованному адресу, CSRF, закрытость `data/` и `secrets/`, отсутствие токенов в UI. Для HTTPS включить `WIZARD_SECURE_COOKIE=1`, bind на loopback и установить согласованный прокси. Интернет-доступ проверяется из внешней сети, отдельно от LAN.

## Маленькая реальная приёмка

Проверка чтения/автозаполнения разрешена владельцем по **Dead Shell**, `title_id=92be6259-40cd-51df-a6ba-4eb54a14f261`. Визард показывает изменения и применяет их только после подтверждения. Карточку не менять. Эта проверка не подменяет контекст Star Troopers при реальном переводе: перед MT проверить сохранённую анкету и инструкции.

Отдельный тестовый проект имеет разрешённое отображаемое имя **«тест — <короткий ID>»** и уникальный slug. Для платной приёмки взять 5–10 подтверждённых строк видимого листа `D:\bdhc_wizard\WS.Localizations.xlsx`, один выбранный target. Платный вызов и его объём согласуются отдельно. Полную книгу не переводить автоматически. Скачать результат, проверить ключи, новые переводы, сохранность готовых target-значений и отсутствие скрытых листов. Перепроверить старые PID/health и записать фактический адрес.

## Автозаполнение инструкций переводчику

На шаге «Контекст и термины» единственное точное совпадение имени проекта с карточкой БДХК подтягивается автоматически. Сохранённая связь с title_id имеет приоритет. Сходство по подстроке требует выбора; доступен ручной поиск по имени или ссылке. Название игры и имя локального проекта хранятся отдельно.

Блок «Готовые инструкции переводчику - если не уверены не меняйте» показывает редактируемые роль, стиль и инструкции для каждого выбранного языка. Проверенный результат сохраняется на сервере автоматически. «Сохранить инструкции» доступна после ручных изменений и сохраняет контекст и тексты вместе. При уходе с несохранёнными изменениями есть подтверждение. Отдельного поля «Роль игрока» нет; старые данные сохранены.

Без подключённой LLM используются базовые правила с явным уведомлением. Жанр и атмосферу отсутствующей карточки шаблон не выдумывает. Ручные и старые поля без происхождения автоматически не заменяются; ручную роль при смене игры/языков нужно проверить. Подробности настройки и неизвестного результата: docs/product/guides/profile-agent.md.

## Неподтверждённый ответ перевода

Если запуск отклонён из-за несовпадения языков сохранённых инструкций, вернитесь на шаг «Контекст и термины», раскройте инструкции, проверьте текущий язык в роли и нажмите «Сохранить инструкции». Кнопка «Сохранить контекст» сохраняет анкету отдельно. Затем повторите запуск на шаге проверки. Интерфейс показывает конкретную причину отказа API вместо общего сообщения; сетевые и серверные сбои сохраняют общее сообщение.

Если внешний Weblate вернул серверную ошибку или ответ платного запроса не получен, визард сразу проверяет сохранённые переводы. Готовый результат подтверждается автоматически, после чего задание продолжает следующие шаги. Если результат ещё не готов, задание остаётся работающим и повторяет только чтение примерно каждые 30 секунд. Подготовленный выпуск увеличивает ожидание до 30 минут без нового прогресса, с общим пределом два часа на операцию; подробности и переменные настройки: docs/product/guides/persistent-projects.md. Граница ожидания сохраняется в SQLite и не сбрасывается при перезапуске worker. Такой же предел применяется к запросу HTTP 202 с адресом задачи или без него. Изменение начинает действовать после согласованной установки выпуска.

Временная недоступность чтения не вызывает повторную оплату. При истечении ожидания задание получает состояние «не подтверждено». Кнопка «Продолжить незавершённое задание» заново проверит сохранённый результат; ранее отправленный платный запрос автоматически не повторяется. Подтверждённое завершение означает готовность экспорта, а не отсутствие замечаний качества у внешнего Weblate.

## Проблемы с листами

На шаге «Файлы» под проблемным листом показываются причина и подсказка. Если лист не нужен для перевода, снимите его галочку и нажмите «Сохранить выбор»: остальные листы сохраняют свой выбор. Визард не исключает проблемные листы автоматически. Если лист нужен, исправьте заголовки языковых столбцов (например `ru` и `en`) и загрузите исправленную книгу. Предупреждение остаётся видимым после снятия галочки; для ранее загруженных книг без подробной диагностики выводится общее объяснение. Скрытые листы исключаются до анализа и не появляются в списке.

## Добавление языка в тот же проект

Карточка проекта и скачивание включают результаты всех завершённых языков этого проекта с тем же исходным лок-китом. Выбор нового языка в визарде относится к текущему заданию и не удаляет предыдущие языки. При повторной обработке языка используется его последний завершённый результат, в том числе после возобновления старого задания. Столбцы сопоставляются по коду языка и строки по ключам; служебные столбцы сохраняются. Незавершённое задание не заменяет опубликованный результат. Результаты отдельных заданий остаются неизменными; накопленный лок-кит собирается при чтении, без повторного перевода.

После завершённой локализации новый запуск этого локального проекта использует прежний проект Weblate и его компоненты. Меняются выбранные языки; второй проект с тем же названием не создаётся. Исходный язык, выбранные листы, ключи и исходные строки должны совпадать. Визард проверяет как сохранённый лок-кит, так и реальные исходники Weblate при каждом возобновлении. Обновление исходного лок-кита — отдельный сценарий: несовпадение блокирует добавление языка, чтобы не заменить существующие файлы.

Заполненные строки нового языка из лок-кита загружаются до MT с режимом `conflicts=ignore`. Готовые переводы Weblate не заменяются, переводятся только пустые строки выбранного языка. При конфликте итоговый экспорт добавляемого языка использует сохранённое значение Weblate. Переводы других языков и прошлые snapshots заданий сохраняются. Для одного проекта одновременно допускается только одно активное или неподтверждённое задание. При неподтверждённом платном переводе сначала продолжите прежнее задание, чтобы проверить его результат; статус ошибки при опросе не разрешает новый платный запуск.

Глоссарий существующего проекта сохраняется. При добавлении языка новую таблицу глоссария не загружайте: расширение глоссария отдельной загрузкой пока блокируется. Явный HTTP 400 у операции импорта/создания отделён от неизвестного сетевого результата: после устранения причины кнопка продолжения допускает новый неплатный запрос с проверкой отсутствия объекта. Неизвестный результат платного MT по-прежнему не вызывает повторный запрос.

Готовые значения загружаются отдельным bilingual XLIFF 1.2 (`.xlf`): `trans-unit/resname` содержит точный ключ строки, `source` — исходный текст, `target` — перевод. Пустые переводы исключены. XML сохраняет разметку как текст; `xml:space` и кодирование CR обеспечивают точную обратную проверку ключей, исходников и переводов. Расширение `.xlf` позволяет Weblate выбрать двуязычный формат до формата PO существующего компонента. Файл для создания компонента остаётся monolingual PO. Результат загрузки проверяется чтением заполненных строк; серверные autofix могут изменить пробелы или пунктуацию. Durable-операция `seed-xliff` сохраняет историю старых `seed`/`seed-bilingual` и при продолжении сначала проверяет наличие уже загруженных значений.

После добавления языка Weblate некоторое время возвращает существующий объект и файл, пока его background import ещё не создал строки в БД. Визард ожидает, пока API `total` достигнет числа строк компонента, и только затем подтверждает готовность языка, загружает имеющиеся переводы и допускает MT. Во время ожидания повторное создание языка, upload и платный перевод не отправляются.

## Backup и откат

Ежедневный `wizard-backup.timer` сохраняет согласованный SQLite backup в `shared/backups/`. В SQLite находятся snapshots заданий и экспорта. Для текущих черновиков дополнительно сохранить приватный каталог `shared/data/uploads/`; секреты копируются отдельной процедурой. Настроить копию backup вне этого сервера и срок хранения после первой установки. Не копировать живой `wizard.sqlite` без WAL: использовать `python -m app.backup <каталог>`.

```bash
sudo bash /opt/bdhc/weblate-wizard/current/deploy/rollback.sh
```

Откат меняет только службы визарда и symlink `current`; shared data сохраняется. Если предыдущего выпуска нет, визард останавливается. При смене схемы SQLite совместимость старого выпуска нужно проверить отдельно: destructive downgrade не поддерживается. Сетевую публикацию убрать только для визарда; БДХК не откатывать.

Нагрузочные, длительные и расширенные проверки выполняются после запуска по разделу плана «После запуска».

Фактическая приёмка 2026-10-02: пять строк видимого `Default`, target `de`, результат 5/5. `docs/product/reports/2026-10-02-02-wizard-lan-deployment.md` содержит адреса, PID, runtime release и сведения о backup.
