# Изоляция неопределённого задания и подготовка внешней сборки

Эта процедура сохраняет неизвестный финансовый результат. Она не завершает
перевод и не разрешает повторный запрос. Изолированный проект остаётся доступен
для чтения и диагностики; новые платные действия через визард запрещены независимо
от пользователя или локального имени подключения. Самостоятельные действия
пользователей непосредственно в Weblate эта локальная защита не блокирует.

## Подготовка изоляции

Применение к рабочей БД требует отдельного разрешения и окна обслуживания.
Перед ним отключите внешние записи и генерацию профиля, остановите все старые
API/worker-процессы, которые могут изменить задание. Работающий старый API может
перезаписать статус уже начавшейся транзакцией. Сам CLI службы не останавливает.

Сделайте свежий согласованный бэкап и проверьте восстановление. Манифест формата
`deploy/verify_backup.py` должен содержать `schema: 1` и SHA-256 каждого файла.
Дополнительно включите в `files`:

- `data/wizard.sqlite` — согласованную копию текущей SQLite;
- `restore-result.json` — успешные проверки `database`, `baseline_app`, `login`,
  `projects`, `file_checksums`, каждую со значением `ok`;
- `run-reconciliation.json` — результат свежей сверки только чтением.

Сверка содержит `schema: 1`, `run_id`, `owner`, `project`, `remote_project`,
`payload_sha256` исходной строки JSON в `jobs.data`, `operations_sha256`
(алгоритм `app.db.revision`), `outcome: provider_unknown`, `live_lease: false`,
`pending: 0` и `observed_at` — Unix-время. Её возраст при первом применении
не должен превышать 900 секунд. Это операторское свидетельство сверки, а не
подтверждение оплаты провайдером. Материалы локальных репетиций использовать
в production нельзя.

Запускайте из каталога визарда; сначала без `--apply`:

```sh
python3 deploy/isolate_legacy_run.py /path/to/wizard.sqlite RUN_ID \
  --expected-payload-sha256 PAYLOAD_SHA256 \
  --backup-manifest /path/to/verified-backup/manifest.json \
  --reason 'Сохранить неизвестный результат без повторной отправки'
```

CLI использует только стандартную библиотеку и не обращается к сети. Он проверяет
контрольные суммы, восстановление, весь долговечный снимок БД, идентичность
задания, аренду, другие активные задания и связанные quality-операции. Изменение
долговечных данных после бэкапа требует нового бэкапа. Сессии и heartbeat не входят
в эту сверку. Поддерживаются исходная схема 0001 и расширенная схема 0004.

Только после разрешения добавьте `--apply`. В одной `BEGIN IMMEDIATE` транзакции
меняются лишь статус задания на `archived_unknown` и новая запись
`run-isolation:<run-id>` в `records`. Payload, intent, ответы и ключи остаются
прежними. Повторное применение той же операции не создаёт новых записей; другая
причина или другой манифест не перезаписывают существующую изоляцию.

Валидная запись разрешает пройти проверку обслуживания. Статус без записи,
повреждённая запись, несовпадение payload или другое неизвестное задание
останавливают процедуру. Проверка действует и при откате только кода.
После изоляции сохраните новый согласованный бэкап: это baseline установки.
Автоматического снятия изоляции нет.

## Подготовка сборки Weblate

Операторские инструменты находятся в отдельной рабочей ветке Weblate:
`deploy/build-offline-release.sh` и `deploy/check-import-capacity.py`.
Они не подключаются к production, не вызывают Compose, импорт или очистку Docker.

Проверяется физическое свободное место Windows: перед подготовкой C должен
иметь не менее 90 ГиБ, D — 50 ГиБ. Виртуальный свободный объём WSL дополнительным
местом не считается. Контекст и архив образа размещаются на D; Docker-слои при
текущем устройстве WSL расходуют C.

```sh
# Только проверка физических дисков; Docker не вызывается.
bash deploy/build-offline-release.sh --repo . --commit FULL_COMMIT_SHA \
  --output /mnt/d/releases/UNIQUE_RELEASE --mode dry-run

# Чистый Git-архив и проверенный контекст, без сборки образа.
bash deploy/build-offline-release.sh --repo . --commit FULL_COMMIT_SHA \
  --output /mnt/d/releases/UNIQUE_RELEASE --mode prepare
```

Каталог вывода должен быть новым. Подготовка использует только указанный полный
SHA, проверяет каждый член архива до извлечения, запрещает приватные каталоги,
`.env`, БД, выходящие за пределы архива ссылки и нерассмотренные кандидаты ключей.
Исторические синтетические credential-фикстуры разрешены только по точному хешу.
Манифест содержит SHA исходников и архива, базовый digest, платформу и NumPy.

Сборка с `--mode build` требует отдельного разрешения; в этом локальном этапе
она не выполняется. Будущий запуск использует только локальный Unix-сокет Docker,
классический builder, `linux/amd64`, закреплённый базовый образ и NumPy 2.3.5.
Контроль каждые две секунды прерывает только новый клиент сборки при расходе
свыше 40 ГиБ или остатке C менее 50 ГиБ. Это предохранитель, а не дисковая квота:
другие программы и работа между измерениями тоже расходуют место.

После разрешённой сборки выполняется проверка упаковки в новом контейнере без
сети и production-данных: импорт базовых модулей, наличие machinery через
`find_spec` без загрузки Django-моделей и версия NumPy. Это не проверка
инициализации Django или подключения к БД. Манифест дополняется image ID, размером образа и
SHA-256 экспортированного архива. Изменение базового digest или NumPy вызывает
отказ до начала сборки.

## Импорт, установка и откат

Проверка импорта только читает место и сверяет переданные оператором image ID и
commit с манифестом. Значения берутся из отдельного чтения фактического образа.
Для Docker storage и временного каталога требуется не меньше
`max(8 ГиБ, 2 × размер несжатого образа + 3 ГиБ)` свободного места на каждом.
Сам импорт этот инструмент не выполняет.

Перед очисткой потребуется сохранить текущий production-образ вне сервера,
повторно проверить согласованный список кандидатов и получить разрешение.
Нехватка места останавливает импорт; общая очистка, volumes и чужие стеки
не затрагиваются.

Установка Weblate, затем визарда выполняется в отдельное разрешённое окно.
Начните с выключенными внешними записями и генерацией профиля. Проверьте
архивный статус, запрет resume/claim, сохранность переводов/квитанций и работу
остальных проектов. Старое задание не возобновляйте.

При откате сохраняйте актуальную БД, изоляцию и журналы. Используйте совместимый
старый API только для чтения, Weblate в изолированном web-only режиме; оба воркера
визарда должны оставаться выключенными и замаскированными, внешние записи и
генерация профиля — выключенными. Старую БД поверх новых данных не восстанавливайте.
