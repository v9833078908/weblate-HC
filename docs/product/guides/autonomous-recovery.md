# Автоматическое восстановление и проверка без изменений

Согласованный контракт: `docs/product/plans/2026-10-23-wizard-autonomous-recovery-read-only-quality.md`
в репозитории Weblate HC. Реализация выполняется на отдельных рабочих копиях.

## Сохранность исходного задания

Перед изменениями 23 октября 2026 года создан приватный локальный бэкап
`autonomous-plan-before-20261023-004155`: PostgreSQL, файлы Weblate, SQLite,
конфигурация и Git bundles обеих программ. PostgreSQL восстановлен в отдельную БД
(490 migrations), SQLite проверен `integrity_check` и восстановлен отдельно.
Архив и секреты не публикуются.

Исходное завершённое задание содержит 1662 перевода. Контрольный digest
упорядоченных `(id, source, target, state, context)`:
`43829ee3838f546e45722db13082d82e`. До разработки записано 158 MT receipts;
исторические receipts сохраняются, включая неопределённые.
Эти данные не являются тестовой площадкой для исправлений.

## Гарантия повторной оплаты

При неопределённом результате провайдера запрос автоматически не повторяется.
Ни новый ключ Weblate, ни другая модель, ни разбиение пакета не снимают запрет.
Сначала используются сохранённый ответ и штатная сверка. Остальные, доказанно
не отправленные строки продолжаются независимо.

Возможности внешнего маршрута считаются неподтверждёнными, пока не проверен
его конкретный контракт. Документация LiteLLM описывает response cache:
https://docs.litellm.ai/docs/proxy/caching . Кэш настраивается отдельно и может
не содержать ответа; повторный POST при cache miss способен вызвать модель.
Поэтому кэш сам по себе не является разрешением повторной отправки.
Для корпоративного LiteLLM billing idempotency и бесплатный полный lookup
не подтверждены. Для OpenRouter восстановление полного ответа по исходному
request ID также не включается без проверки доступности на данном маршруте.
Чужие ключи и реальные платные запросы для проверки контракта не используются.

## Режимы

- `repair`: полный цикл с прежними ограничениями прав, ревизий и области задания.
- `verify_only`: готовые переводы проверяются и экспортируются; перевод,
  кандидаты, исправления, изменение статусов, снятие hold и propagation запрещены.

Проверка судьями может требовать новой оплаты. Актуальные полученные оценки
переиспользуются; неизвестный ответ судьи не отправляется повторно автоматически.
Частичный результат явно перечисляет непереведённые и непроверенные строки.

## Тестовый объём

Публичный синтетический сценарий содержит шесть листов:
1042, 38, 328, 18, 6 и 230 строк (всего 1662).
Никакие тексты приватного лок-кита, ключи и ответы провайдера в fixtures не входят.

## Работа через интерфейс

На этапе качества выберите исправление подтверждённых ошибок либо
«Только проверка — без изменения переводов». Этот выбор относится к этапу
качества после первичной локализации и закрепляется в задании.

Для уже готового задания откройте его карточку и нажмите «Проверить готовые
переводы без изменений». Предварительная проверка читает проект и показывает
язык, число строк и оценку запросов. Денежная стоимость остаётся неизвестной,
если нет подтверждённого расчёта; оценка двумя судьями может оплачиваться отдельно.
Кнопка запуска создаёт новое задание проверки и новый файл. Старое задание,
его выгрузка и режим подключения проекта сохраняются, включая связь только для чтения.
Пустой перевод не запускает скрытую подготовку MT: отдельная проверка его отклоняет.

«Проверить состояние» перечитывает карточку через GET и не возобновляет оплату.
Обычное восстановление незавершённого задания происходит автоматически.
Явного действия повторной оплаты в этом выпуске нет: неизвестная оплаченная
работа остаётся исключением, а не превращается в разрешение повторного POST.

## Ожидание и результаты

Общий интервал новых producer POST — 75 секунд на endpoint/аккаунт. До проверки
раздельных квот все модели и места судей используют общий консервативный слот.
GET-опросы не занимают этот слот; полный Retry-After сохраняется между перезапусками.
Опрос использует 5/10/20/30/60 секунд, отсутствие прогресса 1800 секунд даёт
предупреждение. Общее окно — 21600 секунд, максимум — 86400. Изменение окна
наблюдения не означает повторной отправки запроса провайдеру.

Отчёт различает заполненность, два распознанных ответа судей, текущий PASS,
технические/терминологические проблемы и неопределённые финансовые исходы MT.
При частичном MT судьи получают заполненную часть, итоговый scan и выгрузка
сохраняют весь исходный объём и перечисляют пропуски. Готовый файл с исключениями
не объявляется чистым результатом качества.

Содержимое проверяется до и после скачивания. В режиме проверки дополнительно
сверяется защищённый digest исходной сессии. Ручная правка делает результат
устаревшим и сохраняется. Изменённый результат получает другой идентификатор;
старые export/report не перезаписываются. Поздние оценки можно получить отдельным
заданием проверки; сохранённые ответы провайдера переиспользуются по прежней идентичности.

## Хранение и совместимость

Weblate миграции 0150–0152 добавляют журнал и привязку к run. Закрытые полные
ответы хранятся приватно ещё 30 дней после успешного завершения. Неопределённые
ответы не удаляются автоматически; текстовые тела не попадают в UI/диагностику.
Semantic fences и исторические receipts не удаляются вместе с телом.
Визард миграцией 0004 добавляет только ссылки на per-unit recovery и делает
автоматическую копию SQLite перед обновлением схемы.

Старые задания без доказательств доставки остаются консервативными: истечение
lease или 404 не доказывает отсутствие оплаты. Новые recovery/verify режимы
включаются только после проверки capabilities согласованного выпуска Weblate.
