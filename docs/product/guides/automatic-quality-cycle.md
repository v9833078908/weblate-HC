# Автоматический цикл качества

Этот документ описывает прежний цикл версии 1. Полный цикл с унификацией повторов,
итоговым snapshot и проверкой стабильности экспорта описан в
`docs/product/guides/full-quality-cycle-v2.md`; для него нужен отдельный флаг
и расширенный серверный API.

Цикл качества является необязательным продолжением машинного перевода. Он предназначен для запуска из FastAPI-визарда и не заменяет ручную работу в Weblate UI.

## Предварительные условия

- Визард настроен на тот же Weblate через `WEBLATE_API_BASE_URL` и существующий защищённый токен.
- `WIZARD_EXTERNAL_WRITES=1` и `WIZARD_QUALITY_CYCLE_ENABLED=1`.
- Токен имеет права `translation.auto` и `unit.review` для проекта.
- Producer API сообщает `judge=true`, `judge_seats=2`, выбранный MT-движок и отсутствие блокирующих причин.
- В задании выбран один проверяемый язык. Для ручной приёмки используется `de`.

Если условие не выполнено, новый запуск отклоняется до платной обработки. Уже созданное состояние хранится в SQLite и может быть продолжено после устранения временной причины.

## Порядок обработки

1. После перевода worker создаёт долговечный цикл качества и проверяет возможности Weblate.
2. Визард запускает один удалённый judge run. Два судьи обрабатываются внутри него.
3. Worker опрашивает только состояние запуска; сетевые ошибки чтения повторяются с ограниченной задержкой, а изменяющий POST не повторяется вслепую.
4. Визард получает структурированные решения судей и замечания `repeat-drift`/`glossary`. Тексты исходника, перевода и доказательств в его БД не сохраняются.
5. Кандидат допускается к применению только при наличии двух мест судей и признака `candidate_verified`.
6. Weblate применяет пакет с проверкой ревизии, отсутствия человеческого утверждения и обязательной терминологии. Одна отклонённая строка не отменяет остальные.
7. Для реально изменённых строк выполняется адресная повторная проверка по новой ревизии.
8. При оставшихся исправимых замечаниях выполняется второй и последний раунд. После него цикл всегда формирует отчёт и допускает экспорт.

Итоговый статус `completed` означает, что открытых исключений нет. `completed_with_exceptions` означает, что экспорт создан, но некоторые строки требуют внимания. В отчёте отдельно считаются применённые кандидаты, чистые строки, устаревшие решения, человеческие утверждения, конфликты терминологии и неподтверждённые двумя судьями варианты.

## Одинаковый перевод повторов

Проверка `repeat-drift` группирует одинаковый исходный текст в одном языке и отмечает группы с разными вариантами перевода. Пустые значения не считаются отдельным вариантом. Проверка глоссария отличает обязательный термин от рекомендованного: обязательный конфликт блокирует автоматическое применение кандидата, рекомендованный остаётся замечанием.

Текущая автоматика не заменяет произвольно один уже существующий перевод другим только потому, что обнаружена неодинаковость. Исправление применяется лишь тогда, когда два судьи сформировали и подтвердили безопасный кандидат для конкретной строки. Остальная неодинаковость сохраняется в отчёте без остановки задания.

## Ручная проверка

1. Подготовить отдельный тестовый проект и строки немецкого языка, не содержащие ценных утверждённых переводов.
2. Добавить две одинаковые исходные строки с разными немецкими переводами и отдельную строку с обязательным термином глоссария.
3. В финальном шаге визарда включить автоматический цикл и выбрать `de`.
4. Убедиться, что карточка запуска проходит фазы предварительной проверки, судей, применения и повторной проверки.
5. Открыть отчёт: безопасные подтверждённые варианты должны иметь результат `applied`, защищённые или неразрешённые — явную причину исключения.
6. Сверить Weblate: утверждённые человеком и изменённые после решения строки не должны быть затёрты; экспорт должен соответствовать последнему состоянию Weblate.

Повторная отправка `POST` вручную для устранения сетевой ошибки запрещена: сначала нужно продолжить сохранённое задание, чтобы worker проверил удалённое состояние.
