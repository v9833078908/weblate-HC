# Producer-фронт HCGameLoc: бриф решений

Дата: 2026-09-14. Статус: бриф на согласовании; после одобрения — промпт для
Lovable (прототип на моках) и отдельный план бэкенд-контрактов в
`docs/product/plans/`. Не является планом реализации.

Источник: интервью с владельцем продукта (15 решений), исследование
документов, кода и рынка read-only субагентами. Вводные владельца: продюсеры
Hero Craft не будут пользоваться скиллами, «магия» — на бэкенде; текущий
UI Weblate старомоден и перегружен; все существующие функции сохраняются;
цель — LLM-first TMS уровня top-игроков; конечный артефакт — промпт для
Lovable/Emergent под прототип морды поверх бэкенда.

## 1. Цель, успех, не-цели

**Цель.** Продюсер загружает файл (лок-кит игры или тексты для стора) и без
знания Weblate получает переведённый, проверенный результат в нужном
формате; всё, чему нельзя доверять, вынесено в одну очередь решений с
понятной причиной.

**Видимый успех.** Критический путь из инструкции
(`/Users/eli/Downloads/Weblate - локализатор текстов-v1-14_09_2026, 16_02_38.pdf`:
проект → импорт кита и глоссария → языки → промпты → пакетный MT с ручным
фильтром → судья → скачать) сжимается до: *«Сделать локализацию» один раз в
пустом проекте → загрузить файл → (опционально) «Проверить качество» → решить N строк →
скачать*. Ни одного ручного шага «языки», «промпты», «фильтр
`state:empty`», «базовый файл `metadata/ru`».

**Не-цели.** Новый переводческий редактор; удаление функций Weblate;
Git PR из фронта (план гейта `docs/product/plans/2026-08-10-git-localization-quality-gate.md`
— отдельно); числовой скор качества; auto-approve без калибровки
(`docs/product/vision/llm-first-product-architecture.md` §4.5); интеграция
БДХК за пределами чтения карточки игры; массовое заполнение БДХК.

## 2. Текущее поведение и источники

- Vision и инварианты: `docs/product/vision/llm-first-product-architecture.md`
  (§4.1 блокируют только детерминированные чеки, судья advisory; §6 — 0–100
  в UI не показывать), `docs/product/vision/2026-08-15-producer-first-product-research.md`
  (персона, Producer mode §5, `LocalizationRun` §8, критерии успеха §10).
- Сокращение UI: `docs/product/designs/2026-09-01-02-producer-ui-reduction.md`
  — P0 применён на dev и prod, P1/P2 не сделаны; Advanced-режим обязателен.
- Судья: `weblate/trans/models/judge.py` (`ProducerRun`, `JudgeRunUnit` —
  пока только судейские прогоны), отчёт `weblate/trans/views/judge.py`,
  политика severity `docs/product/plans/2026-08-25-01-judge-producer-ux-and-delivery.md`
  (critical держится до аудируемого решения, major = `judge-flag`, minor =
  `judge-note`, dismiss judge-чеков выключен).
- Intake: `weblate/utils/views.py:create_component_from_kit`,
  `weblate/trans/views/create.py` (draft → preview → confirm, glossary
  append), `loc_kit_ingest/` — **только CSV/TSV/XLSX**; `.txt` явно отвергается
  тестом; JSON там — профили, не киты. Исходный язык выводится из крайней
  левой заполненной языковой колонки (`loc_kit_ingest/infer.py`) и после
  создания компонента неизменяем.
- Стор-тексты: `/Users/eli/Downloads/lokalizaciya-tekstov-dlya-storovstim.md`
  — формат «Файлы метаданных магазина приложений» (`weblate/formats/txt.py`),
  лимиты Google Play / App Store вшиты в формат по каноническим именам
  файлов, Steam и произвольные поля — флаг `max-length` на строку,
  `bbcode-text` для Steam, региональные коды (`en-US`, `pt-BR`, `zh-Hans`),
  базовый файл `metadata/ru` не подставляется сам.
- REST: есть проекты, компоненты, добавление языка компоненту,
  `machinery_settings`, `autotranslate` (синхронный, без task id),
  статистика/чеки/units, `GET /api/tasks/{id}/`, скачивание per-language.
  **Только HTML/session**: kit draft/preview/confirm, glossary append,
  fan-out языков на проект, multilingual XLSX, отчёт и резолюции судьи,
  dismiss/mass-fix, matrix. Единой сущности «прогон конвейера» нет.
- Дизайн-контракт: `DESIGN.md` (токены под shadcn/Tailwind, «тихий
  продуктовый SaaS»).
- Рынок (Lokalise, Crowdin, Phrase, Smartling, Transifex, Gridly, Tolgee,
  Lilt): одна кнопка «перевести всё», очередь «review N strings» вместо
  каталога чеков, глоссарий/стиль как одноразовая настройка, PM-дашборд,
  self-correction до показа человеку; жалобы на Phrase/Crowdin — «много
  параллельных статусов, перегружено». Их «единый 0–100 + порог» **не
  берём** (противоречит §4.1/§6).

## 3. Решения интервью

| # | Вопрос | Решение |
|---|---|---|
| 1 | Позиционирование | Отдельный producer-фронт (SPA) поверх REST; Weblate остаётся как Advanced под той же учёткой, ссылка «Открыть в Weblate». Вход — родной Weblate, отдельного экрана авторизации нет. В UI — «проект» и «лок-кит», не «игра» (поправка владельца 2026-09-14) |
| 2 | Граница «магии» | Загрузка запускает импорт → языки → MT → детерминированные чеки автоматически; судья — отдельная кнопка «Проверить качество» с оценкой стоимости/времени до запуска |
| 3 | Целевые языки | Настраиваются один раз в wizard-е «Сделать локализацию» (пресет Hero Craft; колонки кита предотмечены); каждая загрузка переводится на все языки проекта; готовые переводы из колонок кита импортируются и не перезаписываются |
| 3a | Второй тип входа | Тексты для сторов (Steam / Google Play / App Store / произвольный) — отдельный компонент в том же проекте; региональные коды выводит бэкенд из языков проекта по таблице соответствия |
| 4 | Ввод стор-текстов | Форма с полями конкретного стора; бэкенд собирает `metadata/<locale>/<field>.txt`, ставит флаги, базовый файл, языки. Лимиты Google Play / App Store — из формата (канонические имена), Steam/custom — явный версионируемый источник лимитов |
| 5 | Промпты проекта | В wizard-е — привязка к карточке игры в БДХК; если есть блоки B (бриф) и C (голос и стиль) — бэкенд генерирует persona/style/language_instructions из них; иначе короткая анкета (5–8 вопросов) → генерация; анкету можно пропустить — дефолтный профиль студии. Продюсер промпты не видит, в Advanced они редактируемы. БДХК питает только промпты; терминологию из БДХК не тянем |
| 6 | Глоссарий | Шаг wizard-а с рекомендацией загрузить, можно пропустить и добавить позже (первая загрузка создаёт, следующие — append-only); плюс список извлечённых из кита кандидатов в термины с добавлением по одному или всех сразу — отдельная LLM-механика со своим промптом и «умной» моделью, задаваемой конфигом через LiteLLM или OpenRouter |
| 7 | Качество | Одна очередь «Требуют решения» на проект, группировка по языкам; у строки одна причина на русском, обратный перевод (когда есть); действия по типу: блокирующий чек → «Исправить с помощью AI» (автоисправимые — mass-fix без LLM) / «Открыть в Weblate»; находка судьи → те же + «Принять как есть» (аудируемое исключение с причиной). Названия чеков и вкладка «Проверки» не показываются; ложное срабатывание детерминированного чека снимается только в Advanced |
| 8 | Результат | Кнопка «Скачать результат» на проекте и на компоненте; кит — XLSX / CSV / JSON / формат исходного импорта (включая txt-подобные), стор — ZIP `metadata/…` + экран «поля по языкам» с копированием; Git — в Advanced |
| 9 | Непрошедшая строка в выгрузке | Ключ остаётся, значение пустое; рядом с кнопкой — «N ключей выгружены пустыми → Требуют решения». Ни одна строка из файла не выпадает |
| 10 | Роли | Продюсер — весь критический путь, включая запуск судьи и исключения, видит отчёт по деньгам за MT и судью; Администратор AI Tools — ключи, модели, пресет языков, бюджеты, Advanced-операции. Add-ons/VCS/легаси-UI — в Advanced по ссылке |
| 11 | Статус | Карточка прогона в приложении (этапы, языки, честный `queued/running/no-update`) + письмо по завершении и при сбое, со ссылками на очередь и скачивание |
| 12 | Прототип | Полный click-through на моках по будущей API-схеме; типизированный API-клиент с закрытым списком эндпоинтов, переключатель `mock/live` в одном файле |
| 13 | Язык UI | Только русский |
| 14 | Стиль | `DESIGN.md` как обязательный контракт: refinement, не redesign |
| 15 | Повторная загрузка | Новые ключи переводятся; изменённый источник переводится заново автоматически (старый target — в историю, прежнее «Принять как есть» сбрасывается) |

## 4. Продуктовая модель

**Сущности (язык продюсера → Weblate).** Проект → `Project` (в UI —
«проект»; «карточка игры» — только сущность БДХК). Контент →
`Component` трёх видов: *лок-кит* (po-mono из таблицы), *глоссарий* (TBX),
*стор* (`appstore`-формат, один компонент на стор). Прогон → обобщённый
`ProducerRun` (`kind: translate | judge`). Строка-решение → `Unit` с
блокирующим чеком или judge-чеком. Деньги → `LLMUsageLog`, связанный с
прогоном.

**Навигация (7 пунктов, из vision §5, сведённых к критическому пути).**
Проекты → Проект: *Обзор* (языки, прогоны, деньги) · *Загрузить* (кит / стор) ·
*Требуют решения* · *Глоссарий* · *Скачать* · *Настройки проекта* (языки,
профиль/анкета, стор-поля) · *Advanced → Weblate*.

**Потоки.**

1. *Сделать локализацию* (wizard из пустого проекта; экран-приглашение «Это
   автоматический wizard. Загрузите лок-кит»): лок-кит (drag&drop; бэкенд
   показывает распознанный исходный язык из первой колонки, найденные
   языки, ошибки строк; строки без текста во всех языках — в карантин, не в
   компонент) → языки (пресет, колонки кита предотмечены, можно
   снять/добавить) → профиль проекта (карточка игры в БДХК; если найдена и
   заполнены B и C — «профиль импортирован», иначе анкета или пропуск) →
   глоссарий (загрузить / пропустить; кандидаты из кита) → «Сделать
   локализацию» → прогон #1. Сам проект создаётся отдельно минимальной
   формой (имя), как в Weblate; wizard не создаёт проект.
2. *Загрузить кит в проект с локализацией*: тот же экран загрузки; полная
   таблица; новые ключи переводятся, изменённые — заново, Explanation и
   готовые переводы сохраняются; результат — прогон.
3. *Тексты для стора*: выбрать стор → форма полей с лимитами и счётчиками →
   «Перевести» → прогон → экран «поля по языкам» / ZIP.
4. *Проверить качество*: выбрать компоненты/языки → оценка (строк, $, часов)
   → подтвердить → прогон `judge` → очередь.
5. *Требуют решения*: фильтр язык / компонент / тип (блокирует · судья);
   карточка строки: ключ, источник, перевод, обратный перевод (из улик
   судьи; для чек-only строк — по запросу, см. открытые пункты), одна
   причина, история попыток, действия по типу (§3, п. 7).
6. *Скачать*: компонент или весь проект, формат, сводка «выгружено / пустых»,
   ссылка на очередь.

**Статус прогона.** `queued → running (import → languages → translate[lang]
→ checks) → completed | failed`; `no-update` при потере liveness
(`weblate/utils/celery.py`). Судья: `queued → running → completed | failed`

- счётчики исходов (`JudgeRunUnit.Outcome`). Прогон никогда не «завершён»
без явного результата; повторный запуск — только незавершённого хвоста
(`state:empty`).

## 5. Правила качества (связывающие)

- Блокируют выгрузку только детерминированные чеки (`game-markup`,
  `game-line-break`, `game-number`, `game-token`, `max-length`, `bbcode`,
  стоковые). Строка с блокирующим чеком не экспортируется; в файле — пустое
  значение.
- Судья advisory: critical держится до аудируемого решения, major/minor —
  улики, отгружаются. «Принять как есть» — только для находок судьи, с
  причиной, с записью в историю строки.
- Числовой скор не показывается. Причина — текст на русском; чек-код
  (`game-markup`) — только в Advanced.
- Прогон MT всегда с фильтром `state:empty` — фильтр продюсеру не виден и
  не редактируется; «перевести заново» для изменённого источника — по
  событию изменения источника, не по ручному фильтру.
- Судья другого семейства моделей, чем переводчик; пер-языковые тиры
  доверия (§4.6) — правило бэкенда, фронт показывает «pass не подтверждён
  вторым сигналом» как advisory.

## 6. Бэкенд-контракты, которые заказываются

Существующее переиспользуется (проекты, языки компонента,
`machinery_settings`, статистика, units, `tasks`). Новое — REST под
`/api/producer/…` (имена ориентировочные; финализирует план бэкенда):

| Ресурс | Что закрывает |
|---|---|
| `POST projects/` (имя) и `POST projects/{slug}/localization/` (языки + профиль: `bdhc_title_id`, ответы анкеты или дефолт + id загрузок кита/глоссария + выбранные кандидаты) | поток 1 без ручных шагов; один коммит wizard-а |
| `GET bdhc/titles/?q=`, `GET bdhc/titles/{id}/profile/` | привязка карточки; статус блоков B/C |
| `POST projects/{slug}/uploads/` (`kind: loc-kit | glossary | store`, файл или поля стора) → валидация (исходный язык, языки, ошибки строк, карантин); `uploads/{id}/confirm/` → прогон | intake без draft/confirm-HTML |
| `GET stores/{store}/fields/` | схема полей, лимиты, разметка; Steam/custom — версионируемый источник |
| `POST projects/{slug}/runs/` (`kind: judge`), `POST runs/estimate/`, `GET runs/{id}/`, `POST runs/{id}/resume/`, `GET projects/{slug}/runs/` | единый прогон с этапами, языками, liveness, стоимостью |
| `GET projects/{slug}/decisions/?language=&kind=`, `POST decisions/{unit}/repair/`, `POST decisions/{unit}/accept/` | очередь решений; accept только для judge-находок |
| `GET projects/{slug}/glossary/candidates/?upload=`, `POST projects/{slug}/glossary/terms/` | извлечение кандидатов (своя модель/промпт через конфиг; `upload` — в wizard-е, пока кита ещё нет как компонента), добавление по одному/всем |
| `GET projects/{slug}/export/?content=&format=`, `export/summary/` | XLSX/CSV/JSON/исходный формат; полный набор ключей; сводка пустых |
| `GET projects/{slug}/costs/`, `GET me/` | деньги по прогону/языку/модели из `LLMUsageLog`; имя пользователя в шапке |
| формат-адаптеры | контракт «парсер → каноническая таблица `key / source / targets / explanation` → рендер обратно»; на каждый формат — образец от продюсеров и lossless round-trip тест |
| уведомления | письмо по `completed`/`failed` прогона на существующей почтовой инфраструктуре |

Аутентификация — родная сессия Weblate (фронт на том же origin, CSRF-заголовок
на мутациях) либо Bearer-токен (`weblate/api/authentication.py`); отдельного
экрана входа нет. CORS нужен только если фронт хостится на другом origin.

## 7. Прототип (Lovable)

- Стек: React + Vite + TS + Tailwind + shadcn/ui; Supabase не нужен.
- `src/api/client.ts` — единственный файл с эндпоинтами из §6 и
  существующего API; `src/api/mock/` — фикстуры; переключатель `VITE_API_MODE=mock|live`.
  Промпт запрещает выдумывать эндпоинты вне списка.
- Фикстуры: проект «Pirate Ships» (лок-кит, глоссарий, Steam, Google Play;
  9 языков; прогон завершён; прогон судьи идёт; 14 строк в очереди — 3
  блокируют, 11 судья; стоимость по прогонам); проект без БДХК-карточки
  (анкета); пустой проект без локализации; пользователь сессии.
- Экраны: проекты → пустой проект (приглашение) → wizard «Сделать
  локализацию» → обзор проекта → загрузка кита / стор-форма → карточка
  прогона → очередь → скачать → настройки → ссылка Advanced. Экрана входа
  нет.
- Дизайн: токены и правила `DESIGN.md` целиком; контролы 36px, карточки без
  теней, одна `primary` на область, статус — бейдж + иконка, не только цвет;
  фокус видим; логические свойства; UI на русском.
- Доступность: `ACCESSIBILITY.md` и `docs/contributing/frontend.rst` как
  ограничения промпта.

## 8. Существенные режимы отказа

- Первая колонка кита — не исходный язык → прототип показывает стоп на
  экране загрузки («исходный язык определён как `de`: первая заполненная
  колонка»), не выпадающий список.
- Строки без текста во всех языках (po-ошибка, отклоняет весь файл) →
  карантин отдельным списком, файл проходит.
- Судья недоступен / ключ не задан → кнопка «Проверить качество»
  заблокирована с причиной для админа, MT продолжает работать.
- Потеря liveness прогона → `no-update` честно, кнопка «перезапустить
  хвост», не «завершено».
- Расхождение схемы mock/live → ловится типизированным клиентом при
  переключении, не в экранах.

## 9. Сценарии приёмки прототипа

1. Из списка проектов за ≤6 экранов пройти «Сделать локализацию» с китом и глоссарием, увидеть
   прогон и «готово: 9 языков».
2. Загрузить второй кит с 3 новыми и 2 изменёнными строками → прогон
   показывает 5 переведённых, остальные не тронуты.
3. Стор-форма Google Play: превышение лимита поля видно до отправки; Steam —
   лимит из явного источника.
4. Запуск судьи показывает оценку ($, часы, строк) до подтверждения.
5. В очереди: блокирующая строка не имеет «Принять как есть», судейская —
   имеет; действие пишет причину; счётчик на обзоре меняется.
6. Скачать XLSX: полный набор ключей, 3 пустых, сводка рядом с кнопкой.
7. Каждый экран проходим с клавиатуры; статус не передаётся одним цветом.

## 10. Открытые пункты и допущения

Открытые (нужен ответ владельца или отдельное решение):

1. Образцы «странных» форматов (txt, JSON-киты) — без них грамматика
   адаптеров не определена; обещание «вернуть в том же формате» действует
   только для форматов с образцом и round-trip тестом.
2. Удалённые из кита ключи: текущий update-flow po-mono удаляет юнит,
   отсутствующий в шаблоне; выбрать «удалять» или «хранить и не выгружать».
3. Обратный перевод для строк с чек-only проблемой (без судьи): показывать
   по запросу (дешёвая модель, новый вызов) или не показывать.
4. Интеграция БДХК: спека `docs/product/designs/2026-08-31-bdhc-producer-questionnaire-spec.md`
   выносит интеграции в отдельные задачи; read-only чтение карточки нужно
   согласовать с командой БДХК (транспорт — существующий MCP/API).
