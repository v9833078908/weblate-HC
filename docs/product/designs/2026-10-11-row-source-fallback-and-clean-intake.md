# Построчный выбор исходного языка и понятная диагностика лок-кита

Статус: проект решения для согласования. Основание — запрос пользователя от
2026-10-11 и обследование WS.Localizations.xlsx от 2026-10-08.

## Правила пользователя

Заявленный исходный язык сохраняется в настройках проекта. Только для строки,
у которой нет текста на этом языке, автоматически использовать русский или
английский текст из той же строки. Пустые строки не показывать как ошибки,
предупреждения, карантин или отдельную пользовательскую метрику.

Детерминированный порядок при отсутствии заявленного текста: `ru`, затем `en`,
без повторного рассмотрения заявленного языка. Это предлагаемая политика для
согласования: пользователь назвал оба языка, но не задавал их приоритет.
Например, `en` → `ru`; `ru` → `en`; `de` → `ru` → `en`.

Не использовать другие языки, соседние строки или автоматически переведённый
текст как запасной исходник. Региональный вариант не приравнивать к базовому
языку без явного подтверждённого соответствия колонок. Не угадывать язык по
содержимому через LLM. Формулы не являются исходным текстом. Использовать
сохранённый признак формулы XLSX, а не проверку первого символа строки: обычный
текст, начинающийся с `=`, сам по себе не является вычисляемой ячейкой.

## Контракт строки

Для непустой строки с уникальным ключом хранить `declared_source`,
`effective_source`, `effective_text`, `source_origin` (`declared`/`fallback`),
`original_row`, исходные значения всех языковых колонок и координаты файла/листа.
Выбор запасного текста не меняет исходную пустую ячейку заявленного языка.

Пробельная языковая ячейка считается отсутствующей. Проверка пустоты не удаляет
пробелы из выбранного текста: перевод получает его оригинальное значение.
Запасная колонка распознаётся независимо от того, выбран ли этот язык целью.
Если колонка заявленного языка отсутствует полностью, алгоритм также может
использовать подтверждённые колонки `ru`/`en`.

Пустая строка после исключения подтверждённых служебных колонок не образует
переводимую единицу. Строка с ключом без текста не считается пустой: она остаётся
в проблемах. Непустая строка без ключа и повтор ключа также остаются проблемами;
повтор проверяется по всему логическому листу до разделения по исходным языкам.
Служебная колонка с неизвестной ролью не исключается из этой проверки молча.

Готовые переводы не перезаписывать. Если целевой язык совпадает с фактическим
исходным, значение уже присутствует: не создавать перевод на самого себя и не
отправлять платный запрос. Если заявленный язык выбран исходником проекта, он
не становится новой целью автоматически только из-за отсутствия текста строки.

## Передача в Weblate без изменения Django/Celery

Текущий worker, сравнение и экспорт используют `manifest.source` для всех строк.
Переименовать русский текст в английский исходник недопустимо. Решение —
разделить один логический лист на технические компоненты с фактическими
исходными языками. Каждый компонент содержит только свою группу строк.

Основной компонент сохраняет прежний идентификатор `kit-N`. Дополнительные
компоненты получают стабильные идентификаторы `kit-N-src-ru` и `kit-N-src-en`.
`N` берётся из закреплённого соответствия логических листов, а не из размера
группы или порядка непустых групп. Пустой компонент не публикуется.

В manifest v2 добавить `sheets` с полными исходными строками и языковыми
колонками логических листов. Технические `components` содержат
`logical_sheet_id`, `source`, `targets` (без `source`), исходные координаты,
профиль и строки для существующего writer. Профиль имеет фактический исходный
язык и пропускает строки, которые принадлежат другим группам. Результат
повторного разбора профиля обязан точно совпасть с запланированной группой.
При формировании групп сохранить ограничения объёма загруженного файла.

Глобальные `manifest.source` и `manifest.targets` остаются заявленным выбором
пользователя. Каждый вызов API, seed, MT и проверка используют исходник и цели
технического компонента. Источник явно присутствует в реальном запросе LLM.
Общие инструкции переводчика не должны ошибочно предписывать единый исходный
язык всем группам. Пользовательские инструкции не переписывать автоматически:
явное противоречие источников показать перед запуском и потребовать исправления.

Глоссарий применяется только при совпадении исходного языка и наличии нужного
целевого языка. Не инвертировать английский глоссарий в русский автоматически.
Недоступность подходящего глоссария для запасной группы показать в раскрываемых
сведениях; существующие глоссарии и настройки Weblate не изменять.

## Сравнение, повторный запуск и выгрузка

Логическая идентичность строки — `(file, sheet, key)`, независимо от исходного
языка технической группы. Сохранённое соответствие дополнительно связывает эту
идентичность с фактическим исходником и remote component. Старые соответствия
`file + separator + sheet` продолжают означать основной компонент.

Повторный запуск с тем же выбранным исходным текстом повторно использует
компонент и готовые переводы. Появление нового заявленного текста или исчезновение
старого запасного текста не даёт права автоматически удалить старую строку,
переместить её в другой компонент или повторно оплатить перевод. Изменение
фактического исходника существующей строки показывается как конфликт изменения
источника по прежней политике безопасного сравнения; до решения запись этой
строки запрещена. Не создавать скрытый дубль в другой группе.

Экспорт объединяет технические группы обратно в один лист по `logical_sheet_id`
и `original_row`. Ключи, порядок строк, исходные пустые ячейки, другие языки и
служебные значения остаются исходными; добавляются только разрешённые результаты
в целевые колонки. Не выдавать по отдельному XLSX-листу на запасной язык.
Запрещено обещать сохранение оформления и работающих формул: существующий
экспорт пересобирает XLSX и пишет формулы как строки, это отдельная задача.

Исторические jobs/exports/manifests не переписываются. Для чтения manifest v1
фактический исходник компонента равен `manifest.source`. Запасной выбор действует
при подготовке новой версии, не меняет уже завершённую задачу.

## Интерфейс

- Удалить сообщения и показатели о пропущенных пустых строках. Из пользовательских
  totals и карантина исключить `blank`; исходный снимок старого задания сохранить.
- «Исходные строки» заменить на «Строки с данными». «Карантин» заменить на
  «Строки, требующие проверки». Число подготовленных учитывает запасные строки.
- Показать спокойную сводку «Для N строк использован запасной исходный язык»
  с раскрываемым списком файла, листа, номера, заявленного/фактического языка.
- Вместо сотен координат формул показывать сводку по выбранным листам и
  служебным колонкам, например «Units: C, E, G — подсчёт длины текста».
- Подтверждённые колонки с формулами убрать из обязательных ручных решений.
  Настройки доступны через закрытую по умолчанию кнопку «Структура колонок».
  Неизвестные роли или формулы в настоящих языковых колонках требуют решения,
  не назначаются служебными только потому, что там есть формула.
- Проблемные строки показывать с листом, номером, причиной и доступными языками;
  добавить рабочую пагинацию. Автоматической подстановки самого содержимого
  строки в общий журнал и диагностический отчёт не делать.

## Проверяемый пример

Для исследованного WS.Localizations.xlsx заявлен `en`. 4382 пустые строки
исчезнут из пользовательских сообщений. Для 21 строки без `en` алгоритм проверит
`ru`; в сохранённом файле он также отсутствует. В Tutorial 105–106 есть только
испанский, который не разрешён как альтернатива. Поэтому все 21 строки этого
конкретного файла останутся требующими проверки, число допущенных останется 1657.
Не обещать, что новая политика восстановит эти строки автоматически.

## Вне объёма

Не менять Weblate Django/Celery, модели/провайдеры LLM, тарифы и таймауты;
не запускать перевод старых проектов; не восстанавливать отсутствующие исходники
догадками; не редактировать оригинальный XLSX; не добавлять испанский в запасные
языки без нового запроса пользователя.
