# ТЗ: доработка анкеты и карточки игры в БДХК

Дата: 2026-08-31. Статус: ТЗ для разработчика БДХК; согласованные решения — из
`docs/product/designs/2026-08-28-universal-game-context-db.md` (концепция
согласована 2026-08-30).

## Что делаем и зачем

Карточка игры в БДХК становится единым источником фактов об игре для четырёх
продуктов: локализация строк (Weblate), анализ фидбека (GamePulse), автоответы
на отзывы (GamePulse Autoanswer), локализация скриншотов. Сегодня каждый продукт
добывает контекст сам и вручную; анкета продюсера покрывает только гейм-дизайн
(ЦА, жанр, core-геймплей) и ничего не говорит о голосе игры, стиле, языках.

Эта задача — **только про БДХК**: схема данных, анкета продюсера, правила
качества данных и отдача через существующие read-only интерфейсы (MCP/API).
Интеграции продуктов с БДХК — отдельные задачи, сюда не входят.

## Что в текущей базе ломает использование как AI-контекста

Замер живой БДХК (75 игр, 2026-08-28; перепроверено на карточке
`tiny-space-arena-1v1-battles-sim` 2026-08-31):

1. Факты с `content = null` помечены `is_ai_context = true` — пустота уезжает
   в промпт как факт.
2. `game_project_fields` — свободные слоты «поле 1»…«поле 10»: 16 записей из 47
   так и называются «поле N», контент дублирует анкету.
3. 11 из 83 фактов опросника — буквально «Проверка опросника», тоже с
   `is_ai_context: true`.
4. `games.monetization_notes` — проза без лимита (тысячи символов), которую
   нельзя целиком класть в промпт.
5. Локали в двух конвенциях одновременно: `ru` и `ru-RU`, `en` и `en-US`,
   `pt-BR`/`pt-PT` вперемешку с голым ISO.
6. Ни одна карточка не одобрена (`requires_review` 56, `needs_review` 17), при
   этом статус ни на что не влияет.

## Объём задачи

1. Новые и пересмотренные поля анкеты продюсера (блоки A–D ниже) с текстами
   вопросов, подсказок и примеров для интерфейса.
2. Отдельная сущность «Известные проблемы» (блок E) — не часть анкеты.
3. Справочник референсов (блок F).
4. Сквозные поля управления и серверная защита от заглушек (блок G).
5. Миграция существующих данных на новую форму (блок H).
6. Пилот: ревизия 10–14 уже содержательно заполненных игр по новой форме.

Принцип формы: **enum, теги и короткие поля с жёстким лимитом; свободный текст
только там, где enum не выражает смысл**. У каждого поля есть вариант
«не применимо» — он отличается от «не заполнено». Заполняемость определяется
формой: свободные поля в текущей базе дали «поле N» и тестовый мусор.

---

## Блок A. Идентичность игры

Часть полей заполняется автоматически или администратором, продюсер только
проверяет. В анкете продюсера из этого блока — три вопроса (серия, язык
оригинала, стадия жизни).

| Поле | Тип | Кто заполняет |
|---|---|---|
| `title_id` | внутренний slug | система; **не** Android-пакет: у iOS другой bundle id, `game_id`-пакет остаётся legacy-ссылкой |
| `display_name` | строка | из стора, продюсер проверяет |
| `series_id` | ссылка на серию, nullable | продюсер |
| `source_locale` | BCP-47 | продюсер |
| `lifecycle` | enum: `softlaunch` / `global` / `sunset` | продюсер (маппинг из текущего `status`) |
| `age_rating`, `content_flags[]` | enum | автоматически из стора |
| `store_links[]` | таблица (platform, store_app_id, package_name, url) | автоматически |
| `owner_producer`, `source_owner` | пользователи | администратор |
| `title_binding[]` | (system enum: weblate / gamepulse, external_id) | администратор; явная таблица связей вместо угадывания по пакету |

Тексты для интерфейса продюсера:

- **Серия** — «Если игра — сиквел или часть серии, укажите серию. Общие
  описания и стиль серии наследуются, вы заполняете только отличия».
- **Язык оригинала** — «На каком языке пишутся тексты игры изначально (язык,
  с которого переводят). Пример: русский».
- **Стадия жизни** — «Софтланч — игра доступна ограниченно; глобальный релиз —
  доступна везде; закат — игра больше не развивается, только поддерживается».

## Блок B. Игровой бриф

Одна запись на игру, суммарный бюджет **4000 символов** — это не пожелание:
потребители режут контекст на этом размере, длинный бриф ухудшает вывод модели.
Интерфейс показывает счётчик оставшегося бюджета.

Существующие типы фактов опросника сохраняются и получают лимиты; новые поля
помечены «(новое)».

| Поле | Тип / лимит | Вопрос продюсеру в интерфейсе | Подсказка и пример |
|---|---|---|---|
| `genre[]` | enum + свободное до 100 | «Жанр игры» | Выберите из списка (стратегия, конструктор, match-3, …) и при необходимости уточните словами. Пример: «конструктор кораблей, build-and-battle» |
| `premise` (новое) | текст 300 | «Одним-двумя предложениями: кто игрок и что он делает в игре?» | Так вы объяснили бы игру человеку, который её не видел. Пример: «Игрок — пиратский капитан: строит форт, собирает флот исторических парусников и сражается с другими игроками» |
| `setting_and_era` (новое) | текст 600 | «Мир игры: где и когда происходит действие?» | Место, эпоха, технология/магия, важные особенности мира. Пример: «Золотой век пиратства, Карибы, XVII век; лёгкая мистика: проклятые корабли, кракены». Сейчас поле `setting` пусто почти у всех игр |
| `world_tone[]` (новое) | enum + свободное 200 | «Настроение мира» | Выберите: серьёзное / комедийное / мрачное / уютное / героическое / ироничное — и уточните словами. Это не стиль текстов (он ниже), а атмосфера самой игры |
| `core_loop` | текст 800 | «Основной игровой цикл: что игрок делает снова и снова?» | Цепочка действий через стрелки. Пример: «собирай ресурсы → улучшай корабль → автоматический бой → новые модули → усиление» (текущий `core_gameplay`) |
| `meta` | текст 400 | «Долгосрочная прогрессия: ради чего игрок возвращается неделями?» | Прокачка аккаунта, коллекции, сезоны, лиги (текущий `meta`) |
| `player_goal` | текст 300 | «Главная цель игрока» | Пример: «собрать непобедимый флот и возглавить рейтинг PvP-лиги» (текущий `player_goal`) |
| `fun_points` | текст 400 | «За что игроки любят игру? 3–5 пунктов» | Точки удовольствия — то, что игроки хвалят в отзывах. Пример: «радость от идеального билда; рост кораблика в дредноут; победа над более сильным» (сейчас лежит в свободном слоте) |
| `target_audience` | текст 400 | «Кто ваша аудитория?» | Возраст, интересы, стиль игры. Пример: «мидкор 18–45, поклонники sci-fi и конструкторов, ценят планирование, а не реакцию» (текущий `target_audience`) |
| `key_modes[]` | список: (название до 60, описание до 300) | «Основные режимы игры» | По одной строке на режим, с внутриигровым названием. Пример: «Варпы — PvP-сборки в PvE-волнах ради варп-коинов» (сейчас в свободном слоте) |
| `multiplayer` | текст 300 | «Есть ли мультиплеер и какой?» | Пример: «асинхронное PvP против слепков других игроков» (текущий `multiplayer`) |
| `retention` | текст 400 | «Ключевые фичи удержания» | Что возвращает игрока каждый день (текущий `retention`) |
| `monetization_model` (новое) | enum: `f2p_iap` / `f2p_ads` / `f2p_mixed` / `premium` / `subscription` | «Модель монетизации» | Автоподстановка из стора, продюсер проверяет |
| `monetization_notes` | текст 400 | «Что важно знать о монетизации? Коротко» | Только то, что влияет на общение с игроками: премиум-валюты (с названиями!), VIP, батл-пасс. Не вставляйте экономический дизайн целиком — текущее поле без лимита придётся сократить |
| `live_ops` (новое) | bool + текст 400 | «Есть ли регулярные события/сезоны?» | Пример: «сезоны по 4 недели, ивенты по выходным, регулярные распродажи» |
| `content_types[]` (новое) | multi-enum | «Какие тексты есть в игре?» | Отметьте всё, что есть: надписи интерфейса / описания способностей / описания предметов / патчноуты / пуш-уведомления / обучение / диалоги / лор / тексты для стора. От этого зависит, какие вопросы о стиле вам зададут |
| `geo_availability` | enum + список стран | «География релиза» | worldwide или список (текущий `geo_availability`) |

`genre_perception` (текущий тип факта) складывается в свободную часть
`genre[]` — отдельное поле не сохраняется.

## Блок C. Голос и стиль

Главная дыра текущей анкеты: именно этот блок нужен всем трём LLM-потребителям
(перевод строк, автоответы, тексты креативов), и сегодня его нет вообще — стиль
задаётся вручную в каждом продукте заново. Запись на игру плюс возможность
переопределить отдельные поля для конкретного языка.

Вводный текст в интерфейсе: «Этот раздел определяет, как игра „разговаривает“ с
игроком — в переводах, ответах на отзывы и на скриншотах в сторе. Отвечайте
так, как если бы объясняли новому копирайтеру, что можно и что нельзя».

| Поле | Тип / лимит | Вопрос продюсеру | Подсказка и пример |
|---|---|---|---|
| `tone` | текст 600 | «Опишите характер текстов игры» | Каким тоном игра говорит с игроком? Пример: «энергичное пиратское приключение; прямой, слегка грубоватый тон; без канцелярита» |
| `register` | enum: formal / informal / mixed | «Формально или неформально?» | Неформально = как с приятелем; формально = как банк с клиентом |
| `player_address` | enum + заметка на язык | «Как обращаться к игроку?» | На «ты» или на «вы»? Для каждого языка можно уточнить: ру — «ты», de — «du», es — «tú» |
| `humor` | текст 200 | «Уместен ли юмор и где?» | Пример: «да, в анонсах и описаниях предметов; не в сообщениях об ошибках и платежах» |
| `profanity_policy` | enum: none / mild / uncensored | «Допустима ли грубость?» | none — совсем без грубости; mild — лёгкая («чёрт побери»); uncensored — без ограничений |
| `emoji_policy` | enum: never / sparing / free | «Эмодзи в текстах?» | never — никогда; sparing — изредка, в пушах и ответах на отзывы; free — свободно |
| `forbidden[]` | до 20 пунктов по 200 | «Чего в текстах быть не должно?» | Запреты стиля и обещаний. Примеры: «не обещать возвраты и сроки фиксов», «не превращать пиратов в пародию», «не упоминать конкурентов» |
| `dnt_brand_terms[]` | список строк | «Названия, которые никогда не переводятся» | Название игры, студии, торговые марки. Пример: «Pirate Ships», «HeroCraft» |
| `names_policy` | enum: translate / transliterate / keep_verbatim | «Что делать с именами собственными?» | Переводить по смыслу («Чёрная Жемчужина»), записывать русскими буквами («Голдберг») или оставлять как в оригинале («Goldberg») |
| `character_voices[]` | таблица: (имя до 60, register enum, заметка до 200) | «Персонажи с собственной манерой речи» | Только те, у кого манера отличается от общего тона. Пример: «Боцман — грубо, идиомы; Адмирал — формально, коротко; Культисты — архаично, зловеще» |
| `notification_style` | текст 200 | «Стиль пуш-уведомлений» | Пример: «коротко, срочно, один призыв к действию; восклицательные знаки — как в оригинале». Показывать, только если в `content_types` отмечены пуши |
| `patchnotes_style` | текст 200 | «Стиль патчноутов» | Пример: «сохранять структуру списка; голос разработчика, без маркетинга». Показывать, только если отмечены патчноуты |

Чего в блоке сознательно нет: роль переводчика («You are a senior game
localizer»), правила плейсхолдеров и тегов, правила consistency — это общие
системные шаблоны потребителей, одинаковые для всех игр, а не факты об игре.

## Блок D. Языки

Нужен всем четырём продуктам и отсутствует везде. Хранится как таблица
`title_locale`, продюсер заполняет через мультиселект.

| Поле | Тип | Вопрос продюсеру | Подсказка |
|---|---|---|---|
| `locale` | BCP-47, канонический | — | Выбор из справочника, не свободный ввод. Сервер канонизирует: `ru-RU` → `ru`, `pt-BR` остаётся `pt-BR` |
| `scope` | enum: interface / store | «Языки интерфейса игры» и отдельно «Языки страницы в сторе» | Список стора автоподтягивается, продюсер проверяет |
| `status` | enum: shipped / planned / dropped | «Какие языки уже в игре, какие планируются?» | shipped — уже в игре; planned — в планах; dropped — были и убраны |
| `is_source` | bool | — | Ровно один язык оригинала на scope; проставляется из `source_locale` |
| `locale_note` | текст 500 | «Особенности для конкретного языка» | Пример: de — «десятичный разделитель — запятая»; ja — «катакана для заимствований» |
| `raw_locale` | строка | — | Служебное: как код пришёл из источника, для провенанса |

Справочник локалей — один на всю базу, с таблицей канонизации существующих
кодов (`ru`+`ru-RU` → `ru` и т.д., полный список расхождений — в блоке H).

## Блок E. Известные проблемы (отдельная сущность, не анкета)

Заполняется саппортом/оператором по событию (инцидент, плановые работы,
известный баг), а не продюсером при онбординге. В интерфейсе — отдельный
раздел карточки «Известные проблемы», не шаг анкеты.

`title_issue`: (`title_id`, `issue_key`, `issue_summary` текст 300, `answer`
текст 1000, `locale`, `scope` enum: store_reply / support / patch_note,
`valid_from`, `valid_until`, `status`, `owner`).

Ключевое поле — `valid_until`: ответ «ведём работы 12 августа» обязан истечь
сам, а не жить, пока кто-то не вспомнит выключить флаг.

## Блок F. Референсы

Таблица `title_ref`: (`title_id`, `kind` enum: wiki / build / walkthrough_video
/ store_page / press_kit / discord / telegram / support_form / gdd,
`url_or_ref`, `locale`, `access_note` текст 200, `updated_at`).

Вопрос продюсеру: «Ссылки, по которым можно изучить игру: вики, билд, видео
прохождения, каналы сообщества. Для закрытых материалов укажите в заметке, как
получить доступ». Минимум для содержательной карточки — хотя бы одна ссылка
вида wiki / build / walkthrough_video.

## Блок G. Управление данными и защита от заглушек

Важнее любого нового поля. Каждая запись каждого блока несёт:

| Поле | Значение |
|---|---|
| `revision` | монотонный номер; старые ревизии не удаляются |
| `review_status` | draft / in_review / approved / rejected / deprecated |
| `authored_by`, `approved_by`, `approved_at` | правило: автор ≠ одобряющий |
| `source` | enum: producer_form / store_import / wiki_import / ops / llm_proposal |
| `updated_at` | у карточки — максимум по дочерним записям |
| `content_hash` | стабильный хэш содержимого, для инвалидации у потребителей |

Серверная фильтрация заглушек — **пригодность для AI вычисляется, а не
выставляется флажком**. Поле не отдаётся во внешние срезы, если содержимое:

- `null`, пустая строка, прочерки и повторяющийся токен;
- тестовые маркеры: «проверка», «тест», «test», «asdf», «поле N»;
- совпадает с названием поля;
- короче минимального порога поля.

`is_ai_context` остаётся ручным разрешением («можно отдавать в AI»), но
перестаёт быть достаточным условием: заглушка не отдаётся даже с флагом.
Текущее поведение — `content: null` с `is_ai_context: true` — баг, чинится
этим правилом.

Роли: продюсер авторствует; владелец игры одобряет фактическую и творческую
часть; отсутствие одобрения не скрывает содержательные поля, но статус и
происхождение всегда отдаются вместе с данными.

## Блок H. Миграция существующих данных

1. Существующие `fact_type` опросника переезжают 1:1 с новыми лимитами:
   `target_audience`, `core_gameplay`→`core_loop`, `meta`, `player_goal`,
   `retention`, `multiplayer`, `geo_availability`. `genre_perception`
   вливается в свободную часть `genre[]`.
2. `game_project_fields` (свободные слоты) размечаются вручную в ходе пилота:
   «Точки фана» → `fun_points`, «Основные режимы игры» → `key_modes[]`,
   остальное — в соответствующие поля или в мусор. Слоты «поле N» с пустым
   содержимым удаляются. После пилота механизм свободных слотов закрывается.
3. `games.monetization_notes` сокращается до 400 символов в ходе ревизии
   (полный текст сохраняется в референсы как документ, если жалко терять).
4. Локали канонизируются по таблице: `ru-RU`→`ru`, `en-US`→`en`, `de-DE`→`de`,
   `fr-FR`→`fr`, `es-ES`→`es`, `it-IT`→`it`, `pl-PL`→`pl`; `pt-BR`/`pt-PT`,
   `zh-Hans`/`zh-Hant`, `es-US` сохраняют регион. Исходное значение — в
   `raw_locale`.
5. Дублей анкеты не остаётся: у Tiny Space Arena сегодня две версии одних и
   тех же ответов (docx и опросник) — при миграции выбирается одна, вторая
   уходит в историю ревизий.

## Пилот и приёмка

Пилот: 10–14 уже содержательно заполненных игр перезаполняются по новой форме
(продюсер + владелец игры), до массового заполнения остальных.

Задача принята, когда:

1. Анкета в интерфейсе ведёт продюсера по блокам A–D с вопросами, подсказками
   и примерами из этого ТЗ; поля с условием показа (пуши, патчноуты) появляются
   только при соответствующих `content_types`.
2. Счётчик бюджета брифа работает; ни одно текстовое поле не принимает больше
   своего лимита.
3. Карточка пилотной игры отдаёт через существующий read-only интерфейс все
   заполненные поля новых блоков с `review_status`, `source`, `revision` и
   `content_hash` — и не отдаёт ни одной заглушки (проверка: текущие
   null-факты с `is_ai_context: true` исчезают из выдачи без ручной чистки).
4. Локали в выдаче только канонические; `raw_locale` доступен как провенанс.
5. «Известные проблемы» с истёкшим `valid_until` не отдаются.
6. У каждой записи пилотных игр `authored_by` ≠ `approved_by` либо запись
   висит в `in_review`.

## Вне объёма этой задачи

- Интеграции продуктов с БДХК (GamePulse, Autoanswer, Weblate, локализатор
  скриншотов) и срез `/bundle?consumer=…` — отдельные задачи.
- Терминология и глоссарий (слой терминов): следующий этап, наполняется из
  глоссариев Weblate через ревью-очередь, а не продюсером.
- Технические ограничения (`title_constraint`, `ui_slot`, разметка, лимиты
  длины строк) и креативные слои — этап локализатора скриншотов.
- Настройки потребителей: категории классификатора, коррекции доменов,
  шаблоны промптов, лимиты ответов сторов.
- Массовое заполнение всех 75 игр до завершения пилота.
