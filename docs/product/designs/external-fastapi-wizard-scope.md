# Внешний визард на сервере БДХК

Дата: 2026-10-01. Статус: согласованная спецификация; локальная реализация проверена 2026-10-02, production-публикация ожидает разрешения.

## Пользовательский результат

Пользователь открывает визард по сетевому адресу с другого компьютера, входит, создаёт выделенный проект внешнего Weblate, выбирает карточку БДХК или заполняет анкету вручную, загружает локкит, подтверждает языки и колонки, запускает перевод и скачивает локкит с результатом. Сохраняются существующие быстрый режим из четырёх шагов и подробный из восьми; оба используют один сохранённый черновик.

## Размещение и внешняя доступность

Разработка ведётся в отдельном проекте `D:\bdhc_wizard\repo`; установка — на проверенном Linux-сервере БДХК в `/opt/bdhc/weblate-wizard`. UI карточек 18501, API 19100, read-only фасад 19101 и бот сохраняют существующий запуск. Визард имеет собственные venv, БД, файлы, секреты, API-процесс, worker и systemd-службы.

Предложен порт 18511, после проверки свободы. UI — `/console/`, API — `/api/producer/` одного origin. Внешний доступ из корпоративной сети предполагает сетевой интерфейс и правила firewall; для интернета необходимы согласованный публичный адрес и HTTPS-публикация через прокси/DNS/NAT. Частный адрес 192.168.0.180 не означает публичную доступность. Точный вариант сети уточняется у владельца до публикации. Локальная проверка через SSH-туннель не считается внешней приёмкой.

## Данные и интеграции

- Собственная SQLite WAL на локальном диске, busy timeout 30 секунд, один API-процесс и один worker. Черновики, профили, manifests и run snapshots сохраняются; длительные операции выполняются worker, а не HTTP-запросом.
- Собственная cookie-сессия, права на проекты, CSRF и проверка Origin. Нет общего пароля по умолчанию. Пользовательский вход не использует широкие права личного Weblate-токена. Файлы доступны только после проверки прав; секреты только на backend, вне Git и UI.
- БДХК: четыре разрешённых GET через `http://192.168.0.180:19101` с Bearer-токеном; base URL задаётся конфигурацией. Схема 12.7 и context_hash, сохранение title_id и provenance. Предложения блоков B/C применяются с подтверждением; пустые поля сохраняют ручной ответ. Неизвестная схема/timeout/неполная карточка позволяют ручной ввод. Source и роль игрока не угадываются по content_locale/player_goal; языковые правила применяются по точной локали. Обратной записи и импорта терминов БДХК нет. Штатный last_used_at — допустимый служебный побочный эффект чтения.
- Внешний Weblate: `https://l10n.herocraft.com/api/`, `Authorization: Token …`. Стандартные проекты, компоненты, machinery settings, загрузка/скачивание и MT. Сервис получает фактические права создания и перевода на новом проекте; ранее прочитанный список проектов не доказывает все эти права.
- Генерация persona/style/instructions использует отдельную серверную LLM-конфигурацию и существующий prompt; без неё доступен явный ручной ввод. Persona/style <=4000 символов, инструкции <=1000 на выбранный язык, без молчаливого обрезания. Простое открытие шага не вызывает генерацию.
- Ключи БДХК, Weblate и генератора профиля независимы. Токен Weblate не отправляется по HTTP или другому host, автоматические redirects с ключом отключены.

## Локкит и перевод

Поддерживаются текущие табличные CSV/TSV/XLSX, табличный TXT и ZIP с этими таблицами; Source/targets, листы и колонки подтверждаются пользователем. Таблица до 20 MiB, ZIP до 50 MiB, суммарная распаковка до 100 MiB и 100 файлов; более строгие существующие ограничения процессора сохраняются. Вложенные ZIP, symlink и выход за каталог запрещены.

Автономный loc_kit_ingest готовит PO po-mono и необязательный пользовательский TBX-глоссарий. Manifest сохраняет идентичность строк, исходные ключи, контекст, порядок, метаданные и заполненные target. Перевод выполняется только для пустых строк выбранных языков через один настроенный engine внешнего Weblate. Загрузка исходных переводов предшествует MT. Нет отдельного нового сценария split.

Worker сохраняет стадии и удалённые идентификаторы. Повторное нажатие запуска не создаёт второе задание. Неизвестный исход POST требует сверки; платный MT не повторяется вслепую. Перезапуск восстанавливает наблюдение за удалённым заданием. Отмена прекращает будущие локальные этапы; остановка уже запущенного удалённого перевода зависит от подтверждённой возможности API.

Экспорт XLSX/CSV/JSON собирается из полученных переводов и сохранённого manifest. Ключи и метаданные сохраняются; оформление и макросы Excel, полный бинарный round-trip исходного файла не обещаются. Карантин, невыбранные строки и неполные языки видны в отчёте; исходный файл сохраняется для сопоставления. Связанные сводка и скачивание используют один ExportSnapshot.

## Тестовый проект и скрытые листы

Создаваемый тестовый проект в визарде и внешнем Weblate называется **«тест»**. Его источник данных — Star Troopers по предоставленной владельцем [ссылке Google Play](https://play.google.com/store/apps/details?id=com.herocraft.game.strategy.pvp.star.troopers&hl=en&pli=1), package name `com.herocraft.game.strategy.pvp.star.troopers`. Исходник `D:\bdhc_wizard\WS.Localizations.xlsx` хранится без изменений и вне Git. Короткая реальная приёмка использует 5–10 подтверждённых строк видимых листов и один target на отдельном проекте Weblate с именем «тест» и уникальным техническим slug `test-<уникальный-идентификатор>`; полный платный перевод автоматически не запускается. Название Star Troopers хранится как источник данных, а не используется как название создаваемого проекта. Одноимённый чужой проект автоматически не выбирается. Пример можно повторно загрузить обычным визардом после запуска сервиса; новый прогон получает собственный run_id, повтор запроса одного прогона не создаёт дубликат.

В предоставленной книге шесть видимых листов: `Default`, `Units`, `Perks`, `Settings`, `GDPR`, `Tutorial`. Девять скрытых исключены: `Arcade`, `Store`, `Default (Old)`, `Tutorial (Old)`, `Units (Old)`, `Perks (Old)`, `Arcade (Old)`, `Settings (Old)`, `GDPR (Old)`.

Обрабатываются только листы со статусом `visible`. `hidden` и `veryHidden` исключаются backend до анализа, определения структуры, LLM-примеров и контекста, PO/TBX, отправки в Weblate, перевода и переведённого экспорта. Названия не определяют разрешение; попытка выбрать скрытый лист через API возвращает 400 `sheet_not_visible`. Допускается учёт имени и причины исключения, без ячеек скрытых листов. Неизменяемый частный оригинал книги может содержать их, но не отправляется целиком во внешний Weblate или LLM. Добавляется одна компактная проверка фильтра в существующий набор обработки кита.

Read-only проверка 2026-10-01 не нашла Star Troopers в доступном БДХК: resolve по package name 404, поиск по названию/`troopers` дал пустой список. Это исторический результат поиска исходной игры. Владелец затем разрешил проверку заполненной карточки Dead Shell: реальное чтение и подтверждаемое автозаполнение проверены. Отдельная карточка «тест» для этого не требуется. Контекст Dead Shell не подставляется автоматически в перевод Star Troopers. Если понадобится собственная тестовая карточка, её создают штатными средствами БДХК; фасад визарда остаётся read-only.

Внешний Weblate требует уникального отображаемого имени проекта. До ответа владельца сохраняется точное имя «тест», при конфликте приложение безопасно прекращает создание. Вариант «тест — <короткий ID>» для повторных независимых проектов остаётся вопросом согласования.

## Объём и приёмка

Реализуется текущая форма с доработками, необходимыми для реального перевода, и БДХК 3.1. Stores, extraction, judge/repair, новые split-механизмы, письма, финансовая отчётность и запись в БДХК не входят.

До запуска достаточно небольшого автоматического набора по доступу, автозаполнению, сохранности данных и восстановлению без повторного платного вызова; успешной сборки UI; одного реального согласованного кита 5–10 строк с одним target и проверки внешнего адреса с другого компьютера. Нагрузочные, длительные и расширенные проверки следуют после запуска. Обнаруженные критические проблемы данных/секретов исправляются до публикации.

План реализации: `docs/product/plans/2026-10-01-external-fastapi-wizard.md`. Для данного Linux-сервера он заменяет размещение `C:\BDHC` из предыдущего Windows-плана. Исходные модули и форма подготовленного переносимого комплекта используются повторно.

Карточка Dead Shell не изменялась; локкит Star Troopers остаётся отдельным источником теста обработки данных.

## Разрешение владельца 2026-10-02

Подтверждены установка нового сервиса с доступом только из корпоративной сети, уникальные тестовые имена «тест — <короткий ID>» и один небольшой платный прогон. Целевой язык по последующему уточнению владельца — немецкий (`de`); приёмка использует пять подтверждённых строк видимого листа. Интернет-публикация сейчас не требуется. Это уточнение заменяет прежнее ожидание разрешений; исторические результаты локальных проверок сохранены.
