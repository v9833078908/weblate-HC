# План: перевести плановую очередь повторов на выбранный прототип

Дата: 2026-09-21.
Статус: **готов к исполнению в отдельной сессии; реализация не начата.**

## Решение, которое этот документ фиксирует

Базовый план `docs/product/plans/2026-09-17-repeat-drift-reconciliation-and-managed-reuse.md`
не изменяется: модель (RepeatPolicy/RepeatGroup/RepeatMembership/RepeatDecisionEvent),
безопасность (preview, подписанный токен, `Unit.translate(..., propagate=False)`,
approved не перезаписывается, guarded undo), платный контур (два триггера, верхняя граница,
unknown cost, неизвестно после отправки), права и контракты §3 остаются как есть.

**Изменяется один экран:** нативная очередь групп (задача 3 базового плана,
`repeat_queue.html`). Состав и состояния страницы не меняются; меняется иерархия подачи
группы. Выбранный вариант — прототип `.impeccable/prototypes/repeat-queue/proto-v2.html`
(его сохраняем как отслеживаемый источник: `analysis/prototypes/repeat-queue/queue-variant-a.html`).

Две фигуры показываются рядом для сравнения: **A** — плотная очередь с таблицей и раскрытой
группой (исходный вариант, `index.html`); **B** — одна группа = один вопрос, детали свёрнуты
(выбранный, `proto-v2.html`). Пользователь выбрал B; A остаётся первичным источником для сравнения.

## Контракт экрана (новый, для задачи 3)

**Группа в очереди отвечает на один вопрос** «Что сделать с этой группой?», а не является
карточкой данных с тремя радиокнопками. На её первом экране:

1. **Вопрос-заголовок:** одинаковый текст «Что сделать с этой группой?» (`label-strong`, 14px/600).
   Это не `heading-page`: 24px не использовать, реальная страница несёт свой `h1`.
2. **Источник группы:** 18px, моноширинный (`heading-card`/`code-md`).
3. **Сводка:** число вхождений, компоненты (бейджи `text-bg-secondary`), статус группы
   (`Требует решения` / `Решена` / `Конфликт одобренных` — только эти три),
   счётчик примечаний: конфликты, замки, ограничения, устаревшие связи, независимые.
4. **Варианты:** по строке каждый: count (`7×`), текст моноширинным, происхождение
   (автор/движок, без технических details).
5. **Три действия, равной ширины, видны всегда:**
   - `Переводить одинаково` — основной путь; подпись содержит выбранный вариант («взять X для всех совместимых»);
   - `Оставить разные переводы` — осмысленное решение, а не «отмена»;
   - `Свой вариант` — поле ввода + `Применить`, всегда на экране (не «за стеклом»).
6. **Диагностика свернута, но не за стеклом:** `Подробности` (`<details>`) открывает
   ключи, контексты, состояния, метки, замки, ограничения, provenance. Это не «скрытая
   информация», а диагностика, доступная одним кликом; контексты остаются в первом экране
   выше (они основание решения).
7. **Решённая группа не показывает три кнопки:** статус, общий вариант и ссылка на историю.
8. **Конфликт одобренных — не бинарный выбор:** «Переводить одинаково» недоступно с причиной
   («сначала выберите вариант для approved»); «Оставить разные» доступно, конфликт остаётся.
9. **Копирайт в терминах действия, а не механики:** «Переводить одинаково» / «Оставить разные
   переводы» / «Свой вариант» / «Посмотреть, что изменится». Фразы вида «ничего не выбрано
   заранее», «подписанный токен», `propagate=False` с экрана уходят (остаются в коде/тестах).

**Не меняется относительно базового плана:** preview, подписанный токен, применение,
per-group отчёт, история, guarded undo, платные триггеры с ценой/лимитом в точке запуска
(бейдж `платно` остаётся — не делать второй круг), keyboard-модель, состояния платного контура
(недоступно/отменено/неизвестно), механика пустого набора меток, межпроектная блокировка,
409 в редакторе, REST-контракт, локализация строк.

## Критерии сдачи

1. Прототип доступен как отслеживаемый источник и открывается одной командой; A и B лежат рядом.
2. Экран очереди отвечает на один вопрос на группу; три действия видны всегда; диагностика под «Подробности».
3. Ни одного «заранее выбранного» решения; approved и конфликтующий approved не перезаписываются.
4. Платный контур не регрессировал: цена/лимит/unknown остаются в точке запуска.
5. Клавиатура и a11y проверены в браузере, мобильный 390px без горизонтального скролла.
6. Тесты view проходят; сквозной smoke по §6 базового плана не затронут.

## Риски и открытые вопросы

- **Согласование копирайта с русским языком интерфейса:** «Переводить одинаково» читается как «делать общий перевод», не «переводить повторно». Проверить на 2–3 продюсерах до мёржа; фолбэк — «Сделать общим переводом».
- **`<details>` вместо модалки:** нативный Weblate почти не использует `details`; если `prek`/browser-тесты покажут проблемы, заменить на `collapse` (Bootstrap) с тем же содержимым и теми же aria.
- **Клавиша `P` для preview:** конфликтует с существующими shortcut'ами редактора (если они есть на странице очереди); при конфликте переназначить на `V` («просмотр»).
- **Сводный счётчик примечаний:** «1 замок · 1 ограничение длины» — текст длиннее бейджей; если на 390px строка ломается, перенести на вторую строку.

## Что этот план НЕ делает

- Не меняет RepeatPolicy/RepeatGroup/RepeatMembership/RepeatDecisionEvent, миграции, сервис `repeats.py`, transport recommendations, MT-reuse, REST 409 — это отдельные задачи базового плана.
- Не даёт разрешение на реализацию: базовый план всё ещё «на утверждение».
- Не затрагивает Producer Console: консоль читает те же решения (роадмап 2.6), адаптер и экран `RepeatQueue.tsx` — отдельная задача после нативной реализации.
