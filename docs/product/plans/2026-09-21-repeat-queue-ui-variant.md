## 1. Что фиксирует документ

Выбран вариант C: `analysis/prototypes/repeat-queue/queue-variant-c.html`.
История: вариант A (плотная таблица, `queue-variant-a.html`) был отклонён в
пользу B («один вопрос за раз», `queue-variant-b.html`); ревью от 2026-09-22
нашло в B два блокирующих дефекта (заранее выбранный вариант на кнопке и
запись в обход предпросмотра) и перегруженную карточку. Вариант C собран по
итогам ревью и заменяет B. Запуск прототипов описан в
`analysis/prototypes/repeat-queue/README.md`.

Прототип - свидетельство контракта, а не код: шаблоны пишутся по разделу 2,
а не копируются из HTML.

### 1.1. Что этот документ меняет в базовом плане

1. `weblate/templates/repeat_detail.html` не создаётся. Раскрытие группы -
   панель внутри очереди; список вхождений живёт в панели, длинный список
   догружается ссылкой (раздел 2.5).
2. Новые файлы: `weblate/templates/snippets/repeat_group.html`,
   `weblate/static/js/repeat-queue.js`, `weblate/static/styles/repeat-queue.css`
   (подключаются из `repeat_queue.html` по образцу
   `translate.html` -> `bulk-accept-suggestions.js` / `bulk-accept.css`).
3. Статусы группы: четыре (`Требует решения`, `Конфликт одобренных`,
   `Конфликт правил`, `Решена`). «Устаревшая связь», «замок», «нет прав»,
   «ограничение длины» - примечания у группы и у вхождения, не статусы.
   Базовый план перечислял stale/protected среди состояний; они сохраняются
   как примечания и как причины в предпросмотре.
4. Отметка «сделать независимым» на отдельном вхождении из карточки убрана.
   Исключить получателя можно в предпросмотре (галочка «записать»);
   «Оставить разные переводы» - решение всей группы. Независимость одного
   вхождения по-прежнему доступна из редактора (раздел 2.8).
5. Свой вариант идёт только через предпросмотр. Базовый план это и требовал;
   вариант B нарушал.
6. Подтверждение «область без меток» переезжает из предпросмотра применения
   на страницу правила (раздел 2.9): применение решения область правила не
   меняет.

### 1.2. Что не меняется

Модель (`RepeatPolicy`/`RepeatGroup`/`RepeatMembership`/`RepeatDecisionEvent`),
подписанный токен и порядок применения (§3.2), «одобренное не
перезаписывается», guarded undo, платный контур (два триггера, лимит,
неизвестная цена, состояние «неизвестно»), права, REST 409, per-group отчёт.

## 2. Контракт экрана

### 2.1. Страница

- URL `/repeats/<project>/<language>/`, view `repeat-queue` в
  `weblate/trans/views/repeats.py`. Заголовок страницы - стандартные
  хлебные крошки Weblate: `Проекты / <проект> / <язык> / Повторы`.
- Доступ к странице - доступ к проекту (`user.can_access_project`);
  компоненты, вхождения, варианты и рекомендации строятся только из
  `Component.objects.filter_access(user)` (базовый план §3.1). Применение -
  `unit.edit` на каждом получателе; правило - `project.edit`.
- Ширина содержимого ограничена 1120 px (`.rq`), остальная страница -
  обычный `container-fluid`.

### 2.2. Панель фильтров

- GET-форма `aria-label="Фильтр очереди"`: `Язык` (select; смена языка -
  переход на URL другого языка), `Компоненты` (чекбоксы, только доступные;
  по умолчанию компоненты активного правила, без правила - все), `Метки
  исходника` (dropdown с чекбоксами; по умолчанию метки правила, без правила
  - все). Фильтр применяется при изменении (JS отправляет форму); без JS
  показана кнопка `Показать` в `<noscript>`.
- Справа: панель проверки вариантов судьёй со состояниями «начать / идёт /
  результаты» и счётчиками четырёх групп: готово, выбрать самостоятельно,
  нужен новый перевод, не проверено. Панель заменяет кнопку `Обновить
  рекомендации` и строку состояния рекомендаций. Она ведёт к обычной форме
  запуска судьи для мест очереди; запуск записывает только вердикты и не
  меняет состояния строк, не создаёт вариантов для исправления и не запускает
  платную проверку самостоятельно. Ссылка `Правило области` остаётся.
- Слов «бесплатно», «токен», «propagate» на экране нет: платное действие -
  единственное с бейджем, всё остальное подразумевается бесплатным.

### 2.3. Вкладки статуса

Ссылки `?status=all|open|conflict|resolved` с счётчиками в бейджах;
активная - `aria-current="page"`. Счётчики считаются по отфильтрованной
области. `conflict` включает конфликты одобренных и конфликты правил.

### 2.4. Список групп

- Порядок: конфликты правил, конфликты одобренных, требующие решения,
  решённые; внутри - по числу вхождений по убыванию. Внутри статуса сначала
  источники до трёх слов, затем группы по числу вхождений по убыванию.
  Пагинация -
  стандартный `paginator.html`, 20 групп на страницу. Над списком строка:
  «Показаны N групп из M. Сначала конфликты одобренных, затем нерешённые.» и
  подсказка `↑ ↓ между группами, Enter раскрыть` (`<kbd>`).
- Группа - `<li>` с `<h3>` и кнопкой-раскрывателем (WAI-ARIA disclosure):
  `aria-expanded`, `aria-controls` на панель, панель - `role="region"
  aria-labelledby`. В кнопке: исходник (моноширинный, 16/600), строка
  сводки («5 вхождений · 3 перевода · dialogs, ui · 1 ограничение длины»),
  бейдж статуса. У решённой группы в сводке общий перевод и автор/дата
  решения.
- Раскрыта одна группа: указанная в `?group=<id>`, иначе первая нерешённая
  на странице. Раскрытие другой сворачивает открытую (JS); без JS все
  панели свёрнуты, кроме одной, и раскрытие - ссылка `?group=<id>#g-<id>`.
  Панели всех групп страницы рендерятся сервером.
- Раскрытая группа отмечена левой линией 2 px `--wl-color-primary` от
  заголовка до конца панели и фоном `--wl-color-surface` у заголовка.

### 2.5. Раскрытая группа

Порядок блоков сверху вниз, между блоками 16 px:

1. **Описание.** Объединённые различающиеся Explanation исходных строк
   группы (до трёх, затем «и ещё N»); если пусто - «не задано ни у одного
   вхождения» приглушённым.
2. **Примечание** (только если есть): устаревшая связь («У вхождения `key`
   исходник изменился после прошлого решения, поэтому прежняя связь
   сброшена: оно снова участвует в выборе.»), нет прав («2 вхождения в
   компоненте `ui` вне ваших прав на правку: они останутся как есть,
   остальные можно записать.»), все одобрены (раздел 2.6), конфликт правил
   («К исходнику добавили метку, и теперь он подходит двум правилам: …»).
3. **Решение** - `<fieldset>` с `<legend>` «Что сделать с этой группой?» и
   одним radiogroup. Вариант с одной формой может быть заранее выбран, только
   если судья проверил его текущий текст, он единственный без ошибок и группа
   готова. Рядом показываются отметка судьи, обратный перевод и причина ошибки,
   если она есть. Даже при таком выборе предпросмотр и подтверждение обязательны.
   Для остальных групп ничего не выбрано заранее. Порядок вариантов:
   одобренные (по числу одобренных вхождений), затем по числу вхождений,
   затем по алфавиту. Строка варианта:
   - формы перевода моноширинным; для языков с несколькими формами - по
     строке на форму с меткой формы (`1`, `2+`, по `Plural` языка);
   - различия относительно самого частого варианта подчёркнуты
     (`<mark class="diff">`; пословный diff через `difflib`, сервер);
   - «где стоит»: «N × - `key` назначение (компонент); …» - до трёх ключей,
     назначение - Explanation исходной строки (усечённый до 60 символов) или
     context, при `max-length` - «до 24 символов»;
   - происхождение: «вручную, A. Leroy» / «перевод модели» / «вручную и
     перевод модели, 3 одобрены» - по последнему `Change` каждого вхождения
     (`automatically_translated`, автор, одобривший);
   - для проверенной судьёй группы у варианта показаны отметка проверки,
     обратный перевод и причина ошибки, если судья её указал. Единственный
     вариант без ошибок предварительно выбран только в готовой группе с одной
     формой; предпросмотр и подтверждение остаются обязательными. Подробный
     контракт проверки и выбора: `docs/product/plans/2026-09-24-repeat-queue-producer-ux.md`;
   - бейджи справа: `Одобрено` (или `3 одобрены`), `Рекомендация модели`;
   - под рекомендованным вариантом абзац «Основание модели: …»
     (`aria-describedby` с radio). Рекомендация показывается только для
     результата с текущим snapshot fingerprint (базовая задача 4); устаревшая
     рекомендация на карточке не показывается.
   Затем разделитель и два пункта: `Свой вариант` (radio; при выборе
   раскрываются поля по числу форм с подписью «Плейсхолдеры, разметку и
   длину проверим в предпросмотре, для каждого вхождения отдельно.») и
   `Оставить разные переводы` (radio; описание «Переводы не меняются.
   Вхождения станут независимыми, проверка «Непоследовательный повтор»
   перестанет их сравнивать.»).
4. **Действия.** Одна кнопка `Посмотреть, что изменится` (`btn-primary`,
   `aria-disabled="true"` до выбора; клик по недоступной кнопке пишет в
   подсказку «Сначала выберите вариант.»). Рядом подсказка `aria-live="polite"`,
   до выбора «Выберите вариант, чтобы продолжить.», после выбора - текст по
   формуле 2.5.1. Кнопка отправляет POST в предпросмотр.
5. **Строка гарантии** (постоянная): «До предпросмотра ничего не
   записывается. Одобренные переводы не меняются.»
6. **Вхождения (N)** - `<details>`, по умолчанию свёрнут; таблица в
   `.table-scroll` (`role="region"`, `aria-label="Вхождения группы «…»"`):
   `Ключ`, `Где` (компонент · назначение), `Сейчас` (моноширинный),
   `Состояние`, `Примечание` (замок «сейчас правит X», «нет прав на правку»,
   «исходник изменился 18.09, связь сброшена», «до 24 символов»), ссылка
   `Открыть` в редактор. Не более 10 строк; дальше кнопка-ссылка
   «Показать остальные N» -> `?group=<id>&members=all#g-<id>`.

#### 2.5.1. Подсказка под кнопкой

Сервер считает для каждого варианта и передаёт в `data-hint` radio.
Для варианта или своего варианта над вхождениями группы, доступными
пользователю: `W` - будут записаны (не одобрено, не заблокировано, есть
`unit.edit`, связь не устарела, текущий перевод отличается); `S` - уже
совпадают; `A` - одобренные с другим переводом; `X` - пропущенные (замок,
нет прав, устаревшая связь). Текст собирается из предложений:

- `W > 0`: «Запишется в W вхождений.»; `W = 0`: «Записывать нечего.»;
- `S > 0`: «S уже совпадают.» (для одобренного совпадающего - «Одобренное
  уже совпадает, конфликта не будет.»);
- `A > 0`: «A одобренных останутся другими: группа сохранит конфликт
  одобренных.»;
- `X > 0`: «X пропустим: замок, нет прав или связь устарела, подробности в
  предпросмотре.».

Для «Оставить разные переводы»: «Переводы не меняются. N вхождений станут
независимыми.» плюс «Конфликт снимется.» для группы в конфликте.
Числительные - через `ngettext`.

### 2.6. Конфликт одобренных

- Группа с двумя и более одобренными переводами получает статус
  `Конфликт одобренных` и идёт в начале списка.
- Если есть неодобренные вхождения, варианты выбираются как обычно; подсказка
  предупреждает `A одобренных останутся другими…`, отчёт после записи
  показывает `Частично`.
- Если все вхождения одобрены: строки вариантов без radio (класс
  `is-locked`), у каждой ссылка `Открыть в редакторе`; примечание «Оба
  вхождения одобрены, поэтому общий перевод здесь записать нельзя:
  одобренный перевод меняет рецензент в редакторе. Здесь можно только
  подтвердить, что переводы разные намеренно.»; выбирается только
  `Оставить разные переводы`.
- «Оставить разные» снимает конфликт: все вхождения становятся
  независимыми (`RepeatMembership.mode = independent`, причина
  `keep-different`), проверка перестаёт их сравнивать (базовая задача 6).

### 2.7. Предпросмотр и отчёт

- View `repeat-preview`, POST из формы группы (`group`, `choice`
  `variant:<hash>|custom|keep`, `custom_form_<n>`). Заголовок «Что
  изменится: «<исходник>», общий перевод <перевод>» (для «оставить разные» -
  «…: оставить разные переводы»). Ссылка `Назад к группе «…»` над
  заголовком ведёт в очередь с этой группой раскрытой.
- Вводный абзац: «Ничего ещё не записано. Запишутся только отмеченные
  вхождения, каждое получит состояние «Переведено»; одобрить их сможет
  рецензент. Одобренные переводы не меняются.»
- Таблица (`.table-scroll`, `aria-label="Что изменится, по вхождениям"`):
  галочка `записать` (отмечена для записываемых; для замка/нет прав/устарело
  - `disabled` с причиной в `aria-label`; для одобренных совпадающих и
  неизменяемых - без галочки), `Вхождение` (ключ + компонент · назначение),
  `Сейчас`, `Станет` (перевод после autofix этого получателя, базовый план
  §3.2; «не меняется» приглушённым), `Примечание` («20 из 24 символов,
  влезает» / «не влезает в 24 символа: пропущено» / «Сейчас правит A. Leroy.
  Вернётся в очередь, когда правка закончится.» / бейдж `Одобрено` «уже
  совпадает»).
- Кнопка `Записать N вхождений`; N следует за галочками (JS), при N = 0 -
  «Нечего записывать» и `aria-disabled`. Рядом `Назад` и подсказка «Отменить
  можно, пока строки не изменены после записи.» Если с момента карточки
  набор изменился, абзац об этом («На карточке было 4 вхождения: с тех пор
  одно заблокировано правкой. …»).
- Подписанный токен (базовый план §3.2) содержит группу, revision, выбранный
  перевод или `keep`, полный список получателей с fingerprints; POST
  применения передаёт токен и выбранные id, сервер принимает только
  подмножество списка токена. Устаревшая группа -> страница «Группа
  изменилась» с кнопкой `Обновить предпросмотр`, без записи.
- Отчёт (view `repeat-report`, один шаблон и для одной группы, и для
  пакета): заголовок «Записано: K групп из M полностью или частично»,
  абзац «Каждая группа вернула свой итог. Ни одна одобренная строка не
  изменена.», строка перепроверки (`aria-live`, «пересчитано 2 группы из 4»),
  таблица `Группа` / `Итог` (`Записано`, `Разные намеренно`, `Частично`,
  `Не записано`) / `Подробности` («3 вхождения записаны, 1 одобренное уже
  совпадало, 1 пропущено: правил A. Leroy.») / действие (`Отменить запись`,
  `Обновить предпросмотр`, `Показать вхождения`). Зелёный итог только когда
  записаны все записываемые и конфликта не осталось.

### 2.8. Редактор, Zen, REST

- При сохранении вхождения shared-группы с переводом, отличным от общего,
  под полем перевода появляется блок «Ваш перевод отличается от общего» с
  двумя radio: `Предложить его как общий` («Сохранится эта строка. Остальные
  N вхождений вернутся в очередь, где вы посмотрите, что изменится, и
  подтвердите.») и `Сделать эту строку независимой` («Сохранится эта
  строка. Она выходит из общего перевода, остальные вхождения не
  меняются.»). Ничего не выбрано; без выбора сохранение возвращает ошибку
  «Перевод не сохранён. Строка входит в группу повторов: выберите, что
  сделать с отличием, и повторите сохранение.» Слов «409» и «API» на экране
  нет.
- Zen: те же два значения в JSON-ответе `save_zen`; REST: поле решения и
  409 по базовому плану.
- Блок проверки «Непоследовательный повтор» в редакторе получает ссылку
  `Открыть очередь повторов` на очередь проекта и языка с раскрытой группой
  этой строки.

### 2.9. Правило области

Страница `Правило общих повторов: <язык>`: абзац «Правило действует на
будущие строки и запуски автоматического перевода. Уже переведённое оно не
трогает.», блок с чекбоксами компонентов (только этого проекта) и меток
(«Строка попадает под правило, если у неё есть любая из выбранных меток.
Без меток правило охватит все строки выбранных компонентов.»), блок
«Область без меток» с обязательной галочкой «Подтверждаю: все строки
компонентов …» (появляется только при пустом наборе меток), блок
«Пересечение с другим правилом» (сохранение запрещено, пока область не
сужена), кнопки `Сохранить правило` / `Отмена`.

### 2.10. Состояния

- Пусто: «В компонентах … для <язык> все повторы переведены одинаково или
  решены. Новые строки из загрузок попадут сюда сами: правило области
  действует.» + `Показать решённые группы (N)` + `Правило области`.
- Нет прав на часть вхождений - примечание в группе и причина в
  предпросмотре, не ошибка после записи.
- Конфликт правил - статус группы и примечание; reuse и применение
  запрещены (базовый план §3.1).
- Рекомендации недоступны (нет профиля модели) - кнопка `Запустить`
  `aria-disabled` с пояснением; очередь работает.

### 2.11. Клавиатура и доступность

- Модель WAI-ARIA accordion: Tab ходит по кнопкам-заголовкам групп и
  элементам раскрытой панели; на кнопке-заголовке `ArrowDown`/`ArrowUp`
  переводят фокус между группами, `Home`/`End` - к первой/последней,
  `J`/`K` - псевдонимы стрелок и работают только при фокусе на заголовке;
  `Enter`/`Space` раскрывают (нативно). Страничных однобуквенных горячих
  клавиш нет (WCAG 2.1.4); `keyboard-shortcuts.js` Weblate не трогается.
- Видимый фокус: `outline: 2px solid var(--wl-color-primary); outline-offset: 2px`
  на всех интерактивных элементах экрана, включая заголовки групп и radio.
- Radio - нативные `form-check-input`, отмеченное состояние в цвете
  `--wl-color-primary`; главная кнопка использует `aria-disabled`, а не
  `disabled`, чтобы оставаться в порядке табуляции и объяснять причину
  через подсказку `aria-live`.
- Статус и итог никогда не передаются одним цветом: бейдж с текстом.
  Бейджи не меньше 12 px. Контраст текста не ниже 4.5:1 (проверять
  `text-muted` на `--wl-color-surface`).
- Таблицы - в `.table-scroll` с `tabindex="0"`, `role="region"` и
  уникальным `aria-label`; на 390 px горизонтального скролла страницы нет.
- Анимация одна: раскрытие панели 200 мс, отключена при
  `prefers-reduced-motion`.
- Проверять по `ACCESSIBILITY.md` и `docs/contributing/frontend.rst`.

### 2.12. Визуальные правила (по `DESIGN.md`)

Один акцент (`--wl-color-primary`) для интерактивности, цвета бейджей
только для статуса. Кнопки экрана без капсулы: 4 px радиус, 14/600,
высота 36 px (`.rq .btn-primary`); капсульная `.btn-primary` темы остаётся
на публичных страницах. Исходник и переводы - моноширинным. Шкала
размеров: 12 (бейджи, `kbd`), 14 (текст, подписи), 16 (исходник группы), 18
(заголовок страницы состояния). Тени не используются, границы 1 px
`--wl-color-border`. Ширина текста абзацев не больше 72ch.

## 5. Допущения по открытым решениям базового плана

Контракт опирается на следующие ответы; если базовый план решит иначе,
меняются только указанные разделы.

1. «Изменить общий перевод» в редакторе (§1.5) сохраняет только текущую
   строку и переводит группу в «Требует решения» с новым кандидатом;
   остальные вхождения применяются через предпросмотр (раздел 2.8). При
   выборе «сразу вся группа» блок редактора должен вести в предпросмотр.
2. Вхождения с одинаковыми source и context (`Unit.same`) считаются одним
   кластером: в панели они показаны одной строкой «где стоит» с пометкой
   «синхронизируются Weblate», решение применяется к кластеру целиком.
3. Кандидат, сгенерированный MT для разрешённой группы, показывается в
   панели как обычный вариант с происхождением «перевод модели», не как
   решение человека.
4. Экран входит в выпуск A базового плана (задачи 1-3); кнопка
   `Обновить рекомендации` и бейджи рекомендации появляются с выпуском B
   (задача 4) и до него не рендерятся.

## 6. Критерии сдачи

1. Очередь показывает группы списком; раскрыта одна; у неё одно решение и
   одна главная кнопка; ничего не выбрано заранее.
2. Подсказка под кнопкой до предпросмотра честно называет число записей и
   судьбу одобренных; предпросмотр совпадает с ней или объясняет разницу.
3. Одобренные переводы и вхождения вне прав не меняются ни в одном сценарии;
   «оставить разные» снимает конфликт без записи переводов.
4. Клавиатура и экранный диктор проходят раздел 2.11; на 390 px нет
   горизонтального скролла; контраст не ниже 4.5:1 в обеих темах.
5. Все строки экрана переведены на русский; технических слов на экране нет.
6. Тесты views проходят; сквозной smoke §6 базового плана не затронут.
