# План (пост-фактум): review_scope и защита от знаменателя/ID в weblate-lqa

**Дата:** 2026-08-22
**Статус:** реализовано в коммите `daf92ab` (документируется задним числом по
требованию AGENTS.md — план был согласован в чате перед реализацией, но не
зафиксирован в `docs/product/plans/` до начала правок).

**Контекст:** первоначальный скилл `weblate-lqa` (план
`docs/product/plans/2026-08-22-weblate-lqa-skill.md`, коммиты `35f97ef`, `52b2fe4`) был
прогнан на реальном компоненте `victory-banner/common` (DE). Самопроверка
результата вскрыла два независимых бага.

## Что менялось и где

1. **`scripts/audit_component.py`**
   - `compute_mqm_score` считал знаменатель (`total_words`) по всему компоненту,
     даже когда вердикты покрывали только часть юнитов — тихая экстраполяция на
     непроверенный остаток. Добавлено обязательное поле `review_scope` в файле
     вердиктов (`{"coverage": "full"}` либо `{"reviewed_unit_ids": [...]}`);
     без него скрипт падает с понятной ошибкой вместо неверного счёта.
   - Добавлена `resolve_review_scope()`: считает знаменатель строго по
     заявленному скоупу, проверяет что все ID из `reviewed_unit_ids`
     существуют, и что каждый вердикт ссылается на юнит внутри заявленного
     скоупа.
   - При `coverage_mode == "sample"` грейд всегда `Not gradable (partial
     coverage)`, независимо от числового скора — компонент не может получить
     чистый Pass/Grade A-C при частичном покрытии.
   - Дополнительно обнаружен и закрыт **второй баг** в процессе тестирования:
     вручную набранный файл вердиктов содержал 3 неверных `unit_id`
     (опечатка/трансрипция при копировании из вывода инструмента) — вердикты
     ссылались не на те строки. Добавлена кросс-проверка `verdict.context`
     против реального `context` юнита по `unit_id`; при расхождении — явная
     ошибка вместо тихой порчи не той строки при попытке "исправить" перевод.
   - `--save-verdicts-draft` теперь сохраняет заглушку `review_scope` с
     инструкцией её обязательно заполнить.
   - Markdown-отчёт получил секцию Review Coverage (юниты/слова: сколько
     проверено из скольких, %) и метку словосочетания "SAMPLE-SCOPED,
     non-projectable" vs "component-wide" на самом скоре.

2. **`references/mqm-game-profile.md`**
   - Новый раздел "Sampling & Coverage" (§4): формализует правило "скор всегда
     считается по фактически проверенной выборке, никогда — экстраполяцией на
     весь компонент без 100% покрытия".
   - Уточнено определение `grammar_syntax` vs новая категория `style`:
     паттерн-расхождение между грамматически ВЕРНЫМИ соседними строками — это
     `style` (Neutral, 0pt), а не `grammar_syntax` (Minor, 1pt). Исправлена
     собственная ошибка классификации из первого прогона аудита
     (`BuildHelp_LineDeletePoint`).
   - Таблица Release Gates (§5) получила отдельную строку "Partial coverage
     (any score)" → "Not gradable (partial coverage)" / "Blocked — audit
     incomplete".

3. **`SKILL.md`**
   - Step 4 получил обязательную дисциплину: агент обязан трекать точный
     список ID реально просмотренных юнитов (не только тех, где нашёлся
     дефект) — этот список становится `review_scope.reviewed_unit_ids` в Step 5.
   - Step 5 переписан: сборка `review_scope`, чтение `mqm_score`/
     `coverage_mode`/`grade` из вывода инструмента (не пересчитывать вручную),
     явное требование маркировать находки как "analyst-reviewed", если не
     вызывался реальный two-seat LLM-judge (`weblate/trans/judge.py`).
   - Шаблон "Standard Output Format" (§2) получил таблицу Coverage и грейд
     `Not gradable (partial coverage)`.
   - Добавлен раздел "Known Pitfalls" с обоими найденными багами как уроками
     для будущих запусков скилла.

4. **`docs/operations/audits/2026-08-22-victory-banner-common-de-lqa.md`** (сам аудит)
   - Перевыпущен с исправленными `unit_id` (345028/345042/345047 вместо
     345025/345037/345039) и корректным покрытием (126 юнитов / 912 слов
     вместо 124/907) — старая версия указывала чинить не те строки.

## Верификация

- 3 фикстуры: partial-coverage (знаменатель = слова выборки, не всего
  компонента), full-coverage (знаменатель = весь компонент), missing
  `review_scope` (падает с понятной ошибкой) — все прогнаны через CLI.
- Отдельно проверено, что новая context-consistency проверка ловит реальный
  найденный баг (перепрогон со старыми неверными ID → явная ошибка с
  указанием какой ID/контекст не совпадает).
- Живой перепрогон на `victory-banner/common/de` через API с исправленными
  вердиктами — 94.85 (sample-scoped, 126/448 юнитов, 912/1410 слов).
- Зеркалировано в `.omp/skills/weblate-lqa/` и `~/.claude/skills/weblate-lqa/`.

## Вне скоупа (не изменено в этой итерации)

- Реализация вызова реального LLM-judge — по-прежнему принимает только готовые
  вердикты человека/будущего судьи.
- Открытый пункт `ButtonReload`/`ButtonReloading` (см. отчёт §3) — не добавлен
  как формальный вердикт, зафиксирован как известный пробел.
