# План удаления созданных в визарде карточек (Implementation Plan)

> Для исполнителя: выполнять шаги последовательно с навыком `executing-plans`. Этот документ описывает план, а не разрешение на удаление. До подтверждения владельца разрешены только проверки и подготовка.

**Дата:** 2026-10-02. **Статус:** выполнен. Владелец подтвердил локальную очистку трёх карточек и удаление внешних тестового проекта и Lord Ambermaze; внешние действия с Dead Shell исключены. Итог: `docs/product/reports/2026-10-02-wizard-project-cleanup.md`.

**Цель:** убрать три указанные карточки из визарда, сохранив проекты, существовавшие во внешнем Weblate до тестирования.

**Архитектура:** одноразовый скрипт очищает только собственную SQLite и связанные файлы визарда по точному списку идентификаторов. Основной вариант не обращается к внешнему Weblate для изменения или удаления данных. Удаление внешних тестовых проектов — отдельный, явно согласуемый этап.

**Стек:** Python, SQLite, существующие модели `backend/app/models.py`, systemd и SSH; без новых зависимостей и изменений интерфейса.

**Спецификация:** запрос владельца: удалить карточки именно сейчас созданных в визарде проектов, не повредив прежние проекты `https://l10n.herocraft.com/`. Локальный список ниже фиксирует границы основной операции.

## Общие ограничения

- Основная очистка ограничена парами `(owner="producer", local_slug)` из таблицы. Другие и вновь созданные проекты автоматически в список не добавляются.
- Название игры, префикс `test`/`wizard` и время создания не используются как самостоятельное условие удаления.
- Не удалять пользователей, сессии, heartbeat, настройки, токены, резервные копии и исходные книги на рабочем компьютере.
- Не менять БДХК, её карточки, API, интерфейс карточек, фасад и Telegram-бот. Карточка Dead Shell в БДХК остаётся.
- Не вызывать DELETE, POST или PATCH внешнего Weblate в основной операции. Все внешние проекты, включая созданные тестовые, в этом варианте сохраняются.
- Любое удаление или изменение работающего экземпляра начинается только после подтверждения владельца этого плана. До этого службы продолжают работать.

## Файлы реализации

- Создать `scripts/cleanup_wizard_projects.py`: предварительный отчёт, резервирование, проверка точного списка, транзакционная очистка локальных данных и архивирование файлов. Никаких импортов клиента Weblate и сетевых операций.
- Создать `tests/test_project_cleanup.py`: короткие проверки на временной SQLite и временных каталогах.
- Отмечать результаты исполнения в этом документе: фактические ID, резервная копия, количество удалённых записей и результат восстановления служб.

Интерфейсы скрипта: `build_cleanup_manifest(data_dir: Path, projects: list[tuple[str, str]]) -> dict` и `apply_cleanup_manifest(data_dir: Path, manifest: dict, archive_dir: Path, expected_digest: str) -> dict`. Первая функция только читает; вторая повторно проверяет снимок и применяет согласованный список. По умолчанию CLI работает без удаления; применение требует `--apply` и `--expected-digest` подготовленного manifest.

## Внимание при проверке

- Совпадающее имя игры при другом slug: проект сохраняется.
- Новые или изменённые записи после подготовки отчёта: очистка прекращается до обновления отчёта.
- Активный worker, действующая lease или неподтверждённая операция перевода: очистка не начинается.
- Общий файл или экспорт, на который ссылается другой проект: не удаляется.
- Каталог вне разрешённого корня, symlink или неподходящий UUID: обработка файлов прекращается.

## Отдельный этап: удаление внешних тестовых проектов

Удаление локальной карточки не удаляет проект на `https://l10n.herocraft.com/`. Владелец отдельно подтвердил удаление следующих slug; проверены сохранённые ответы создания HTTP 201 и текущие ID 20/21. Оба удаления выполнены, отсутствие подтверждено HTTP 404:

1. `test-5dacb142c2714e46-3cc5dcb7`.
2. `wizard-58022f2c0c50452a-e23aa04f` — один проект, содержащий результаты нескольких языков; не несколько независимых проектов.

Перед таким удалением проверить точные объекты через API, сохранённые подтверждения создания первого задания и наличие выполняющихся переводов; выгрузить имеющиеся результаты всех языков. Сохранить список остальных внешних проектов для сравнения после операции. Использовать штатное удаление строго по этим двум slug и только при подтверждённой принадлежности. Не обещать восстановление внешнего проекта из локальной SQLite: она не является полной резервной копией Weblate.

`wizard-058c83ed9e414dbb-01958461` для Dead Shell в этот список не включать: создание отклонено. Если точный объект всё же существует, выяснить его происхождение отдельной проверкой. Существующие внешние проекты с именами Dead Shell или Lord Ambermaze и другими slug не трогать.

**Критерий завершения основного плана:** три локальные карточки исчезли, связанные локальные данные сохранены в архиве, визард снова работает; никаких изменений во внешнем Weblate и БДХК не произведено.

## Итог исполнения

Основной скрипт работал только с локальными данными. Отдельная согласованная операция удалила внешние проекты ID 20 и 21; остальные 13 проектов и 41 компонент сохранили ID, slug и ссылки на репозитории. Существующий внешний `dead-shell`, ID 11, доступен с HTTP 200.

Перед применением повторный отчёт показал 12 записей вместо первоначальных 13: временный черновик уже истёк и был удалён штатной очисткой. Точный список карточек и шести заданий не изменился. Удалены 12 записей и 6 заданий; три оставшихся каталога результатов перенесены в архив. Дополнительные проекты в очистку не включались.

Резервная копия: `/opt/bdhc/weblate-wizard/shared/backups/cleanup-20261002-approved`. В ней сохранены исходная SQLite, manifest с SHA-256, копии и архивированные каталоги, выгрузки всех языков двух внешних проектов, перечни внешних проектов до/после и отчёт об удалении. Локальная копия прошла `PRAGMA integrity_check` и содержит все три прежние карточки. Рабочая БД не восстанавливалась, поскольку очистка завершилась успешно.

Проверено 54 функциональных теста, форматирование и линтер. Проверка скрипта независимым агентом выявила недостаточную проверку вложенных общих файлов; исправление проверено воспроизведением до/после. Дополнительно проверено сохранение частичного отчёта при ошибке перемещения. Дополнительные тесты на некорректный UUID и добавление записи не включались: проверка UUID и сравнение полного снимка выбранных объектов присутствуют в скрипте.

Фактический вход по LAN, список проектов и интерфейс возвращают HTTP 200, карточек — 0; API каждой удалённой карточки возвращает HTTP 404. Пользователь и 11 существующих сессий совпадают с резервной копией; проверочная сессия после входа закрыта. Heartbeat сохранён. Readiness визарда и health-check API/UI/фасада БДХК — HTTP 200. PID основного API `1001139`, интерфейса карточек `1027425`, Telegram-бота `1052749` и фасада `1076287` остались прежними. Перезапускались только собственные службы визарда.
