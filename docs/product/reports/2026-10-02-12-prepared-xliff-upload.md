# Загрузка готовых переводов и готовность нового языка

В отдельный визард установлен runtime `b0f60767a705` (XLIFF — `720192d248d1`, ожидание строк — `b0f60767a705`). Восстановлено существующее английское задание `2e5d00e8-3b0f-488d-b446-d3e012a15ce7` в прежнем проекте Lord Ambermaze `wizard-58022f2c0c50452a-e23aa04f`. Полный английский перевод ещё не завершён; задание ожидает продолжения пользователем.

## Причины остановки

Предыдущее исправление bilingual PO помогло `kit-3`, но `kit-4` снова вернул HTTP 200 с `not_found: 200`, `accepted: 0`. API показывал точные совпадения исходников и контекстов. При загрузке `.po` Weblate сначала пробует monolingual формат существующего компонента; файл загрузки переведён в однозначный bilingual XLIFF 1.2 `.xlf`.

Реальный XLIFF upload принял все 200 строк `kit-4`. Затем загрузка в только что созданный английский язык `kit-5` вернула `not_found: 118`, `accepted: 0`. Проверка на следующем `kit-6` подтвердила отдельную гонку: создание языка вернуло HTTP 201; первый GET языка — HTTP 200, `total: 0`, список units — 0. Через две секунды GET показывал `total: 77` и 77 units. Объект и файл языка становятся доступны раньше строк в БД.

## Исправления

XLIFF хранит точный ключ в `resname` и `id`, исходник в `source`, перевод в `target`. Исключаются пустые переводы, сохраняются повторяющиеся исходники с разными ключами, Unicode, теги и переносы. XML экранируется, CR кодируется как `&#13;`; точный parse-back сравнивает все три значения. Создание компонента по-прежнему использует monolingual PO. Upload использует `conflicts=ignore`, durable-ключ `seed-xliff` и предварительное чтение уже заполненных строк. Старые ответы `seed`/`seed-bilingual` сохраняются.

Worker на каждом проходе ожидает `total` не меньше числа строк компонента перед подтверждением языка, upload и MT. Во время ожидания он освобождает lease с задержкой опроса, не создаёт язык повторно и не отправляет upload или платный запрос. Неизвестные результаты запросов автоматически не повторяются.

## Фактическое восстановление

Согласованные SQLite backups: `wizard-20261002T032602Z.sqlite` и `wizard-20261002T033510Z.sqlite`. Восстановление проводилось под отдельным lease, с проверкой отсутствия активных jobs и запретом `start_translation`. Перед загрузкой каждого языка проверялись число units и точное соответствие ключей и исходников; страницы units читались полностью.

Для `kit-5` сохранён известный ответ прежней загрузки с нулевым accepted в `seed_recovery`. GET подтвердил все 118 units готовыми и все английские targets пустыми.
