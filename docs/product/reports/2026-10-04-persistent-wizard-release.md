## Реализованное поведение

Подключение существующего проекта требует выбора и подтверждения, загружает языки, компоненты, переводы, глоссарий и доступные настройки. Подключённые и прежние проекты визарда защищены от записи. Общий переключатель внешней записи выключен по умолчанию и не отменяет эту защиту.

Для новых проектов, создаваемых этим выпуском после разрешения записи, добавлены постоянная привязка, версии оригинальных файлов, сопоставление листов, точный отчёт изменений, перевод выбранных пустых строк по unit ID, сохранение прежних языков и истории выгрузок. Пользовательский глоссарий публикуется в отдельную версию компонента после просмотра и отдельного согласия; пересечение с существующими терминами блокируется.

Пояснения новых строк передаются через explanation. Ручной профиль требует проверки языков; объединение project-level инструкций сохраняет остальные языки и приватные настройки engine. Неопределённые внешние операции проверяются чтением без автоматического повторения платного POST. Диагностика скачивается владельцем без секретов и полного текста игры.

## Принятые решения и их последствия

1. Запрет пользователя на изменение существующих проектов принят как ограничение поверх плана: только GET и привязки read-only. Последствие: старые проекты доступны для чтения и выгрузки, перевод из визарда для них не включён.
2. Рабочая ветка создана вручную для отдельного репозитория в разрешённом временном каталоге, потому что встроенный worktree-инструмент связан с другим checkout. Последствие: изменения не подменяют рабочую копию Weblate и до интеграции остаются в отдельной ветке.
3. Учёт шагов и команды проверок выполнялись в PowerShell вместо POSIX helper-скриптов навыка. Последствие: эквивалентный ручной журнал, без автоматически созданных brief-файлов.
4. Привязки из подтверждённого старого журнала защищены даже после включения записи для новых проектов. Последствие: прежний тест повторной записи заменён проверкой запрета; прежние игры не обновляются.
5. Замечание о 104 полных чтениях на порцию перевода повышено до существенного и исправлено. Последствие при ошибочной оценке: небольшой рефакторинг и дополнительная проверка; нагрузочная сертификация этим не заявляется.
6. Пользовательский глоссарий для нового собственного проекта создаёт отдельный компонент версии; исходные термины с пересечениями блокируются. Последствие: редакционные конфликты требуют исправленной таблицы, существующие термины не перезаписываются.
7. Установка, платная приёмка и реальная запись остаются отдельным этапом после требуемого планом разрешения. Последствие: имитация API не доказывает выполнение конкретной внешней Celery/LLM-задачи.
8. Нагрузочная приёмка отложена согласно утверждённому плану. Последствие: пропускная способность не сертифицирована.

## Оставшийся этап

Задача 8 завершена в части локальной приёмки, подготовки сборки и изолированного восстановления. Требуются явное разрешение установки только визарда с выключенной внешней записью, свежий проверенный бэкап и проверка копии baseline перед переключением. Отдельно требуется согласовать новый платный тест на 5–10 строках выделенного нового тестового проекта и язык. Действующие игры для платного теста не используются.

Git remote у отдельного репозитория не настроен: публикация в корпоративный репозиторий не выполнялась. Для передачи готовятся ZIP выпуска и Git bundle исходной ветки, без секретов и пользовательских лок-китов.
