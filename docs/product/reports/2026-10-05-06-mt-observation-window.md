# Увеличение ожидания машинного перевода

Статус: подготовлено локально; на сервер не установлено.

## Подтверждённая причина

В задании `ea1a3601-d02b-4323-a6eb-4e289b7a9583` внешний Weblate сохранял переводы после истечения пятиминутного окна визарда. При неизвестном результате POST визард продолжал только GET до фиксированного дедлайна, затем требовал ручного продолжения. Рост числа переводов окно не продлевал. Единственная незаполненная строка `quest.invasionkillmonsteraxe` удерживала подтверждение первого языка. API и история строки показали пустой target, отсутствие запрещающих флагов и ошибок проверок, но не причину отсутствия ответа LLM. После сохранения этой строки и продолжения задания первый язык был подтверждён, запустился второй. Позднейшая проверка показала завершение задания и 963/963 заполненных строк для каждого языка. Это не означает отсутствие замечаний качества: Weblate показывает 18 строк с проверками для `zh_Hans` и 33 для `zh_Hant`.

## Изменение

По умолчанию машинный перевод наблюдается 30 минут без роста числа заполненных строк. Рост продлевает ожидание; повторное чтение того же результата не продлевает его. Абсолютный предел — два часа на одну операцию. Все отсчёты и счётчики сохраняются в SQLite и переживают замену процесса. Для старого intent без времени операции используется консервативная граница от начала задания и прежнего дедлайна, если он сохранён. Точное время отдельного старого запроса восстановить нельзя; перезапуск не выдаёт ему новое окно ожидания.

Настройки: `WIZARD_MT_OBSERVATION_SECONDS=1800`, `WIZARD_MT_MAX_OBSERVATION_SECONDS=7200`, допустимо `60 <= idle <= maximum <= 86400`. Обе границы проверяются при создании конфигурации до отправки запросов. Политика применяется к первоначальному переводу, HTTP 202 с наблюдаемой задачей или без неё и пакетам инкрементального перевода. Остальные операции сохраняют своё пятиминутное ожидание. HTTP-таймаут одного обращения к Weblate остаётся 300 секунд: общий срок наблюдения и таймаут соединения имеют разные назначения.

Существующее поле API `coverage` и диагностический JSON получают количество переведённых строк, общее количество в операции, время прогресса и дедлайн. В них не включаются текст игры и секреты. UI в этом выпуске не меняется.

Внешний POST не повторяется автоматически. Неизвестный результат после обоих пределов остаётся неизвестным: отсутствие нового прогресса не подтверждает прекращение Celery. Для незаполненной строки сохраняется путь исправления в Weblate и последующего продолжения визарда. Автоматическое создание перевода вместо внешнего сервиса и новый платный запрос этим выпуском не добавляются.

## Проверки

Ошибка сначала воспроизведена тестом: через десять минут ожидания задание становилось `unknown`. После исправления проверены продление при новом прогрессе, отказ от бесконечного продления при одинаковых GET, общий предел для потерянного ответа и незавершённой задачи, настройка меньшего допустимого окна, возобновление старого intent без POST, сохранение отсчёта после перезапуска, инкрементальная обработка и безопасные диагностические счётчики. Полный набор: 183 теста прошли. Ruff для изменённых Python-файлов прошёл. Единственное предупреждение полного набора — существующее предупреждение Starlette о версии httpx в TestClient. Отдельная проверка кода выявила отсутствие временной границы у некоторых старых записей; исправление проверено тремя первоначально падавшими регрессиями. Дополнительно проверено сохранение частичного инкрементального прогресса через сериализованный checkpoint и достижение общего предела без второго POST.

Все проверки выполнены с изолированными данными и заменой сетевой границы. Дополнительные платные переводы и изменения внешнего Weblate во время подготовки выпуска не выполнялись.

## Установка и возврат

Установка требует отдельного явного разрешения согласно `docs/product/guides/deployment.md` и `deploy/install.sh`. Перед установкой нужен новый полный бэкап текущего `release-9868b21a17d4`, включая завершённое задание и экспорт, проверка хешей и восстановление в изолированной копии. Старый бэкап, созданный до этого задания, не заменяет новую точку возврата. Во время установки сохраняются режимы защиты существующих проектов и настройки агента; меняются только службы визарда. Миграция схемы БД не требуется.

После установки проверить readiness, вход, чтение завершённого задания, защиту подключённых проектов и фактические значения обеих границ. Не запускать новый платный перевод для проверки. Откат кода — через `deploy/rollback.sh` с новой проверенной резервной копией; он не отменяет уже выполненные операции Weblate. До отдельного разрешения running instance не переключается.

## Дополнительная защита интерфейса

Следующий самостоятельный шаг — список оставшихся строк с файлом, листом, ключом и ссылкой на Weblate. Для повторного платного перевода одной строки сначала нужен подтверждённый результат прежнего задания, затем явное действие пользователя, повторная проверка пустого target и ограничение запроса точными ID. Если Weblate не отдаёт результат задачи, исправление строки вручную позволяет обойтись без повторного платного запроса. Продолжение других языков при частичном результате требует отдельного статуса и выгрузки с явными пропусками; помечать такой результат полностью завершённым нельзя. Эти функции не включены в текущий выпуск ожидания.
