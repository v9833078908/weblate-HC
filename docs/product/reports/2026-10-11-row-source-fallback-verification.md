## Решения реализации

- Использован существующий Windows Python/Git вместо Bash/uv-помощников: рабочее дерево и окружение привязаны к Windows. Цена решения — переносимость служебных команд; продуктовый код не зависит от них.
- Тестам задан отдельный временный каталог; TestClient запускался вне песочницы из-за локального socketpair Windows asyncio. Внешние API во всех тестах заменены имитациями. Цена решения — тестовая среда требует локального сокета, разрешения продукта не расширяются.
- Проверки интеграции выбора исходника объединены с задачей манифеста: промежуточный код не публиковал неверно маркированный source. Цена решения — границы коммитов отличаются от границ тестовых задач.
- Для смешанных исходников роль агента детерминированно указывает язык текущего запроса; стиль и языковые инструкции агента сохраняются. Цена решения — менее свободная формулировка роли, зато она не противоречит фактическому источнику.
- Для полностью пустой подтверждённой исходной колонки структурный анализ получает временную пробу. Она не сохраняется и не переводится; реальные строки остаются проблемными. Цена решения — корректность опирается на подтверждённую структуру колонок.
- Выбор выгрузки адресует логические листы и объединяет технические группы, включая листы только с проблемами. Не выбранные служебные колонки и исходные ячейки не заменяются запасным текстом.

## Финальное ревью и исправления

Независимое ревью всей ветки выявило пять важных замечаний, без критических. Все подтверждены локальным воспроизведением и исправлены за один проход: шесть backend регрессий сначала упали, затем прошли; дополнительный frontend тест блокировки пустого набора также прошёл после воспроизведённого FAIL. Полные проверки повторены после исправлений.

- Историческая привязка листа wizard-owned проекта не заменяется предложенной привязкой. Это сохраняет обнаружение смены исходника и предотвращает дублирование оплачиваемой строки. Цена решения — изменение установленной привязки требует отдельного явного сценария миграции.
- Сохранение ручной роли переводчика сохраняет введённый текст. Нейтрализация исходника применяется только к предложениям агента; несовместимая ранее привязанная ручная роль требует проверки. Цена решения — пользователь отвечает за подтверждённые ручные формулировки.
- Восстановление v2 использует логические листы, включая файлы только с проблемами. Исторические снимки не переписываются. Цена решения — такие версии остаются доступными для исправления, хотя пока не могут публиковаться.
- Нулевой допуск блокирует запуск до создания задания и внешних запросов; интерфейс объясняет причину. Цена решения — полностью проблемный набор нужно исправить перед запуском.
- Подтверждённая языковая роль участвует в распознавании неизвестного заголовка. Без распознанного заголовка используется первая строка, показанная анализом колонок; индексы проверяются. Цена решения — произвольный заголовок за неподтверждёнными вводными строками автоматически не угадывается.

Мелких отложенных замечаний нет. Ревью не оценивало серверную установку/фактический серверный откат (задача 8 требует отдельного разрешения) и реальные внешние платные ответы Weblate/LLM (проверки намеренно локальные). Эти ограничения не заменяются утверждением о live-проверке.

## Ограничения и установка

Нет платной проверки на внешнем Weblate и серверной установки нового выпуска. Изменение языка/текста ранее опубликованного ключа блокирует план и требует явного решения пользователя. Глоссарий не инвертируется; наличие совместимого источника/цели показывается в раскрываемых сведениях.

У wizard отсутствует Git remote: изменения сохранены в локальной ветке и комплекте исходников. Чужой репозиторий Weblate не используется для публикации. Цена решения — внешняя Git-публикация остаётся недоступной, но source bundle хранит историю для восстановления.

При откате на baseline с manifest v2 оба worker остаются выключенными и замаскированными. Старый код нельзя запускать на новых заданиях без проверки совместимости; локальный откат не отменяет записи Weblate. Историю принятых/неизвестных операций необходимо сверить до возобновления, старую БД поверх неё автоматически не восстанавливать.
