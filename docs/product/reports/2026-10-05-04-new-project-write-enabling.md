# Разрешение записи для новых проектов

5 октября 2026 года пользователь разрешил внешнюю запись при условии создания отдельного нового проекта и сохранности ранее существовавших проектов Weblate. На установленном `release-e53392ccf98a` изменена только настройка `WIZARD_EXTERNAL_WRITES=0` → `1`; исходники, UI и привязки проектов не менялись.

## Проверка условия перед включением

На сервере выбранный локальный проект `wizard-2c0ef0fba7cf4cb9` (`Test_API_LOC`) имеет `persistent: true` и не связан с внешним проектом. В очереди локализации нет заданий. Оба ранее подключённых проекта имеют `read_only: true` и не имеют происхождения `created-v2`.

На изолированной копии актуальной базы вызван `start_run` с фактическим выбранным черновиком `63fecd02-d930-41eb-9a34-c5d837488483`. Он зарезервировал отдельный slug `wizard-2c0ef0fba7cf4cb9-6929e736`, не включил переиспользование проекта. Чтение Weblate через GET подтвердило отсутствие объекта с этим тестовым slug; в реальный Weblate записей не было. Production-запуск выберет свой новый случайный суффикс.

Тому же worker на копии передан искусственный ответ «объект уже существует». Задание остановилось с `remote_collision` до первой операции записи. Попытки запустить локализацию в обеих подключённых привязках завершились `project_read_only` до формирования рабочего задания. Общий флаг записи не отменяет этих проверок.

Дополнительно локально прошли 32 теста `test_project_links.py`, `test_run_resume.py`, `test_persistent_flow.py`, `test_weblate_client.py`. Они проверяют подключение только для чтения, legacy-защиту, наблюдение неизвестных операций без повторных POST, сохранение старых переводов и работу с точными локалями.

## Изменение сервера

Перед изменением остановлены только три собственные службы визарда и создан свежий полный приватный бэкап кода, данных, конфигурации, секретов и units:

`/opt/bdhc/weblate-wizard/shared/backups/pre-write-enable-20261005T034623Z`

Контрольные суммы и SQLite integrity проверены до и после включения. Дополнительная закрытая копия прежней конфигурации находится в `shared/backups/write-enable-config-*`. Новый бэкап остаётся на сервере; ранее согласованная приватная копия бэкапа установки вне сервера сохраняется отдельно.

После атомарной замены env запущены только API, worker и профильный worker визарда. Фактическая конфигурация всех трёх процессов подтверждает `external_writes_enabled: true`, включённый агент и `openai/gpt-6-luna`.

## Что доступно пользователю

После обновления вкладки кнопка запуска становится доступна при готовом лок-ките и профиле. Первый запуск выбранного `Test_API_LOC` создаёт отдельный внешний проект с новым slug, затем импортирует строки и запускает перевод. Совпадение названия или наличие подключённого проекта не разрешает его изменение.

Визард сохраняет возможность дальнейшей работы с проектами, которые сам создал с происхождением `created-v2`; это отличается от подключённых заранее существовавших проектов, остающихся только для чтения. Перед повторной записью в собственный проект требуется подтверждённый план изменений. Неизвестный результат ранее отправленной операции не разрешает её автоматическое повторение.

Настройка разрешает сеть записи, но не доказывает успешность внешнего импорта или оплачиваемого перевода: они этим сценарием не выполнялись. Реальный запуск остаётся действием пользователя в интерфейсе.

Для возврата запрета записи достаточно вернуть `WIZARD_EXTERNAL_WRITES=0` и перезапустить только службы визарда после проверки безопасной границы заданий. Свежий полный бэкап сохраняет исходное значение `0`. Возврат локальной конфигурации не отменяет операции, уже принятые внешним Weblate.

История исходников и отчёт сохраняются локальным коммитом и Git bundle; remote самостоятельного визарда отсутствует. Исторический отчёт установки с выключенной записью остаётся неизменным: новое разрешение описано настоящим отчётом.
