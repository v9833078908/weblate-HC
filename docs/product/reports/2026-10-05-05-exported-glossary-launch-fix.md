# Исправление запуска с экспортированным глоссарием

## Причина

Запрос локализации `Test_API_LOC` остановился до создания задания при разборе приложенного `Test_API_LOC глоссарий.xlsx`. Детерминированный импортёр не распознал заголовок `Ключ / контекст`. Исключение `InferenceError` вышло из `prepare_glossary` без преобразования в ответ API, поэтому пользователь увидел общее сообщение HTTP 500. В момент диагностики таблица заданий оставалась пустой: внешний проект, компоненты и перевод этим запросом не создавались.

Этот файл использует формат ранее выгруженного глоссария Weblate: служебные строки перед заголовком, сериализованная пара `[раздел, исходный термин]`, языковые колонки, `Пояснение исходного термина` и `Флаги исходного термина`. На сервере обнаружены 197 записей; все сериализованные пары соответствуют исходному термину. Предшествующая проверка разрешения записи проверяла запуск только с лок-китом, без тела запроса с приложенным глоссарием; она не покрывала этот отказ.

## Изменение

В границе FastAPI добавлен узкий адаптер именно этого экспортного формата. Он строит закрытый профиль TBX `record-map`, сохраняет смысл контекста, исходные пояснения, поддерживаемые флаги и все имеющиеся языковые значения. Оригинальные загруженные строки остаются в черновике; копия для парсинга содержит раздел отдельно от исходного термина. Новые выбранные языки получают пустые колонки, без выдуманных переводов терминов. Общий автономный импортёр не меняется.

После адаптации остаются проверки точных заголовков, всех заполненных ячеек, повторов контекста, совпадения ключа с исходным термином, допустимых флагов и обратной проверки TBX. Неподдерживаемая структура не игнорируется: автоматическая подготовка глоссария возвращает `glossary_validation` (HTTP 400), указывает файл и лист, предлагает исправить файл или убрать глоссарий. Ни задача, ни внешний запрос при таком отказе не создаются.

Защита существующих проектов не меняется: подключённые проекты остаются только для чтения; первый запуск неподключённого проекта резервирует отдельный slug. Реальный запуск перевода остаётся действием пользователя.

## Проверка

Регрессионный тест воспроизводит полный запрос HTTP локализации с новым лок-китом, двумя китайскими вариантами и приложенным экспортированным XLSX. До изменения тест получал HTTP 500, после — HTTP 202 и задачу только в тестовой базе. Отдельно проверено содержимое архивов TBX после обратного чтения: контекст, перевод, пояснение и флаг. Негативные случаи включают неизвестные заголовки, повреждённый контекст, несоответствие исходному термину, неизвестный флаг, лишнюю ячейку, повтор контекста и отсутствие терминов.

Полная проверка backend: **170 passed**, Ruff check и форматирование прошли. Предупреждение Starlette об устаревшем транспорте TestClient осталось прежним; frontend не менялся.

На изолированной копии фактических серверных данных тот же полный запрос с обоими upload ID получил HTTP 202. Подготовлены 963 строки лок-кита и 197 терминов. Проверены соответствие всех контекстов оригиналу, сохранность пояснений и существующих переводов, пустые значения новых целевых языков и обратное чтение TBX. Сеть запрещена через перехват socket connect, рабочая база и внешние сервисы не использовались для записи. Приватные термины в отчёт не включаются.
