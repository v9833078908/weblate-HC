## Что создать для визарда

1. **`game-context-brief`**: отбирать подтверждённые факты карточки и описывать жанр, сеттинг, игровой цикл, аудиторию и голос игры кратко. Пустые данные не заменять догадками. Различать имя локального проекта и название выбранной игры.
2. **`weblate-profile-author`**: формировать `persona` и `style` по контракту Weblate; явно разделять UI и диалоги, сохранять глоссарий, числа, теги, переменные и разделители. Не приписывать всем играм жанр приключений с головоломками.
3. **`game-locale-instructions`**: формировать отдельный текст для каждого точного кода языка, включая письменность и регион. Сначала учитывать подтверждённые правила БДХК и ручные правила пользователя, затем справочник языковых особенностей.

Это три пакета инструкций одного встроенного агента. Для первой версии достаточно одного контролируемого вызова LLM с тремя пакетами и строгой JSON-схемой. Отдельный агент для каждого навыка, доступ к shell и доступ модели к API записи Weblate не требуются.

Формат пакетов можно организовать по [Agent Skills specification](https://agentskills.io/specification): `SKILL.md` и ограниченные справочные файлы. Однако установка навыка в Codex сама по себе не подключает его к FastAPI. Backend должен явно загрузить версионированные инструкции, подготовить данные и проверить ответ. Описание переносимых пакетов также есть в [официальной документации OpenAI Skills](https://developers.openai.com/api/docs/guides/tools-skills); смена текущего провайдера на OpenAI для данного решения не нужна.

## Языковые источники

[Microsoft Localization Style Guides](https://learn.microsoft.com/en-us/globalization/reference/microsoft-style-guides) содержит отдельные руководства для языков и регионов. Использовать как источник при составлении кратких собственных справок; это правила технической локализации, которые надо согласовать с голосом конкретной игры. Само наличие ссылки в каталоге не означает, что содержание каждого руководства уже изучено.

[Unicode CLDR / LDML](https://www.unicode.org/reports/tr35/) — источник структуры локалей, письменностей, регионов и форматов. Он не определяет сюжет, характер персонажей и тон игры. Коды запросов остаются точными кодами Weblate; нормализация для поиска не меняет их при сохранении.

Начальный набор собственных справок: `ru`, `en`, `fr`, `it`, `de`, `zh_Hans`, `zh_Hant`, `ko`, `ja`, `pt_BR`, `es_MX`, `pl`, `cs`, `nl`. Для иной локали агент сохраняет точный код и показывает, если у проекта нет проверенной специализированной справки. `zh_Hant` задаёт письменность; регион Тайвань или Гонконг не следует автоматически приписывать только по этому коду.

## Что уже реализовано

В FastAPI-визарде:

- `backend/app/integrations/bdhc.py`: поиск, разрешение идентификатора и чтение `knowledge`, отображение части брифа и стилевых профилей.
- `backend/app/routes/bdhc.py`: предварительный просмотр и явное подтверждение; применение сейчас сбрасывает `generated`.
- `backend/app/integrations/llm.py`, `profile.txt`: генерация `persona`, `style`, `language_instructions` через OpenRouter или корпоративный LiteLLM, строгая схема ответа.
- `backend/app/routes/profiles.py`: генерация при сохранении анкеты, если настроены ключ и модель. Сначала сохраняет анкету с `generated=None`, затем вызывает LLM.
- `console/src/screens/wizard/ProfileIntegration.tsx`: локальный шаблон с жёстко заданными приключениями/головоломками, без автоматического поиска карточки и с пустыми новыми языковыми инструкциями. Передача сгенерированных инструкций в состояние формы требует отдельного исправления, чтобы результат LLM появился без перезагрузки и не затёр ручной ввод.

У текущего вызова LLM нет отдельного поля названия игры и исходного языка; список целей берётся из последнего найденного черновика проекта, а не из переданного токена. При нескольких черновиках это ненадёжно. Новый агент должен работать с конкретным черновиком, версией карточки и текущим исходным языком.

Работающая конфигурация прочитана без изменения сервера и без чтения значений ключей: `bdhc_configured=true`, `PROFILE_LLM_MODEL` пуст, `profile_key_configured=false`, endpoint по умолчанию OpenRouter, `external_writes=false`. Поэтому существующий LLM-путь сейчас не настроен. Наличие машинного перевода в Weblate не означает наличие ключа генератора в визарде.

## Границы исследования

LLM не вызывался, генерация и перевод не оплачивались. Содержимое карточек не публиковалось сторонним сервисам. Проекты Weblate не изменялись. Качество сторонних навыков на игровом корпусе ещё не измерено; окончательный выбор правил проверяется на контрольных примерах при реализации.
