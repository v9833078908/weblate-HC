# Неоднородные повторы: исследование TMS и контекст сессии

Дата: 2026-09-17.
Статус: исследование и передача контекста; не утверждённый план реализации.
Область: предотвращение необоснованных расхождений повторяющихся строк при
LLM-переводе в HCGameLoc и разбор накопленных расхождений Anvil Saga, ru → fr.

## 1. Исходная задача и намерение пользователя

Продюсер столкнулся с неоднородным французским переводом Anvil Saga:
<https://l10n.herocraft.com/projects/anvil-saga/-/fr/>. Интерфейс показывал
около тысячи строк с проверкой `repeat-drift`; воспринимаемая задача —
вручную исправлять каждую из них.

Пользователь последовательно попросил:

1. Оценить серьёзность проблемы на production, предложить решение с хорошим UX
   и измеримым качеством локализации.
2. Проверить существующий план session canon.
3. Использовать уже имеющиеся возможности Weblate, в частности память переводов,
   и посмотреть на соседние исследования контекста и RU/EN → zh-Hans.
4. Проверить фактическую проектную память Anvil Saga.
5. Вернуться к исходной цели: после следующего прогона получить как можно меньше
   необоснованных `repeat-drift`, а не углубляться в TM ради TM.
6. Запустить параллельных исследователей и выяснить практики зрелых TMS.
7. Сохранить исследование и контекст сессии в отдельном документе.

Цель — предотвращать необоснованные различия и уменьшать число человеческих
решений. Не цель — обнулить счётчик подавлением проверки или принудительным
выравниванием переводов, которым по контексту положено различаться.

## 2. Что было разрешено и что сделано

- Production исследовался только чтением: HTTP GET к REST API, выгрузка файлов,
  локальные вычисления. Переводы и настройки не менялись.
- Платных вызовов LLM и команд внутри production-контейнеров не было.
- Внешнее исследование выполнено тремя параллельными исследователями:
  Phrase/Trados/memoQ; Crowdin/Lokalise; Smartling/Transifex.
- Ключевые положения дополнительно проверены по официальным страницам.
- Проверка поставщиков документальная: экспериментальных запусков этих TMS
  на корпусе Anvil Saga не выполнялось.
- Код продукта, настройки checks, machinery и propagation не изменялись.
- Пользователь не утверждал реализацию, миграции, новый прогон перевода,
  изменение production или автоматическое исправление существующих строк.

До создания этого документа в рабочем дереве оставались два untracked-артефакта
предыдущего аудита:

- `docs/operations/audits/2026-09-17-anvil-saga-fr-repeat-drift.md`;
- `analysis/data/anvil-saga-fr-repeat-drift-2026-09-17.json`.

Они не изменялись при сохранении этого документа и не включаются в его коммит.
Наличие их на диске не означает, что они доступны в другом checkout. Старый
аудит содержит первоначальные выводы; поправки ниже имеют приоритет.

| Метрика | Наблюдение |
|---|---:|

| Переведено по исходному ответу statistics API | 9 481 |
| Групп точных повторов исходника | 748 |
| Строк внутри этих групп | 2 156 |
| Групп с разными французскими вариантами | 387 |
| Строк внутри расходящихся групп | 1 096 |

Длина исходника — только способ приоритизации просмотра, не доказательство,
что строка является названием квеста или пригодна для общего перевода.

`repeat-drift` — advisory-проверка: она отмечает каждого участника расходящейся
группы, включая пригодный вариант. Поэтому 1 096 замечаний не означают
1 096 плохих переводов или 1 096 независимых редакторских решений.

Примеры заметных расхождений:

- «Угроза с севера»: 18 вхождений, 5 вариантов французского названия.
- «Дева по имени Данна»: 26 вхождений, 4 варианта.
- «Выгодное спасение»: 18 вхождений, 5 вариантов.
- «Основание»: варианты `Monture`, `Armature`, `Base`, требующие смыслового
  решения, а не выбора по частоте.

Ключи вида `Quest`, `Fail`, `Complete`, `Title` дают основание исследовать
общность игрового объекта, но не заменяют подтверждение назначения строк
и проверку в игре.

### 3.2. Границы первоначальной оценки качества

В первоначальном аудите разобраны 21 блокирующее срабатывание: 19 `duplicate`
на смехе и два `game-number`. В просмотренных примерах они признаны ложными
или семантически допустимыми переводами. Это не доказывает отсутствие других
дефектов во всех 9 482 строках.

Совпадение 184 самостоятельных терминов с глоссарием подтверждено для этих
терминов, но не доказывает соблюдение глоссария во всех предложениях. Ранние
попытки приблизительного морфологического поиска дали ложные находки и не
должны использоваться как количественная оценка нарушений.

Дата `timestamp` у юнитов не доказывает, что все они переведены одним запуском.
Формулировка первоначального аудита «все расхождения созданы одним прогоном»
слишком сильная без истории конкретного запуска.

## 4. Фактическая проектная память

### 4.1. Запрос и полнота

Выполнен GET:

```text
/api/memory/?project=anvil-saga&source_language=ru&target_language=fr&limit=250
```

Ответ: `count=47`, `next=null`, 47 уникальных ID. У всех записей проверены
project ID и origin игрового компонента. Секреты и содержимое ключей API
в документ не включены.

| Метрика | Результат |
|---|---:|
| Записей проектной RU→FR-памяти | 47 |
| Различных исходных текстов | 43 |
| Записей с `from_file=true` | 0 |
| Записей с `shared=true` | 0 |
| Из 387 расходящихся групп покрыты точным исходником | 5 |
| Из них имеют единственный target в проектной памяти | 2 |
| Из них имеют конкурирующие targets | 3 |
| Групп без точного совпадения в проектной памяти | 382 |

Во всей проектной памяти четыре исходника имеют по два разных target; только
три из них входят в сохранённые 387 групп. Историческая память и текущие
расхождения не обязаны совпадать.

### 4.2. Покрытые группы

| Исходник | Вариантов в TM | Текущее состояние соответствующих строк |
|---|---:|---|
| «Как и обсуждали, с горкой.» | 1 | Один approved, второй translated |
| «Этот работник слегка проголодался. Покормите его, пока он не начал голодать!» | 1 | Один approved, второй translated |
| «Ха-ха-ха! Ну, время покажет. Не скучай тут, Артур.» | 2 | Оба approved |
| Реплика Санты и Снежной Королевы про клетки | 2 | Оба approved |
| Реплика про подарочный молот | 2 | Оба approved |

Все десять юнитов дополнительно прочитаны через `/api/units/{id}/`:
восемь имеют state 30, два — state 20; все десять target совпали с сохранённым
снимком. Все восемь записей TM, относящихся к этим группам, совпали с одним из
вариантов снимка.

Однозначные кандидаты памяти:

- `PeasantDebtReturn2` — approved `Comme convenu, avec un petit extra.`;
  `TorturerDebtReturn2` — translated `Comme convenu, avec un supplément.`.
  Перед унификацией нужно проверить контекст говорящих.
- Одобренный вариант сообщения о голодном работнике:
  `Cet ouvrier a un petit creux. Nourrissez-le avant qu'il ne soit affamé !`.
  Второе вхождение `HungryWorker` имеет иной неодобренный перевод.

Память не выбрала общий вариант за человека: в трёх группах она хранит оба
одобренных перевода. Approved отдельной строки не означает утверждение
единственного варианта всей группы.

### 4.3. Что не покрыто и что не проверено

Для четырёх источников — «Угроза с севера», «Дева по имени Данна»,
«Выгодное спасение», «Основание» — записей нет ни в проектном ответе,
ни в отдельном поиске по доступной токену RU→FR-памяти без project-фильтра.
Последняя в целом содержала 18 471 запись; целиком она не выгружалась.

Ограничения:

- `project=` у list API выбирает project/project-file scopes. Это не полный
  набор workspace/shared/personal/global источников реального движка.
- Все 387 групп не проверялись по всем внешним областям памяти или fuzzy-поиском.
- REST list не отдаёт `status` и `context`. GET веб-экспорта с API-токеном
  перенаправил на `/accounts/login/`; сессионного экспорта не было.
- Approved-состояния юнитов проверены, но active/pending конкретных Memory
  records напрямую не получены.
- `/api/memory/lookup/` не использовался как доказательство отсутствия
  конфликтов. Этот endpoint возвращает один выбранный match, а не весь
  набор предложений `WeblateMemory` с unit-specific context penalty.
- Machinery API проекта вернул только `openrouter`, но это проектные
  настройки. Из этого нельзя заключать, что глобальная TM отключена или
  не участвовала в историческом запуске.

Вывод: «две однозначные группы» — результат проверки проектной памяти,
а не оценка полного покрытия всеми источниками реального движка.

## 5. Как различаются существующие механизмы Weblate

Проверено чтением текущего кода сессии; это не проверка установленного
production-кода.

| Механизм | Назначение | Ограничение |
|---|---|---|
| `WeblateMemory` | Постоянные пары переводов и области памяти | Несколько вариантов, active/pending, штраф за другой context |
| `WeblateTranslation` | Поиск по текущим translated-юнитам | Не только approved, не та же база, что Memory |
| Native propagation | Распространение одной строки | Требует одинаковые source **и context** |
| `repeat-drift` | Обнаружение разных targets для точного source | Группирует также разные contexts/ключи |
| Глоссарий | Термины и их пояснения | Не канон всех целых предложений |
| Few-shot LLM | Демонстрации принятого стиля/перевода | Мягкое влияние, не обязательное переиспользование |
| Session canon, план | Новые короткие термины внутри запуска | Не реализован; подсказка, не гарантия общего target |

### 5.1. Native propagation уже включена, но не решает эту задачу

API компонента вернул `allow_translation_propagation=true`.
`UnitQuerySet.same()` в `weblate/trans/models/unit.py` проверяет равенство
source и context, проект и языки. `repeat-drift` в
`weblate/checks/consistency.py` сравнивает точный source между разными ключами.

Следовательно, vendor-style sharing между разными ключами не достигается
простым включением уже существующей настройки.

### 5.2. Балл TM — не качество локализации

Изолированная локальная проба текущего `WeblateMemory.get_quality()`
с точным source подтвердила:

| Запись | Балл |
|---|---:|
| Active, тот же context | 100 |
| Active, другой непустой context | 95 |
| Pending, другой context | 66 |
| Active, пустой context | 100 |

Это similarity/priority, не человеческая оценка качества. Балл 95 может
выиграть у LLM с `max_score=90`, если оба результата участвуют в выборе,
но не делает reuse семантически безопасным.

### 5.3. Приоритет результата не равен предотвращению вызова

`docs/admin/machine.rst` обещает не выполнять MT при 100% TM.
В прочитанном пакетном `BatchMachineTranslation.batch_translate()` вызов
`_translate_sources()` расположен до проверки качества уже найденного
результата. `fetch_machinery_matches()` передаёт batches каждому выбранному
сервису.

Изолированная проба текущего метода с зависимостями-заглушками показала:
при уже имеющемся TM-результате 100 путь следующего движка вызван, но
сохранён результат TM. БД, сеть и реальная LLM не использовались.

Это конкретное несоответствие документации локальному пути, не доказательство
фактической стоимости прошлого production-запуска. Два отдельных прохода
TM-only → LLM по оставшимся пустым строкам дают более явный контроль, но
не предназначены для автоматической нормализации существующих конфликтов.

### 5.4. LLM cache не заменяет политику повторов

Контекст LLM включает ключ монолингвального юнита; контекст влияет на cache
identity. В uncached-пути LLM возвращает `pending:{index}`. Поэтому нельзя
по общей поддержке fan-out в базовом machinery делать вывод, что разные
контексты LLM уже автоматически переводятся один раз.

Один исследователь первоначально сделал такой вывод, затем отозвал его.
Он не является результатом исследования.

Основные файлы:

- `weblate/memory/machine.py`;
- `weblate/memory/tasks.py`;
- `weblate/api/views.py` и `weblate/api/serializers.py`;
- `weblate/machinery/weblatetm.py`;
- `weblate/machinery/base.py` и `weblate/machinery/llm.py`;
- `weblate/trans/machinery.py` и `weblate/trans/autotranslate.py`;
- `weblate/trans/models/unit.py`;
- `weblate/checks/consistency.py`;
- `docs/admin/memory.rst` и `docs/admin/machine.rst`.

## 6. Исследование зрелых TMS

### 6.1. Crowdin: основной экземпляр и переопределения

Официальная документация разделяет detection, visibility и sharing:

- Regular detection сравнивает source text.
- Strict detection сравнивает source text и key.
- `Show` оставляет все экземпляры независимыми.
- `Show, but auto-translate them` показывает все, но позволяет наследовать
  перевод основного экземпляра.
- Hide-режимы скрывают дубликаты; branch-режимы имеют ограничения по пути,
  ветке и формату.

Первый экземпляр — master. Дубликаты наследуют его перевод, пока не имеют
собственного. Собственный перевод прекращает наследование; его удаление
восстанавливает наследование. Если сначала перевести дубликат, ответ не
распространяется обратно на master и остальные дубликаты.

Ключевая цитата: “duplicates inherit the master string’s translation as long
as they don’t have their own”.

Источник: [Crowdin Import Settings](https://support.crowdin.com/enterprise/project-settings/import/#duplicate-strings).

Практический вывод: не нужно скрывать строки, чтобы перестать переводить их
независимо. Но первый импортированный master — правило идентичности,
а не доказательство наилучшего качества его перевода.

### 6.2. Smartling: дедупликация до перевода

После parsing, до предоставления строк переводчику, Smartling выполняет
deduplication. Три одинаковых вхождения в примере HTML представлены одной
строкой; её перевод используется во всех трёх местах экспортированного файла.

Идентичность учитывает:

- Text, включая tags, placeholders и пробелы;
- Variant, который может задаваться ключом формата;
- Namespace, часто имя файла.

Разные variant или namespace сохраняют строки отдельными. Поэтому это не
безусловная дедупликация по source между всеми ключами и файлами.

Источники:

- [String Uniqueness](https://help.smartling.com/hc/en-us/articles/360049585953--Introduction-to-Strings-String-Uniqueness);
- [String Variants](https://help.smartling.com/hc/en-us/articles/360008143853-String-Variants);
- [SmartMatch](https://help.smartling.com/hc/en-us/articles/115003184894--Smartling-s-SmartMatch);
- [CAT Tool Settings](https://help.smartling.com/hc/en-us/articles/115003085554-Customize-CAT-Tool-Settings).

SmartMatch не перезаписывает сохранённые переводы. CAT auto-propagation внутри
job — отдельный механизм от дедупликации импорта. Защита опубликованного
контента зависит от workflow и прав; published не универсальный immutable-флаг.

### 6.3. Phrase TMS: распространение, исключения, конфликты TM

Повтор определяется одинаковым текстом с правилами обработки тегов. Plural
forms не считаются repetitions. Настроенное распространение работает после
подтверждения в CAT editor; отдельное вхождение можно исключить нажатием
на значок repetition.

Документация прямо разделяет editor propagation и batch pre-translation:
это разные этапы, а не доказательство дедупликации MT-запросов.

В TM 100% означает точный source без совпадающего контекста, 101% — контекстное
совпадение. Есть настройка штрафа за несколько разных 101% targets: они
показываются как 100%; при пороге pretranslation 101% не применяются.

Источники:

- [Repetitions](https://support.phrase.com/hc/en-us/articles/5709708706460-Repetitions-TMS);
- [TM Match Context](https://support.phrase.com/hc/en-us/articles/9386879839900-Translation-Memory-Match-Context-TMS);
- [Optimize TM Matches](https://support.phrase.com/hc/en-us/articles/9386873028892-Optimize-Translation-Memory-Matches-TMS);
- [Pre-translation](https://support.phrase.com/hc/en-us/articles/5709717749788-Pre-translation-TMS).

Phrase Strings — другой продукт: key-based identity, явные Linked Keys и
TM-before-MT pretranslation. Не переносить поведение TMS на Strings.

- [Linked Keys, Strings](https://support.phrase.com/hc/en-us/articles/12949643568412-Linked-Keys-Strings);
- [Pre-translation, Strings](https://support.phrase.com/hc/en-us/articles/5822187934364-Pre-translation-Strings).

### 6.4. Trados Studio: распространение после подтверждения

Auto-propagation включён по умолчанию; обычный сценарий — точный повтор
в том же файле, заполнение пустых/неподтверждённых сегментов. Перезапись
confirmed настраивается отдельно. Есть выбор starting point и prompting.

Batch pretranslation имеет отдельные параметры threshold, overwrite,
confirm/lock; locked-сегменты защищены. Context Match и PerfectMatch —
терминология Trados, её нельзя механически приравнивать к числовым уровням
memoQ. Политика безопасного выбора из конкурирующих точных TM-ответов
не установлена по найденным страницам.

Источники:

- [Auto-propagation settings](https://docs.rws.com/en-US/trados-studio-2024-sr1-1187677/file-options-editor-auto-propagation-344868);
- [Auto-propagate confirmed translation](https://docs.rws.com/en-US/trados-studio-2024-sr1-1187677/auto-propagate-confirmed-translation-342130);
- [Pre-translate Files](https://docs.rws.com/en-US/trados-studio-2024-1145319/running-batch-tasks-pre-translate-files-548281);
- [TM Matches](https://docs.rws.com/en-US/trados-studio-2024-sr1-1187677/tm-matches-341353).

### 6.5. memoQ: source propagation и однозначное переиспользование

При включённом auto-propagation подтверждение повторяющегося сегмента
распространяет перевод по документу/view. Направление обычно вперёд,
возможно в обе стороны. Документация предупреждает проверить контекст.

Важная небезопасная для нас настройка: обычно propagation может перезаписывать
существующие переводы; для защиты confirmed нужно снять соответствующий
флажок. Статус propagated-сегмента настраивается; Confirmed — default.
Эти defaults не следует копировать в HCGameLoc.

В pretranslation есть явная защита:
`Use only if there’s a single TM or corpus match` — при нескольких exact/context
совпадениях строка не заполняется. Pretranslation не меняет edited/confirmed
сегменты. MT применяется, когда нет подходящего TM/LiveDocs-совпадения.

Источники:

- [Auto-propagation settings](https://docs.memoq.com/current/en/Workspace/auto-propagation-settings.html);
- [Pre-translate and statistics](https://docs.memoq.com/12-4/en/Workspace/pre-translate-and-statistics.html);
- [TM match rates](https://docs.memoq.com/12-2/en/Concepts/concepts-match-rates-from-translation-m.html);
- [Repetition views](https://docs.memoq.com/current/en/Workspace/create-view-filtering-and-sorting.html).

### 6.6. Lokalise: явное связывание ключей

Duplicate Finder позволяет найти одинаковые значения в выбранном языке,
затем связать ключи parent → children. Изменение parent обновляет children,
при экспорте ключи остаются представлены корректно.

Это управляемая операция, не автоматическое признание одинакового source
одной identity. Merge — другая, более разрушительная операция: один ключ
имеет один перевод на язык. Bulk unlink/unmerge отсутствует; документация
рекомендует snapshot. Finder не работает между проектами/ветками и игнорирует
значения длиннее 1 000 символов. Описанная функция относится к Lokalise Expert.

Источник: [Duplicate translations](https://docs.lokalise.com/en/articles/1400533-duplicate-translations).

Для HCGameLoc полезен принцип явной связи, но не изменение игровых ключей
или формата экспортируемого loc-kit ради её реализации.

### 6.7. Transifex: TM раньше генерации, форматные ограничения

При включённом TM Fill-up 100% TM применяется перед AI/MT. Автоматические
переводы по умолчанию не попадают в TM до Reviewed; у AI есть дополнительные
опции, ослабляющие этот барьер.

Context-aware TM различает совпадающий текст и совпадающий контекст.
Для DOCX официально описано одно отображаемое вхождение и перевод всех
дубликатов при экспорте. Общее наличие Repetitions/filter не доказывает
такое же поведение для PO/JSON.

Источники:

- [Machine Translation setup](https://help.transifex.com/en/articles/6271130-setting-up-machine-translation);
- [TM with Context](https://help.transifex.com/en/articles/6224753-translation-memory-with-context);
- [TM Fill-up](https://help.transifex.com/en/articles/6224817-setting-up-translation-memory-fill-up);
- [Repetitions](https://help.transifex.com/en/articles/6304101-repetitions);
- [Microsoft Word](https://help.transifex.com/en/articles/6221124-microsoft-word);
- [Preventing Translation Edits](https://help.transifex.com/en/articles/6244376-preventing-translation-edits).

## 7. Best practices: синтез, а не универсальные defaults

1. Отделять detection повторов, translation identity, sharing, TM retrieval
   и approval. Это разные решения.
2. Переводить разрешённый повтор один раз и переиспользовать ответ, а не
   надеяться на одинаковую генерацию независимых экземпляров.
3. Явно задавать область и исключения. Одинаковый текст не равен одинаковому
   назначению. Технический ключ не всегда смысловой контекст, но отбрасывать
   все ключи столь же неправильно.
4. Не выбирать первый из конкурирующих approved/TM targets автоматически.
   Однозначность и соответствие контексту важнее формального процента.
5. Сначала переиспользовать пригодное принятое решение, затем генерировать
   остаток. Fuzzy-кандидат не равен разрешённой автоматической замене.
6. Защищать approved, locks и параллельные правки; propagation не должна
   автоматически означать approval.
7. Показывать группы, основной вариант, затрагиваемые вхождения, происхождение,
   конфликты и исключения. Не измерять работу только числом отмеченных строк.
8. Хранить историю и предусматривать откат без затрагивания более поздних правок.
9. Отдельно измерять качество и экономию запросов: наличие propagation не
   доказывает дедупликацию HTTP-вызовов или конкретную экономию токенов.

W3C рекомендует reuse в одном и том же контексте либо для самостоятельной
фразы; при сомнении — отдельные строки. Короткие прилагательные и слова вроде
`On`, `None`, `Time` особенно зависят от согласования и смысла.

Источник: [W3C: повторное использование строк](https://www.w3.org/International/articles/text-reuse/).

Полезный дополнительный UX-пример, не заявление о рыночном лидерстве:
[Taia auto-propagation](https://help.taia.io/how-to/cat-editor/auto-propagate-repeated-segments/).
Есть панель групп, конфликты сверху, происхождение Auto; разные человеческие
переводы не перезаписываются молча, в диалоге замены ничего не выбрано заранее.

## 8. Рекомендуемое направление для HCGameLoc

Это рекомендация сессии, а не утверждённый контракт реализации.

Ближайший образец — управляемое sharing Crowdin/Smartling, защита неоднозначных
совпадений memoQ/Phrase и сохранение имеющихся сущностей Weblate там, где
они покрывают задачу.

### 8.1. Новые прогоны

Нужна явная политика для выбранной области:

- переводить точные повторы совместно;
- переводить независимо;
- исключить конкретное вхождение из общего перевода.

Политика может применяться к набору строк, без ручного связывания каждого
повтора. Однако наборы названий/сообщений и диалогов нельзя молча считать
равноценными; если типы не размечены, их нельзя надёжно вывести из длины.

Для разрешённой группы:

- однозначный подходящий принятый вариант переиспользуется;
- при его отсутствии создаётся один общий результат;
- конкурирующие принятые варианты требуют решения, а не выбора первого или
  наиболее частого;
- результат применяется только к разрешённым для записи актуальным юнитам;
- маркеры, plural forms, ограничения и пользовательские изменения проверяются
  для каждого получателя;
- retry/redelivery не должны создавать новый вариант уже решённой группы.

Не требуется заранее строить LLM-классификатор семантической совместимости:
такой обязательный этап не обнаружен как стандарт исследованных TMS.
Но автоматизация не получает права считать все одинаковые source взаимозаменяемыми.

### 8.2. Накопленные конфликты

Существующие 387 групп требуют отдельного согласования. Запуск только по пустым
строкам не уберёт старые чеки. Включение нового sharing не должно задним числом
молча заменять существующие targets, особенно approved.

Нужна операция выбора по группе с просмотром вхождений и явным сохранением
контекстных исключений. Не регенерировать весь компонент ради счётчика.

### 8.3. Долговечные решения — обязательный вопрос до плана

Обещание «при следующей дозагрузке учитывать принятое решение» невозможно
выполнить только параметром одного запуска. Обычная TM хранит пары, но не
полный контракт членства в группе и исключений.

До реализации нужно определить:

- где сохраняются policy, выбранный основной вариант и overrides;
- устойчивую идентичность членов группы при обновлении loc-kit;
- область связи: проект/компонент/язык/тип контента;
- что происходит при изменении source, смыслового контекста, ограничений,
  удалении или замене основного экземпляра;
- как изменение делает старое решение неактуальным и возвращает его на рассмотрение;
- кто может менять связь и как это отражается в истории;
- как чек отличает необоснованное расхождение от разрешённого исключения;
- как retry, параллельные задачи и правки не расходятся в выборе результата;
- как выполняется откат с сохранением последующих человеческих изменений.

Это не решение создать отдельную подсистему canon. Сначала следует проверить,
какие существующие сущности Weblate можно использовать. Но долговечное
представление этих решений необходимо, и его дизайн ещё не согласован.

## 9. Метрики и критерии проверки предложения

Для групп с разрешённым общим переводом предлагается строгий критерий:
ноль новых расхождений при обычном запуске, повторе задачи и дозагрузке.
Это будущий критерий, не достигнутый результат.

Для всего компонента отслеживать отдельно:

- новые необоснованные расхождения;
- подтверждённые ошибки из-за неправильного объединения контекстов;
- допустимые намеренные варианты;
- группы, потребовавшие человеческого решения, и время до принятия;
- major/critical-дефекты в явно объявленной проверенной выборке;
- сохранность approved и параллельных изменений;
- число обработанных строк и групп;
- реальные запросы, токены и стоимость.

Не обещать процент снижения до пилота на сохранённых данных. Не превращать
долю одинаковых targets в общий балл качества локализации.

## 11. Поправки к ранним формулировкам сессии

- 1 408 повторных строк сверх первых экземпляров не равны 1 408 HTTP-запросам:
  machinery использует batches. Это не измеренная экономия стоимости.
- Повторный MT-запуск не обязательно стирает approved: зависит от выбранного
  режима и реализации. Риск надо проверять конкретно, не утверждать безусловно.
- Отсутствие истинных дефектов в просмотренных blocking-check примерах не
  означает отсутствие дефектов во всей локализации.
- Совпадение 184 отдельных терминов не равно полному соблюдению терминологии.
- Одинаковый timestamp не доказывает один исторический MT-run.
- Сильный промпт/session canon может уменьшить вероятность drift, но не
  гарантирует равенство результата.
- TM-score 100 не равен человеческому approval или отсутствию конкурентов.
- API best-match не является полным списком реальных machinery suggestions.
- Две однозначные группы относятся к project-scoped exact lookup, не ко всем
  возможным источникам памяти.
- Наличие `openrouter` в project API не доказывает отсутствие глобальной TM.
- Fan-out базового machinery не доказывает source-only fan-out LLM.
- Native propagation уже включена, но ограничена source+context.
- Проверки поставщиков документальные; гарантии числа LLM HTTP-запросов не
  установлены.

## 12. Точка продолжения

Сначала согласовать желаемую политику повторов и исключений для реального
содержимого проекта, а не начинать с отключения `repeat-drift` или импорта
всех текущих вариантов как «канонической» памяти.

Затем подготовить ограниченный пилот на сохранённых данных: отделить
доказанно общие сообщения от контекстных вариантов, проверить интерфейс
решения по группе и определить долговечное представление policy/master/override.
Только после этого писать план изменения MT-пути с точными файлами,
контрактами, проверками и границами rollout.

Перед кодом требуется утверждение плана по правилам репозитория. Отдельно
требуется разрешение на production-изменения и любые платные генерации.
