# Что выводится из лок-кита автоматически

Дата: 2026-08-28. Замер под вопрос: достаточно ли ссылки на стор и текущих
лок-китов, чтобы собрать базу знаний по игре.

Материал: `analysis/data/heart-abyss-hub-1-units-9lang.tsv` — реальный
диалоговый кит Heart of the Abyss, 396 строк данных, колонки
`context` + 10 локалей (`ru` источник, плюс de, en, es, fr, it, ja, ko,
zh_Hans, zh_Hant). Колонок примечаний, лимитов и спикера в ките нет.

## Структура

| Замер | Значение |
|---|---|
| Строк данных | 396 |
| Локалей | 10 (ru источник) |
| Кандидатов в термины (≤30 символов, без плейсхолдеров) | 180 (45%) |
| Строк с плейсхолдерами или разметкой | 0 (0%) |
| Строк, идентичных во всех локалях (сигнал DNT) | 0 |
| Сегментов в ключе | 4 у 237 строк, 5 у 159 |

Второй сегмент ключа — это **спикер или локация**:

| Сегмент | Строк | Что это |
|---|---|---|
| `fisherman` | 146 | персонаж |
| `teahouse` | 76 | локация |
| `ramen` | 45 | локация |
| `scrappy` | 39 | персонаж |
| `asuna` | 38 | персонаж |
| `first` | 29 | сцена |
| `bathman` | 11 | персонаж |
| `guard` | 7 | персонаж |

Вывод по структуре: пространство имён ключа даёт `kind` для персонажей и
локаций и группировку по сценам. Дизайн
`docs/product/designs/2026-08-28-universal-game-context-db.md` оставляет `kind`
полем ручного заполнения; замер показывает, что его можно предзаполнять из
ключа, и в этой части дизайн стоит уточнить.

## Согласованность собственных имён

Проверены два имени, встречающиеся в тексте.

`Леон`, 5 строк:

| Локаль | Передача | Стабильность |
|---|---|---|
| en | Leon | 5/5 |
| de | Leon | 5/5 |
| ja | レオン | 5/5 |
| ko | 레온 | 5/5 |
| zh_Hans | 莱昂 | 5/5 |
| zh_Hant | 雷恩 | 5/5 |

Внутри каждой локали стабильно, но zh_Hans и zh_Hant выбрали разные имена.

`Хадзуо`, 7 строк:

| Локаль | Передача | Стабильность |
|---|---|---|
| en | Hazuo | 7/7 |
| de | Hazuo | 7/7 |
| ja | ハズオ | 7/7 |
| ko | 하즈오 | 7/7 |
| zh_Hans | `哈祖欧` ×2, `哈祖奥` ×4, `一夫` ×1 | **3 варианта** |
| zh_Hant | 葉月 | 7/7 |

Разбор zh_Hans по строкам:

| Ключ | Передача |
|---|---|
| `hub1_first_1_24` | 哈祖欧 |
| `hub1_teahouse_1_31` | 哈祖奥 |
| `hub1_scrappy_1_12` | 一夫 |
| `hub1_scrappy_1_19` | 哈祖欧 |
| `hub1_teahouse_2_38` | 哈祖奥 |
| `hub1_scrappy_2_11` | 哈祖奥 |
| `hub1_scrappy_2_18` | 哈祖奥 |

`一夫` — это не вариант транскрипции, а другое имя (японское Kazuo).
zh_Hant при этом внутренне согласован на `葉月` (Hazuki), то есть выбрал
японское имя вместо фонетической передачи — принципиально иное решение, чем в
zh_Hans.

Английский плывёт в описании того же персонажа: `у барахольщика Хадзуо`
переведено то как `Hazuo the junk dealer's` (`hub1_teahouse_2_38`), то как
`Hazuo's Thousand Trinkets Shop` (`hub1_teahouse_1_31`) — название лавки в
источнике отсутствует.

Итог: на одно имя в одном файле кит даёт **пять конфликтующих «отгруженных»
переводов**. Автоматический экстрактор терминов из такого кита производит не
глоссарий, а отчёт о конфликтах.

## Что кит не даёт вообще

- `definition`. Из кита видно, что `Хадзуо` существует и к нему обращаются в
  сценах `scrappy`; что он барахольщик, лежит только в прозе диалога и ни в
  одном поле не выражено.
- Алиасы и сленг игроков. Структурно отсутствуют: сленг живёт в сообществе, а
  не в ките. Источник для него — корпус фидбека.
- Лимиты символов, шрифты, слои креативов. В этом ките нет ни одной такой
  колонки.
- Голос и тон, известные проблемы, контакт поддержки.

## Следствия для дизайна

1. Ключевое решение дизайна — «термины текут из Weblate, а не в него» —
   подтверждено замером, а не выведено: кит несогласован, и загрузка его прямо
   в базу знаний импортировала бы дефекты как факты.
2. Извлечение терминов из кита нужно ставить как **очередь ревью с отчётом о
   конфликтах**, а не как импорт. Конфликт вида «одно имя, N передач в одной
   локали» — самый ценный артефакт этого прохода.
3. `kind` для персонажей и локаций можно предзаполнять из пространства имён
   ключа; дизайн следует поправить в этой части.
4. Расхождение zh_Hans и zh_Hant по обоим именам — не обязательно ошибка, но
   решение, которое сейчас никто не принимал явно и никто не видит.

## Воспроизведение

Замер сделан на `analysis/data/heart-abyss-hub-1-units-9lang.tsv` чтением
через `csv.DictReader` с разделителем табуляции; подсчёты: длина и наличие
плейсхолдеров по регулярному выражению `\{[^}]*\}|%[A-Za-z_]+%|<[^>]+>|\$`,
согласованность имён — подстрочным поиском по колонкам локалей на
подмножестве строк, где имя присутствует в `ru`.
