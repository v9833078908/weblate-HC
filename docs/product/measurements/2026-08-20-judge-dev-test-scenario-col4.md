# Тест-сценарий LLM-судьи на dev: CoL4 / common / tr

Ручной приёмочный сценарий для фичи из
`docs/llm-first/plans/2026-08-13-01-judge-verdict-core.md`.
Цель прогона - убедиться на живом компоненте, что судья работает как задумано,
и увидеть его границы. Прод не затрагивается: судья там выключен.

Объект: <http://localhost:3001/projects/col4/common/tr/> (`po-mono`, источник
`ru`, 82 строки, все переведены, `state=20`). Проект - Choice of Life: Samosbor.
Глоссарий проекта: `col4/glossary` (TBX, источник `ru`, 765 записей).

Откат в конце файла.

## Чекпойнт 0. Судья виден в форме

<http://localhost:3001/projects/col4/common/tr/> - блок «Автоматический перевод».

Должно быть:

- в списке «Режим автоматического перевода» пятый пункт **«Add as translation
  with an LLM judge»** (строка ещё не переведена в ru-локали - это ожидаемо);
- под описанием две серые строки: «The current filter matches N strings» и
  «A judge run costs in the worst case up to M LLM requests»;
- жёлтая плашка «This translation already has judge verdicts...» - следствие
  дымового прогона;
- чекбокс «Overwrite the existing translation».

Известный дефект (уже в плане 2, не баг этой ветки): счётчик показывает **0
strings**, потому что считает жёстко `state:<translated`, а не введённый фильтр.
На полностью переведённом компоненте цифра всегда 0 и оценка запросов - тоже 0.
Не ориентируйтесь на неё в этом прогоне.

Если режима в списке нет - проверьте, что вы под суперюзером и что у проекта
включён review.

## Чекпойнт 1. Аудит существующих переводов (overwrite off)

Это основной кейс: судья не переписывает человеческие переводы, а выносит по ним
вердикт.

Форма:

| Поле | Значение |
|---|---|
| Режим | Add as translation with an LLM judge |
| Фильтр (`q`) | `state:>=translated AND position:>=20 AND position:<=29` |
| Источник | Машинный перевод, механизм `openrouter`, порог 80 |
| Overwrite | **выключен** |

Нажать «Применить» **кнопкой** (не через Enter в textarea - так проверяется живой
submit формы).

Что должно произойти:

1. Редирект обратно на страницу перевода, сверху сообщение о запущенной задаче с
   полосой прогресса.
2. Первые вердикты - примерно через минуту, весь батч из 10 строк - за 1.5-2.5
   минуты (2 батча × 2 seat'а = 4 запроса).
3. Счётчики переведённого **не меняются**: строки остаются `state=20`. Судья без
   `JUDGE_MAY_APPROVE` не выдаёт «одобрено», а `pass` оставляет как есть.
4. Тексты переводов **не меняются** ни в одной строке. Это главная гарантия
   режима аудита: при выключенном overwrite ни MT-фаза, ни ремонт не пишут в
   уже переведённые строки.

Проверка в шелле:

```sh
docker exec dev-docker-weblate-1 weblate shell -c "
from weblate.trans.models.judge import JudgeVerdict, active_verdict
qs=JudgeVerdict.objects.filter(unit__translation__component__project__slug='col4',
                               unit__translation__language__code='tr')
print('rows', qs.count(), 'unparsed', qs.filter(unparsed=True).count())
from collections import Counter
print(Counter(v.verdict for v in qs))
"
```

Ожидается: строк = 2 × число отсуженных юнитов, `unparsed = 0`, преобладает
`pass`, единичные `flag`. `reject` на этом наборе маловероятен.

## Чекпойнт 2. Карточка вердикта на странице строки

Открыть любую отсуженную строку, например
<http://localhost:3001/translate/col4/common/tr/?offset=1>.

Должно быть в правой колонке, **над** «Что нужно проверить»:

- карточка **«AI judge verdict»**;
- для `pass`: зелёная галочка, «Accepted», под ней строка «<модель> · N минут
  назад». Ошибок не перечисляется - их нет;
- для `flag`: флажок и «Questionable», плюс по одной строке на каждую ошибку в
  формате `категория/серьёзность (seat <модель>): описание` - описания на
  английском, это by design (их читает продюсер, не переводчик);
- для `reject`: красный крест, «Rejected» и красный бейдж **«Will not ship»**.

Под полем перевода должен быть блок **«Approximate reconstruction»** - обратный
перевод целевой строки на русский. На строке 1 это «Авторы».

Отдельно проверить: в карточке «Что нужно проверить» **не должно** быть пунктов
`judge-flag` / `judge-reject`. Судейские проверки живут только в своей карточке;
детерминированные - в своей.

## Чекпойнт 3. Навигация и фильтры

- <http://localhost:3001/search/col4/common/tr/?q=check%3Ajudge-flag> - ровно те
  строки, где коллегия дала `flag`;
- то же с `check:judge-reject`;
- строки с `pass` не попадают ни в один из фильтров.

Число совпадений должно совпасть с шелл-подсчётом из чекпойнта 1. Если фильтр
находит больше - значит проекция «поехала» относительно вердиктов, это баг.

## Чекпойнт 4. Устаревание вердикта

1. Взять строку с вердиктом (любую из отсуженных).
2. Изменить перевод: например, дописать точку в конце, сохранить.
3. Перезагрузить страницу строки.

Должно быть: карточка судьи меняется на **«Relates to a previous version»** с
пояснением, что вердикт относится к прежней версии. Строка при этом уходит из
`check:judge-flag` / `check:judge-reject` (проекция снимается на следующем
`run_checks`, который запускается сохранением).

Механика: вердикт привязан к хешу текста; изменение текста делает его stale, и
он больше не проецируется в проверки, но остаётся в истории.

## Чекпойнт 5. Критичная ошибка → «На правку» (reject)

Здесь проверяется единственная ветка, которую первый прогон на dev не увидел
живьём.

1. Открыть строку `BUG_TYPE_2`: источник `В событии {0} нет видимых ответов`,
   текущий перевод `Olay {0}'da görünen yanıt yok`.
2. Испортить смысл инверсией отрицания: заменить перевод на
   `Olay {0}'da görünen yanıt var` (было «нет ответов», стало «есть ответы»).
   Сохранить. Детерминированные проверки при этом не срабатывают - плейсхолдер
   и пунктуация на месте, так что вердикт будет чисто судейским.
3. Запустить судью с фильтром `context:BUG_TYPE_2`, overwrite выключен.

Должно быть:

- вердикт `reject` (severity `critical`, категория `mistranslation`), в карточке
  красный «Rejected» + «Will not ship»;
- **состояние строки переходит в «На правку»** (`state=10`), то есть после
  прогона она числится непереведённой в статистике;
- текст перевода при этом **не переписан** - overwrite выключен, судья только
  снял доверие;
- строка попадает в `check:judge-reject`.

Если вердикт оказался `flag`, а не `reject`, - это не поломка кода, а решение
модели; повторите на более грубой порче (сменить число или имя).

Проверка гейта выгрузки: временно поставить проекту
<http://localhost:3001/settings/col4/#workflow> политику коммитов «Без строк,
требующих правки» и выполнить «Зафиксировать» в компоненте. Отклонённая строка
не должна попасть в файл `tr.po`:

```sh
docker exec dev-docker-weblate-1 sh -c "grep -A3 BUG_TYPE_2 /app/data/vcs/col4/common/tr_TR.po"
```

После проверки политику вернуть в «Все строки».

## Чекпойнт 6. Ремонт (overwrite on)

Ремонтная петля работает только по «писаемым» строкам: пустым, «на правку» или
любым при включённом overwrite.

1. Оставить строку `BUG_TYPE_2` в состоянии «На правку» после чекпойнта 5.
2. Запустить судью с фильтром `context:BUG_TYPE_2`, overwrite **включён**,
   механизм `openrouter`, порог 80.

Должно быть:

- фаза 1: строка перезаписывается машинным переводом и ставится «на правку»;
- фаза 2: судья оценивает новый текст; при `reject` делается **одна** попытка
  ремонта (`JUDGE_MAX_REPAIR_ATTEMPTS=1`), в БД появляется второй раунд с
  `attempt=1`;
- итоговый текст - осмысленный турецкий перевод с отрицанием на месте, состояние
  `state=20`, если последний вердикт `pass`/`flag`.

```sh
docker exec dev-docker-weblate-1 weblate shell -c "
from weblate.trans.models.judge import JudgeVerdict
qs=JudgeVerdict.objects.filter(unit__context='BUG_TYPE_2', unit__translation__language__code='tr').order_by('timestamp')
for v in qs: print(v.attempt, v.seat, v.max_severity, v.verdict, v.errors[:1])
"
```

Ожидается два раунда: `attempt=0` с `critical`, `attempt=1` с меньшей
серьёзностью.

## Чекпойнт 7. Валидация формы: overwrite только для судьи

Выбрать режим «Добавить как перевод», поставить галочку «Overwrite the existing
translation», применить.

Должно быть: форма не отправляется, у поля ошибка **«Overwrite applies only to
the LLM judge mode»**. Это защита от того, чтобы обычный автоперевод молча
переписал отсуженные строки.

## Чекпойнт 8. Прогресс переживает перезагрузку

1. Запустить прогон на 10-20 строках.
2. Пока полоса прогресса идёт, нажать F5 два-три раза.

Должно быть: после каждой перезагрузки полоса **одна** и она продолжает
обновляться до конца задачи (раньше прогресс терялся, а сообщение о задаче
дублировалось).

## Чекпойнт 9. Транспортный сбой не превращается в мнение

Проверяется, что недоступная модель даёт `unparsed`, а не «всё хорошо».

```sh
docker exec dev-docker-weblate-1 weblate shell -c "
from django.test import override_settings
from weblate.auth.models import User
from weblate.trans.models import Component
from weblate.trans.judge_loop import run_judge_batch
u=User.objects.get(username='admin')
t=Component.objects.get(project__slug='col4', slug='common').translation_set.get(language__code='tr')
units=list(t.unit_set.filter(context='DATA_LOADING'))
with override_settings(JUDGE_MODEL_SEAT_2='nonexistent/model-xyz'):
    res=run_judge_batch(units, writable_ids=set(), user=u)
for unit in units:
    print(unit.context, res[unit.id].verdict, res[unit.id].max_severity)
"
```

Должно быть: seat 2 записан как `unparsed`, но вердикт коллегии берётся у seat 1
(нераспарсенный голос не понижает и не повышает раунд). В UI строка при этом не
меняет состояние. Если бы `unparsed` читался как `pass`, это была бы ошибка
класса «деньги потрачены, дефект пропущен».

Дополнительно: если **все** seat'ы не ответили, карточка на странице строки
показывает «Judge's answer was not parsed», а прогон добавляет предупреждение
«N strings were left unjudged».

## Чекпойнт 10. Деньги и атрибуция

```sh
docker exec dev-docker-weblate-1 weblate llm_usage_report --project col4 --days 1
```

Должно быть: строки с моделями обоих seat'ов, непустой `col4` в проекте
(атрибуция починена в этой ветке), суммарная стоимость. Ориентир по дымовому
прогону: 3 строки = 4 запроса = $0.0069, причём почти вся сумма - reasoning-токены
deepseek. Расход определяется не числом строк, а всплесками reasoning, поэтому
экстраполировать линейно нельзя.

## На что смотреть критически

1. **Промпт зашит под другую игру.** `weblate/trans/judge_prompts/verdict.txt`
   объявляет судье «пошаговая стратегия про Вторую мировую, формальный
   военно-политический регистр - это норма». CoL4 - постапокалиптический
   квест-карточник. Ждите ложных `major` по регистру и «правильным» именам
   (на прошлом прогоне модель именно так забраковала корректное «Сэр»).
   Каждый `flag` в этом прогоне стоит прочитать как гипотезу, а не приговор.
2. **Разметка CoL4.** Строки используют `$` как перенос и Unity-теги
   (`<size=60>`). Проверьте, не начнёт ли судья считать их ошибками: в промпте
   про `$` ничего не сказано, а детерминированные проверки `game-line-break` и
   `game-markup` уже закрывают эту зону. Дубли из судьи - шум.
3. **Счётчик и дефолтный фильтр** (чекпойнт 0) - известные разрывы, закрываются
   планом 2 вместе с фильтром `has:judge`.
4. **Метка режима не переведена** в ru-локали.

## Откат dev-стенда

```sh
# судья выключается удалением локального override и полным пересозданием
rm dev-docker/docker-compose.override.yml
WEBLATE_PORT=3001 ./rundev.sh

# вернуть review-флаг проекта, если он был не нужен
docker exec dev-docker-weblate-1 weblate shell -c "
from weblate.trans.models import Project
p=Project.objects.get(slug='col4'); p.translation_review=False; p.save(update_fields=['translation_review'])"

# убрать вердикты прогона
docker exec dev-docker-weblate-1 weblate shell -c "
from weblate.trans.models.judge import JudgeVerdict
print(JudgeVerdict.objects.filter(unit__translation__component__project__slug='col4').delete())"
```

Вердикты можно и оставить: они не влияют на выгрузку, а проекции проверок
снимаются автоматически, как только текст строки меняется.
