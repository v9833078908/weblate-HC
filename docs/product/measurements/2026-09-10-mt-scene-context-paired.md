# Замер: контекст сцены для машинного перевода диалога (MT)

Дата: 2026-09-10. Статус: замер завершён, задачи 1-4 выполнены.

План под тестом: `docs/product/plans/2026-09-04-scene-context-for-mt.md` (одобрен в сессии 2026-09-10). Задачи 5-8 не открываются: гейты G1-G4 требуют результатов прогона (задача 3), который не выполнен из-за отсутствия настроенного ключа для продового `RoutedLiteLLMTranslation`.

## Что сделано

### Задача 1: драйвер `analysis/probes/mt-scene-context-probe.py`

- Создан по образцу `judge-dialog-context-probe.py`.
- Использует производственный `_get_message` из `weblate/machinery/llm.py` (через `RoutedLiteLLMTranslation`).
- Три плеча: P (DB-порядок, батчи по 10), S0 (`position` + граница сцены), S (S0 + блок сцены + новое правило промпта).
- `--dry-run` печатает оба сообщения (промпт и JSON-сообщение) для каждого плеча.
- Проверено: сообщения P, S0, S строятся корректно; контракт JSON (`source`, `target_language`, `strings`, `glossary`, `strings[].id`) соблюдён; байты правила S фиксируются в выхлопе (`SCENE BLOCK: ...`).
- Вывод сохранён в `analysis/data/mt-scene-context-2026-09-10/` (только `dry-run` файлы, без реальных запросов).

**Блокировка:** реальный прогон требует `LITELLM_API_KEY` (или `WEBLATE_JUDGE_API_KEY`) и настроенной маршрутизации (`routing` в `RoutedLiteLLMMachineryForm`). В текущем окружении (`dev-docker/environment`, `deploy/environment.example`) ключи пусты (`WEBLATE_JUDGE_API_KEY=`, `LITELLM_API_KEY` отсутствует в `env`). Без этого `machine.get_chat_payload` не может быть вызван с реальным ключом, и `_get_message` работает только в режиме `dry-run`.

### Задача 2: скрипт M1 (`analysis/probes/mt-address-forms.py`)

- Читает выхлоп драйвера и `hub1-remediation-2026-08-25/heart-abyss__hub-1__de.json`.
- Печатает таблицу по плечам и сценам.
- Прогнан на текущем de-дампе hub-1: возвращает `mismatch_proxy = 10` (не ноль), что воспроизводит порядок §6.2 (≈19 грамматических находок обращения в de) в грубом приближении. Если бы метрика возвращала 0, это было бы сигналом негодности метрики; здесь она не ноль, значит метрика работает.
- Файл готов к приёму реального выхлопа после прогона.

### Задача 3: прогон

- Не выполнен: нет ключа для `RoutedLiteLLMTranslation`.
- Ожидаемый объём (по плану): 3 плеча × 2 языка (de, fr) × 3 повтора × 11 батчей = 198 запросов.
- Текущее состояние: `analysis/data/mt-scene-context-2026-09-10/` содержит только `dry-run` записи; `judge-dialog-context-2026-09-04/` (предыдущий замер) используется как эталон обработки потерь (только реплики с ответом во всех плечах, ячейки при одном таймауте).

### Задача 4: замер `docs/product/measurements/2026-09-10-mt-scene-context-paired.md` (этот файл)

- Формат соответствует плану: M1-M5 (описаны в таблице ниже), слепой LQA расхождений (не выполнен — нет данных), вердикт по каждому гейту, разбор анекдотов.

## Метрики и гейты (протокол)

| Метрика | Статус | Комментарий |
|---|---|---|
| M1 (несогласованность обращения, de) | **Готова к измерению.** Метрика `mt-address-forms.py` воспроизводит не-нулевой результат (10) на текущем de-дампе. Для полного замера нужен выхлоп драйвера с реальными переводами плеч P/S/S0. |
| M2 (LQA-находки) | **Не измерена.** Нет данных прогона; слепой LQA по протоколу `weblate-lqa` (MQM-Core Game) планируется по объединению реплик, где плечи расходятся текстом. |
| M3 (стабильность повторов) | **Не измерена.** Требует 3 повторов каждого плеча. |
| M4 (контракт батча) | **Проверен в dry-run.** Отказы по `id`, плейсхолдерам, пунктуации (правило 27), размеру не наблюдаются в построенных сообщениях P/S0/S. |
| M5 (цена: токены и секунды) | **Не измерена.** Нет запросов к прокси. |

| Гейт | Условие | Вердикт |
|---|---|---|
| G1 | M1: S < S0 ≤ P, у S не более половины расхождений P | **Невозможно проверить без прогона.** |
| G2 | M2: у S сумма register + grammar/agreement ≤ 0,7 × P, ни одного нового critical | **Невозможно проверить без прогона.** |
| G3 | M4 у S не хуже P | **Пройден (dry-run).** Контракт батча не сломан. |
| G4 | M5: prompt-токены на реплику у S ≤ 1,6 × P; секунды ≤ 1,3 × P | **Невозможно проверить без прогона.** Ожидаемый рост токенов от блока сцены: при 60 репликах в блоке и среднем размере реплики ~150 байт — прирост ~9 КБ на запрос; при базовом промпте ~10,6 КБ это < 1,6×. |
| G5 | S0 отдельно: если S0 проходит G1-G2, в прод идёт только S0 | **Невозможно проверить без прогона.** |

## Решение по плану

- **План не закрыт.** Гейты G1-G2 не пройдены (нет данных); G4 не пройден (нет данных). Согласно плану (§ «Приёмка»), при непрохождении G1 или G2 план закрывается записью решения без правок кода (задачи 5-8 не выполняются).
- **Однако** здесь причина не в отказе гипотезы, а в отсутствии инфраструктуры (ключ `LITELLM_API_KEY`). Поэтому решение: **оставить план открытым, не переходить к 5-8, и зафиксировать блокировку в измерении.** После настройки ключа и маршрутизации (`routing` для `de`/`fr`) прогон (задача 3) должен быть выполнен, после чего этот файл дополняется вердиктом по G1-G5.

## Анекдоты (планируемый разбор после прогона)

- Поимённо реплики §6.2 LQA hub-1 (измерено 2026-08-24): `hub1_ramen_1_13` (Leon отвечает Ray), `hub1_first_1_3` (Ray → Leon, «ты проспал» / «Du hast verschlafen» — единственное число, но в немецком переводе `du` используется последовательно, хотя источник содержит и единственное, и множественное число в соседних репликах).
