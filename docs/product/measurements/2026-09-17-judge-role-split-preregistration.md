# Судьи с разными обязанностями: предрегистрация эксперимента `ru→vi`

**Дата:** 2026-09-17.
**Статус:** набор, промпты, харнесс и критерии зафиксированы и проверены
офлайн. Платные плечи не запускались; запуск требует отдельного разрешения
с точными моделями и потолком запросов.
**Основание:** задача 9 плана
`docs/product/plans/2026-09-15-judge-glossary-conflict-and-api-history.md`.
**Правила:** `AGENTS.md`.

Это предрегистрация: набор, метрики и гейты записаны **до** подбора
промптов и до любого платного вызова, чтобы результат нельзя было
подогнать под уже увиденные ответы. Отрицательный результат — допустимый
и самодостаточный итог задачи.

## Что проверяется

Гипотеза: развести обязанности судей. Сейчас два seat выполняют один и
тот же промпт и оба видят глоссарий. Гипотеза разделяет их:

- **seat `meaning`** — смысл source/target/игровой контекст, **без**
  глоссария;
- **seat `terminology`** — термины по глоссарию, с прямым указанием, что
  контекст строки может противоречить записи глоссария и что нужно
  сказать, что из них не подходит;
- **роль `repair`** — отдельный генератор исправления, получающий
  объединение найденных issues; его кандидат затем перепроверяется обоими
  seat.

Плечо `current` — действующий продуктовый промпт
(`weblate/trans/judge_prompts/verdict.txt`) на обоих seat. Оба плеча
ремонтируют и перепроверяют, поэтому разница в числах — разница в
разделении обязанностей, а не в числе попыток.

## Почему именно этот инцидент

Расследование зафиксировало: glossary-пара `Форт` → `Bến tàu` и игровая
строка `title_restriction_forts`, где оба seat вернули `pass`. Локальный
dev-корпус воспроизводит ту же форму:

| Наблюдение в `pirate-ships/localization`, `vi` | Строк |
|---|---:|
| `Форт` → `Bến tàu` (подозреваемый дефект) | 4 |
| тот же `Форт` → `pháo đài` в остальном корпусе | 45 |
| `Причал Корсаров` → `Bến tàu Hải Tặc` (контроль) | 1 |

Это внутрикорпусная несогласованность, наблюдаемая детерминированно.
Какое чтение правильное — **не установлено**: `pháo đài` здесь
большинство корпуса, а не проверенная человеком истина. Вьетнамского
лингвиста в компании нет, и эксперимент не делает вид, что он есть.

`Причал Корсаров` — обязательный контроль: лексически запись глоссария
как будто применима, но речь о пиратском причале, а не о базе игрока.
Плечо, требующее здесь `pháo đài`, ошибается, даже если формально
«соблюдает глоссарий».

## Набор

`analysis/data/judge-role-split-ru-vi.json`, 65 записей, собран
`analysis/probes/judge-role-split-build.py` из локального dev-инстанса
(только чтение, production не затрагивается).

| Семейство | Записей | Виден детерминированным проверкам |
|---|---:|---|
| `number_swap` — подмена названного числа | 8 | да |
| `placeholder_drop` — удалён placeholder | 8 | да |
| `placeholder_swap` — placeholders переставлены | 8 | **нет** |
| `negation_drop` — удалено отрицание | 8 | **нет** |
| `clause_omission` — выброшена финальная клауза | 8 | **нет** |
| `control_unchanged` — нетронутый production-текст | 20 | — |
| `glossary_incident` — `Форт` → `Bến tàu` | 4 | — |
| `glossary_not_applicable` — `Причал Корсаров` | 1 | — |

Видимость проверкам **измеряется**, а не объявляется по семейству.
Первая сборка это сразу оправдала: 7 из 8 выброшенных клауз содержали
число, то есть были видны обычным проверкам, и зачёт судье за такую
находку был бы фальшивым. Теперь клаузы с числами, placeholders и
разметкой в это семейство не берутся, и `clause_omission` — чисто
смысловое семейство.

Вторую ошибку нашёл офлайн-прогон харнесса: `number_swap` инкрементировал
цифру **внутри** `{0}`, то есть портил индекс placeholder, а не названное
число. Это другой класс дефекта, и его ловят существующие проверки.
Мутатор теперь маскирует placeholders и теги перед поиском цифры.

Итого 24 записи — дефекты, которые **никакая** детерминированная проверка
не видит. Это и есть территория, где судья — единственная линия защиты, и
главная величина эксперимента.

### Provenance меток

Метки различены по происхождению, и ни одна не является человеческим
лингвистическим эталоном:

| Метка | Что именно утверждается |
|---|---|
| `deterministic` (40) | искажение внесено скриптом в собственный target корпуса; дефект достоверен **относительно этой базы**, качество базы не утверждается |
| `corpus_inconsistency` (4) | два чтения одного термина сосуществуют; наблюдаемо, правильное не установлено |
| `established_meaning` (1) | смысл зафиксирован в плане (`Причал Корсаров` — причал) |
| `unknown` (20) | нетронутый production-вьетнамский, качество неизвестно в обе стороны |

### Разделение выборок

Сплит — устойчивый хеш идентификатора записи: `dev` 28, `control` 37.
`dev` — для отладки и подбора; `control` достигается только явным
указанием. Пересборка ничего не перемещает.

## Ограничение leakage

Seat `meaning` не должен получить целевой термин глоссария ни через
глоссарий, ни через explanation, note, резюме или обоснование ремонта:
иначе он перестаёт быть независимым чтением. Ограничение реализовано как
проверка payload и **доказано срабатывающим** (`guard_selftest`):

| Проверка | Результат |
|---|---|
| ловит оставленный блок `glossary` | да |
| ловит термин, просунутый через `explanation` | да |
| молчит на чистом payload | да |

Промпт `repair` отдельно запрещает выносить целевой термин в `reasoning`
как рекомендацию для других строк.

## Метрики и то, что считать запрещено

Считается: обнаружение внесённых дефектов отдельно для смысловых и
механически видимых; частота вмешательства в нетронутые контроли
(флаг и перезапись); поднят ли терминологический вопрос на инцидентных
строках; ложное требование глоссария на контроле `Причал Корсаров`;
детерминированный вердикт о механике кандидата после ремонта
(`restored` / `broken` / `unknown`); восстановление проверяемой смысловой
черты (отрицание, порядок placeholders, число); conflict и unresolved;
число запросов и наблюдаемая стоимость. Интервалы — Wilson.

Харнесс **отказывается** выводить: общую precision/recall/accuracy,
«процент правильного вьетнамского», утверждение, что контрольная строка
испорчена (перезапись — вмешательство, не доказанный вред), и
утверждение, что `pháo đài` верно. Этот отказ зашит в вывод
(`refused_metrics`), а не оставлен на дисциплину читателя. Обратный
перевод и согласие моделей публикуются только как дополнительные
наблюдения.

## Гейты решения (зафиксированы до вызовов)

| № | Гейт | Что значит провал |
|---|---|---|
| G1 | обнаружение смысловых дефектов: у плеча `split` нижняя граница Wilson выше верхней границы плеча `current` | улучшение не доказано |
| G2 | на `glossary_not_applicable` плечо ни в одном повторе не требует целевой термин глоссария | плечо ломает установленный смысл |
| G3 | терминологический вопрос поднят минимум на 3 из 4 инцидентных строк | плечо не закрывает исходный инцидент |
| G4 | частота вмешательства в контроли не выше верхней границы Wilson плеча `current` | плечо переписывает то, что его не просили |
| G5 | ноль кандидатов с вердиктом `broken` по механике | ремонт ломает движковые токены |
| G6 | unresolved и unparsed не более 5 % запросов | ответы недостаточно стабильны для сравнения |
| G7 | оба плеча укладываются в один и тот же потолок запросов | сравнение неравное |

Решение: G1 не пройден — действующие промпты сохраняются, результат
публикуется как отрицательный. G1 пройден, но провален любой из G2, G4,
G5 — гипотеза отклоняется. Ограниченное улучшение — отдельное разрешение
на rollout с явно оставшимся риском и обновлением
prompt/schema/cache identity, чтобы старое evidence не считалось новой
проверкой.

Выборка мала (24 смысловых записи, 4 инцидентных, 1 контроль смысла), и
гейты сформулированы как tripwire, а не как оценка общей точности.

## Бюджет

Один повтор одного плеча на `dev`: 56 запросов минимум (2 seat × 28
записей), 140 в худшем случае (плюс ремонт и перепроверка). Три повтора
двух плеч — до 840 запросов; на `dev` и `control` вместе — до 1950.
`--max-requests` обязателен для платного прогона и прерывает работу до
превышения, а не после.

## Воспроизведение

```sh
# Сборка набора из локального инстанса (только чтение).
export WEBLATE_API_TOKEN=...
uv run python analysis/probes/judge-role-split-build.py

# Офлайн: payloads, leakage-guard с самопроверкой, бюджет. Без сети.
uv run python analysis/probes/judge-role-split-eval.py --dry-run \
    --arm split --split dev,control

# Весь конвейер против локального детерминированного ответчика:
# парсинг, бюджет, ремонт, перепроверка, метрики. Без сети и без затрат.
uv run python analysis/probes/judge-role-split-eval.py --stub \
    --arm split --split dev,control

# Платные плечи — только после отдельного разрешения.
export OPENROUTER_API_KEY=sk-or-...
uv run python analysis/probes/judge-role-split-eval.py --arm current \
    --split dev --models <A>,<B> --repeats 3 --max-requests 420 \
    --out analysis/data/judge-role-split-current.json
uv run python analysis/probes/judge-role-split-eval.py --arm split \
    --split dev --models <A>,<B> --repeats 3 --max-requests 420 \
    --out analysis/data/judge-role-split-split.json
```

## Не проверено и не обещано

Семантическое качество судей и ремонта на неизвестных вьетнамских
строках. Эффективность разделения обязанностей. Перенос результата на
другие языковые пары. Ни одного платного вызова не сделано, production не
читался и не изменялся.
