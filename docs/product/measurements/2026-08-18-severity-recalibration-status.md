### Почему корпус не с `/tmp`

Прежний прогон держал 124 юнита в `/tmp/st2_zh_units.jsonl`, который
пропал; из-за этого корпус пришлось тянуть заново. Теперь он лежит в
`analysis/data/` и закоммичен. Прод не менялся с 2026-08-14 (исправленная
выгрузка отдана файлом, не записана в Weblate —
`docs/operations/plans/2026-08-14-st2-zh-corrected-export.md`, раздел «Что не
сделано»), поэтому свежий read-only pull воспроизводит исходные целевые
строки, судившиеся тогда.

### Офлайн `check_glossary`: как получены 5 срабатываний

Детерминированный матчер по 30 терминам с word-boundary по источнику
(зеркало `attach_glossary`) и допуском коротких форм 省 / 级 (правка
гранулярности из `docs/llm-first/plans/2026-08-14-intra-component-consistency-check.md`,
задача 1). Даёт ровно {24160, 24161, 24179, 24240, 24241}, ноль ложных.
Расхождение с планом на 24221: там термин `уровня→级别`, но 级别 покрыт
допуском 级, а блокирующий дефект 24221 — инверсия ролей плейсхолдеров,
принадлежащая судье, не глоссарию. Расхождение для замера несущественно.

## Блокер: `openrouter.ai` не резолвится в этой среде

С хоста и из dev-контейнера:

```text
openrouter.ai         → No address associated with hostname
github.com            → 140.82.121.3        ok
google.com            → 209.85.233.138      ok
l10n.herocraft.com    → отвечает           ok
hcbifrost.herocraft.com → 89.19.213.124     ok
```

Блок точечный по `openrouter.ai`. Прогон 2026-08-14 ходил в OpenRouter
напрямую «с хоста» — другое состояние сети. Ключ OpenRouter из dev-настройки
машинерии `openrouter` валиден (`sk-or-v1-…`, base_url `openrouter.ai/api/v1`),
но ни один вызов не проходит. Единственная достижимая LLM-поверхность —
шлюз LiteLLM `hcbifrost` — требует chat-ключа, которого нет, и не
гарантирует те же модели; смена модели ломает сопоставимость (плечо A
обязано воспроизвести baseline на `deepseek-v4-pro` + `qwen3-235b`).

Поэтому две тратящие стадии — разметка 124 строк (~$0.30) и прогон плеч
A/B/C ×5 ×2 судьи (~$1.02) — из этой среды не исполняются.

## Runbook возобновления

Рекомендуемый путь — **прогон через VPS** (уже санкционированный маршрут:
`analysis/probes/col4-fr-monitor.sh` достаёт ключ и ходит в OpenRouter через
прод-контейнер `hcgameloc-weblate-1`): не нужен новый доступ, модели те
же, read-only к прод-данным, трата в рамках $4. Альтернатива — открыть
egress на `openrouter.ai` в этой среде. Шлюз `hcbifrost` — только если
его список моделей содержит `deepseek/deepseek-v4-pro` и
`qwen/qwen3-235b-a22b-2507` под теми же ID.

Аннотаторы — **не из семейств коллегии** (не deepseek, не qwen):
например `anthropic/claude-sonnet-5` и `openai/gpt-5.4`.

```sh
export OPENROUTER_API_KEY=...   # из dev Setting openrouter или прод

# 1. Разметка 124 строк на none/minor/major/critical двумя не-семейными
#    моделями; выход — st2-zh-groundtruth.json {unit_id: {severity, reason, annotator}}.

# 2. Прогон плеч, оба судьи, n=5:
for arm in A B C; do
  for m in deepseek/deepseek-v4-pro qwen/qwen3-235b-a22b-2507; do
    python3 analysis/probes/st2-zh-recalibration.py --arm $arm --model $m --repeats 5
  done
done
# сохраняет analysis/data/st2-zh-recal/arm{A,B,C}-<model>-run{1..5}.json

# 3. Скоринг: медиана+разброс REAL/FP на знаменателе 14 дефектов;
#    матрица severity (судья × разметка) на 124; шумовой пол n=5;
#    R0-R3 к медианам. Результат — отдельный документ замеров.
```
