# План: внутрикомпонентная согласованность — включить глоссарный чек

Дата: 2026-08-14. Статус: **не начат.**

Закрывает строку «Чек внутрикомпонентной несогласованности» из
`docs/LLM-first/2026-08-13-phase0-measurements.md`.

Основание — три измерения, а не два, как в первой редакции:

- **Трек C фазы 0.** На `col4/data/fr` **84 из 146** групп с одинаковым
  источником (57.5%) переведены по-разному, и стоковый чек
  `inconsistent` не пометил **ни одной**.
- **Прогон zh_Hans без глоссария.** Из шести дефектов, пропущенных
  коллегией, три — чисто терминологические. Судья видит строку по одной
  и к межстрочному дрейфу слеп по построению.
- **Прогон zh_Hans с глоссарием 2026-08-14.** Глоссарий в руках судьи
  **снимает 8 ложных тревог, но глушит структурное чутьё** — три строки
  словесной каши (24180-24182) qwen перестаёт замечать, потому что
  видит «все термины на месте». Recall с глоссарием в промпте: 73%
  против 100% без него. **Глоссарий — правильный инструмент, но не в
  руках судьи.**

Отсюда архитектурное решение: глоссарный чек работает детерминированно,
**до** судьи и **отдельно** от него. Судья не получает глоссарий в
промпте.

## Что уже есть и не требует кода

- `GlossaryCheck` (`weblate/checks/glossary.py:24`, `check_id:
  check_glossary`, `default_disabled = True`) — подстрочное совпадение
  для языков без пробелов, включая китайский.
- Глоссарий `summer-glossary`: **30/30 терминов**, `zh_Hans` переведён
  полностью. Среди них ровно спорные: `конвой→商队`, `ход→回合`,
  `штурм→进攻`, `оборона→防御`, `уровень→等级`, `провинция→省份`,
  `Боевой путь→征战历程`, `Мины→地雷`.
- На компоненте `summer-update` чек не включён:
  `check_flags = 'max-length:100, ignore-source-max-length'`,
  `enforced_checks = []`.

Детерминированный проход (приближение логики `GlossaryCheck`) даёт
**11 строк**:

| Настоящие — 6 | Артефакты гранулярности — 5 |
|---|---|
| 24240, 24241 `конвой→车队` вместо `商队` | 24137, 24138 `级` вместо `等级` |
| 24221 `уровня→级别` вместо `等级` | 24246 `升级` вместо `等级` |
| 24160, 24161 `ход→天` вместо `回合` | 24158, 24219 `省` вместо `省份` |
| 24179 `штурма→突袭` вместо `进攻` | |

Точность: 55% (вдвое выше коллегии судей без глоссария — 28%).
Цена: ноль. Время: доли секунды. Воспроизводимость: абсолютная.

Артефакты — одно явление: глоссарий хранит полную форму, перевод
использует нормативное китайское сокращение (`省份` → `省`, `等级` →
`级`). Это лечится вариантами термина, а не правкой строк.

## Открытые дефекты, которые глоссарный чек не закроет

- 24190 `防御工事惨败` — в цели есть `防御工事`, внутри которого
  подстрока `防御`; чек считает термин соблюдённым и молчит.
- 24200 `幸存国家 {0}` — глоссарного термина в строке нет.
- 24183, 24184 `我军损失` для «Получено урона» — термина `урон` в
  глоссарии нет.
- 24180-24182 — словесная каша; глоссарный чек проходит (все термины
  на месте), и поэтому **не должен отключать судью**.

Именно эти четыре класса остаются судье — и именно поэтому судья
**не должен получать глоссарий**: иначе он, как qwen в прогоне, увидит
«термины на месте» и пропустит структурный дефект.

## Задача 1. Включить `check_glossary` и починить гранулярность

Кода не требует. Глоссарий наполнять не надо — он уже полон.

### Step 1: Варианты терминов

Добавить в `summer-glossary` варианты с флагом `read-only` для
сокращённых форм, чтобы чек принимал и `省份`, и `省`:

```
провинция → 省份
провинция → 省   (read-only)
уровень → 等级
уровень → 级     (read-only)
```

Флаг `read-only` означает, что термин не участвует в подстановке при
переводе, но участвует в проверке.

### Step 2: Включить чек на компоненте

`check_glossary` выключен по умолчанию. Включить на `summer-update`
штатной настройкой чеков компонента, не правя `CHECK_LIST` глобально.

### Step 3: Измерить

Ожидаемо: 6 строк получают `check_glossary` (24240, 24241, 24221, 24160,
24161, 24179). Ложных сработок — 0 (после правки гранулярности).
Записать фактическое число.

Отдельно проверить 24144 (`МАКС→MAX`) — этот термин в глоссарии
отсутствует, и хорошо: латиница в китайском UI — не глоссарный дефект,
а судейский.

Приёмка: шесть известных юнитов помечены; ложных сработок ноль.

## Задача 2. `RepeatDriftCheck` — для col4, не для st2

На `summer-update` повторяющихся источников почти нет (2 группы, 1 с
дрейфом). Чек повторов здесь не платит. На `col4` — 84 группы с
дрейфом, и это его территория.

Задача 2 первой редакции этого плана (класс `RepeatDriftCheck` в
`weblate/checks/consistency.py`) **сохраняется**, но в план
согласованности она входит ссылкой, а не полным TDD-разворотом: детали
— в задаче 2 выше. Приоритет ниже задачи 1.
