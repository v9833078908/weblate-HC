# План: добивка слоя 0 — автофикс `!?:` и backfill-команда

Статус: **согласован 2026-08-11** (ревью quick wins из разбора
Cathedral). Основание: замер по прод-данным COL4 — модель дописала `!`
в 39 юнитах, `?` в 37, `:` в 7 (итого 83, та же форма дефекта, что у
уже отгруженного `RemoveAddedFinalStop`); исторических юнитов с
проваленными автофиксируемыми чеками ~1380 (7.5% инстанса), и автофиксы
до них не дотягиваются, потому что работают только на записи
(`weblate/trans/models/unit.py:2406`, `fix_target()`).

Обратный класс — модель **потеряла** пунктуацию источника (`!` в 67,
`?` в 13) — сознательно не трогаем: дописывание недетерминированно,
это остаётся чеку `end_stop` и судье.

Порядок: задача 1 -> задача 2, чтобы backfill прошёл одним проходом.

## Задача 1. Расширить снятие добавленного терминала на `!`, `?`, `:` (XS)

Файлы: `weblate_customization/src/weblate_customization/autofixes.py`,
тесты `weblate_customization/tests/test_autofixes.py`; после правки —
`cp -r weblate_customization/src/weblate_customization dev-docker/data/python/`.

- Условие то же, что у точки: источник **не** заканчивается терминальной
  пунктуацией, цель заканчивается на один из `!`, `?`, `:` -> снять.
  Область символов — узкая, ASCII, как в замере; CJK-эквиваленты не
  трогаем.
- **Французская пара.** `AddFrenchPunctuationSpacing` держит U+00A0
  перед `:` и U+202F перед `!`/`?`: снимать надо пару
  `[NBSP|NNBSP]? + знак` целиком, иначе в конце строки остаётся висячий
  узкий пробел. Порядок в `AUTOFIX_LIST`: снятие терминала — до
  расстановки французских пробелов, и фикс обязан быть идемпотентен к
  уже расставленной паре.
- Приёмка: тесты — `«…dépêche !»` при источнике без терминала ->
  `«…dépêche»` (пробел снят вместе со знаком); `«…код :»` -> `«…код»`;
  источник с терминалом — цель не тронута; повторный прогон автофиксов
  ничего не меняет.

## Задача 2. Management-команда `reapply_autofixes` (S)

Файлы: `weblate/trans/management/commands/reapply_autofixes.py`, тесты
в `weblate/trans/tests/test_commands.py`.

- `--dry-run` по умолчанию: печатает счётчики изменяемых юнитов по
  компонентам и примеры diff, ничего не пишет. Запись — только с
  явным `--apply`.
- Фильтры `--project` / `--component`; прогон покомпонентный —
  ~1380 записей `Change` и коммиты в VCS размазываются по управляемым
  порциям.
- Пропускаются glossary-компоненты и read-only юниты.
- Запись через `unit.translate(..., change_action=ActionEvents.AUTO)` с
  сохранением текущего state; пере-прогон чеков и `enforced_checks` на
  записи — желаемый эффект (снятые `end_stop` исчезают, настоящие
  дефекты остаются).
- Приёмка: dry-run на dev-стенде показывает ожидаемые счётчики и ноль
  записей; `--apply` на одном компоненте снимает автофиксируемые
  проваленные чеки, не меняя state и не трогая юниты без дефекта;
  повторный `--apply` — ноль изменений (идемпотентность).

## Секвенирование с судьёй

- **Трек B фазы 0 команду не ждёт**: golden set нормализуется
  автофиксами in-flight при сборке
  (`2026-08-11-phase0-schema-and-judge-calibration.md`, задача B1).
- **Прод-прогон `--apply` — предусловие первого пишущего прогона судьи
  (фаза 2)**: иначе судья тратит бюджет и очередь flag на ~1400 юнитах,
  которые код чистит бесплатно. Прод-прогон — деплой; выполняется
  только после отдельного явного согласования, покомпонентно, сначала
  dry-run.

## Вне объёма

- Восстановление потерянной пунктуации (недетерминированно — чек/судья).
- Автофиксы для CJK-пунктуации и языкоспецифичных терминалов (`hy`,
  `hi/bn/or` и т.д.) — не наблюдались в замерах.
- Изменение самих чеков (`end_stop` остаётся как есть).
