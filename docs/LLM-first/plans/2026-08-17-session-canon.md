# План: внутрипрогонный канон терминов (session canon)

Дата: 2026-08-17. Статус: **не начат, ждёт одобрения**.

**Цель:** термин, которого нет в глоссарии, должен переводиться одинаково в
пределах одного прогона автоперевода — и по итогам прогона предлагаться в
глоссарий человеку. Механизм включается флагом настройки сервиса, по
умолчанию выключен, включается пер-проектно (для теста на проде).

## Мотивация, измеренная

- На `col4/data/fr` **84 из 146** групп с одинаковым источником переведены
  по-разному; стоковый чек `inconsistent` не пометил ни одной
  (`docs/LLM-first/plans/2026-08-14-intra-component-consistency-check.md`).
- У Cathedral аналогичный механизм `first_mentions` — самый весомый
  измеренный рычаг конвейера: 23.4 % строк стадии правки закрываются
  подстановкой канона без вызова модели
  (`docs/LLM-first/2026-08-11-cathedral-localizer-analysis.md`, раздел 4.1:
  ключ `(source_lang, source_text[, semantic_tag])`, тег только для коротких
  неоднозначных юнит-токенов, подстрочный отбор терминов ≥ 3 символов,
  **до 15 пар** в секцию `Glossary / Previous Mentions`).

Три уровня дефекта:

| Уровень | Пример | Покрытие этим планом |
|---|---|---|
| A. Точный повтор источника под разными ключами | `幸存国家 {0}` | да |
| B. Короткий термин-юнит, позже входящий в длинные строки | «Урон» → «Получено урона» | да (подстрока/стем) |
| C. Термин, живущий только внутри длинных строк | — | **нет** (alignment-извлечение, вне объёма) |

## Проверенные факты кода (почему дыра структурная)

| Факт | Где |
|---|---|
| Ключ кэша переводов включает хэш построчного контекста → одинаковые источники под разными ключами переводятся независимо | `weblate/machinery/llm.py:1155-1166` |
| Propagation требует совпадения source **и** context — дрейфующие группы не видит | `weblate/trans/models/unit.py` (propagate) |
| Few-shot намеренно исключает вывод самого движка; менять нельзя | `llm.py:1265`, `:1315-1319` |
| Батч N не видит решений батчей 1..N-1: глоссарная секция строится только из БД | `llm.py:1177` (`_get_batch_glossary`) |
| Инстанс сервиса живёт один прогон автоперевода; батчи гоняются тредпулом | `weblate/trans/autotranslate.py:609-615`, `:142` |
| `_ensure/_clear_secondary_context_cache` — **call-scoped** (очистка в конце каждого `batch_translate`), для канона НЕ годится; канон = атрибут инстанса + Lock | `llm.py:417-425`, `:2611-2622`; `autotranslate.py:74` |
| Инстансы MACHINERY нигде не кэшируются глобально — instance-scoped = run-scoped | `forms.py:1309`, `autotranslate.py:613`, `machinery/views.py` |
| Настройки сервиса читаются `self.settings.get(...)`; проектные настройки перекрывают глобальные пополево | `llm.py:357-358`, `weblate/trans/models/project.py:1332-1351` |
| Валидированный ответ батча появляется на успешном выходе `_fetch_llm_batch` | `llm.py:2636` |
| Части ключа кэша, зависящие от промпта, живут в `get_translation_cache_parts`; `get_translation_cache_extra_parts` — только плюралы, `()` для остальных | `llm.py:1131-1167`, `:1107-1129` |
| Алерты компонента: dismissable, `details` JSONField — готовая поверхность для кандидатов | `weblate/trans/models/alert.py:65-78` |
| Починка по вердикту судьи — обычный вызов движка перевода через `failing_checks` | план судьи, «Три нативных механизма», п. 1; `llm.py:493-528` |

## Внешняя валидация (2026-08-17, три независимых исследования)

- Мягкая инъекция терминов в промпт поднимает и точность терминов, и общее
  качество; жёсткое навязывание хуже гибкого (WMT25 findings
  <https://aclanthology.org/2025.wmt-1.30/>, DuTerm
  <https://aclanthology.org/2025.wmt-1.112/>).
- Переиспользование собственных принятых переводов прогона как контекста —
  опубликованный работающий механизм (SELF-RAMT
  <https://aclanthology.org/2025.wmt-1.13/>, оптимум K=3); model collapse —
  про рекурсивное обучение, не про ограниченный inference-reuse
  (<https://www.nature.com/articles/s41586-024-07566-y>).
- Few-shot остаётся человеческим: качество target'ов демонстраций —
  доминирующий сигнал ICL (<https://aclanthology.org/2023.findings-emnlp.61/>).
- First-accepted-wins — норма CAT (Phrase Repetitions
  <https://support.phrase.com/hc/en-us/articles/5709708706460-Repetitions-TMS>);
  кандидаты в термбазу через человека — стандартный workflow
  (memoQ Candidates, Smartling suggested→approved); динамический контекст в
  ключе MT-кэша — прецедент Tolgee
  (<https://github.com/tolgee/tolgee-platform/commit/77c3de4fc74e3ba1ef7cccd51dd1eb257494aa0a>).
- Ни один мейнстрим-инструмент не распространяет машинный вывод внутри
  задания без гейта; наш дизайн (инъекция в промпт + обязательный вызов
  модели) консервативнее индустрии.

## Решения

1. **Флаг.** `session_canon` — `BooleanField(required=False)` в
   `LLMBasicMachineryForm` (`weblate/machinery/forms.py:469`), по умолчанию
   выключен. Чтение: `self.settings.get("session_canon")`. Включение на
   проде для теста — пер-проектной настройкой машинерии (пополевой оверрайд,
   `project.py:1332-1351`): глобальная конфигурация остаётся выключенной.
   С выключенным флагом поведение сервиса бит-в-бит прежнее (тест).
2. **Жизненный цикл.** `self._session_canon: dict[str, CanonEntry]` +
   `threading.Lock`, инициализация в `__init__`. Никакого ensure/clear:
   инстанс умирает с прогоном. Паттерн `_secondary_context_cache` не
   копировать — он call-scoped и обнулил бы канон каждые 10 строк.
3. **Ключ.** Нормализация — общий Django-free хелпер
   `weblate_customization.textkey` (NFC, casefold, вырезать плейсхолдеры
   `{0}`/`%KEY%`, схлопнуть пробелы, срезать конечную пунктуацию).
   Тот же хелпер обязан использоваться RepeatDriftCheck и гейтом
   (`docs/plans/2026-08-10-git-localization-quality-gate.md`, Task 4) —
   две реализации группировки запрещены. Дизамбигуация: для ключей
   ≤ 3 символов в ключ входит `unit.context` (приём Cathedral 4.1 —
   «m» метр vs минута).
4. **Наполнение.** На успешном выходе `_fetch_llm_batch` (`llm.py:2636`),
   только при включённом флаге: источники term-like (≤ 4 слов, ≥ 3 символов,
   есть буквенный токен, не только стоп-/служебные слова, без терминальной
   пунктуации предложения, не из одних плейсхолдеров) записываются
   first-accepted-wins. Конфликт параллельных батчей: первый записанный
   побеждает, второй логируется. Источники, уже покрытые глоссарием по тому
   же ключу, не канонизируются.
5. **Инъекция.** В `_get_batch_glossary` (`llm.py:1177`): канон-записи, чей
   ключ входит в источник юнита (подстрока; для ru-источника — стемы через
   `count_inflected`, `weblate/checks/morphology.py`), добавляются как
   `LLMGlossaryEntry` с флагом происхождения `session-canon`, **в конце**
   глоссарной секции (стабильный префикс промпта — см. комментарий
   `_get_full_glossary` о кэшируемом префиксе). Кап 15 записей на запрос
   (потолок Cathedral 4.1; ожидаемый оптимум 3-5 по SELF-RAMT/BSC),
   ранжирование: число вхождений, длина термина. Человеческий глоссарный
   термин вытесняет канон-запись с тем же ключом всегда.
6. **Кэш.** Хэш подмешанных в юнит канон-записей — новая часть в
   `get_translation_cache_parts` (`llm.py:1131`), рядом с
   `get_llm_glossary_cache_part`. Хэшируется срез юнита, не весь словарь
   (иначе рост канона инвалидирует ключи всех строк прогона). В
   `get_translation_cache_extra_parts` не класть — плюральный путь.
7. **Кандидаты в глоссарий.** По завершении прогона автоперевода
   (`autotranslate.py`, после обработки всех батчей) сервис отдаёт
   `get_session_canon_candidates()`: записи с ≥ 2 вхождениями, отсутствующие
   в глоссарии. AutoTranslate поднимает на компоненте dismissable-алерт
   `GlossaryTermCandidates` с `details` = список
   `{source, target, occurrences, language}`. Продюсер вносит принятые
   термины штатным UI глоссария (или loc-kit append), алерт закрывает.
   **Автозаписи в глоссарий нет** — совпадает с candidate-workflow всех
   исследованных инструментов. Новый прогон замещает details алерта.
8. **Наблюдаемость.** Каждая инъекция логируется (pk юнита, ключи записей);
   счётчики прогона: записей в каноне, инъекций, конфликтов — в тот же лог.

## Совместная работа с LLM-as-Judge (`2026-08-13-01-judge-verdict-core.md`)

Разделение ролей: канон — **предотвращение** дрейфа при генерации, судья —
**детекция** качества после, RepeatDriftCheck — детекция остаточного дрейфа.

- **Судья канона не видит — намеренно.** Независимость мест коллегии —
  измеренное ядро дизайна судьи (B2': переголосования снимали настоящие
  дефекты, 46 ошибочных снятий из 48). Вердикт судьи по канонизированной
  строке — единственная внутриконвейерная защита от плохого first-accepted
  рендеринга: если судья валит строку, у которой рендеринг пришёл из канона,
  это сигнал на весь канонический ключ, а не шум.
- **Починка видит канон автоматически и бесплатно.** Стадия починки — обычный
  вызов движка перевода (план судьи, нативный механизм 1): внутри того же
  прогона канон подмешается сам; в отдельном позднем прогоне канон пуст, и
  починка опирается на глоссарий, куда частые записи к тому времени внесены
  человеком из кандидатов. Ничего специально соединять не нужно.
- **Протухание вердикта не затронуто:** хэши вердикта считаются от текста
  перевода, канон меняет только промпт.
- **Кандидаты ревьюятся там же, где видна карточка «Оценка ИИ»** (задача 12
  плана судьи): продюсер видит вердикты по юнитам-носителям термина в
  момент решения о глоссарии. Обогащение алерта судейской статистикой —
  возможное v2, не в этом плане.

## Не входит

- Уровень C (alignment-извлечение терминов из длинных строк).
- Прямая подстановка повторов без вызова модели (индустрия подставляет
  только человечески-подтверждённое; наш канон машинный). Возможное v2
  после замера.
- Автозапись в глоссарий; персистентность канона между прогонами.
- Изменения few-shot (`_filter_confirmed_examples`) и судейского промпта.
- UI сверх алерта (отдельные страницы, кнопки «принять термин» — v2).

## Приёмка

- Все новые тесты зелёные через `./rundev.sh test`; линт
  `uv run prek run --files <изменённые>`; mypy без новых ошибок к baseline.
- С выключенным флагом: ни одного нового запроса к БД в путях перевода,
  промпт и ключи кэша неизменны (тесты задач 3-5).
- Продовый тест: флаг включается на одном проекте пер-проектной настройкой;
  замер на живом прогоне — доля повторных групп (по `textkey`),
  отрендеренных консистентно, до/после; счётчики инъекций из лога; алерт
  с кандидатами появился и осмыслен. Решение о расширении — по этому замеру.
- Изменение прод-конфигурации — только с явного одобрения (working
  agreement: деплой отдельно от реализации).
