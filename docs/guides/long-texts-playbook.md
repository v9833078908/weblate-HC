# Плейбук: длинные тексты (2000+ знаков) в Weblate

Для продюсера, который получил от команды не подписи кнопок, а полотна: лор,
письма, брифинги миссий, описания в сторе, патчноуты, туториалы. Всё делается
мышкой, без кода.

Продолжение `docs/guides/producer-guide-weblate.md`: там общий путь «кит ->
компонент -> автоперевод -> ревью», здесь только то, что на длинных текстах
работает иначе.

## Короткий ответ

| Что за текст | Тип компонента | Как заводить |
|---|---|---|
| Длинная строка, которую движок достаёт по ключу (описание миссии, письмо, лор-запись в таблице кита) | **Тот же формат, что у остального кита** (моноязычный PO из лок-кита). Формат менять не надо | Отдельным компонентом: :guilabel:`Отправить файлы перевода` с отдельной таблицей |
| Цельный документ, который никто не достаёт по ключу (описание в сторе, патчноут, EULA, страница туториала, лор-книга) | **`Plain text file`** - Weblate режет его на абзацы, каждый абзац становится строкой | :guilabel:`Перевести документ`, один документ = один компонент |

Развилка одна: **кто читает результат - движок по ключу или человек как
документ**. Всё остальное вытекает отсюда.

Отдельный компонент - да, почти всегда. Но не потому, что «иначе длинное не
переведётся»: причины ниже, в разделе «Зачем отдельный компонент».

## Порога «2000 знаков» в Weblate не существует

Это первое, что надо снять с повестки. В коде нет ни одной константы, которая
срабатывала бы на 2000 символах. Ограничение длины перевода считается так:

- мягкий счётчик в редакторе - `максимум(100, длина исходника x 10)`
  (`weblate/trans/models/unit.py:2644`);
- жёсткая проверка при сохранении - в десять раз больше этого счётчика
  (`weblate/trans/validators.py:25`).

Для исходника в 2000 знаков жёсткий предел получается 201 000 символов.
Упереться в него невозможно.

Ошибка :guilabel:`Translation text too long!` на длинном тексте означает не
длину, а **неправильно заведённый компонент**: моноязычный файл подключён как
двуязычный, и Weblate считает исходником не текст, а ключ. Для ключа
`quest_01_desc` (13 знаков) предел падает до 2300 символов - и перевод на 2400
знаков не сохраняется. Лечится не настройкой длины, а
:guilabel:`Одноязычный базовый файл языка` в настройках компонента. То же самое
пишет апстрим: `docs/user/translating.rst`, раздел «Translated string length».

## Что на длинных текстах ломается на самом деле

Пять честных проблем. Ни одна не про лимит.

**1. Машинный перевод режется на пачки по 10 строк.** Размер пачки зашит в код
(`weblate/machinery/llm.py:391`), продюсер его не меняет. Десять строк по 2000
знаков - это 20 000 знаков в запросе и столько же в ответе. Ответ генерируется
токен за токеном, поэтому запрос идёт долго: у движка `LiteLLM` одна попытка
живёт 55 секунд (жёсткий потолок корпоративного прокси,
`weblate_customization/src/weblate_customization/machinery.py:408`), у
`OpenRouter` - 120 секунд.

Что происходит при обрыве: Weblate не теряет строки, а делит пачку пополам и
переспрашивает, рекурсивно до одной строки
(`weblate/machinery/llm.py:2751`). Итог - переводы будут, но прогон по
компоненту длинных текстов идёт в разы дольше и дороже, чем по такому же числу
подписей. Это нормально, а не сбой. Планируйте время.

**2. Память переводов не работает.** Совпадение ищется по строке целиком.
Два письма, отличающиеся одним абзацем, для памяти - две разные строки, 0%
совпадения. На коротких строках память даёт экономию 40-60% на патчах; на
полотнах - ноль. Weblate не режет строки на предложения: в нём нет
SRX-сегментации, которая есть в Phrase, Lokalise и Trados. Единственная
сегментация в Weblate - структурная, по формату файла (см. плейбук Б).

**3. Правка исходника = перевод заново целиком.** Разработчик поправил одно
предложение в письме на 2000 знаков - строка целиком уходит в
:guilabel:`Требуется правка`, и переводить её надо целиком.

**4. Проверки и AI-судья работают по строке, а не по предложению.** Одна
потерянная цифра или один лишний `$` красит всё полотно. Найти место ошибки в
2000 знаках глазами - отдельная работа. Особенно это касается
`game-line-break`: в длинном тексте разделителей `$` десятки, и отчёт скажет
только «их число не сошлось».

**5. Таблица кита с переносами строк читается ненадёжно.** Апстрим прямо
предупреждает: автоопределение диалекта CSV ломается именно на значениях с
переносами строк (`docs/formats/csv.rst`). Для длинных текстов отдавайте XLSX
или TSV, а не CSV, либо просите команду не ставить настоящие переносы внутри
ячейки - в текстах Hero Craft перенос и так кодируется символом `$`.

## Зачем отдельный компонент

Не ради лимитов и не ради движка перевода: настройки движка (персона, стиль,
инструкции по языкам) живут **на уровне проекта** и на компоненты не делятся.
Отдельный компонент даёт четыре вещи, которых иначе нет:

1. :guilabel:`Флаги перевода` на весь компонент
   (`weblate/trans/models/component.py:795`). Для полотен это главный рычаг:
   `ignore-game-length` снимает проверку роста длины со всего компонента разом,
   `max-length:N` наоборот вводит бюджет, если текст ложится в фиксированный
   блок. На смешанном компоненте так сделать нельзя - флаг накроет и подписи
   кнопок.
2. :guilabel:`Принудительные проверки` (там же, строка 804) отдельно для
   полотен и отдельно для UI.
3. :guilabel:`Приоритет` - полотна обычно переводят позже подписей.
4. Отдельная статистика и отдельный прогон
   :guilabel:`Автоматический перевод`. Прогон по 300 длинным строкам не будет
   держать в очереди 5000 коротких.

## Плейбук А. Движок читает текст по ключу

Это случай лок-кита Hero Craft: описания миссий, письма, лор-записи лежат в той
же таблице, что и всё остальное, и движок достаёт их по ключу. **Формат менять
нельзя.** Разрезать полотно на абзацы тоже нельзя: движок ждёт один ключ - одно
значение.

1. Попросите команду отдать длинные тексты **отдельной таблицей** (или
   отдельным листом XLSX). Критерий отбора простой: строка длиннее ~300 знаков
   или содержит больше двух `$`.
2. :guilabel:`Добавить новый компонент перевода` -> вкладка
   :guilabel:`Отправить файлы перевода`, как в шаге 1 основного гайда.
   Название - «Тексты», «Лор», «Миссии»; плашка - `texts`, `lore`, `missions`.
3. :guilabel:`Настройки` -> :guilabel:`Перевод` ->
   :guilabel:`Флаги перевода`: поставьте `ignore-game-length`. Проверка
   `game-length` на исходниках длиннее 80 знаков разрешает рост только до
   1.35x; на художественном тексте это ложные срабатывания, а реального слота
   у полотна нет.
4. :guilabel:`Настройки` -> :guilabel:`Основное` ->
   :guilabel:`Приоритет`: :guilabel:`Низкий`, если полотна переводятся после UI.
5. Автоперевод запускайте **порциями**: :guilabel:`Операции` ->
   :guilabel:`Автоматический перевод`, в поле фильтра - один язык за раз. Не
   ставьте всё сразу на все языки: пачки по 10 полотен идут медленно, и очередь
   Celery будет занята часами.
6. Ревью - только с ярлыком. Поставьте ярлык до прогона (вариант А из шага 10
   основного гайда): в полотнах отличить машинный перевод от старого по глазам
   невозможно.

### Разделитель `$` в длинных текстах

В полотне разделителей десятки. Автофикс `LineSeparatorSpacing` сам уберёт
пробелы, прилипшие к `$`, но не восстановит потерянный разделитель. Если
`game-line-break` красит компонент массово - это не шум, это модель теряет
разбивку на абзацы. Лечится инструкцией в :guilabel:`Стиле перевода` проекта, а
не флагом `ignore-game-line-break`.

## Плейбук Б. Документ

Подходит, когда результат читает человек, а не движок: описание в сторе,
патчноут, лицензия, страница туториала, лор-книга в вики. Здесь Weblate умеет
то, чего нет в плейбуке А: **режет документ на абзацы, каждый абзац становится
отдельной строкой** (`docs/formats/txt.rst`). Это возвращает и память
переводов, и вменяемые проверки, и правку «изменился один абзац - переводится
один абзац».

1. Сохраните текст в `.txt` в кодировке UTF-8. Абзацы разделяются **пустой
   строкой** - именно она задаёт границу строки перевода.
2. :guilabel:`Добавить новый компонент перевода` -> вкладка
   :guilabel:`Перевести документ`.

   | Поле | Что писать |
   |---|---|
   | :guilabel:`Документ для перевода` | сам `.txt` |
   | :guilabel:`Проект` | игра |
   | :guilabel:`Название компонента` | «Описание в сторе», «Патчноут 1.4» |
   | :guilabel:`URL-плашка` | `store-description`, `patchnotes-1-4` |
   | :guilabel:`Целевой язык` | оставить пустым |

3. На следующем экране Weblate сам поставит формат `Plain text file` и
   заполнит маску. Проверьте, что :guilabel:`Одноязычный базовый файл языка`
   заполнен, - без него компонент будет прочитан как двуязычный, и вернётся
   ложная ошибка про длину.
4. Дальше всё как обычно: языки, глоссарий, автоперевод, судья.

Один документ - один компонент. Патчноут следующей версии заводится новым
компонентом, а не заменой файла: так остаётся история и работает память
переводов между версиями.

### Почему `Plain text file`, а не Markdown или HTML

- **Markdown переносит строки в выходном файле.** Параметр
  :guilabel:`Максимальная длина строки` по умолчанию 80 знаков
  (`weblate/trans/file_format_params.py:701`). Если файл потом читает движок
  или скрипт, где перенос значим, - получите разбивку, которой не просили.
  Поднять можно максимум до 1000. Берите Markdown, только если результат
  публикуется как Markdown.
- **HTML** годится, если исходник уже HTML: тогда единицей перевода становится
  элемент (`<p>`, `<li>`). Для голого текста это лишний слой.
- `Plain text file` ничего не переносит и ничего не размечает.

### Что нужно знать про документные форматы

- **Файл больше не источник правды.** Для `txt`, `markdown` и `html` правки,
  сделанные в самом файле, обратно в Weblate не читаются
  (`docs/snippets/format-database-backed.rst`). Меняете текст - меняете его в
  Weblate, а не в файле.
- **Порядок абзацев - это контекст.** Вставили абзац в середину исходника -
  контекст всех последующих сдвинулся, и переводы могут потеряться. Апстрим
  предупреждает об этом прямо. Если абзацы часто переставляют, включите
  :guilabel:`Deduplicate identical strings` в
  :guilabel:`Параметрах формата файла`: единицей станет сам текст абзаца, а не
  его позиция.
- **Формат не хранит флаги, контекст и пояснения.** Это ограничение файла, а не
  Weblate: :guilabel:`Флаги` и :guilabel:`Пояснение` у строки лежат в базе и
  работают как обычно - и глоссарий, и судья, и проверки. Просто они не
  переживут пересоздание компонента из файла.

## Таблица форматов

| Формат | Единица перевода | Когда брать | Чего опасаться |
|---|---|---|---|
| Моноязычный PO (из лок-кита) | одна строка кита целиком | движок достаёт текст по ключу | нет памяти переводов, медленный автоперевод, проверки по всему полотну |
| `Plain text file` | абзац | документ для человека | правки в файле не читаются обратно; перестановка абзацев теряет перевод |
| `Markdown file` | блок Markdown | результат публикуется как Markdown | выходной файл переносится по 80 знаков |
| `HTML file` | элемент (`<p>`, `<li>`) | исходник уже HTML | то же, что у Plain text |
| CSV | ячейка | не для длинных текстов | автоопределение диалекта ломается на переносах строк внутри ячейки |

## Чек-лист

- [ ] Ответил на вопрос: движок по ключу или документ для человека.
- [ ] Длинные тексты вынесены в отдельный компонент (в обеих ветках).
- [ ] :guilabel:`Одноязычный базовый файл языка` заполнен - иначе будет ложная
      ошибка про длину.
- [ ] Для ветки А: `ignore-game-length` во :guilabel:`Флагах перевода`
      компонента.
- [ ] Для ветки Б: формат `Plain text file`, абзацы разделены пустой строкой.
- [ ] Автоперевод запускается порциями по одному языку.
- [ ] Ярлык на строки поставлен **до** прогона автоперевода.
- [ ] Таблица кита с длинными текстами отдана в XLSX или TSV, не в CSV.

## Чего делать нельзя

- Резать полотно на абзацы, если движок достаёт его по одному ключу. Собрать
  обратно Weblate не умеет - в нём нет объединения сегментов при выгрузке.
- Ждать от Weblate сегментации по предложениям. Её нет и не планируется:
  единственная сегментация - структурная, по формату файла.
- Менять размер пачки машинного перевода. Он зашит в код и не выведен в
  интерфейс.
- Чинить :guilabel:`Translation text too long!` настройкой длины. Это симптом
  неправильной двуязычной настройки компонента.
