# Гайд продюсера: от компонента до точного машинного перевода

Пошаговая инструкция для продюсера, который работает только через веб-интерфейс
Weblate и не трогает код. Всё, что здесь описано, делается мышкой.

Все примеры - на живом проекте **CoL4** (Choice of Life: Samosbor):
<https://l10n.herocraft.com/projects/col4/>. Подставляйте свой проект вместо
`col4` и свой компонент вместо `data`.

Интерфейсные подписи приведены так, как они выглядят при русском языке
интерфейса. Часть строк пока только на английском - они так и записаны.

## Словарь на три минуты

| Термин | Что это на практике |
|---|---|
| Проект | Игра. Полка, на которой стоят все её тексты. У проекта свои настройки перевода и свой глоссарий. |
| Компонент | Один файл-источник внутри игры: диалоги, UI, описания предметов. У каждого свой формат и свой язык-источник. |
| Перевод | Один язык одного компонента, например `data/fr`. |
| Строка | Одна реплика или подпись. У неё есть ключ, исходный текст, перевод и состояние. |
| Глоссарий | Отдельный компонент-словарь проекта: термины и их утверждённые переводы. |
| Проверка | Автоматический контроль качества строки: несовпадение пунктуации, потерянный плейсхолдер и так далее. |
| Автоматические предложения | Движки машинного перевода. Наш основной - `OpenRouter`. |

Иерархия: **проект -> компонент -> перевод -> строка**.

## Что нужно до старта

1. Проект уже создан администратором. Если проекта нет - это к администратору,
   создание проектов вне зоны ответственности продюсера.
2. Файл с текстами: ZIP с файлами перевода либо таблица лок-кита CSV, TSV, XLSX.
3. Решение, какой язык в файле является исходным.

## Шаг 1. Создать компонент из файла

<https://l10n.herocraft.com/create/component/> или на странице проекта :guilabel:`Добавить` ->
:guilabel:`Добавить новый компонент перевода`.

Вкладок пять. Нужна третья: :guilabel:`Отправить файлы перевода`. Она для тех,
у кого нет git-репозитория или он не нужен.

| Поле | Обязательно | Что писать |
|---|---|---|
| :guilabel:`Translation files (ZIP) or loc-kit table (CSV, TSV, XLSX)` | да | Сам файл. |
| :guilabel:`Проект` | да | Проект, в который добавляется компонент. |
| :guilabel:`Название компонента` | да | Например «Диалоги» или «UI». |
| :guilabel:`URL-плашка` | да | Латиницей, например `dialogs`. |
| :guilabel:`Использовать в качестве словаря` | нет | Ставить только для таблицы терминов, см. шаг 6. |
| :guilabel:`Исходный язык` | да | Язык, с которого переводим. |

Как читается файл:

- **ZIP**: в именах файлов должны быть коды локалей (`fr.po`, `ja.json`).
  Weblate разложит их по языкам.
- **Таблица CSV, TSV, XLSX**: первый столбец считается столбцом ключей, если
  сам не является распознанным языком; остальные языки берутся из строки
  заголовка; переводы, которые уже есть в таблице, импортируются сразу.

Важное следствие для лок-китов Hero Craft: если в таблице нет столбца с
ключами, первым столбцом окажется язык, и он станет ключом. Чтобы русский стал
языком-источником, а не ключом, в таблице нужен отдельный столбец ключей перед
ним.

После создания Weblate ставит фоновую задачу: создаёт компонент, раскладывает
языки, считает статистику и прогоняет проверки качества. Обычно это секунды,
на больших китах - минуты. Страница компонента обновится сама.

Подробности загрузки таблиц: `docs/admin/projects.rst`, раздел
«Glossary tables from CSV, TSV, and XLSX».

## Шаг 2. Добавить целевые языки

Страница компонента -> :guilabel:`Языки` -> :guilabel:`Начать новый перевод`
(адрес `https://l10n.herocraft.com/new-lang/col4/data/`).

Языки, которые уже были в файле, добавлять не нужно - они появились сами.

## Шаг 3. Добавить новые строки, которые прислал разработчик

Разработчик передаёт пару: **ключ** (`EVENT_601_ANSWER_12`) и **текст на
языке-источнике**. Ключ - это то, по чему игра находит строку, он должен
совпадать с кодом до символа. Путь зависит от того, подключён ли компонент к
git.

Где смотреть: страница компонента -> :guilabel:`Настройки` ->
:guilabel:`Система контроля версий`. Значение `local` означает, что git-а нет
и файлы живут внутри Weblate. Любое другое (`git`, `github`, ...) - вариант А.

### Вариант А. Компонент подключён к git

Источник правды - репозиторий. Строки заводит разработчик, продюсер их только
переводит.

1. Разработчик добавляет ключ и текст в файл-источник и пушит.
2. Weblate забирает изменения: по вебхуку сразу после пуша, по расписанию либо
   вручную - страница компонента -> :guilabel:`Операции` ->
   :guilabel:`Обслуживание репозитория` -> :guilabel:`Обновить`. Там же есть
   варианты :guilabel:`Обновление с помощью слияния` и
   :guilabel:`Обновление с перебазированием`, их выбирают только по просьбе
   разработчика.
3. Новые строки появляются во всех языках как непереведённые. Дальше - обычный
   автоперевод с фильтром `state:<translated` (шаг 8).

Продюсер может завести строку и сам, интерфейсом из варианта Б, если у
компонента включено :guilabel:`Управление строками`. Тогда строка ложится в
файл-источник внутри Weblate и уезжает в репозиторий коммитом: автоматически,
если стоит :guilabel:`Отправлять при коммите` и заполнен
:guilabel:`URL для отправки в репозиторий`, иначе - кнопкой
:guilabel:`Коммит`, а затем отправкой в репозиторий. Договоритесь с
разработчиком заранее, кто заводит строки: если этого не сделать, ключ,
созданный в Weblate, и ключ, созданный в коде, разъедутся.

Отдельный случай - двуязычные форматы (например `.po` рядом с `.pot`,
XLIFF-пары). В них строки извлекаются из кода утилитой сборки, и добавленные
в Weblate строки будут потеряны при следующем обновлении. Для таких
компонентов :guilabel:`Управление строками` держат выключенным, а строки
заводит только разработчик.

### Вариант Б. Git-а нет, компонент создан из файла

Так работают компоненты, загруженные на шаге 1. Weblate сам ведёт для них
внутренний репозиторий, отдавать строки некому, поэтому строки заводит
продюсер.

Что должно быть включено в :guilabel:`Настройки` компонента (у компонентов из
лок-кита включено по умолчанию):

- :guilabel:`Управление строками` - разрешает добавлять и удалять строки;
- :guilabel:`Правка базового файла` - разрешает править файл языка-источника.

**Одна-две строки.** Открыть перевод на **языке-источнике** (например
<https://l10n.herocraft.com/projects/col4/data/ru/>) -> :guilabel:`Операции` ->
:guilabel:`Добавить новую строку перевода`.

| Поле | Что вписать |
|---|---|
| :guilabel:`Ключ перевода` | Ключ от разработчика, буква в букву |
| Текстовое поле с названием языка-источника | Исходный текст строки |
| :guilabel:`Ед. число` / :guilabel:`Мн. число` | Множественное - только если в игре у строки есть формы для разных количеств |

**Пачка строк (импорт CSV к существующим строкам).** Тот же экран ->
:guilabel:`Файлы` -> :guilabel:`Отправить перевод`, режим
:guilabel:`Добавить новые строки`. Файл заливается **на странице
языка-источника** (например `.../data/ru/`), а не на французском или другом
целевом языке. Новые ключи добавляются к существующим, ключи, которые уже есть
в компоненте, пропускаются - ничего не перезаписывается.

Файл - CSV в UTF-8 с англоязычной шапкой ровно из этих столбцов:

```text
context,source
EVENT_601,Пойдём со мной
EVENT_601_ANSWER_1,Отказаться
```

- `context` - ключ от разработчика;
- `source` - исходный текст;
- третий столбец `target` разрешён, но при загрузке в язык-источник не
  используется.

Такой файл собирается в Excel или Google Sheets за минуту: две колонки,
«Сохранить как CSV UTF-8». Шапка обязательна и именно по-английски.

Строки с пустым `source` создадут пустые исходные строки - модели нечего будет
переводить, поэтому заполняйте текст до загрузки.

**Лок-кит заливать сюда нельзя.** Таблицу с шапкой вида `key,ru,en,ja`
Weblate не понимает: он не сообщит об ошибке, отчитается «обработана 1 строка»
и создаст **пустую строку без ключа и текста**, которую придётся искать и
удалять руками. Проверено. Кит целиком заводят только как новый компонент
(шаг 1), а для добавления строк в существующий компонент пересобирают файл в
формат `context,source` выше или просят разработчика прислать `.po`.

Режим :guilabel:`Заменить существующий файл перевода` тоже добавит новые
строки, но перезапишет файл целиком: в нём должны быть и все старые строки.
Без крайней необходимости не используйте.

После добавления строка появляется во всех языках компонента как
непереведённая. Дальше - автоперевод по фильтру `state:<translated` (шаг 8).

### Что важно помнить в обоих вариантах

- Ключ задаётся один раз, при создании строки. Изменить его в интерфейсе
  нельзя: ошиблись - удалите строку и создайте заново.
- Строка добавляется на языке-источнике: у одноязычных форматов, а это все
  компоненты из лок-кита, на странице французского перевода пункта добавления
  не будет.
- Удаление строки - там же, где добавление, и оно необратимо: перевод на всех
  языках исчезнет вместе с ней.
- Сразу после добавления полезно заполнить :guilabel:`Пояснение` (шаг 7):
  для новой строки у модели нет ни контекста, ни соседних реплик.

## Шаг 4. Настроить движок перевода под свой проект

<https://l10n.herocraft.com/machinery/col4/> -> строка `OpenRouter` ->
:guilabel:`Настроить`.

Это личная настройка вашего проекта. Продюсер соседней игры правит свою
страницу, ваши тексты он не заденет.

Три поля, которые уходят в запрос к модели:

| Поле | Что это | Пример |
|---|---|---|
| :guilabel:`Личность переводчика` | Кто переводит и что за продукт | `You translate narrative dialogue for a dark fantasy game. Preserve each speaker's voice, including profanity.` |
| :guilabel:`Стиль перевода` | Как звучит текст, что запрещено | `Colloquial, grim, concrete. Never soften profanity.` |
| :guilabel:`Инструкции для конкретного языка` | Правила под конкретный язык, JSON | `{"fr": "Обращение на vous везде, включая реплики NPC.", "ja": "Плейн-форма для внутренних мыслей героя."}` |

Правила для JSON-поля: это объект вида «код языка - текст», код должен
существовать в Weblate, до 1000 символов на язык. Ошибка в JSON не даст
сохранить форму и покажет, что именно не так.

**Ключ API, URL и таблицу моделей не трогайте.** Форма показывает их
заполненными, потому что отображает итоговую настройку, включая унаследованную
от инстанса. При сохранении проект запоминает только то, что вы реально
изменили; ключ и модели останутся общими и продолжат обновляться
централизованно.

Право на эту страницу - :guilabel:`Редактирование проекта`. Нет доступа - к
администратору.

### Универсальная «Личность переводчика» для игр Hero Craft

Заготовка на всю студию, снята с рабочей конфигурации CoL4 (приложение А) и
обобщена. Скопируйте её в поле :guilabel:`Личность переводчика` своего проекта
и замените три места в квадратных скобках. Остальное менять не нужно: это
одинаково верно для любой нашей игры.

```text
You are a senior game localization specialist working on "[НАЗВАНИЕ ИГРЫ]",
a [ЖАНР: narrative choice-based / mid-core strategy / arcade] mobile game
published by HeroCraft for Android and iOS. [ЯЗЫК ОРИГИНАЛА, обычно Russian]
is the original language of the script and your source.

You have shipped mobile games before, so you know what these strings are:
each one is either text the player reads on a phone screen or a control the
player taps. A vague or overlong string is a gameplay bug, not a style issue:
it either misleads the player or overflows a fixed-width control.

You treat the project glossary as law. You never invent a second name for
something the glossary has already named, and you never quietly drop a term
you do not recognise.

You never touch engine markup or placeholders, and you never change a
string's final punctuation or its leading and trailing whitespace.
```

Что здесь важно и почему это работает на всех проектах:

- **Роль и платформа.** Модель подстраивает длину и регистр под телефон, а не
  под книгу.
- **Что такое строка.** Прямое указание, что переполнение и двусмысленность -
  это баг, а не вопрос вкуса.
- **Глоссарий как закон.** Снимает главный источник разнобоя в наших играх.
- **Разметка и пунктуация.** Дублирует общие правила движка: повтор в
  «Личности» заметно повышает соблюдение.

Всё, что специфично для конкретной игры - мир, тон, ругательства, формат
тегов, длина реплик - идёт в :guilabel:`Стиль перевода`, а не сюда. Готовый
образец такого стиля: приложение А.

## Шаг 5. Как формулировать инструкции, чтобы модель слушалась

Замер на живых данных проекта CoL4, французский:

- Формулировка-пожелание «сохраняй пунктуацию исходника» исправила 21 строку
  из 40.
- Та же мысль как запрет + пример «было / стало» - 40 из 40.

Рабочая формула:

1. Запрет, а не просьба: «Never add», «Do not», а не «try to keep».
2. Пример пары: исходник -> правильный результат.
3. Явно перебить конфликт: «even when the existing translation has one».
4. Одно правило - один пункт. Списком, а не абзацем.
5. Писать инструкции лучше по-английски: промпт и рассуждения модели на
   английском, смешение языков в инструкциях снижает точность.

Плохо: `Постарайся не добавлять лишние точки.`

Хорошо:

```text
Never add a sentence-final period that the source does not have.
Source "Он ушёл" with existing translation "Il est parti." must produce "Il est parti".
```

## Шаг 6. Глоссарий - главный рычаг точности терминов

Перед каждым запросом Weblate ищет в строке термины из глоссариев проекта и
кладёт найденные в запрос вместе с переводом, пояснением и флагами. Модель
обязана применить их как написано. Это сильнее любых уговоров в поле
:guilabel:`Стиль перевода`.

Где:

- Отдельный компонент-словарь в проекте. Их может быть несколько, например
  «Роли и организации», «Мир и место действия», «Быт и предметы».
- Создать: тот же :guilabel:`Отправить файлы перевода` с галкой
  :guilabel:`Использовать в качестве словаря`. Для таблицы это отдельный
  сценарий с выбором листа и предпросмотром, лист берётся ровно один.
- Добавить один термин на ходу: в редакторе строки панель словаря ->
  :guilabel:`Добавить термин в словарь`.

Флаги термина:

| Флаг | Смысл | Когда ставить |
|---|---|---|
| :guilabel:`Терминология` | Термин обязателен во всех языках глоссария | Имена ключевых сущностей, механик, предметов |
| :guilabel:`Непереводимый термин` | Оставить как есть, не склонять | Названия брендов, коды, имена собственные |
| :guilabel:`Нежелательный перевод` | Так переводить нельзя | Запрет на неудачный вариант, который модель повторяет |

Термин попадает в запрос к модели, только если у него есть перевод на нужный
язык. Исключение - непереводимые: они уходят как есть. Нежелательные варианты
в запрос не попадают.

Поле :guilabel:`Пояснение` у термина тоже уходит в запрос: туда пишут, чем
различаются два одинаковых слова в разных контекстах.

Разнобой в именах персонажей и названиях предметов лечится здесь, а не в
настройках движка.

## Шаг 7. Пояснения к конкретным строкам

Открыть строку в редакторе. Ниже перевода:

- :guilabel:`Пояснение` (:guilabel:`Для всех языков`) - справка для всех
  языков сразу: кто говорит, где показывается, какая длина допустима. Уходит в
  запрос к модели как справочное поле.
- :guilabel:`Флаги перевода` - технические пометки для строки, включая
  включение и отключение отдельных проверок.
- Заметка разработчика из файла (если она там была) тоже уходит в запрос;
  модель использует её для выбора рода, регистра и тона.

Одна строка стабильно переводится неверно из-за неоднозначности исходника -
пишем пояснение и перезапускаем автоперевод только по ней.

## Шаг 8. Запустить автоматический перевод

Страница перевода (<https://l10n.herocraft.com/projects/col4/data/fr/>) ->
:guilabel:`Операции` -> :guilabel:`Пакетный автоматический перевод`.

| Поле | Значение по умолчанию | Что важно знать |
|---|---|---|
| :guilabel:`Режим автоматического перевода` | :guilabel:`Добавить как предложение` | :guilabel:`Добавить как перевод` пишет сразу в перевод. :guilabel:`Добавить с пометкой «На правку»` помечает результат как требующий вычитки. |
| Фильтр строк | `state:<translated` | Ограничивает выборку. **Пустое поле означает «все строки»**, включая уже переведённые и вычитанные вручную. |
| :guilabel:`Источник` | :guilabel:`Машинный перевод` | Второй вариант - брать переводы из других компонентов. |
| :guilabel:`Механизмы машинного перевода` | `OpenRouter` | Можно выбрать несколько; результат с большей оценкой побеждает. |
| :guilabel:`Порог оценки` | 80 | Ниже порога результат не применяется. Для LLM влияет слабо, обычно не трогают. |

Безопасный порядок для новой настройки:

1. Режим :guilabel:`Добавить как предложение`, узкий фильтр - например
   `state:<translated AND check:end_stop`.
2. Посмотреть предложения глазами на 20-30 строках.
3. Устраивает - повторить с режимом :guilabel:`Добавить как перевод`.

Полезные фильтры:

| Фильтр | Что выбирает |
|---|---|
| `state:<translated` | Непереведённое |
| `state:needs-editing` | Помеченное «На правку» |
| `has:check` | Все строки с проваленными проверками |
| `check:end_stop` | Только с несовпадением финальной точки |
| `source:"Гигахрущёвка"` | По тексту исходника |

Синтаксис поиска целиком: `docs/user/search.rst`.

### Две ловушки, проверенные на практике

1. **Пустой фильтр в режиме «Добавить как перевод» перезаписывает всё.**
   Ручные правки и вычитанное будут заменены машинным вариантом без
   предупреждения. Всегда оставляйте фильтр.
2. **Повторный прогон по уже переведённым строкам - это не перевод заново.**
   Модель получает существующий перевод и просьбу его улучшить, и по умолчанию
   склонна вернуть его без изменений. Если нужно именно переписать, правило
   должно быть сформулировано как запрет с примером (шаг 5).

Прогресс большого прогона виден на странице перевода. Результат записывается
одной операцией в конце: если задачу прервать, изменений в текстах не будет.

## Шаг 9. Проверить качество и починить

Страница перевода -> :guilabel:`Аналитика` -> :guilabel:`Неудачные проверки`.
Список сгруппирован по типу проверки с количеством строк.

Что означают частые проверки:

| Проверка | Симптом |
|---|---|
| `end_stop` | В исходнике точки нет, в переводе есть, или наоборот |
| `punctuation_spacing` | Нарушены типографские пробелы, актуально для французского |
| `reused` | Один и тот же перевод у разных исходников |
| `same` | Перевод совпал с исходником |
| `game-line-break` | В строке с разделителем `$` в исходнике он потерян, добавлен или рядом с ним появился пробел |
| `game-number` | В переводе нет числа, которое есть в исходнике: другой урон, радиус или длительность |

Алгоритм лечения:

1. Проблема системная и повторяется по всему проекту -> правило в
   :guilabel:`Стиль перевода` или :guilabel:`Инструкции для конкретного языка`.
2. Проблема в терминах -> глоссарий.
3. Проблема в одной строке -> :guilabel:`Пояснение` к строке.
4. После правки - автоперевод с фильтром по этой проверке, сначала в режиме
   предложений.

Проваленные проверки уходят в запрос к модели вместе со строкой, и модель
обязана их исправить. Поэтому повторный прогон по `has:check` после правки
инструкции обычно и есть лечение.

## Шаг 10. Выгрузить только что автопереведённые строки на ревью

Задача: добавили несколько строк, прогнали автоперевод, и теперь нужно отдать
на вычитку **только эти строки**, не тратя время на то, что переведено раньше.
Всё делается через интерфейс, без обращения к администратору.

### Вариант А. Поставить ярлык до запуска (самый чистый)

1. Перед автопереводом на странице компонента в поле поиска введите:

   ```text
   state:<translated
   ```

   Это ровно те строки, которые сейчас уйдут в прогон.
2. :guilabel:`Операции` -> :guilabel:`Массовое редактирование` -> действие
   :guilabel:`Добавить ярлык`, например `review-2026-08-19`.
3. Запустите автоперевод (шаг 8).
4. После завершения откройте :guilabel:`Файлы` ->
   :guilabel:`Скачать переводы в виде XLSX в ZIP-файле` на уровне компонента.
   Чтобы скачать **только помеченные**, сначала отфильтруйте список: на
   странице компонента введите в поиске `label:review-2026-08-19`, затем
   :guilabel:`Операции` -> :guilabel:`Массовое редактирование` ->
   :guilabel:`Скачать`. В ZIP будет по одному XLSX на язык, внутри - только
   нужные ключи.
5. После ревью снимите ярлык тем же массовым редактированием.

### Вариант Б. Ярлык забыли, фильтруем по дате и автору

Автоперевод пишется от имени системного пользователя `mt:openrouter`, поэтому
его легко отличить от ручных правок.

На странице конкретного перевода (например `.../data/fr/`):

1. :guilabel:`Файлы` -> :guilabel:`Настроить скачивание`.
2. В поле «Фильтры» вставьте запрос:

   ```text
   is:automatically-translated AND changed:>=2026-08-19
   ```

   Дату подставьте свою; «сегодня» - это `changed:>=today`.
3. Формат - :guilabel:`XLSX`, кнопка «Скачать». В файле будут только строки,
   автопереведённые после указанной даты, независимо от того, сколько всего
   уже переведено в проекте.

На экране: тот же запрос работает в поле поиска на странице перевода - Weblate
покажет список совпадающих строк, и вы сразу попадёте в редактор на первую из
них.

Ограничение: «Настроить скачивание» есть только на уровне **одного языка**.
Для всех языков сразу - либо вариант А, либо повторить этот шаг для каждого
языка, либо сохранить готовые ссылки вида:

```text
https://l10n.herocraft.com/download/col4/data/fr/?q=is:automatically-translated AND changed:>=2026-08-19&format=xlsx
```

(подставить свой компонент и коды языков `de`, `ja`, `pt_BR`, ...).

### Что выбрать

| Сценарий | Способ |
|---|---|
| Разово проверить 1-2 языка | Вариант Б, форма «Настроить скачивание» |
| Регулярный процесс «добавил ключи -> автоперевод -> ревью» | Вариант А, ярлык до запуска |
| Забыли поставить ярлык | Вариант Б по языкам или готовые ссылки |

## Шаг 11. Забрать готовые переводы в игру

Страница компонента -> :guilabel:`Файлы` ->
:guilabel:`Скачать файлы перевода в виде ZIP-архива`. Прямая ссылка:

```text
https://l10n.herocraft.com/download/space-arena/lockit/?format=zip
```

Это выгрузка файлов из репозитория компонента как есть. Внутри архива папка
`<проект>/<компонент>/`, а имена файлов ровно те, с которыми компонент живёт:
`ch.json`, `de.json`, `en.json`, ..., `jp.json`, `kr.json`, `pt.json`. Такой
архив можно распаковать поверх игровых локалей без переименований. Перед
упаковкой Weblate фиксирует незакоммиченные правки, поэтому выгрузка всегда
актуальна.

Остальные пункты того же меню для сборки не годятся:

| Пункт | Что получится |
|---|---|
| :guilabel:`Download translations as JSON in a ZIP file` (`format=zip:json`) | Файлы генерируются заново из базы. Имена - `<проект>-<компонент>-<код>.json`, коды берутся внутренние: `ja`, `ko`, `pt_BR`, `zh_Hans`. Псевдонимы языков проекта на эту выгрузку не действуют. |
| :guilabel:`Скачать переводы в виде XLSX в ZIP-файле`, CSV, XLIFF | Форматы для ревью и внешних переводчиков, не для сборки. |

Если в скачанном архиве у файлов появилась приставка с названием проекта и
компонента или коды языков не совпадают с игровыми - выбран не тот пункт меню,
возьмите :guilabel:`Скачать файлы перевода в виде ZIP-архива`.

Имена файлов и коды языков задаются один раз: маской файлов при создании
компонента (шаг 1) и полем :guilabel:`Псевдонимы языков` в настройках проекта,
например `ch:zh_Hans,kr:ko,pt:pt_BR`. Псевдоним нужен там, где игровой код
отличается от кода Weblate; `jp` Weblate понимает как `ja` сам. Псевдонимы
действуют на имена файлов компонента, то есть на выгрузку исходных файлов, и
не действуют на конвертированные выгрузки.

## Что нельзя сделать из интерфейса

Есть базовый список правил, общий для всех проектов инстанса: плейсхолдеры
`{0}` и `%KEY%`, теги разметки `<color=...>`, разделитель строк `$`, формат
ответа модели, правило про финальную пунктуацию. Это движок, он один на всех
и живёт в коде.

Граница простая:

- Правило верно для всех игр и всех языков -> базовый промпт, задача
  администратора.
- Правило про вашу игру, ваш тон, вашу терминологию, ваш язык -> поля из шага 4
  плюс глоссарий, задача продюсера.

Также только через администратора: выбор модели для языка, ключ доступа,
подключение новых движков, включение и отключение проверок на уровне
компонента.

## Чек-лист запуска новой игры

1. Компонент загружен из файла, исходный язык выбран верно.
2. Целевые языки добавлены.
3. С разработчиком согласовано, кто заводит новые строки: он в репозитории или
   продюсер в Weblate.
4. `OpenRouter` настроен: заполнены :guilabel:`Личность переводчика` и
   :guilabel:`Стиль перевода`, ключ и модели не тронуты.
5. Для языков с особыми правилами заполнены
   :guilabel:`Инструкции для конкретного языка`.
6. Глоссарий залит или заведён, ключевые имена помечены как
   :guilabel:`Терминология`, бренды - как :guilabel:`Непереводимый термин`.
7. Пробный прогон: режим предложений, 20-30 строк, глазами.
8. Полный прогон с фильтром `state:<translated`.
9. :guilabel:`Неудачные проверки` просмотрены, системные проблемы вынесены в
   инструкции, прогон повторён по `has:check`.
10. Проверена выгрузка: :guilabel:`Файлы` ->
    :guilabel:`Скачать файлы перевода в виде ZIP-архива`, имена файлов внутри
    архива совпадают с игровыми.

## Приложение А. Образец: настройки CoL4

Реальная конфигурация проекта <https://l10n.herocraft.com/machinery/col4/>,
как она заполнена на момент написания гайда. Берите за образец структуры:
заголовки-разделы, короткие абзацы, запреты вместо пожеланий, примеры прямо в
тексте.

### Личность переводчика

````text
You are a senior game localization specialist working on "Choice of Life: Samosbor", a narrative choice-based mobile game by Blazing Planet Studio and HeroCraft for Android and iOS. Russian is the original language of the script and your source.

You have shipped interactive fiction before, so you know what these strings are: each one is either a card of narrative prose the player reads on a phone screen, or a tappable choice that sends the player down a story branch. A vague choice line is a gameplay bug, not a style issue.

You treat the project glossary as law. You never invent a second name for something the glossary has already named, and you never quietly drop a term you do not recognise.
````

### Стиль перевода

````text
## Setting and tone

Soviet-flavoured post-apocalyptic dystopia inside an endless brutalist megastructure. Keep the bureaucratic, hopeless, oppressive atmosphere. The register is dark and serious with black humour.

Do not add slang or casual wording unless the source character speaks that way. Do not soften, sanitise or explain away lines that are crude, cruel or absurd in the source: that is the voice of the game. Equally, do not make neutral narration coarser than it is.

Keep the narrative tense consistent across the whole project: present and past tense as used in everyday speech. Do not switch into a literary or archaic narrative tense for individual strings.

## Terminology and names

Apply the project glossary exactly. Never invent a second rendering for a term the glossary covers, and use the same rendering in every string. Personal names, patronymics and nicknames follow the glossary spelling character for character.

Never leave Cyrillic characters in a target language that does not use Cyrillic. This includes in-world signs, form numbers, bureaucratic codes and joke strings: localise them so the joke still works in the target language, never copy them across unchanged.

If a term looks like project terminology but is not in the glossary, translate it consistently and keep it consistent with the terms that are.

## Player choices

Choice lines drive story branches. Keep them short, concrete and unambiguous: the player must understand the consequence before tapping. Never merge two options into one vague phrase. Never make two different source options read identically in the target.

## Consistency

Identical source strings must receive identical translations. Two different source strings must not collapse into the same target string.

## Markup and placeholders

Strings contain engine markup and substitutions, for example:

 ```

 <size=60>Authors</size>
 <color=#FF0000>...</color>
 $$ / $
 {0} / %KEY%

 ```

Translate only the text inside the tags. Tags, their attributes, their order and their count, and every placeholder ($, $$, {0}, %KEY%), must stay exactly as in the source.

`$` and `$$` are the engine's line separators. Never replace them with real newlines, never add newlines next to them, and never change how many there are.

## Punctuation, whitespace and length

Reproduce the source's final punctuation exactly. If the source ends without a full stop, the translation ends without one. This applies to every choice line and every short label. Keep leading and trailing whitespace as in the source.

Follow the typographic conventions of the target language for quotation marks, spacing around punctuation and apostrophes.

Keep the target close to the source in length. UI labels, buttons and choice lines must not grow noticeably: they render in fixed-width controls on a phone, and overflow is a shipped bug. Prefer the shortest natural wording that keeps the meaning.
````

### Инструкции для конкретного языка

Для французского. Обратите внимание: правила касаются только того, что
специфично для языка, всё остальное уже сказано выше. В поле вписывают
JSON, поэтому переводы строк внутри значения записаны как `\n`:

````json
{
  "fr": "Address the player with \"vous\" (narration and NPC lines alike). Use \"tu\"\nonly where the Russian source uses \"ты\"; never mix \"tu\" and \"vous\" inside\none string or one scene.\n\nNarrate in present and passé composé. Never use passé simple or imparfait\ndu subjonctif: this is a game script, not a novel.\n\nTypography: put a non-breaking space (U+00A0) before ! ? ; : and inside\nguillemets. Use « » for quotations, matching the source's quotes one for\none. Use the straight apostrophe ' (U+0027), not '.\n\nDo not add a final full stop that the source does not have; this applies\nespecially to choice lines such as \"Промолчать\" -> \"Se taire\".\n\n\"Партия\" is le Parti (masculine), never la partie."
}
````

То же самое в читаемом виде, как это выглядит в запросе к модели:

````text
Address the player with "vous" (narration and NPC lines alike). Use "tu"
only where the Russian source uses "ты"; never mix "tu" and "vous" inside
one string or one scene.

Narrate in present and passé composé. Never use passé simple or imparfait
du subjonctif: this is a game script, not a novel.

Typography: put a non-breaking space (U+00A0) before ! ? ; : and inside
guillemets. Use « » for quotations, matching the source's quotes one for
one. Use the straight apostrophe ' (U+0027), not '.

Do not add a final full stop that the source does not have; this applies
especially to choice lines such as "Промолчать" -> "Se taire".

"Партия" is le Parti (masculine), never la partie.
````

Лимит - 1000 символов на язык, поэтому в это поле идут только те правила,
которые нельзя вывести из :guilabel:`Стиля перевода`: форма обращения,
времена, типографика, ловушки конкретных слов.
