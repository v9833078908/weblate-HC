## Трек A. `response_format: json_schema` на пути OpenRouter

### Задача A1. Код

Файлы: `weblate/machinery/openai.py`, `weblate/machinery/llm.py` (шов
парсинга), `weblate_customization/src/weblate_customization/machinery.py`,
тесты в `weblate/machinery/tests.py`.

- Схема включается только для `RoutedLLMTranslation` (OpenRouter):
  дженерик OpenAI-сервис не трогаем, часть провайдеров схему не
  поддерживает. Прецедент — `weblate/trans/loc_kit.py:425-443`, включая
  `provider.require_parameters: true`.
- Корень strict-схемы обязан быть объектом, поэтому ответ заворачивается
  в конверт `{"translations": [{"parts": [...]}, ...]}`. Парсинг
  разворачивает конверт до `_normalize_translations`; plain-массив
  остаётся принимаемым (другие сервисы, выключенная схема).
- Recovery-парсер (`_repair_json_*`) не удаляется: он общий для всех
  LLM-сервисов, на пути OpenRouter просто перестаёт срабатывать.
- Приёмка: юнит-тесты — payload OpenRouter-сервиса содержит
  `response_format.json_schema.strict` и `provider.require_parameters`;
  конверт разворачивается; payload и парсинг остальных сервисов
  байт-в-байт прежние.

### Задача A2. Замер

Инструмент: `analysis/probes/col4-eval-harness.py`, та же выборка 150 строк
COL4 ru->fr (fingerprint `4db4b89dfd4b`). Среда: **dev-docker**, не прод
(A1 меняет код ядра; прод-образ не пересобирается ради эксперимента).
Плечи сравниваются только внутри одной среды.

- Плечи (4): baseline b20 | schema b20 | schema b10 | baseline b10,
  concurrency 2, back-to-back с паузой ~20 с; второй раунд через
  ~20 минут (протокол `analysis/data/col4-batch-size-eval.json`).
- Статус критерия: json_schema принимается по инварианту транспорта
  (Cathedral: 19.6% потерянных вердиктов), а не по выигрышу
  `rejects.json_error` 2 -> 0 — сигнал n=2 на 150 строках
  статистически ничтожен. A2 — гейт отсутствия регрессий, не
  доказательство пользы.
- Базлайн-плечо прогоняется 3x для фиксации дисперсии `json_error`
  (поведение OpenRouter дрейфует внутри окна замера); если базлайн сам
  колеблется 0-2, это фиксируется в выводах без претензии на
  доказанное улучшение.
- Критерии no-regression: coverage 100%; ноль unparsed на всех
  schema-плечах; `end_stop` в полосе базлайна 18-29; glossary 100%;
  cost в пределах +/-10%.
- Решение: schema без регрессий на b20 -> остаёмся на batch 20 (меньше
  запросов); регрессия на b20 -> подтверждается кандидат batch 10.
- Результат: `analysis/data/col4-schema-eval.json` (EVAL_JSON всех плеч +
  выводы), бюджет ~$0.30.

## Трек B. Калибровка судьи на золотом наборе

Standalone-скрипт без Django: ключ OpenRouter передаётся через переменную
окружения. B2 использует `col4-judge-golden.json` для меток и сплитов,
а контекст судьи берёт из зафиксированного B0-дампа
`dev-docker/data/col4-b0-units.jsonl`; ни dev, ни прод не изменяются.

Разметчики реального вывода: Fable (Anthropic) разметил исходные 260
строк, `openai-codex-gpt-5.6-terra-2026-08-12` — top-up из 300 строк;
человек-переводчик на этом этапе недоступен. Прецедент глубины разбора —
`docs/llm-first/measurements/2026-08-11-col4-fr-autotranslate-report.md` (п. 5).
Следствие для интерпретации: семейство судьи может коррелировать с
семейством разметчика. B2 репортирует метрики отдельно по
Fable-разметке, OpenAI-разметке и конструктивным стратам (глоссарные
дефекты и синтетические мутации), независимым от разметчика. Преимущество
судьи, проявляющееся только в страте его семейства, — признак family bias;
выбор должен оставаться обоснованным на конструктивных стратах.
С 2026-08-13 выбор — не «какой судья единственный», а «какая модель
занимает ступень A и какая — ступень B» каскада (дизайн
`docs/llm-first/designs/2026-08-13-judge-native-ui-design.md`). У family bias
появляется второе следствие: ступени A и B обязаны быть из разных
семейств, поэтому замер, показывающий преимущество одного семейства,
ограничивает то, какую ступень оно может занять.

### Задача B0. Разметка реального вывода (error analysis)

Файлы: `docs/llm-first/measurements/2026-08-12-col4-judge-annotation.md` (протокол и разметка),
записи вливаются в `col4-judge-golden.json`.

**Выполнена и дополнена 2026-08-12**:
`docs/llm-first/measurements/2026-08-12-col4-judge-annotation.md` +
`analysis/data/col4-b0-annotations.jsonl` (исходные 260 юнитов) +
`analysis/data/col4-b0-annotations-topup-20260812.jsonl` (300 новых
кандидатов random-clean). Всего 560 юнитов: 436 pass / 124 defect;
чистый пул - 419/512 = 81.8%, Wilson 95% CI [78.3%, 84.9%].
Дамп: `analysis/probes/col4-b0-dump.py`. Top-up размечен отдельно
`openai-codex-gpt-5.6-terra-2026-08-12`; provenance хранится в записи.

Исходную волну из 260 строк размечал Fable; top-up из 300 кандидатов
`random-clean` — OpenAI Codex. На строку: вердикт pass/defect, MQM-тег
(terminology / accuracy / omission / fluency / punctuation / markup),
критика со ссылкой на конкретный span. Улики в контексте разметчика:
source ru, глоссарий, note, failing_checks. Два выхода:

- метки чистой страты B1: «чистая» = pass от разметчика, а не только
  0 failing checks — строка может пройти все чеки и остаться
  семантически неверной; иначе скрытые дефекты «чистой» страты
  считались бы false-flag судьи и тянули калибровку в
  снисходительность;
- сверка классов мутаций с реальностью: класс дефекта, найденный в
  разметке и отсутствующий в списке мутаций, добавляется в список;
  класс, не встреченный в реальном выводе, помечается как
  гипотетический (защита от придуманных категорий отказов).

### Задача B1. Золотой набор

Файлы: `analysis/probes/col4-judge-goldenset-build.py`,
`analysis/data/col4-judge-golden.json`.

**Выполнена и дополнена 2026-08-12**: 919 записей, детерминированная
сборка воспроизводима (`uv run python
analysis/probes/col4-judge-goldenset-build.py`, вывод байт-стабилен). Состав:
clean 419 (train 63 / dev 189 / test 167), terminology 195
(23 / 95 / 77), mutation 305 (24 / 92 / 189).

Отклонения от плана и их основания:

- **Страта 1 — 195, а не 85.** Число 85 — свойство прод-состояния
  матчера (22 канонических термина без словоформ), а не корпуса:
  глоссарий dev-зеркала несёт 153 записи (31 термин + 122 формы),
  поэтому бакет `missed` там не воспроизводим — у семи терминов из
  таблицы п. 10 в нём **ноль** вхождений. Страта собрана той же
  логикой пробника с кэпом 8 на рендеринг; каждая запись несёт `term`
  и `matcher_bucket`, так что любое подмножество восстановимо.
  Точность метки по построению проверена вручную: **30/30**
  (Wilson 95% CI [88.6%, 100%]).
- **Классы мутаций.** `@@PHn@@` снят (0 вхождений в col4), порча
  буквенно-цифрового кода снята (0 кодовых токенов в чистом пуле).
  Добавлены наблюдённые в B0 `quote-frame-dropped` и
  `realia-decapitalised`; критический объём даёт отрицание инфинитива
  (`Ne pas <inf>`) — конвенция ANSWER-строк корпуса.
- **Гигиена генераторов.** Из антонимов исключены пары, управляющие
  разными предлогами (avec/sans, entrer/sortir, commencer/finir),
  снятие отрицания ограничено неэлидированным `ne`, детекция
  подлежащего защищена от клитик и относительных местоимений. Иначе
  мутация даёт грамматическую ошибку вместо смысловой инверсии —
  её судья ловит, не читая смысла, и reject-recall завышается.
- **Целостность сплитов.** Сплит закрепляется на уровне юнита: строка
  с двумя глоссарными дефектами не может попасть в dev одним и в test
  другим. Проверено: 0 юнитов в двух сплитах, 0 пересечений train с
  dev/test, 0 юнитов одновременно clean и terminology.

Мощность на test: critical n=120 даёт измеримый гейт
`reject-recall`; чистых строк n=167 закрывает исходный дефицит
(`n >= 150`) для измерения false-flag и auto-pass. Для 95% Wilson
upper bound `false-flag <= 10%` допускается не более 9 false flags
(5.4%). Строгий CI-гейт `false-reject <= 2%` ещё не сертифицируем:
даже 0/167 даёт upper bound 2.25%; нужны n >= 189 чистых строк в test
или пересмотр порога. Это отдельный узкий разрыв, а не основание
заявлять точечную оценку без интервала.

Актуальные правила сборки:

- каждый выгруженный `target` до разметки прогоняется через
  `AUTOFIXES.fix_target()` (включая расширение автофикса терминала на
  `!?:` из `2026-08-11-layer0-autofix-quick-wins.md`); судья не
  калибруется на детерминированных дефектах, которые слой 0 обязан снять;
- сборка принимает обязательный `--autofix-fingerprint` (строка
  `Active autofixes:` из `weblate reapply_autofixes`) и записывает его
  в метаданные набора; первый пишущий прогон судьи допускается только
  при совпадении отпечатка набора и отпечатка прод-инстанса, иначе —
  явный rebaseline набора с новым отпечатком;
- сплит закреплён на уровне юнита. Few-shot берётся только из train,
  итерации промпта — только по dev, test запечатан до единственного
  go/no-go прогона. Синтетика разделена по непересекающимся базовым
  строкам и seed; после go/no-go test может войти в регрессию, но любое
  существенное изменение промпта или модели требует нового test-среза.

### Задача B2. Прогон судей

Файлы: `analysis/probes/col4-judge-eval.py`, результат в
`docs/llm-first/measurements/2026-08-XX-judge-calibration.md`.

- Судьи: Anthropic mid-tier и OpenAI mini-tier через OpenRouter; точные
  ID фиксируются в результатах из каталога моделей на момент прогона.
  Оба семейства отличны от переводчика (`google/gemini-2.5-flash`) —
  инвариант 3 архитектуры.
- Промпт: MQM error-first, structured output
  `{errors: [{span, category, severity}], verdict}` — schema-enforced с
  первого прогона калибровки, тот же контракт, что пойдёт в прод
  (урок Cathedral: 19.6% вердиктов потеряны на свободном тексте).
  Глоссарий, note и `failing_checks` юнита в контексте — судья не
  пере-доказывает то, что код уже доказал. Вердикт из инвентаря:
  critical -> reject, major -> flag, иначе pass. Батч ~10 строк.
- Инвариант транспорта: неразобранный или пустой ответ судьи — сбой,
  не вердикт: ретрай, затем пропуск строки. В метриках калибровки
  считается отдельной колонкой (`unparsed`), не попадает ни в flag,
  ни в reject.
- Плечи — каскад по дизайну
  `docs/llm-first/designs/2026-08-13-judge-native-ui-design.md`:
  - плечо 1: модель X — ступень A на всём сплите, модель Y — ступень
    B только на flag+reject ступени A;
  - плечо 2: зеркальное (Y — ступень A, X — ступень B);
  - плечо 3 (контроль): каждая модель в одиночку на всём сплите, один
    прогон — базлайн, который каскад обязан побить.
  Ступень B работает на ~20-30% строк, а не на 100%, поэтому бюджет
  каскада не удваивается относительно одиночного судьи. 3x-агрегация
  (самосогласованность одной модели на flag/reject) понижена с
  запланированного плеча до опционального контроля: второе семейство
  замещает её — сбивает и дисперсию, и смещение, тогда как
  самосогласованность сбивает только дисперсию.
- Вердикт трёхзначный, но калибруются две независимые бинарные
  границы, каждая со своими TPR/TNR и разбором дисагриментов:
  граница R «есть critical» — reject против (flag + pass), защита
  релиза; граница H «нужен человек» — (flag + reject) против pass,
  confidence-роутер и главная продуктовая граница.
- Метрики репортятся в таком порядке:
  - по ступеням: recall ступени A на границе H (flag+reject против
    pass) — метрика, решающая, состоятелен ли каскад вообще: всё, что
    ступень A пропустила, больше никто не увидит; precision ступени B
    на подмножестве, которое ступень A эскалировала;
  - каскад end-to-end: confusion matrix и TPR/TNR границ R и H по
    финальному вердикту каскада, а не по каждому судье в отдельности;
  - доля false-critical на чистых test-строках с Wilson 95% CI —
    новая метрика первого класса: ложный critical физически не даёт
    чистой строке уйти в сборку игры, это дефект поставки, а не шум;
  - из прежних, оставшихся значимыми: reject-recall на
    critical-мутациях; (flag u reject)-recall на глоссарных дефектах;
    false-reject и false-flag на чистых; цена и латентность на 1000
    строк.
- Продуктовая метрика: auto-pass rate >= 90% при скорректированном
  miss rate среди auto-pass (Rogan-Gladen по TPR/TNR границы H,
  bootstrap CI): critical ~ 0, major <= 1-2%. Точечные оценки без
  доверительного интервала не репортятся.
- Пороги go для фазы 2 — точечная оценка И нижняя граница 95% CI
  (Wilson): reject-recall (critical) >= 95% при CI >= 88% (тестируемо
  при critical n=120); (flag u reject)-recall (terminology) >= 80%
  (test n=77, CI репортируется как advisory); false-reject <= 2%
  сертифицируется только при >=189 чистых строках в test (текущих 167
  недостаточно даже при 0 false-reject); тот же предел мощности у
  гейта false-critical — он измеряется на той же чистой страте;
  false-flag <= 10% на текущих 167 чистых test-строках допускает не
  более 9 false flags (5.4%).
  Терминологический recall < 80% -> терминология остаётся
  детерминированной (план морфологии), судья судит только семантику.
- Few-shot примеры промпта судьи — только из train-среза B1; итерации
  промпта — по dev; test меряется один раз, после него итерации по
  test запрещены (возврат — только со свежим срезом).
- Бюджет ~$8-15 (~400 записей x 2 модели x до 3x). Набор train + dev
  становится постоянным регрессионным для промпта судьи: любое
  изменение промпта/модели гоняется по нему, как изменения промпта
  переводчика — по eval-харнессу.

## Трек C. Пробник дрейфа не-глоссарных повторов

Файлы: `analysis/probes/col4-repeat-drift-probe.py`, результат — раздел в
`docs/llm-first/measurements/2026-08-XX-judge-calibration.md`.

Проверка переносимости правки 10.1 Cathedral (рантайм-канон
first_mentions, 23.4% их стадии правки) на нашу систему, где точные
повторы закрывает кэш machinery, термины — полный глоссарий <=300, а
детекцию — стоковый чек `inconsistent`:

- По прод-выводу COL4 fr сгруппировать повторяющиеся не-глоссарные
  фразы (n-граммы >= 3 символов, входящие в несколько юнитов) и
  посчитать долю групп с расходящимися переводами.
- Расхождение считается после нормализации (casefold, trim,
  схлопывание пробелов, снятие финальной пунктуации); репортятся обе
  цифры — raw и normalized, чтобы не раздувать «дрейф» косметикой,
  которую слой 0 снимает бесплатно.
- Дрейф материален -> рантайм-канон встаёт в фазу 2/4 отдельным
  дизайном (порядок батчей и concurrency ломают семантику канона —
  проектировать, не копировать). Дрейф незначим -> закрыто замером,
  как п. 10.4 анализа закрыл проверку порядка тегов.
- Read-only, без LLM-вызовов, бюджет $0.
