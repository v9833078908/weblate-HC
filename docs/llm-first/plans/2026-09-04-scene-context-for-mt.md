# План: сцена как единица контекста для машинного перевода диалога

Дата: 2026-09-04. Статус: ожидает одобрения. Ничего из нижеследующего не
делается до одобрения; задачи 5-8 - только при прохождении гейтов задачи 4.

Преемник отклонённого плана
`docs/llm-first/plans/2026-08-20-judge-dialog-context.md`: тот измерял
окно ±1 по `position` для *судьи* и не нашёл эффекта. Этот план ставит
другой вопрос - контекст *сцены* для *переводчика*, где сосед не
справочный материал, а часть задачи (кто кому отвечает, на «ты» или «вы»,
каким регистром).

## Что установлено до плана

- Переводчик уже видит батч из 10 строк в одном запросе
  (`weblate/machinery/llm.py:391`, `_get_message` :1196-1247) и правило 1
  промпта велит переводить «по порядку». Но порядок - порядок выборки БД:
  `AutoTranslate.get_units()` (`weblate/trans/autotranslate.py:337-343`)
  не сортирует, `Unit.Meta` (`weblate/trans/models/unit.py:713`) не задаёт
  `ordering`, `fetch_machinery_matches` (`weblate/trans/machinery.py:200-204`)
  режет присланный список по 10 без оглядки на сцену. Соседство внутри
  батча случайно, границы батча режут сцену в произвольном месте, а
  строки за пределами батча невидимы.
- Спикер текущей строки переводчику дан: `note` = имя персонажа
  (`hub1_*`: `Ray`, `Leon`, `Yaeko`), правило 26 промпта
  (`llm.py:248`) велит брать из него регистр и род. Не дано: адресат,
  число адресатов, регистр *собеседника*, перевод предыдущих реплик той же
  сцены - то есть всё, что определяет `du/ihr/Sie`, `tu/vous`, `お前/あなた`.
- Именно этот класс доминирует в LQA hub-1
  (`docs/llm-first/measurements/2026-08-24-heart-abyss-hub-1-full-lqa.md`):
  register - 124 находки из 414 (§6.1, :174), формы обращения в de - 19
  грамматических находок с системным разнобоем `du`/`ihr`/`Sie` против
  последовательного множественного числа источника (§6.2, :190-195).
  Ротация четырёх юнитов в de (§5.1) - дефект *идентичности* батча, не
  контекста; он закрыт планом
  `docs/llm-first/plans/2026-08-24-llm-batch-string-identity.md` и здесь
  не цель.
- Ключи диалоговых компонентов кодируют сцену: `hub1_ramen_1_13` - сцена
  `hub1_ramen_1`, реплика 13. В hub-1 18 сцен по 7-53 реплик, сосед по
  `position` в 9 % случаев - чужая сцена, в 61 % пар - другой спикер
  (замер `2026-09-04-judge-dialog-context-paired.md`). Единица контекста -
  сцена, не ±1.
- Инфраструктура батча уже есть: строки идут парами `id`/`source`, ответ
  спаривается по `id` (`_resolve_reply_order`), JSON-схема ответа
  фиксирована. Блок сцены - добавка к сообщению, не новый транспорт.
- Gold-переводов hub-1 нет (`analysis/data/hub1-remediation-2026-08-25/`
  хранит state 20 и TSV ревью без полей приёмки; 414 вердиктов LQA от
  2026-08-24 утрачены вместе с `/tmp/lqa`). Инструмент замера - слепой
  LQA-проход по тому же протоколу плюс детерминированная метрика форм
  обращения.

## Гипотеза и плечи

Один срез, три плеча, один драйвер. Всё поверх продового
`RoutedLiteLLMTranslation` и продового промпта на HEAD; плечи различаются
только тем, что названо.

- **P** - прод как есть: порядок выборки БД, батчи по 10.
- **S0** - дешёвая правка: юниты в порядке `position`, батч не пересекает
  границу сцены (ключ сцены - `context` без последнего `_<n>`). Без
  нового контекста в промпте. Отделяет эффект *порядка* от эффекта
  *контекста*.
- **S** - S0 плюс блок сцены в сообщении:
  `"scene": {"key": "hub1_ramen_1", "lines": [{"n": 13, "speaker": "Leon",
  "source": "...", "translation": "..."|null}, ...]}` - все реплики сцены
  по порядку, `translation` только там, где юнит уже переведён и не в
  этом батче; кап 60 реплик (окно вокруг батча, если сцена длиннее).
  Плюс правило промпта, единственная новая строка: блок - справочный
  материал для адресата, числа, регистра и согласованности с уже
  переведёнными репликами; не переводить, не копировать, не цитировать.
  Байты правила фиксируются в выхлопе драйвера.

Корпус: те же три сцены hub-1 (`hub1_first_1`, `hub1_ramen_1`,
`hub1_teahouse_1`, 109 реплик), ru→de и ru→fr. de - потому что там
измеренный системный дефект обращения; fr - потому что ревьюер читает обе
стороны. Три повтора на плечо и язык: 3 плеча × 2 языка × 3 повтора × 11
батчей = 198 запросов, ~час времени прокси.

## Метрики и гейты

| # | Метрика | Как считается |
|---|---|---|
| M1 | Несогласованность обращения (de) | детерминированно: по каждой реплике число адресата из источника (`ты/тебе/твой…` vs `вы/вам/ваш…`) против формы в цели (`du/dich/dein…` vs `ihr/euch/euer…` vs `Sie/Ihnen`); считаются реплики с расхождением и сцены, где форма меняется при неизменном источнике |
| M2 | LQA-находки | слепой проход по протоколу `weblate-lqa` (MQM-Core Game) по объединению реплик, где плечи расходятся текстом; считаются категории register, grammar/agreement, accuracy, omission/addition, terminology, отдельно critical |
| M3 | Стабильность | доля реплик с побуквенно одинаковым переводом между тремя повторами одного плеча; шумовой пол для M2 |
| M4 | Контракт батча | отказы по `id`, плейсхолдерам, пунктуации (правило 27), размеру; из диагностики драйвера |
| M5 | Цена | prompt/completion токены и секунды на реплику по плечу |

| Гейт | Условие |
|---|---|
| G1 | M1: S < S0 ≤ P, у S не более половины расхождений P; иначе гипотеза «контекст чинит обращение» отклонена |
| G2 | M2: у S сумма register + grammar/agreement не выше 0,7 × P и ни одного нового critical класса accuracy/omission; разница вне шумового пола M3 |
| G3 | M4 у S не хуже P (батч не ломается от лишнего блока) |
| G4 | M5: prompt-токены на реплику у S не выше 1,6 × P; секунды не выше 1,3 × P |
| G5 | S0 отдельно: если S0 уже проходит G1-G2, в прод идёт только S0 |

Гейты жёсткие: непрохождение G1 или G2 закрывает план записью решения,
как и `2026-08-20-judge-dialog-context.md`. Прохождение открывает задачи
5-8.

## Что вне плана

- Судья. Если G1-G2 пройдены, отдельная постановка: тот же блок сцены
  (source + target, спикер) в сегменте судьи, гейт - те же
  `teahouse_1_11`/`first_1_3` из отклонённого плана плюс de-обращение.
  Не смешивать с этим срезом: у судьи измеренный ноль на ±1, и его
  стоимость по правилу R3 меряется отдельно.
- Окно ±1 по `position`, `prev_source/next_source` в любом виде.
- Компоненты без сценного ключа (UI, `st2`, `col4`): настройка пуста,
  поведение прежнее. Автоматический вывод ключа сцены без regex.
- TM-примеры, `secondary`, персона по спикеру - другие рычаги, свои
  замеры.
- Деплой: ничего не деплоится; прод остаётся на HEAD до отдельного
  одобрения.
