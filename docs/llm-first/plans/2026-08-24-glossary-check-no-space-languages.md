# План: глоссарный чек для языков без пробелов

Дата: 2026-08-24. Статус: на согласовании.

## Что этот план меняет и что не меняет

Решение 2026-08-11 остаётся в силе: `GlossaryCheck` не включается на компонент
целиком, не попадает в `enforced_checks` и не становится блокирующим гейтом.
План уточняет его по одной оси, которую тот замер не рассматривал вовсе —
**язык цели**, — и обязуется либо расширить решение числами, либо закрыть
вопрос окончательно.

Предыстория, которую план не пересматривает:

- `docs/llm-first/measurements/2026-08-11-glossary-enforcement-analysis.md` —
  на COL4 включённый чек дал бы 2 сообщения на 4023 юнита, оба ложные, а все
  85 настоящих дефектов сидели на стороне источника;
- `docs/llm-first/plans/2026-08-11-glossary-morphological-enforcement.md` —
  задачи 1-5 задеплоены 2026-08-14, «`GlossaryCheck` остаётся
  `default_disabled`»;
- `docs/llm-first/plans/2026-08-14-intra-component-consistency-check.md` —
  задача «включить `check_glossary`» удалена 2026-08-20, «включение чека
  per-component поверх этого решения планом не предусматривается»;
- `docs/llm-first/plans/2026-08-10-git-localization-quality-gate.md:127-133` —
  «Never promote `check_glossary` wholesale to blocking or to Weblate
  `enforced_checks`».

## Почему вопрос вообще стоит открывать

### Асимметрия по языку цели

Шум глоссарного чека — свойство флективных языков, а не чека. Раздел 3 замера
2026-08-11: стеммер снимает от 14 % до 66 % срабатываний в ru, pt_BR, es, tr,
de, fr, hi, id, а для ja, ko, th, zh_Hans, vi отмечено «стеммер не нужен».
Раздел 9 того же замера перечисляет в этих языках настоящие расхождения
терминологии: ja `Armor` → `アーマー` вместо `装甲`, `Reactor` → `動力源`,
th `Blueprint` → `แบบแปลน`, `Ship` → `ยาน`. Это тот класс дефекта, ради
которого гейт и нужен.

Офлайн-прогон по st2 zh_Hans подтверждает:
`analysis/data/st2-zh-glossary-checks.json` — 5 срабатываний, 0 ложных
(`docs/llm-first/measurements/2026-08-18-severity-recalibration-status.md`,
раздел «Офлайн `check_glossary`»).

Механически это заложено в коде: границы слова отключаются для языков без
пробелов — `boundary = r"\b" if language.uses_whitespace() else ""`
(`analysis/probes/glossary-enforcement-measurement.py:159`),
`Language.uses_whitespace` = `base_code not in NO_SPACE_LANGUAGES`
(`weblate/lang/models.py:1099-1100`, список — `weblate/lang/data.py:12`:
zh, ja, th, km, lo, my, ko).

### Флаг можно поставить на язык, а не на компонент

Замер 2026-08-11 ставил вопрос как «включать ли чек на компоненте», потому что
других вариантов не рассматривал. Но `Translation.check_flags` существует
(`weblate/trans/models/translation.py:334`),
`Translation.all_flags = Flags(component.all_flags, self.check_flags)` (:404-406),
а `Unit.get_all_flags` строится от `self.translation.all_flags`
(`weblate/trans/models/unit.py:2494-2496`). Включение только для ja/ko/th/zh —
настройка одного перевода, без правки продуктового кода.

### Почему всё равно нельзя просто включить

`GlossaryCheck.check_single` возвращает **объединение**: `return hard | advisory`
(`weblate/checks/glossary.py:113-115`). Разделение живёт только в тексте
сообщения (`get_description`, :117-174), поэтому запись `Check` создаётся и на
advisory. Замер продуктового кода на проде 2026-08-14 по ru-source когортам:
13559 юнитов, **hard = 0, advisory = 521**. Панель heart-abyss после уборки —
116 записей при ~95 % полезного сигнала (аудит
`docs/operations/audits/2026-08-20-heart-abyss-hub-1-translation-qa.md`,
раздел 13.1). Включение без замера вернуло бы её в шум.

## Цель

Ответить числами на один вопрос: **в языках без пробелов доля настоящих
дефектов среди срабатываний `check-glossary` выше порога приёмки или нет.**

Да — включаем только там и только per-language. Нет — тема закрыта, решение
2026-08-11 остаётся без изменений, и этот план становится её обоснованием на
второй оси.

## Задача 1. Расширить probe на компоненты с не-ru исходником

`cohorts()` (`analysis/probes/glossary-enforcement-measurement.py:67-84`)
пропускает компонент, если `component.source_language.base_code` не входит в
`SOURCE_STEM_LANGUAGES`, а это `frozenset({"ru"})`
(`weblate/checks/morphology.py:39`). Следствие: прод-замер 2026-08-14 на 13559
юнитах покрыл только ru-source когорты, а `space-arena/lockit` (исходник `en`,
4861 ключ, 15 языков) и компоненты Need for Greed не измерялись этим probe ни
разу.

Сторона источника для английского отклонена пунктом 7 отчёта 2026-08-11 и
стемминга не получает — но вопрос этого плана лежит на стороне цели и от
исходного стемминга не зависит.

Ввести флаг `--all-source-languages`: фильтр строки 72 снимается, колонки
`recovered_units` / `recovered_terms` для таких когорт печатаются как `n/a`,
сторона цели считается как сейчас.

Приёмка: probe остаётся read-only; на ru-когортах прогон с флагом и без даёт
идентичные числа.

## Задача 2. Прогон на проде, только чтение

**Требует отдельного одобрения:** команда против `l10n.herocraft.com`, что по
рабочему соглашению в `AGENTS.md` отнесено к деплою.

Прогон идёт по всем компонентам — probe перебирает их всё равно, и
ограничивать его дешевле не становится. Три крупнейших проекта выбираются из
его же вывода, по числу переведённых юнитов в языках без словоизменения и по
наличию наполненного глоссария; остальные попадают в отчёт справочно.

Per-cohort строка probe (`:192-196`) уже печатает нужное — `units`, `hard`,
`advisory`, `lifted` по `project/component/language`. Дополнительно выгрузить
сами сработавшие пары `(юнит, термин)` для языков без словоизменения:
источник, перевод, термин, его канонический таргет, тип срабатывания.

Записать вывод и `glossary_matcher_fingerprint` в
`docs/llm-first/measurements/2026-08-24-glossary-no-space-measurement.md`, а
выгрузку пар — в `analysis/data/` и закоммитить. Корпус в `/tmp` уже один раз
пропадал и его тянули заново
(`docs/llm-first/measurements/2026-08-18-severity-recalibration-status.md`,
раздел «Почему корпус не с `/tmp`»).

## Задача 3. Ревью сработавших строк

LQA проходит выгруженные пары по языкам без словоизменения (zh_Hans, ja, ko,
th и другие из `NO_SPACE_LANGUAGES`, если есть на проде; кандидатом идёт также
`vi` — он изолирующий, границы слова для него работают, и в таблице раздела 3
замера 2026-08-11 он стоит рядом с ними как «стеммер не нужен»).

Три исхода на срабатывание: настоящий дефект перевода / ложное срабатывание /
неверен сам термин глоссария.

Полноту этот замер не оценивает: несработавшие строки не размечаются. Значит
по его результату нельзя утверждать, что чек ловит терминологию — только что
он не шумит и находит столько-то. Для решения о панели этого достаточно, для
решения о гейте — нет, и гейт остаётся вне области.

## Задача 4. Порог и решение

Язык проходит, если доля настоящих дефектов среди его срабатываний не ниже
80 %. Порог привязан к панели: heart-abyss после уборки даёт ~95 % полезного
сигнала при 116 записях (аудит, раздел 13.1), и опускать её мы не имеем права.

Высокая доля «неверен сам глоссарий» — это не приговор чеку, а конфаунд:
сначала правится глоссарий, затем перепрогон.

Язык не прошёл — не включаем, причину записываем.

## Задача 5. Включение, по одному языку

`Translation.check_flags` += `check-glossary` на конкретном переводе прошедшего
языка. Затем `weblate.trans.tasks.update_checks(component.pk, token)` после
`cache.set(component.update_checks_key, token)` — синхронно, иначе таблица
`Check` останется на состоянии последнего касания юнита.

Один язык одного компонента, наблюдение, затем следующий. Не пакетом.

## Задача 6. Привести решения в соответствие

- дописать результат в
  `docs/llm-first/measurements/2026-08-11-glossary-enforcement-analysis.md`
  отдельным датированным разделом, не переписывая старые;
- поправить критерий приёмки
  `docs/llm-first/plans/2026-08-14-intra-component-consistency-check.md:173`:
  «остаётся выключенным» → «выключен для языков с пробелами; для языков без
  пробелов — по замеру 2026-08-24»;
- в `docs/operations/audits/2026-08-20-heart-abyss-hub-1-translation-qa.md`
  пометить строку рекомендации «Включить `check-glossary` на компонентах
  heart-abyss» как отменённую для флективных языков со ссылкой на этот план.

## Вне области

- включение на компонент или проект целиком — остаётся запрещённым;
- `enforced_checks` и блокирующий гейт — остаётся запрещённым;
- флективные языки: advisory там продолжает жить только в промпте судьи через
  `glossary_advisories` (`weblate/machinery/llm.py:517-572`, правила промпта 23
  и 28), в панель чеков не попадает;
- A/B прогон LLM на прирост соблюдения — незакрытая часть задачи 6 плана
  2026-08-11, стоит денег OpenRouter и требует отдельного решения;
- per-term `exact` на именах собственных — независимая и более дешёвая работа,
  санкционированная `quality-gate:130-133`; отдельный план;
- dev-инстанс: `check-glossary` стоит на `heart-abyss/temple` как след
  smoke-теста loc-kit (`docs/product/plans/2026-08-10-loc-kit-glossary-term-description-shape.md:201`),
  а не как решение. Снятие или сохранение — вне этого плана.

## Откат

Снять `check-glossary` из `Translation.check_flags` и повторить задачу 5 шаг
`update_checks`. Записи `Check` исчезают при пересчёте, переводы не меняются:
проверка ничего не пишет в `Unit.target`.
