# План: внешний LLM-judge для валидации переводов (вариант 2)

Батч-скрипт снаружи Weblate: выгрести переведённые юниты редкого языка через REST API, прогнать через LLM-judge (back-translation + семантическая сверка), вернуть результат как комментарии/состояния/предложения. Без правки кода Weblate.

## 0. Проверенные факты (основа плана)

Проверено по коду (ветка HEAD):

- Эндпоинта `/api/v1/units/{id}/review/` НЕ существует. Не использовать.
- Одобрение юнита: `PATCH /api/v1/units/{id}/` с `{"state": 30}` — `weblate/api/views.py:3829`. Требует permission `unit.review` и включённый `translation_review` на проекте (иначе 30 недостижимо, юнит не примет состояние).
- Приём предложения: `POST /api/v1/suggestions/{id}/accept/` с `{"approve": true}` — `weblate/api/views.py:4049`; требует `suggestion.accept` (+ `unit.review` для approve).
- Комментарии: `POST /api/v1/units/{id}/comments/` — `weblate/api/views.py:3900` (роут `api:unit-comments`).
- Список юнитов: `GET /api/v1/units/` с фильтром `q` и пагинацией — `weblate/api/urls.py:42`.
- Первый проход перевода (опционально): `POST /api/v1/translations/{project}/{component}/{language}/autotranslate/` — `weblate/api/views.py:3593`, требует `translation.auto`. Скрипт может сам запускать LLM-перевод перед судом (режимы `translate`/`suggest`/`fuzzy`, фильтр `q`).
- Приём предложения с `approve: true` переводит юнит в `STATE_APPROVED` (`weblate/api/views.py:4049`); при выключенном review workflow вернёт «Translation reviews are turned off».
- Состояния (`weblate/utils/state.py`): `10` needs editing (fuzzy), `11` needs rewriting, `12` needs checking, `20` translated, `30` approved.
- Ограничения API на состояние юнита (`weblate/api/views.py:3800-3813`): через `PATCH` можно выставить только `0/10/20/30`; состояния `11`/`12` выставляются самим Weblate по итогам чеков и через API недоступны («This state cannot be set manually»). `state` всегда отправляется вместе с `target`, причём `target` — это список форм плюрала (`PluralField`, `weblate/api/serializers.py:3106,3470`): скрипт эхо-бэчит список из ответа GET без изменений, иначе 400 («Number of plurals does not match», `views.py:3795`).
- LLM-сервисы (OpenAI/Anthropic/Ollama/Mistral, `weblate/machinery/llm.py`) передают `failing_checks` в промпт перевода: результат чека автоматически подмешивается в следующую LLM-подсказку — контур judge → check → повторная подсказка замыкается без дополнительной работы.

## 1. Предусловия

- Токен API пользователя с правами на проект (минимум: чтение юнитов, добавление комментариев, `suggestion.add`; для авто-одобрения — `unit.review`).
- На проекте включён `translation_review` — обязательное предусловие всего пайплайна, не только авто-одобрения: без review workflow `approve`-семантика недоступна (accept с `approve: true` вернёт ошибку), `state=30` недостижимо, а `flag`-состояния теряют смысл «ожидает ревью».
- LLM-провайдер с API. Судью лучше взять другого провайдера/модель, чем тот, что переводил, — self-judge слабее.
- Python 3.10+, `httpx` (или `requests`), переменные окружения для токенов.

## 2. Архитектура пайплайна

```text
Weblate API ──GET units──▶ [фильтр: язык, состояние, курсор]
                                │
                                ▼
                     LLM judge (батч по N юнитов):
                     1. back-translation target → source_language
                     2. семантическая сверка source vs back-translation
                     3. прямые проверки: утечка source-языка, плейсхолдеры,
                        глоссарий, стиль (критерии ниже)
                                │
                                ▼
                    вердикт: pass | flag | reject (+ причина)
                                │
              ┌─────────────────┼──────────────────┐
              ▼                 ▼                  ▼
   pass: комментарий     flag: PATCH state=10   reject: предложение
   "[LLM-judge] ok"      + комментарий          + комментарий
                         (needs editing/fuzzy)  (если target хуже)
```

### Критерии судьи (минимальный набор для редкого языка)

1. **Back-translation match** — основной: модель, которая не знает редкий язык достаточно хорошо для прямой оценки, надёжнее делает обратный перевод. Сравнение `source` и `back_translation` на потерю/добавление смысла.
2. **Утечка source-языка** — нетронутые слова/фразы из source в переводе.
3. **Плейсхолдеры** — `%s`, `%d`, `@@PH..@@`, HTML-теги на месте (частично закрывается встроенными чеками Weblate — их результат можно читать из поля `failing_checks` юнита и не перепроверять).
4. **Глоссарий** — термины из глоссария проекта использованы как записано.
5. **Стиль/обращения** — только если есть Language-specific instructions для языка; без них не спрашивать у модели «хороший ли стиль» на редком языке — ответ будет галлюцинацией. Это поле формы LLM-сервиса в Automatic suggestions (`machinery/forms.py`, `LLMBasicMachineryForm.language_instructions`), а не общая настройка проекта: админка → Automatic suggestions → сервис → форма (там же, где API-ключ и persona).

Вердикт: `pass` (ничего не найдено), `flag` (сомнительно, нужна human-проверка), `reject` (явная ошибка).

## 3. Шаги реализации

### Шаг 0. Первый проход перевода (опционально)

Если язык ещё не покрыт: `POST /api/v1/translations/{project}/{component}/{language}/autotranslate/` с `{"mode": "translate", "auto_source": "mt", "q": "state:<translated"}`. Это поднимает черновой слой тем же LLM-сервисом, который настроен в Automatic suggestions; судья затем работает по `state:>=translated`.

### Шаг 1. Настройки и токен

- `.env`: `WEBLATE_URL`, `WEBLATE_TOKEN`, `LLM_API_KEY`, `LLM_API_URL`, `LLM_MODEL`, `JUDGE_BATCH_SIZE` (5–10 юнитов), `LANGUAGE_CODE`, `COMPONENT_SLUG`.

### Шаг 2. Курсор и выборка юнитов

- Хранить позицию в локальном файле состояния (`state.json`): последний обработанный `change_id`/`id` юнита и хэш `target` — юнит, отредактированный после судьи, должен быть пересужен.
- Запрос (основной, скоуп задан URL): `GET {WEBLATE_URL}/api/v1/translations/{PROJECT}/{COMPONENT}/{LANGUAGE}/units/?q=state:>=translated&limit=100` + пагинация через `next` — `weblate/api/views.py:3584`. Глобальный `GET /api/v1/units/?q=...` — только запасной вариант; там `component:` матчится по icontains и при одинаковых slug в разных проектах выборка будет шире, нужен ещё `project:`-фильтр.
- Пропускать юниты, где хэш `target` уже в `state.json` (идемпотентность).

### Шаг 3. Судья

- Батчить юниты в один промпт (формат JSON-массива, как в `weblate/machinery/llm.py` — там же готовая схема плейсхолдеров `@@PH\d+@@` для копирования).
- Для каждого юнита: back-translation + вердикт + причина.
- Таймауты и ретраи с экспоненциальной паузой; при 429 — пауза, не ретрай-шторм.
- Лимит: не больше X юнитов за прогон (защита от стоимости); остаток на следующий прогон.

### Шаг 4. Запись результатов

По вердикту:

- **pass**: `POST /api/v1/units/{id}/comments/` с текстом `[LLM-judge] OK — {краткое обоснование}`. Комментарий виден в UI; этого достаточно для аудита.
- **flag**: `PATCH /api/v1/units/{id}/` с `{"state": 10, "target": ["<список форм плюрала как в GET>"]}` (needs editing/fuzzy) + комментарий с причиной. Юнит попадает в фильтр «needs editing» для человека. Состояния 11/12 через API выставить нельзя — только 10.
- **reject**: `POST /api/v1/units/{id}/suggestions/` с исправленным переводом + комментарий. НЕ принимать автоматически — человек решает.
- **НЕ делать `state=30` из коробки.** Авто-одобрение LLM-вердиктом — отдельная настройка `ALLOW_AUTO_APPROVE=false` по умолчанию; включать осознанно и только для pass-вердиктов, и только когда `translation_review` включён.

Все изменения — через один сессионный клиент с заголовком `Authorization: Token {WEBLATE_TOKEN}`.

### Шаг 5. Запуск

- Ручной прогон: `python judge.py --language xx --component proj/slug`.
- Регулярный: cron/systemd timer раз в N часов.
- Сухой режим: `--dry-run` печатает вердикты, ничего не пишет. Первый прогон — только так.

## 4. Риски и как их закрыть

| Риск | Митигация |
|---|---|
| Модель галлюцинирует ошибки на редком языке | Судить через back-translation, а не прямую оценку; `flag` вместо `reject` при низкой уверенности |
| Self-judge (та же модель судит свой перевод) | Разный провайдер/модель для перевода и суда |
| Лавина записей в API | Батчи, лимит на прогон, ретраи с паузой, идемпотентный курсор |
| Юнит изменился между выборкой и записью | Хэш `target` в `state.json`; при несовпадении — пропуск и пересуд |
| Бот случайно одобряет мусор | `ALLOW_AUTO_APPROVE=false` по умолчанию; approve только с `unit.review` и включённым `translation_review` |

## 5. Критерии готовности

1. `--dry-run` на реальном компоненте даёт вердикты без записи.
2. Прогон пишет комментарии и `state=10` для флагов, предложения для reject.
3. Повторный прогон по тем же юнитам ничего не меняет (идемпотентность).
4. Изменённый юнит пересуживается на следующем прогоне.
