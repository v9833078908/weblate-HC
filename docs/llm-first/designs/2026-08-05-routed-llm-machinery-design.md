# Routed LLM Machinery — дизайн

## Цель

Добавить в локальный пакет `weblate_customization` один движок автоматических
предложений, который отправляет запросы в OpenRouter и выбирает model ID по
целевому языку. Таблица маршрутов хранится в настройках Weblate и может быть
заменена целиком на уровне проекта.

## Границы

- Один API-ключ и один OpenAI-совместимый `base_url`.
- Значение `routing` — JSON-объект `код языка → model ID`.
- Маршрут ищется в порядке: точный нормализованный код, базовый код, `"*"`.
- `-` и `_` эквивалентны, регистр не учитывается.
- Карта без `"*"` допустима: для остальных языков движок возвращает
  `is_supported=False`.
- Конфигурация проекта заменяет всю конфигурацию сервиса, а не объединяет только
  поле `routing` с глобальными настройками.
- Production-деплой не входит в задачу.

## Архитектура

`RoutedLLMTranslation` наследует `OpenAITranslation`, чтобы повторно использовать
Bearer-аутентификацию, OpenAI chat-completions payload и разбор ответа. Получение
списка моделей переопределяется: `get_model()` возвращает model ID из маршрута и
не вызывает `/models`.

Оба публичных sync-входа `BaseLLMTranslation` сходятся в
`_download_multiple_translations`, а оба async-входа — в
`_adownload_multiple_translations`. Кастомный класс перехватывает эти две общие
точки, сохраняет target language в `ContextVar`, вызывает родительскую реализацию
и сбрасывает context token в `finally`. Это покрывает обычные и pending-запросы,
не дублируя четыре публичные сигнатуры и не оставляя устаревшее состояние после
ошибки.

## Форма и валидация

`RoutedLLMMachineryForm` наследует базовые OpenAI/LLM-поля, но удаляет поле
`model`, потому что единственным источником model ID является `routing`. Поле
`routing` обязательно и использует `EmptyMappingJSONField` с `Textarea`.

Валидация:

1. принимает только непустой JSON-объект;
2. разрешает специальный ключ `"*"`;
3. проверяет остальные ключи через `validate_language_code` и
   `Language.objects.fuzzy_get_strict`;
4. запрещает пустые model ID;
5. запрещает коллизии после нормализации, например `pt_BR` и `pt-BR`.

Стандартный `validate_settings()` Weblate всегда проверяет `en → de`, что
несовместимо с картой без fallback. Кастомная реализация выбирает первый явный
маршрут, а для карты только с `"*"` использует штатный `de`, затем выполняет
обычный тестовый chat-completions запрос. Ошибка API остаётся видимой ошибкой
формы.

## Ошибки и безопасность

- Если активный target language не имеет маршрута, `get_model()` поднимает
  `MachineTranslationError` до отправки HTTP-запроса.
- `openrouter.ai` добавляется в `trusted_error_hosts`, чтобы project-level
  конфигурация могла показывать безопасные детали ошибок этого известного хоста.
- `base_url` остаётся `WeblateServiceURLField`; существующая защита от private
  targets для project-level настроек сохраняется.
- Пользовательские подписи и help text переводимы.

## Проверка

Тесты должны отдельно доказать:

- валидацию формы, включая карту без fallback и конфликтующие коды;
- точный, базовый и fallback-маршрут;
- отсутствие поддержки без маршрута;
- sync/async × multiple/pending data flow;
- отсутствие запроса к `/models`;
- отсутствие HTTP-запроса для неподдерживаемого языка;
- сброс route context после успешного запроса;
- успешную регистрацию через `WEBLATE_ADD_MACHINERY`.

Dev-smoke запускается на порту 3001. Для этого `rundev.sh` должен уважать уже
заданное значение `WEBLATE_PORT` через shell-default вместо безусловного
присваивания 8080.
